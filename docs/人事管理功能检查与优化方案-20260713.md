# 人事管理功能检查与优化方案

检查日期：2026-07-13  
检查范围：员工档案、入职管理、资料完整度、入职导入、导入导出、岗位入职配置，以及对应移动端流程  
运行方式：本机原生网关、认证、系统服务、前端、MySQL、Redis；未使用虚拟机、Docker 或其他容器

## 一、结论

人事管理已经具备员工档案、入职、调岗、离职、资料完整度、导入导出和岗位规则配置等主流程，权限、脱敏、幂等和高风险二次确认等基础设计较完整。但真实数据和实际页面暴露出三类核心问题：

1. **流程解释不足**：入职单显示 100% 完整，仍无法继续，原页面没有说明组织主数据阻塞原因。
2. **高风险操作易误确认**：离职类型、工资结算、资产交接、竞业决定原先带有安全结论默认值；调岗、离职和岗位配置弹窗在 1280×720 下看不到操作区。
3. **移动端效率较低**：完整度页面一次展开几十个缺失字段，员工档案没有搜索且组织范围文案容易误导，技术码直接展示给 HR。

本轮已直接修复以上高风险和高频问题，并完成真实页面复验。当前员工数据基线为 155 人、完整档案 0 人、待补资料 155 人、平均完整度 32%、账号配置风险 1 人。接下来的重点不再是继续堆页面，而是建立“缺失数据负责人 + 批量治理 + 组织主数据质量门禁”。

## 二、检查步骤与证据

1. 盘点人事菜单、路由、接口、权限点、字段脱敏及桌面/移动端入口。
2. 以管理员账号和真实测试数据走查员工档案列表、详情、编辑、调岗和离职。
3. 走查入职列表、新建、详情、标记就绪、确认、导入和岗位配置。
4. 走查资料完整度的员工、组织、导入导出和岗位配置联动。
5. 在 1280×720 桌面视口检查弹窗可见性、操作密度和错误说明。
6. 在 390×844 移动视口检查信息密度、触控动作、搜索、底部操作区和安全区。
7. 结合接口返回、服务实现和数据库记录核对“页面状态—服务端规则—主数据”一致性。
8. 修复高优先级问题，运行前后端定向测试、生产构建，并按相同数据重新截图复验。

## 四、本轮已实施的优化

### 1. 入职流程可解释性

- 详情接口新增就绪阻塞码，且使用防御性列表复制。
- 桌面和移动端把阻塞码翻译为业务语言；未知码保留安全兜底提示。
- 100% 完整但被组织主数据阻塞时，明确显示修复方向。
- 移动端草稿在服务端允许时优先显示“标记资料就绪”；被阻塞时仍优先“补充资料”。
- “员工档案 · EMPLOYMENT”改为“入职后完善 · 合同社保”，避免把入职后资料误认为当前阻塞项。

### 2. 高风险操作防误用

- 离职关键结论全部取消默认值，表单项补充属性和明确占位提示。
- 空选项不会提前触发高风险判定；非标准离职、未结算、未交接、竞业待定等仍进入二次确认。
- 调岗薪资合计改为四项自动计算，降低分项和合计不一致风险。
- 三类长弹窗均采用固定页脚和正文滚动，在常见笔记本视口可完成操作。

### 3. 移动端效率与可读性

- 完整度缺失字段默认仅显示 3 项，可展开/收起，展开动作不会误跳详情。
- 员工档案增加搜索入口，组织范围文案与实际查询范围一致。
- 合同日期标准化；人员类别、操作类型、状态变化改用中文业务语言。
- 关键按钮保留明确文本和可访问名称，员工卡片使用显式“去补资料”入口。

### 4. 无障碍与一致性

- 修正 Element UI 多抽屉重复标题 ID 导致的错误可访问名称。
- 表单关键项补充字段属性，展开控件提供 `aria-expanded`。
- 优先复用桌面端既有入职日志呈现规则和现有视觉系统，没有新造一套风格。

## 五、后续实施方案

### 第一阶段：主数据止血（1～3 个工作日）

1. 导出所有在用组织的公司、门店、岗位、部门负责人、法人主体配置缺失清单。
2. 按组织负责人补齐数据，优先处理正在阻塞入职的组织。
3. 组织或岗位启用前增加完整性校验：负责人、所属公司、门店映射、默认岗位配置缺一不可。
4. 在人事首页增加“主数据阻塞”队列和责任人，而不是让 HR 在单据里逐条发现。

验收标准：所有草稿/待确认入职单的阻塞原因可见；在用组织关键派生字段缺失数为 0。

### 第二阶段：员工档案批量治理（1～2 周）

1. 按字段归属拆分责任：员工本人、直属主管、组织管理员、HR、合同/社保专员。
2. 生成“组织 × 缺失字段 × 人数”治理清单，支持批量导出、预览导入和失败原因回传。
3. 将只读派生字段与可编辑字段分开统计，避免 HR 被系统字段反复提醒。
4. 对合同到期、账号待配置、离职账号、敏感资料缺失建立明确 SLA。

建议目标：30 天内平均完整度从 32% 提升到 60% 以上；90 天达到 85% 以上；关键合同/身份/组织字段达到 95% 以上。

### 第三阶段：日常效率优化（2～4 周）

1. 调岗改用法人主体主数据选择器，自动带出 ID、编码和名称。
2. 完整度组织榜默认按缺失人数和完成度升序排序，并支持一键进入对应员工队列。
3. 员工列表保留一个主动作，其余动作收进更多菜单，降低误触。
4. 移动端负责人选择改为远程搜索、最近使用和当前组织优先。
5. 建立人事流程指标：首次完成时长、退回率、阻塞原因分布、重复导入率、离职账号停用时延。

## 六、验证结果

- 前端人事定向测试：15 个测试文件，0 失败。
- 后端定向测试：111 个测试，0 失败。
- 前端生产构建：成功；仅保留现有入口体积告警，未发现本轮编译错误。
- 真实页面验证：桌面 1280×720、移动 390×844 均完成复验。
- 未使用虚拟机或容器；包含 Testcontainers 的全量集成测试未运行，改用不依赖容器的明确测试类覆盖本轮服务和控制器变更。

## 七、检查边界

- 本轮以管理员账号和当前测试数据为主，未完整覆盖普通 HR、组织负责人、只读审计员等所有角色组合。
- 为避免改动真实人事状态，调岗、离职、确认入职只验证到提交前和服务单元/控制器测试，没有对现有员工执行破坏性确认。
- OA、库存等非人事服务在本机未全部启动，顶部聚合待办会显示部分来源不可用；不影响本轮人事核心接口和页面检查。
- 本轮没有实施法人主体主数据选择器和批量档案治理，它们需要确定主数据归属和数据清洗责任人后再落地。
