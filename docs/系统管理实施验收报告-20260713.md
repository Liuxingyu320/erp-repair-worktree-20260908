## 2. 已完成的功能与优化

### 2.1 权限和数据范围

- 非法数据范围改为 fail-close，避免配置错误时退化为全量数据。
- 用户、角色、菜单、部门、薪资、门店授权等关键入口补齐控制器和服务层双重校验。
- 用户授权角色、角色授权用户、重置密码、导入模板、配置/字典刷新、日志详情、登录解锁等操作改为独立权限，不再复用过宽权限。
- 在线用户列表增加用户数据范围过滤，普通管理员不能看到范围外账号的 IP、设备和会话信息。
- 菜单树、角色菜单树等辅助接口补齐读取权限和角色数据范围校验。
- 门店授权候选人改为最小字段接口，减少手机号、档案字段等无关信息返回。
- HR 敏感字段默认脱敏，显式查看只返回申请字段并记录元数据审计。

### 2.2 账号和凭据生命周期

- 新增 must_change_password 状态，存量账号不被误锁。
- 创建、导入、重置账号统一生成安全随机的一次性临时密码。
- 临时密码只在创建结果中显示一次，响应禁止缓存，操作日志不记录密码请求或响应。
- 首次登录只能访问改密、个人必要信息和退出接口；改密后恢复正常权限。
- 管理员重置密码后撤销目标用户全部旧会话；扫描超出安全上限或批量读取不完整时 fail-close，不返回虚假的成功。
- 会话撤销由逐键 GET 优化为每批 500 个键的 MGET，避免 1 万会话场景出现大量网络往返。
- Excel 临时凭据及失败明细增加 CSV 公式注入防护。

### 2.3 审计、安全和在线会话

- 操作日志统一脱敏密码、令牌、手机号、证件号、银行卡号和异常文本。
- 日志列表不再返回大段请求/响应正文，详情查询使用独立权限。
- 登录锁定状态可查询，解锁使用受控 POST 写操作并返回前后状态。
- 日志时间统一为 Asia/Shanghai。
- 日志清理由无痕清空改为带批次、时间范围、行数和校验摘要的归档治理。
- 在线列表与密码重置会话撤销均使用有上限的 SCAN，不再调用 Redis KEYS。
- 在线列表明确返回截断状态，支持筛选、分页、损坏键容错、自身会话保护和超级管理员保护。
- Redis 不可用或扫描不完整时返回可识别错误，避免管理员误以为旧会话已全部失效。

### 2.4 数据一致性和并发保护

- 参数配置、薪资方案、薪资明细和调拨审批规则增加版本字段及乐观锁。
- 角色修改和数据范围修改会检查受影响行数，失败时不会继续重建关联数据。
- 菜单、部门批量排序会检查每次更新结果，并发删除或变更时整批回滚。
- 薪资方案支持影响预览、修订快照、历史查询、回滚和紧急修改原因。
- 薪资方案及明细的更新、删除都校验预期版本，避免并发覆盖。
- 调拨审批规则更新/删除要求 expectedVersion，规则和审批节点写入保持事务一致。
- 调拨规则保存前校验目标门店、岗位边界、候选人、冲突规则和审批链完整性。

### 2.5 使用体验

- 用户新增/编辑改为分步向导，明确账号、组织岗位、角色范围和确认步骤。
- 用户编辑采用差量提交，减少隐藏字段或旧页面数据覆盖新数据。
- 用户列表增加角色数、管理范围数、配置状态、列偏好和快捷补齐入口。
- 角色页整合基本信息、菜单权限和数据范围，并提供有效范围预览。
- 参数配置增加类型说明、敏感键保护和并发冲突提示。
- 薪资方案增加影响统计、历史版本和回滚入口。
- 调拨审批规则改为四步向导，提供阻断问题、警告确认、候选人来源和模拟结果。
- 组织和菜单排序增加变更计数、撤销以及未保存离开提醒。
- 最终浏览器复核发现并修复调拨审批抽屉的读屏标题串台问题；现在可被正确识别为“编辑审批规则/新增审批规则”，关闭按钮也具有正确语义。

### 4.2 四角色关键结果

- 超级管理员可以访问系统与 HR 全局范围，但高危操作仍有独立权限和确认。
- 普通系统管理员只能访问授权功能和同部门数据，跨部门详情返回 403。
- HR 只能访问 HR 范围，默认看到确定性脱敏数据；显式查看只返回申请字段并产生审计。
- 门店负责人首次登录被强制改密，改密前直接业务 API 返回 428；改密后只能进入授权门店。
- 操作日志详情、账号解锁、薪资紧急回滚等高危能力未错误授予普通角色。

## 8. 回滚边界

- 应用按“前端 → 后端”的顺序回退。
- 数据库只回滚脚本明确声明的可逆结构和权限项。
- 已生成的一次性密码、用户已完成的改密、审计归档和业务修订记录不做破坏性恢复。
- 若出现数据一致性问题，先关闭相关写入口，再核对新版本期间的 must_change_password、薪资修订、调拨规则版本和审计归档批次。
- 若只有页面交互问题，可以先回退前端；若涉及版本字段或写入契约，前后端与数据库必须按清单整体回滚。
