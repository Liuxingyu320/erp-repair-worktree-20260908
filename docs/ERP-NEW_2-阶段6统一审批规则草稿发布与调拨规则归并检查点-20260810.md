# ERP-NEW_2 阶段 6：统一审批规则草稿发布与调拨规则归并检查点

> 状态：`INV_TRANSFER` 统一规则写入切片和隔离 Mock 闭环已完成；真实独立运行环境、数据库集成和浏览器 E2E 尚未执行

## 1. 本阶段结果

- `/approvals/rules` 在原有规则版本只读审计基础上新增受权限控制的调拨规则配置面板。
- 新前端只允许写入 `INV_TRANSFER` 原生固定模板；其他审批业务继续只读，不提供通用任意流程编辑器。
- 新建规则与初始草稿、复制已发布版本为草稿、受控条件保存、候选人预览、发布和停用已形成同一 Gateway 状态机。
- 调拨审批节点固定为 `L4_MANAGER → L3_MANAGER → OPERATIONS_DIRECTOR → GENERAL_MANAGER`，浏览器不可增删、改序或改审批类型。
- 旧库存调拨规则页归并到统一审批规则中心；旧页面、旧接口和兼容运行链均未删除，也未切换运行开关或迁移数据。

## 2. 契约与安全边界

- 所有写命令要求 CSRF，并使用同值的稳定 `X-Request-Id` 与 `Idempotency-Key`；失败重试复用请求身份，载荷变化后轮换。
- 新建、范围更新、创建草稿、保存草稿、发布和停用的后端入口增加 30 秒重复提交保护；这只证明短时重复提交抑制，不冒充持久化结果重放。
- 编辑使用服务端乐观锁；发布必须基于已保存草稿和当前有效预览，停用必须填写原因，两者均要求显式二次确认。
- 规则读写响应全部要求 `Cache-Control: no-store`；后端规则控制器同时写入 `Pragma: no-cache`。
- 条件字段、操作符和值类型均使用白名单校验；预览只发送调拨类型、申请人、来源/目标组织及业务子类型，不向只读投影扩散原始用户、部门或内部配置快照。
- 管理配置省略组织头，并依赖 `approval:template:edit` 与 `approval:template:publish` 精确权限失败关闭。

## 3. 前端交互与设计

- 桌面端以规则目录、版本审计和右侧配置面板组成单页工作台；窄屏下改为纵向信息流，写操作与危险操作保持清晰分组。
- 固定节点以不可编辑步骤展示，条件采用结构化表单，避免让管理员直接编辑原始 JSON 或内部候选配置。
- 动效遵循 Motion Primitives 的克制反馈原则：只使用短时、可中断的状态过渡；`prefers-reduced-motion` 下关闭非必要动画。
- 信息结构参考用户指定的 21st.dev、React Bits、UI Prompt Library、Magic UI、Motion Primitives、Uiverse 与 MotionSites 提示方向，但未复制外部组件、提示词、素材或品牌组合，也未新增依赖。
