**需要先定清楚的实现契约**

- 图片：建议新增明确的imageUrls列表契约和兼容存储，旧imageUrl作为封面继续提供给旧只读页面；新增方案字段不是现有字段事实。不能只把limit从1改5，也不能把多张URL继续交给单图src。旧客户端执行单图编辑可能覆盖多图时，应拒绝该旧写入或要求使用新界面；只兼容旧客户端读取不等于允许旧写入覆盖。
- 图片清空：字段未提供表示保留，显式空列表表示删除全部引用。先正常保存再重新读取验证；上传完成并不代表业务记录已保存。
- 附件：从当前表单移除与物理删除分开。编辑取消、业务保存失败均保留原文件。遗留未绑定文件可以暂存，清理需要独立引用核验与保留期方案。
- 报销：不默认先自动保存整个草稿再删票。删除只合并服务端发票、关联持久费用项及版本；未保存标题/用途/金额/新行及删除请求期间的本地修改继续保留，dirty继续为真。冲突写操作串行化，迟到响应必须绑定报销ID。
- 内容更新：备注、试用日期、图片、复盘数量都区分“缺失、明确清空、有效值”。不得直接删除通用Mapper的非空条件，否则发送、签署、取消等局部状态对象可能误清数据。
- 销售退货：尽量通过原salesDetailId关联原行；物料类型＋编号共同定位，不能将礼盒编号当商品编号。原单同一种物料不同价格的行也不能混算。新建与编辑当前退货单采用正确的自身占用排除规则。
- 采购：不能因为订单存在待检部分就整单禁止普通退货，已经合格入库部分仍应按剩余额度处理。统计批次累计量和逐次质检增量时不得连接后重复求和；旧流程缺少完整批次事实时按有证据的兼容规则处理。
- 质检幂等：同一请求身份绑定账号/仓库、采购单、批次、数量分类、原因、附件等摘要；数据库同事务保存认领、业务结果与库存事实。同身份不同内容拒绝。重复操作仍校验当前权限。查询暂未找到不代表可以换新身份；未知结果继续用原身份核对或重放。
- 盘点：实盘允许非负数但不受旧实盘上限限制；复盘规则明确。后台默认阈值为0、PC新建默认1，不能宣称所有手机新建都必需复盘；验收应显式创建正阈值案例。历史快照不能通过本次迁移悄悄改成当前库存。
- 合同：草稿员工信息与权威档案的比对不能扩大个人信息读取权限。切换员工不得继承上一人的身份证/手机号；已签署/冻结合同和原始证据不自动刷新为当前档案。

- 数据迁移以新增兼容为主，保留旧字段和历史证据；回填只处理可确定关联的行，歧义行单列处理，不猜测。
- 多图、礼盒退货、通用物料盘点或质检持久请求产生新数据后，旧程序可能无法正确处理；不能直接回退旧程序继续写入。应准备理解新数据的兼容回退版本，或暂停受影响写入口并保留查询，优先前向修复。
- 生产配置变更前保存当前有效配置；验证新配置后再切换，回退恢复原配置并复验真实文件URL。不能仅依据仓库模板认定线上配置。
- 不删除库存、质检、退货流水来“回滚”，不自动重算历史金额，不自动恢复或重写合同身份。
- 代码修复不会自动恢复已物理删除的附件；若只读核验发现受影响记录，核对授权备份后另出逐项恢复方案。
- 历史异常只读检查建议覆盖：取消但有已确认销售退货入库的记录、待检批次关联采购退货、疑似重复质检、无效文件引用、多物料身份缺失、合同账号与身份冲突。这些是核验方向，不是已确认线上有此类坏数据。

**明确排除与完成边界**

- 不把头像API中手写Content-Type直接判为根因：当前Axios在浏览器FormData路径会清除该头，先前内存核验已排除这一误报。
- 当前OE/礼盒上传走inventory业务权限接口和内部上传，不能据通用file:upload要求认定这两页必然403。
- 手机OE/礼盒目前仅查询，不把“缺少编辑入口”当成未经要求的新功能缺陷；本轮要求是多图及展示闭环。
- 不恢复有意退役的OE补货或固定资产超额审批流程，不修改已有考勤工作内容。
- 不把所有现存单据认定为损坏；不把内存测试当真实库、真机或生产验收。
- 本文完成“汇总与方案”；修复实施、数据治理和生产发布是后续可审定动作。本轮没有创建实施工作树、提交、合并或部署。
