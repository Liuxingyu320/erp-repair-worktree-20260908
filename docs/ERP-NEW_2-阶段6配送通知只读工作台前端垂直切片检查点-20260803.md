## 1. 本检查点结论

`erp-ui-next/` 已新增 `/sales/delivery-notices` 配送通知只读工作台，使用 `inventory.delivery-notice.view` 与 `inv:deliveryNotice:list` 双重门禁，只在销售门店或发货仓库叶子上下文读取 ERP-NEW_2 隔离 Mock。页面覆盖通知单号、销售单号、客户和状态筛选、服务端分页、当前页状态指标，以及桌面表格与移动卡片的等价展示。

本切片没有提供详情、生成通知、执行发货、取消或导出入口，也没有把库存扣减、出库流水或跨店调拨描述为已迁移。

## 2. 契约与隔离证据

- 列表端点：`GET /inventory/deliveryNotice/list`。
- 入口权限：`inv:deliveryNotice:list`。
- Reader 只发送 `pageNum`、`pageSize`、`noticeNo`、`salesOrderNo`、`customerName`，以及精确 `status` 或固定 `statusGroup=deliverable`；同时只发送一个当前会话 `Dept-NumId`，GET 不发送 CSRF。
- 请求前通过 `expectedOrganizationId` 拒绝组织漂移；门店上下文解析后拒绝任一跨销售门店记录。
- 仓库上下文要求每行拥有与当前仓库相同的唯一 `warehouseId`；聚合仓库名称但缺少唯一 ID，或返回其他仓库 ID 时整页失败关闭。
- 状态闭集为 `pending`、`delivering`、`completed`、`cancelled`；未知状态失败关闭。
- Java Long 与有效本地创建时间由运行时契约校验。
- 来源销售单 ID、详情、内部操作人、数据范围参数、更新字段与跨商品单位数量汇总均被丢弃。
- 默认 Provider 仍只注入 ERP-NEW_2 隔离 Mock；真实 HTTP Reader 未接入应用启动流程。
- 后端列表响应没有显式 `Cache-Control: no-store` 证明；逐仓归属也依赖当前兼容返回，这是生产注入阻断项。
