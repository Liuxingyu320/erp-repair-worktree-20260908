## 1. 实际结果

1. 收货页不再依赖旧的扁平任务模型，改为消费服务端权威收货规划；allocation、可选正常/隔离库位、待收 serial、剩余量与 `receiptPlanVersion` 均来自同一份规划响应。
2. 新增严格的收货 Draft、创建命令、创建结果和 Mock 演练结果契约。所有数量均为十进制字符串并用 Decimal 校验，最多四位小数；`finalizeShipment` 由规划总剩余量与本次分类总量推导，不能由页面任意指定。
3. lot allocation 支持合格、残损、短缺数量分类；serial allocation 逐件选择处置并反推数量。命令构造器拒绝越量、重复或非候选 serial、非候选库位、blocked/complete allocation、空命令以及夹带字段的零数量分类。
4. 残损或短缺必须同时具备差异说明与证据引用。Mock 证据使用显式 `local-only:` 标识；真实 HTTP Writer 在发请求前拒绝该标识，避免把浏览器演练数据误送到后端。
5. 新增未注入的真实 `TransferReceiptWriter`：只向 V2 收货路径发送后端 DTO 字段，并校验正整数服务端 ID、请求标识、组织/CSRF 头和严格响应守恒。默认应用组合仍使用 unavailable Gateway，不创建真实运行时接线。
6. 页面主操作先进入可聚焦的二次确认面板，再调用 Mock simulator；同一次确认和失败重试复用稳定请求标识。blocked 规划只展示服务端阻断原因并禁用提交。
7. 后端 V2 创建结果中的数量字段改为十进制字符串，与正式前端契约一致；Mutation Executor 返回规范化字符串，既有写事务和幂等边界未改变。
