# 联合修复候选的发布顺序与回滚边界

本文件描述候选代码的发布要求。本轮仅修改隔离工作副本并运行本地测试，未执行生产迁移、部署或生产业务写入。测试通过也不表示以下发布步骤已经完成。

## 先准备可核验的发布包

1. 固定最终源码快照、构建产物哈希和逐项测试证据。保留当前线上版本、配置和数据库备份，并在隔离数据库验证恢复。
2. 核对服务器容量。2026-09-13 阿里云只读检查看到目标 ECS 系统盘约 92.81% 使用率；此数据是检查时快照，发布前须重新核对可用空间，不能据此自动删除文件。
3. 核对新增 SQL 的目标库与执行顺序。根目录 `sql/` 与 `docker/mysql/db/` 镜像一致；`bootstrap-files.list` 仅供新环境初始化，向其中登记不代表已升级现有生产数据库。
4. 先执行本批经过双版本隔离验证的增量结构，再切换对应后端和前端。已有导出包、签约证据、操作回执、版本号和业务历史均须保留，不得用重建表或重置版本替代升级。

## 必须一起升级的接口

| 修复范围 | 新请求要求 | 缓存旧网页的处理 |
| --- | --- | --- |
| 云盘上传 P03 | 每次逻辑上传携带固定 `operationId`；结果不明时先 GET 原回执，只有服务端 `FAILED_SAFE` 允许用原编号重试 | 新后端拒绝缺少编号的 multipart 请求。同步发布 PC/H5 资源并提示旧网页刷新，禁止降级到无回执上传 |
| 定时任务 P04 | 删除携带固定批次号及每条任务的 `revision`；修改、状态切换、手动执行也携带已读版本 | 旧 DELETE 接口明确要求刷新，不再执行删除；前端每次成功修改后刷新版本 |
| 报销提交/撤回 A11、A13 | 请求携带原审批轮次、实例或编辑版本，服务端在根记录锁内核对 | 旧页面缺少预期状态时拒绝写入，不得将旧意图自动套到新一轮审批 |
| 报销导出 A12 | 创建携带固定 `requestId`，绑定创建人、组织和精确报销集合 | 丢失响应先按原编号核对；重下历史包只走 GET。原包缺失明确显示不可用，不暗中重建新批次 |
| 固定资产配置 ROOT-02 | 先读取整店快照与版本，整批保存携带固定请求号、原版本及完整配置集合；旧单行写入口也必须带原版本 | 同步升级配置页面，旧页缺版本时应刷新，不能绕过整店版本校验。历史成功回执与当前配置版本分开展示 |
| 签约方案 HR-N08 | 发布和恢复携带本次预览票据，绑定操作者、方案内容及当时的活动版本；恢复明确选择一个历史版本 | 旧预览、过期票据或活动版本已变化时重新预览确认，不能静默恢复多个版本 |
| 销售仓库修改 INV-N04 | 变更携带销售单版本，根单、通知和明细在同一事务核对 | 新旧页面混用可能触发版本拒绝，应在切换后刷新页面 |

P01 修改的是公共会话组件：认证、系统服务以及所有通过 `AuthLogic.verifyToken` 续期的服务，都必须使用包含原始字节 CAS 的同批构建。仅升级一个入口不能关闭旧服务写回会话的路径。切换时排空旧实例的在途请求，不能同时保留仍使用无条件 SET 续期的旧实例。此机制阻止旧请求复活被撤销的会话，不中断已经进入业务处理的请求。

P01 还须在新 system 服务启动前执行 `erp_security_session_retention_digest_20260913.sql`，增加可空的会话保留摘要列。员工自行改密只保留当前仍然存在的会话，Redis 故障后的补偿遵守同一规则；管理员重置、停用等管理操作仍撤销全部会话。旧任务的空摘要保持原有全撤销行为，不回填历史任务。混合版本中的旧补偿节点仍可能退出当前设备，因此全部节点切换完成前不能宣称此规则已全量生效；回退时保留新增列。

## 后台同步和文件回执

- 云盘 `SUCCEEDED` 回执与节点、容量写入在同一事务。`PROCESSING`、`CLEANING`、`REVIEW_REQUIRED`、`NOT_OBSERVED` 都不是“可以重新创建”的依据。进程中断后仍需按原编号核对存储和数据库；不能仅因等待时间到了就把未知上传当成失败。
- 首次上传若收到绑定原编号的明确“本次未受理”响应，可以更换文件。它不是旧命令的失败回执；恢复过、停止等待过或已经结果未知的上传仍必须核对原记录。报销首次确定拒绝同样保留勾选供调整，结果未知后的重试拒绝不会清除原命令。
- 定时任务定义、批次和删除意图先在数据库原子提交，随后各调度实例同步本机 Quartz。页面“当前调度器已同步”不代表所有实例都已完成；删除后的旧触发器还受执行前数据库版本校验保护。已经开始执行的任务不由此补丁强行中断。
- 报销 ZIP 仅在事务明确回滚时自动清理。提交状态不确定时保留原 ZIP，按命令与批次记录核对。恢复时不得删除已提交批次引用的文件。
- 任务服务和监控服务在本轮阿里云只读检查中未运行。上线前仍须核对实际启用方式、Quartz JobStore、实例数和监控客户端注册配置；这次未证明线上存在匿名监控访问问题。

## 回滚限制

前端可回滚到已适配这些请求协议的版本。后端回滚前必须确认是否已经产生新回执、任务删除意图或版本化写入；不能直接回退到无条件会话续期、无编号上传或无版本任务修改的实现。需要回退时保留新的回执查询、执行校验和同步处理能力，先停止新增写入并核对在途操作，再进行有证据的版本切换。

数据库新增结构与历史回执应保留。真实历史仓库映射修正、旧证书异常处理以及签约文件修复，不包含在自动执行的迁移内，须先输出明确目标、影响数和可恢复结果。

浏览器登录、实际角色权限、生产数据范围以及 Android/iOS 真机推送和签约交接，需要分别验收并记录。未完成的项目应保留“待验收”，不能因为本地源码或模拟请求通过就标为线上完成。
