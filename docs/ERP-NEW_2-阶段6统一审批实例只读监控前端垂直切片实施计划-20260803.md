# ERP-NEW_2 阶段 6：统一审批实例只读监控前端垂直切片实施计划

> 日期：2026-08-03
> 基线：`7f7866b8 feat: add OA purchase workbench skeleton`
> 状态：实施中；只读统一引擎实例列表切片，不代表审批管理或统一审批闭环迁移完成

## 1. 目标与范围

在 `erp-ui-next/` 内新增 `/approvals/instances` 审批实例监控工作台，覆盖有审批实例列表权限的管理员查看统一引擎实例、按业务类型、业务标识、实例状态和回调状态筛选、服务端分页、当前页状态摘要，以及响应式只读展示。

本切片只实现：

- `GET /approval/instances`；
- 权限 `approval:instance:list`；
- 明确的管理员跨组织只读语义，请求不发送组织头；
- 业务类型、精确业务标识、实例状态和回调状态筛选；
- 服务端总记录数，以及当前页流转中、已通过、已结束和回调异常数量；
- ERP-NEW_2 隔离 Mock 默认运行时和未注入的真实只读 HTTP Reader；
- 桌面表格、移动卡片、加载、错误、空状态和最近成功筛选语义。

以下能力明确留待后续独立切片：原业务旧引擎实例合并、实例详情、节点任务、候选人、审批轨迹、终止、改派、回调重试、流程配置、规则发布、配置检查、真实运行时注入和旧审批管理页面下线。

## 2. 审计结论与硬边界

### 2.1 接口与权限拆分

- 统一引擎实例列表：`GET /approval/instances`，权限 `approval:instance:list`；
- 旧引擎模板和实例列表同样使用 `approval:instance:list`，但属于独立兼容聚合边界，本切片不调用；
- 统一实例详情仅要求登录，服务层按参与人或 `approval:instance:query` 判定；旧实例详情使用 `approval:instance:query`；
- 终止、改派和回调重试分别使用 `approval:instance:terminate`、`approval:task:reassign` 与 `approval:callback:replay`；
- 本切片不得展示详情或任何管理命令伪入口，也不得用列表权限调用其他端点。

### 2.2 跨组织管理员视图

- `ApprovalRuntimeController.list` 与 `ApprovalRuntimeMapper.selectInstanceList` 没有当前组织数据范围条件；SQL 种子只把审批管理菜单和 `approval:*` 权限赋给有效超级管理员；
- 新 Reader 显式省略组织头，不把当前店铺或仓库误表达为服务端过滤条件，也不发送 `anchorDeptId`、`applicantUserId`、`params` 或任意数据范围参数；
- 页面明确标注“管理员跨组织只读”，所选业务组织不改变列表范围；
- 默认 Provider 只注入隔离 Mock；真实 Reader 在版本化 OpenAPI、服务端 `no-store` 和生产等价权限负向测试完成前保持未注入。

### 2.3 状态、字段与敏感投影

- 实例状态闭集为 `RUNNING`、`COMPLETING`、`RETURNING`、`REJECTING`、`WITHDRAWING`、`TERMINATING`、`APPROVED`、`RETURNED`、`REJECTED`、`WITHDRAWN`、`TERMINATED`、`INVALIDATED`；
- 回调状态闭集为 `NONE`、`PENDING`、`PROCESSING`、`RETRY`、`SUCCEEDED`、`DEAD`；未知状态失败关闭；
- 业务类型闭集使用当前统一审批目录的 `OA_PURCHASE`、`INV_TRANSFER`、`INV_STOCK_CHECK`、`HR_HEALTH_CERTIFICATE`；
- 实例 ID、申请部门与锚点组织 ID 必须经过 Java Long 边界；审批轮次必须是非负安全整数；开始和完成时间必须是有效本地时间；
- 新列表只保留实例 ID、模板/业务、业务标识、审批轮次、申请人及部门、锚点组织、当前节点、实例与回调状态、开始和完成时间；
- 根实例、前序实例、模板/规则内部 ID、幂等键、业务快照、摘要、路由快照、内部创建更新字段、备注、锁版本和动作计数不进入模型；
- 跨组织响应必须显式声明 `Cache-Control: no-store`，否则 Reader 失败关闭。当前端点没有该响应头证据，因此仍是生产注入阻断项。

## 3. 设计与动效决策

这是高频 ERP/SaaS 管理监控台，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 使用“管理员跨组织范围 → 服务端总记录/当前页状态 → 明确筛选 → 审批实例事实”的层级；
- 业务、申请人、锚点组织、当前节点、实例状态、回调状态和时间在桌面与移动端保持等价；
- 搜索、状态筛选、键盘提交、分页和列表替换不播放动画；
- 只允许按钮按压的 140ms 可中断 `transform` 过渡；
- `prefers-reduced-motion: reduce` 下关闭所有非必要过渡；
- 不新增 React、Tailwind、Motion、GSAP、远程字体或外部组件依赖。

## 6. 验证标准

- 不安全 Long、非法业务类型、非法状态、负审批轮次、无效时间和越界筛选全部失败关闭；
- 新模型不包含快照、摘要、内部规则/版本 ID、幂等键、内部操作人、锁版本或原始数据范围参数；
- HTTP Reader 只发送允许参数，不发送组织头或 CSRF，并强制响应 `no-store`；
- 默认隔离 Mock 可以展示多个 ERP-NEW_2 模拟组织，且不会读取任何真实或共享业务数据；
- 页面明确区分服务端总记录和当前页状态，不把分页样本误报为全局统计；
- 筛选成功后才更新已应用条件，失败时保留最近成功标签并可重试最后请求；
- 页面没有详情、终止、改派、重试、配置、发布、检查或导出伪入口；
- 功能开关和列表权限同时满足才可见且可访问；
- 完整前端验证、迁移生成器、确定性哈希和隔离扫描通过；
- 旧 `erp-ui/`、受保护原项目、Docker、服务、数据库、依赖和真实配置保持零改动。

## 7. 停止线

发现以下任一情况立即停止：

- 需要读取或修改受保护原项目、连接数据库、启动服务或安装依赖；
- 需要修改旧 `erp-ui/`、注入真实 Reader 或把当前组织头误当作管理员列表的数据范围；
- 需要旧引擎聚合、详情或管理命令而没有独立计划；
- 需要扩大普通用户权限或不能证明跨组织列表仅由管理员权限控制；
- 不能证明全部文件、运行目录和测试只位于 ERP-NEW_2 隔离工作树。
