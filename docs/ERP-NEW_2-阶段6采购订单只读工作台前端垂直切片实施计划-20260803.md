# ERP-NEW_2 阶段 6：采购订单只读工作台前端垂直切片实施计划

> 日期：2026-08-03
> 基线：`8cc79238 feat: add stock inventory workbench skeleton`
> 状态：实施中；只读采购列表切片，不代表采购业务闭环迁移完成

## 1. 目标与范围

在 `erp-ui-next/` 内新增 `/inventory/purchase` 采购订单工作台，覆盖当前仓库的采购订单筛选、服务端分页、业务阶段、供应商、精确金额、申请人、仓库和时间信息，并提供桌面表格、移动卡片、加载、错误和空状态。

本切片只实现：

- `GET /inventory/purchase/list`；
- 权限 `inv:purchase:list`；
- 当前仓库的严格数据范围；
- 订单号、标题、供应商、原始状态和采购日期区间筛选；
- 服务端总记录数，以及当前页待收货、待质检、已完成数量；
- 兼容后端投影的采购业务阶段及保守回退推导；
- Mock 默认运行时和未注入的真实只读 HTTP Reader。

以下能力明确留待后续独立切片：新建、保存、提交、详情、收货、质检、上架、取消、删除、导出、采购退货、批次追踪、成本权限治理、真实运行时注入和真实浏览器验收。

## 2. 审计结论与硬边界

### 2.1 接口与权限

- 旧页面：`erp-ui/src/views/inventory/purchase/index.vue`；
- 旧 API：`erp-ui/src/api/inventory/purchase.js`；
- 后端：`InvPurchaseController`、`InvPurchaseServiceImpl`、`InvPurchaseOrderMapper.xml`；
- 只读列表为 `GET /inventory/purchase/list`，权限为 `inv:purchase:list`；
- `GET /inventory/purchase/{orderId}` 使用 `inv:purchase:query`，不属于本切片；
- 保存、提交、收货、质检、取消、删除和导出均为独立动作，本切片不得展示伪入口或合并权限。

### 2.2 组织与传输边界

- 后端采购服务要求仓库上下文；门店或公司上下文不得发送采购列表请求，只显示“请先切换到仓库”；
- 数据范围由服务端 `requireWarehouseContext` 和 `appendShopScope` 计算，前端不得接收或拼装任意组织 ID；
- 当前旧端点通过 `ShopHeaderUtils` 读取 `Dept-NumId`，真实 Reader 只能显式选择该兼容头，不与默认 `X-ERP-Organization-Id` 双发；
- 请求携带 `expectedOrganizationId`，组织在确认后漂移必须在 `fetch` 前失败关闭；
- GET 不发送 CSRF，维持同源 Cookie；真实 Reader 不进入默认 Mock 应用启动路径。

### 2.3 查询与数据契约

- 分页字段为 `pageNum`、`pageSize`；
- 文本筛选为 `orderNo`、`orderTitle`、`supplierName`；
- 原始状态为 `draft`、`submitted`、`received`、`cancelled`；
- 日期区间必须使用 `params[beginOrderDate]`、`params[endOrderDate]`，不得自创扁平参数名；
- 订单 ID 必须通过安全 Long 边界；日期必须是有效的 `YYYY-MM-DD`；
- 金额和数量必须保留为非负十进制字符串，禁止用 JavaScript 二进制浮点参与业务判断或汇总；
- 列表可以保留总量、已收量、剩余量用于缺失阶段时的兼容推导，但不得把混合单位数量展示为“总件数”。

### 2.4 业务阶段

优先使用后端 `businessStage` 投影；缺失时按照后端现有顺序保守推导：

1. `status=cancelled` → `cancelled`；
2. `status=draft` → `draft`；
3. `qcStatus=pending` → `pending_qc`；
4. `qcStatus=rejected/reject` → `qc_rejected`；
5. `status=received` → `completed`；
6. 已收量大于 0 且剩余量大于 0 → `partial_received`；
7. 其他 → `pending_receive`。

同时接受旧前端已定义的 `pending_putaway` 投影，以兼容后端演进；未知状态、未知阶段和矛盾类型一律失败关闭。

## 3. 设计与动效决策

这是高频 ERP/SaaS 数据工作台，采用 Emil Kowalski 为主、Jakub Krehel 为辅的动效权重：

- 参考 `docs/audit-screenshots/inventory-20260713/06-purchase-list.png` 的业务信息，不复制旧页面布局；
- 结合 UI Prompt Library 的后台信息层级、21st.dev 的组件拆分思路和 Motion Primitives 的克制反馈；
- 搜索、筛选、分页、键盘提交、列表替换不播放入场或布局动画；
- 只允许按钮按压、悬停阴影和焦点反馈等 120～180ms 可中断 CSS 过渡；
- 只过渡 `transform`、`opacity`、`box-shadow` 或颜色，不动画布局属性；
- `prefers-reduced-motion: reduce` 下关闭所有非必要过渡；
- 不新增 React、Tailwind、Motion、GSAP、远程字体或外部组件依赖。

## 6. 验证标准

- 不安全 Long、负数/指数/畸形十进制、无效日期、反向日期区间、未知状态或阶段全部失败关闭；
- 业务阶段优先使用后端投影，只在字段缺失时执行精确 Decimal 回退；
- HTTP Reader 只发送允许的查询参数和一个显式旧组织头，组织漂移和跨仓数据都在前端边界失败；
- 门店/公司上下文不调用 Gateway；
- 页面区分服务端总记录数与当前页阶段计数，不误导为全量阶段统计；
- 筛选只有请求成功后才更新“已应用条件”，失败时保留最近成功标签并可重试最后请求；
- 桌面表格和移动卡片包含同等核心信息，无动作列、无隐蔽 hover 操作；
- 功能开关和权限同时满足才可见且可访问；
- 完整前端验证、迁移生成器、确定性哈希和隔离扫描通过；
- `erp-ui/`、受保护原项目、Docker、服务、数据库、依赖和真实配置保持零改动。

## 7. 停止线

发现以下任一情况立即停止：

- 需要读取或修改受保护原项目、连接数据库、启动服务或安装依赖；
- 需要修改旧 `erp-ui/`、注入真实 Reader 或执行采购写动作；
- 后端组织范围、状态或日期语义无法从当前工作树证据确定；
- 需要启用新建、提交、收货、质检、取消、删除、导出或详情而没有独立计划与安全门禁；
- 不能证明全部文件、运行目录和测试只位于 ERP-NEW_2 隔离工作树。
