# ERP-NEW_2 前端骨架：差异裁决移动主操作栏切片实施计划

> 日期：2026-08-03
>
> 分支：`codex/erp-new-2-rebuild`
>
> 基线：`9632a9e9 feat: extend mobile task actions to approval and shipment`

## 1. 结果目标

在 `erp-ui-next/` 既有库存差异裁决工作台中，把真正可执行的“检查裁决草案 / 检查 Mock 草案”接入统一任务主操作栏，使窄屏用户始终能找到唯一下一步，同时补齐确认层关闭后的焦点恢复。

本切片只调整草案复核交互与设计系统接入，不改变差异事实、双方确认、裁决规则、一次性提交协调器、Mock 边界或任何库存、财务和物流执行语义。

## 2. 设计依据

- 延续 `ErpTaskActionBar` 的移动端固定操作模式，在 767px 以下将唯一主操作固定于底部导航上方，并由宿主高度为正文保留空间。
- 采用 Emil Kowalski 的高频工具交互原则：状态切换直接、焦点可预测，不增加装饰性动画。
- 采用 Jakub Krehel 的可访问性原则：打开确认层后聚焦确认标题；按 Esc 或“返回修改”关闭后，将焦点恢复到重新出现的主操作。
- 参考 Motion Primitives 的状态连续性，但不引入第三方动画库、Tailwind 或新依赖。
- 21st.dev、React Bits、Magic UI、Uiverse、UI Prompt Library 与 MotionSites 仅作为结构和质感参考；严肃 ERP 核心任务不使用粒子、持续光效、3D、弹跳或营销式背景。

## 3. 实施范围

修改 `TransferDiscrepancyAdjudicationDraftPanel.vue`：

- 使用嵌入式 `ErpTaskActionBar` 包裹草案复核主按钮；
- 确认层出现时隐藏底部主操作，避免同时暴露两个相互竞争的下一步；
- 确认层取消后等待 DOM 恢复，再通过组件句柄聚焦主操作；
- 保持原有按钮文案、禁用条件、校验流程和提交边界；
- 不新增动画或过渡。

修改 `TransferDiscrepancyAdjudicationPage.test.ts`：

- 先添加失败断言，证明本地 Mock 与显式协调器路径均暴露同一个语义化主操作组；
- 证明确认层出现时主操作组消失、确认标题获得焦点；
- 证明按 Esc 返回后主操作重新出现并恢复焦点；
- 证明默认只读运行时只暴露不持久化的 Mock 草案主操作，已规划状态不再暴露草案主操作；
- 保持写入次数、只读边界和无物理执行声明的既有断言。

## 4. 验证顺序

1. 运行差异裁决页面定向测试，记录新增断言在实现前失败；
2. 实现主操作栏与焦点恢复；
3. 重跑差异裁决页面和 `ErpTaskActionBar` 定向测试；
4. 执行格式、lint、TypeScript、全量 Vitest、OpenAPI 静态门禁和生产构建；
5. 执行隔离路径、分支、Git 状态与危险引用扫描。

本轮不启动 Vite 或浏览器服务，因此 390px 真机/浏览器视觉验收留在以后获得服务启动授权的检查点；当前使用组件响应式契约与自动化测试验证固定栏、触控高度和内容占位。
