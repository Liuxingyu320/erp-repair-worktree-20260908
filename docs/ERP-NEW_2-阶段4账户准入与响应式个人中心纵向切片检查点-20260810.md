# ERP-NEW_2 阶段 4：账户准入与响应式个人中心纵向切片检查点

> 状态：受限账户准入、统一响应式账户中心与后端自助资料安全边界已完成；真实独立运行环境、文件服务和浏览器 E2E 尚未执行

## 1. 本阶段结果

- 登录会话明确分为 restricted 与 ready：强制改密或资料不完整时只保留本人身份、CSRF、密码策略与限制原因，不读取组织树。
- 受限模式只安装账户 Gateway；库存、审批、OA 等业务 Gateway 保持 unavailable，不能用占位组织绕过准入。
- 新增 /credential/change-password、/complete-profile 与 /account 三条路由；路由守卫只允许受限用户进入与限制原因匹配的页面。
- 旧桌面个人中心、移动个人资料、头像、改密子页和入职资料补全被映射为一套 Vue 3 响应式账户体验；旧前端文件没有删除。
- 应用壳层的用户身份区成为桌面与移动均可访问的账户中心入口；本人入口只要求完整登录会话，不伪造业务功能码或用户管理权限。

## 2. 本人资料与安全边界

- 本人资料响应使用固定 SysSelfProfileVo 投影；前端严格拒绝密码哈希、未知用户字段、越界 Long 和外部头像 URL。
- 改密请求由固定 SysSelfPasswordUpdateRequest 承载，只接受当前密码与新密码；请求体不进入操作日志，未知字段直接拒绝。
- 本人基础资料、资料补全、改密和头像上传均启用 30 秒重复提交保护；前端使用稳定且同值的 X-Request-Id 与 Idempotency-Key。
- 个人资料控制器通过 @ModelAttribute 在请求体绑定前设置 Cache-Control: no-store, max-age=0 与 Pragma: no-cache；各入口直接调用时也保持相同头。
- 头像在前后端均限定 JPEG/PNG 和 5 MiB；前端只接受 ERP-NEW_2 同源路径并及时释放对象 URL。
- 15 项入职资料由服务端重新核验；已保存证件号与银行卡号只返回脱敏投影，前端响应契约主动丢弃任何意外明文。
- 密码提交成功或组件卸载时清空全部密码字段；资料补全页卸载时显式清空短生命周期表单。

## 3. 页面与设计

- 强制改密与资料补全使用独立全屏准入壳层，不渲染业务侧栏、组织切换器或“稍后处理”入口。
- 账户中心采用身份摘要、基础资料、入职资料完整度与安全区；窄屏改为单列，头像和所有主要动作保持可达。
- 继续遵循《ERP-NEW_2 前端设计参考与使用约束》：UI Prompt Library 与 21st.dev 只影响后台信息层级，Motion Primitives 只影响克制的状态连续性。
- React Bits、Magic UI、Uiverse 与 MotionSites 仅用于校验局部质感；没有复制第三方代码、品牌、素材、付费提示词，也没有新增 React、Tailwind、Motion 或动画依赖。
- 所有高频输入即时反馈；不使用持续光效、装饰性背景或循环动画，并保留 prefers-reduced-motion 降级。
