# 新增业务需求确认总结

> 文档状态：需求方向已确认，供产品设计、技术设计和开发排期使用  
> 确认日期：2026-07-13  
> 涉及模块：人事管理、OA 固定资产/OE、客户服务、进销存调拨、门店人员管理  
> 项目级实施方案：[新增业务功能优化实施方案](./新增业务功能优化实施方案-20260713.md)

## 一、建设目标

本次需求围绕门店日常经营补充五项能力：

1. 员工健康证管理，并在员工档案中直接展示当前健康证到期时间。
2. OE 器皿破损上报成功后通知仓库及时补货；超过额度时不允许上报，由员工自行购买。
3. 取消现有客户管理的使用方式，改为门店隔离、门店员工可共同维护的客户服务卡。
4. 将门店返仓并入调拨管理，形成仓库到门店、门店到仓库的双向调拨。
5. 店长可以查看所管理员工的必要信息，手机号完整显示、不脱敏。

总体原则：

- 所有数据必须按门店隔离，不能因为拥有菜单权限而看到其他门店的数据。
- 复用现有员工档案、审批、待办、调拨、库存流水和 OE 档案能力，避免建设重复模块。
- 涉及库存变化的业务必须经过发货、收货确认，不能用手工库存调整代替正常业务流程。
- 允许员工共同维护的数据必须记录创建人、修改人、修改时间，保留操作日志。

## 二、需求总览

| 编号 | 功能 | 确认后的处理方式 |
| --- | --- | --- |
| 1 | 员工健康证 | 独立保存健康证记录，同时在员工档案和店长团队页展示当前证件状态及到期时间 |
| 2 | OE 破损与补货 | 额度内上报成功后自动进入仓库待补货；超过额度上报失败，员工自行购买且无需再上报 |
| 3 | 客户服务卡 | 取消旧客户管理页面，保留必要数据关系，改为本门店员工均可查看和编写的服务卡 |
| 4 | 双向调拨 | 在同一个调拨管理中支持门店要货、门店返仓，并复用同一审批规则体系 |
| 5 | 店长查看员工 | 店长查看本店/本人管理范围内员工的经营管理信息，手机号完整展示，其他敏感信息仍不开放 |

## 三、详细需求

### 3.1 员工健康证管理

#### 3.1.1 数据与档案关系

健康证以独立记录绑定员工，不只是在员工档案表中增加两个固定字段。这样可以保存续办历史，并避免新证覆盖旧证。

每条健康证至少包括：

- 员工 ID、员工姓名、所属门店；
- 健康证编号；
- 办理日期；
- 有效期开始日期；
- 到期日期；
- 发证机构；
- 健康证照片或附件；
- 审核状态：待提交、待审核、有效、已驳回、已过期；
- 审核人、审核时间和驳回原因；
- 创建人、创建时间、修改人、修改时间。

同一员工可以有多条历史健康证，但只能有一条“当前有效健康证”。证件状态根据审核结果和到期日期自动计算，不由使用人员手工填写。

#### 3.1.2 员工档案展示

员工档案列表和详情都需要显示：

- 当前健康证状态；
- 当前健康证到期日期；
- 剩余有效天数；
- 是否即将到期或已经过期。

员工档案中的到期日期来自当前有效健康证记录，不重复维护。点击健康证状态可进入该员工的健康证详情和历史记录。

#### 3.1.3 提醒规则

默认在到期前 30 天、15 天和 7 天提醒，提醒对象包括员工本人、所属门店店长和人事人员。提醒天数应设计为可配置项。

已过期或未上传健康证的员工，在员工档案和店长团队页中突出显示，但本期默认只提醒，不直接停用员工账号。

#### 3.1.4 权限

- 员工：查看本人健康证，上传或更新本人待审核资料。
- 店长：查看所管理员工的健康证状态、办理日期、到期日期和附件是否齐全。
- 人事/管理员：审核、驳回、维护和查看历史记录。
- 非本门店、非管理范围人员：不可查看。

#### 3.1.5 验收标准

- 新证审核通过后，员工档案中的到期时间自动更新。
- 历史健康证不被覆盖或删除。
- 到期提醒只发送一次对应节点提醒，不重复轰炸使用人员。
- 店长只能看到管理范围内员工的健康证信息。

### 3.2 OE 器皿破损上报与仓库补货

#### 3.2.1 普通上报

员工选择本门店已配置的 OE 器皿并填写损坏数量、说明和图片。系统按现有额度规则校验本次上报。

当本次损坏在可用额度内时：

1. 破损上报成功；
2. 扣减对应可用上报额度；
3. 自动生成一条“OE 待补货任务”；
4. 仓库在待办或 OE 补货列表中看到该任务；
5. 仓库发出同款 OE，门店确认收货后任务完成。

默认补货数量等于成功上报的损坏数量。仓库如果调整实发数量，必须填写原因，并同时保留上报数量和实发数量。

#### 3.2.2 仓库可见信息

成功上报后，仓库至少可以看到：

- 上报门店；
- OE 名称、OE 编码、分类、规格和参考图片；
- 损坏数量和建议补货数量；
- 损坏说明及现场图片；
- 上报人、上报时间；
- 当前仓库库存；
- 补货状态和处理人。

补货状态建议统一为：待补货、备货中、已发货、门店已收货、缺货待处理、已关闭。

仓库无库存时不能直接完成任务，应标记为“缺货待处理”，以便后续采购或补货处理。

#### 3.2.3 超过额度

当本次损坏超过可用额度时：

- 本次上报失败，不生成破损上报记录；
- 不扣减额度；
- 不生成仓库待补货任务；
- 员工自行购买替换器皿，购买后无需再发起破损上报。

为了避免员工购买的器皿与门店现有器皿不一致，上报失败页面必须保留当前选择的 OE 信息，并提供“查看同款 OE”或“购买参考”入口。入口中应展示准确的 OE 编码、名称、规格、图片和指定购买链接；不得只跳转到一个无法确认型号的通用商城页面。

页面提示建议明确为：

> 当前损坏金额已超过可用上报额度，本次不能上报，也不会生成仓库补货任务。请按照下方同款 OE 信息自行购买，无需再次上报。

#### 3.2.4 补货闭环

成功上报和仓库补货应形成关联关系，能够从破损上报查看补货任务，也能从补货任务返回原始上报。记录至少包括上报数量、计划补货数量、实发数量和实收数量。

仓库发货时产生 OE 出库记录；门店确认收货后产生门店 OE 入库或资产补充记录。发货与收货存在差异时进入差异处理，不能直接标记完成。

#### 3.2.5 验收标准

- 额度内上报成功后，仓库立即能看到对应待补货任务。
- 额度外上报不会留下半成品记录，也不会进入仓库待办。
- 超额页面可以直接查看与当前器皿完全一致的购买参考信息。
- 仓库不能用其他 OE 型号直接替代；确需替代时必须填写原因并由门店确认。
- 上报、发货、收货和差异处理全程可追溯。

### 3.3 客户服务卡

#### 3.3.1 替换方式

取消现有“客户管理”菜单和原有操作页面，改为“客户服务卡”。

旧客户数据不能直接删除。现有销售单等业务已经引用客户记录，因此应保留客户主键和历史业务关系，将可以继续使用的客户姓名、联系方式、所属门店等数据迁移或复用到客户服务卡中。旧的信用额度、已用额度、账期等字段不再出现在门店客户服务卡页面。

#### 3.3.2 服务卡内容

客户服务卡至少包括：

- 客户姓名或常用称呼；
- 客户照片/头像；
- 联系电话；
- 喜欢的茶类；
- 口味偏好标签；
- 冲泡、器具或服务偏好；
- 忌口、过敏及其他注意事项；
- 常用预算区间；
- 最近到店时间；
- 服务备注和历史服务记录；
- 所属门店；
- 创建人、最后修改人和最后修改时间；
- 状态：正常、停用/归档。

“人均多少钱”本期以“常用预算区间”维护。以后销售单具备用客人数时，可以再增加系统自动计算的人均消费，避免人工填写的数值与实际消费不一致。

#### 3.3.3 门店隔离与编辑权限

- 当前门店全部员工都可以查看、新增和编写本门店客户服务卡。
- 员工只能操作当前选择门店的客户，不得查询、搜索或打开其他门店客户。
- 拥有多个门店权限的员工必须先切换到具体门店，客户列表不能把多个门店数据混在一起显示。
- 所有员工修改均记录操作日志，至少保留修改人、修改时间和修改前后摘要。
- 普通员工不执行物理删除；不再服务的客户改为停用或归档，避免历史销售单失去客户关联。

#### 3.3.4 页面建议

- 列表使用头像、姓名、偏好标签、预算区间、最近到店时间组成的卡片式展示。
- 支持按姓名、手机号、茶类偏好和标签搜索。
- 详情页优先展示服务信息，不再以信用、账期等财务字段为核心。
- 客户照片作为受控业务附件保存，不能通过公开固定地址访问。

#### 3.3.5 验收标准

- 旧客户管理入口被客户服务卡替换，但历史销售单客户关系不丢失。
- 同一门店员工可以共同新增和修改客户服务卡。
- 不同门店之间无法通过列表、详情接口、搜索或导出访问彼此客户。
- 每次修改都能追溯到具体员工。

### 3.4 调拨管理支持门店要货与门店返仓

#### 3.4.1 统一入口

门店要货和门店返仓统一放在“调拨管理”中处理，不再单独建设一个孤立的退货模块。

调拨业务类型包括：

| 业务类型 | 库存方向 | 发起方 | 发货方 | 收货方 |
| --- | --- | --- | --- | --- |
| 门店要货 | 仓库 → 门店 | 门店 | 来源仓库 | 目标门店 |
| 门店返仓 | 门店 → 仓库 | 门店 | 来源门店 | 目标仓库 |
| 异店调货 | 门店 → 门店 | 按现有规则 | 来源门店 | 目标门店 |

创建调拨单时先选择业务类型。系统根据类型自动限定来源和目标组织，防止把返仓单错误设置为仓库向门店发货。

#### 3.4.2 审批规则

门店返仓的审核流程与现有调拨管理完全一致：

- 复用现有调拨审批规则、审批层级、候选人计算和审批记录；
- 进入统一待办中心；
- 支持通过、驳回、退回草稿和审批轨迹；
- 同一套审批规则可以按调拨类型配置，必要时允许门店返仓使用单独规则，但不建设第二套审批引擎。

#### 3.4.3 门店返仓流程

门店创建返仓单 → 提交审批 → 审批通过 → 门店发货 → 仓库验收 → 差异处理 → 完成。

返仓单至少包括：

- 来源门店、目标仓库；
- 返仓原因：库存过多、临期、错发、残损、闭店/撤柜、其他；
- 商品/OE/礼盒类型、编码、名称、规格；
- 批次、生产日期和有效期（适用时）；
- 申请数量、实发数量、实收数量；
- 货物状态：正常、残损、待质检；
- 图片、附件和备注。

#### 3.4.4 库存处理

- 提交审批时校验门店可用库存，必要时锁定待返仓数量。
- 门店确认发货时扣减来源门店库存并生成在途数量。
- 仓库实际验收后增加目标仓库库存。
- 正常品、残损品和待质检品进入对应库存状态或库位，不能全部直接进入可销售库存。
- 实发和实收不一致时进入现有调拨差异处理流程。

#### 3.4.5 页面与权限

- 调拨列表增加业务类型筛选和方向展示。
- 门店上下文可以发起要货、发起返仓、处理本店发货和确认本店收货。
- 仓库上下文可以处理要货发货、返仓收货和验收。
- 操作按钮根据当前组织、调拨方向和单据状态显示，不能只依赖前端隐藏，后端必须再次校验。

#### 3.4.6 验收标准

- 同一个调拨管理入口可以完成仓库到门店和门店到仓库两种业务。
- 门店返仓使用现有调拨审批流程和统一待办。
- 只有来源方可以发货，只有目标方可以收货。
- 发货前、发货后、收货后库存数量和库存流水一致。
- 返仓差异能够进入现有差异处理流程并保留处理记录。

### 3.5 店长查看员工信息

#### 3.5.1 查看范围

新增“我的团队”页面：

- 店长查看当前所属门店的在职员工；
- 其他管理岗位可以按直属主管关系查看本人管理的员工；
- 多门店店长必须先选择具体门店，不在一个列表中混合展示多个门店员工；
- 员工调店或离职生效后，自动退出原店长的查看范围。

#### 3.5.2 可见字段

店长可以查看：

- 姓名、员工照片、工号；
- 手机号，完整显示、不脱敏；
- 所属门店、岗位、直属主管；
- 在职状态、入职日期；
- 健康证状态、办理日期和到期日期；
- 合同到期提醒；
- 员工档案资料完整度。

仍不向店长开放：

- 工资、银行卡号；
- 身份证完整号码；
- 家庭住址、户籍地址；
- 其他与门店日常管理无关的人事敏感资料。

#### 3.5.3 编辑权限

本期“我的团队”以查看和提醒为主。店长发现资料错误时提交资料更正，由人事或有员工档案编辑权限的人员处理；不直接赋予店长修改工资、证件、合同等核心档案的权限。

#### 3.5.4 验收标准

- 店长能够看到本门店员工的完整手机号。
- 店长能够直接看到员工健康证到期时间。
- 店长无法访问其他门店或非本人管理范围的员工。
- 通过员工 ID 直接请求详情时，后端仍会执行相同的数据范围校验。
- 店长页面和接口均不返回工资、银行卡等未授权字段。

## 四、跨模块联动

| 来源业务 | 联动目标 | 联动结果 |
| --- | --- | --- |
| 健康证审核通过 | 员工档案、我的团队 | 自动更新健康证状态和到期日期 |
| OE 额度内上报成功 | 仓库待办/OE 补货 | 自动生成同款 OE 待补货任务 |
| OE 超额上报失败 | 同款 OE 购买参考 | 不生成上报和补货任务，只提供准确型号与购买入口 |
| 客户服务卡 | 销售单历史 | 保留客户 ID 和历史业务关联 |
| 门店要货/返仓提交 | 调拨审批、统一待办 | 使用现有调拨审批链和审批轨迹 |
| 调拨发货/收货 | 库存与库存流水 | 按实际发货、实际收货更新对应组织库存 |

## 五、建议实施顺序

### 第一阶段：人事基础

1. 健康证数据、上传审核和到期提醒。
2. 员工档案展示健康证状态和到期日期。
3. 店长“我的团队”页面及完整手机号展示。

### 第二阶段：OE 上报与仓库补货

1. 成功上报自动生成仓库补货任务。
2. 仓库补货列表、发货和门店收货闭环。
3. 超额失败提示及同款 OE 购买参考入口。

### 第三阶段：双向调拨

1. 调拨管理增加门店返仓类型。
2. 复用审批规则和统一待办。
3. 门店发货、仓库验收、差异处理和库存流水验证。

### 第四阶段：客户服务卡

1. 旧客户数据兼容与服务卡数据升级。
2. 替换旧客户管理菜单和页面。
3. 门店隔离、员工共同编辑及操作日志。

## 六、已确认的关键业务口径

1. 健康证独立保存历史记录，但员工档案必须直接显示当前到期时间。
2. OE 损坏超过额度时上报失败，员工自行购买，且无需再次上报。
3. 只有成功的 OE 破损上报才生成仓库补货任务。
4. 旧客户管理页面取消，改为客户服务卡；旧数据关系不能直接删除。
