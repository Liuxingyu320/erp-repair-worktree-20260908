## 1. 目标与范围

在已提交的 `/inventory/products` 商品目录基础上，补齐 `/inventory/products/:productId` 只读详情闭环：

- 通过真实 `GET /inventory/product/{productId}` 读取当前组织授权范围内的商品详情；
- 列表仅在会话具备 `inv:product:query` 时展示桌面与移动详情入口；
- 详情路由同时要求既有 `inventory.product.view` feature 与 `inv:product:query`；
- 展示商品身份、分类、规格、销售参考价、安全库存、供应商、说明和维护摘要；
- 提供组织不可用、权限不足、加载、失败、重试和移动端布局；
- 延续 Java `Long` 字符串边界、单一组织头、GET 无 CSRF、组织漂移保护和 `no-store` 门禁。

本切片仍然只读，不实现新增、编辑、删除、导入导出、分类维护、供应商维护、图片加载或价格编辑。

## 2. 字段与安全边界

详情模型只投影明确批准的字段：

- 标识：商品 ID、编码、名称、SKU、条码、内部名称；
- 分类与规格：分类 ID/名称/路径、等级、规格、尺寸、单位；
- 运营参数：安全库存上下限；
- 销售参考：销售参考价、250g 与 500g 销售价；
- 供应与说明：供应商名称、商品描述、普通备注；
- 组织与状态：所属库存组织、启停状态。

以下字段即使服务端多返回也不得进入详情领域状态或 DOM：

- `purchasePrice`、`costPrice`；
- `supplierPhone`、`supplierRemark`；
- 图片与附件 URL；
- 删除标记、任意未知扩展字段。

销售参考价不是采购/成本价，但仍按有限非负十进制数解析；畸形、负数或非有限值失败关闭。安全库存上下限同样使用有限非负十进制字符串，并验证上限不得低于下限。

## 3. 权限、组织与响应

- 目录 feature 继续由 `inv:product:list` 发布；详情不新增或猜测 feature；
- 详情路由额外要求 `inv:product:query`，缺少权限时列表不渲染入口，直接访问由路由守卫拒绝；
- 前端权限判断与后端保持一致：管理员 `*:*:*` 通配权限满足精确权限要求，普通账号仍逐项精确匹配；
- 页面组件本身再次检查权限和门店/仓库上下文，避免脱离路由单独挂载时发出请求；
- HTTP Gateway 在构造路径前验证正整数 Long 标识；返回商品 ID 必须与请求一致；响应库存组织由后端授权范围决定，不在前端强制等于当前组织，因为仓库可读取上级共享商品；
- 请求发送一个 `Dept-NumId`，组织在 fetch 前漂移时失败关闭，GET 不发送 CSRF；
- 后端详情端点已在前一检查点完成组织范围校验、成本脱敏和 `Cache-Control: no-store`；前端继续以 `requireNoStore` 验证成功响应。

## 4. 界面与动效

本页属于高频 ERP/SaaS 详情，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 使用“状态摘要 + 分组详情 + 明确读取边界”的信息层级；
- 返回目录、重试等高频操作保持即时，不做页面入场序列或路由转场；
- 只对可点击链接提供约 140–180ms 的可中断按压/悬停反馈；
- 不使用循环光效、弹跳、视差、大幅缩放、布局动画或全局 `will-change`；
- `prefers-reduced-motion: reduce` 下关闭非必要过渡；全部状态以文本和语义结构表达。

1. 扩展 model / contract 失败测试，冻结详情字段白名单、十进制约束、库存上下限和敏感字段丢弃；

6. 更新迁移覆盖层，把“详情”从未迁移清单移入已覆盖范围，但继续保持整体“部分实现”；

8. 全部门禁通过后创建独立本地提交；不推送、不合并。

## 7. 验收与停止线

- 详情响应敏感采购/成本、供应商联系与图片字段不会进入前端领域状态或页面；
- 越界/路径型 ID、负价格、库存上下限倒置、可缓存成功响应、请求前组织漂移和响应 ID 不一致均失败关闭；关联组织的数据范围继续由后端权威校验；
- 无 `inv:product:query`、公司层级或无有效库存组织时不发送详情请求；
- 桌面与移动入口、详情分组、错误重试和返回目录具备可访问语义；
- Prettier、ESLint、TypeScript strict、OpenAPI 门禁、Vitest 和 Vite 构建全部通过；
- 不启动服务、不安装依赖、不执行 SQL、不修改端口/配置/运行数据/旧 `erp-ui/` 或受保护原项目；
- 不删除旧前端，不合并、不推送。
