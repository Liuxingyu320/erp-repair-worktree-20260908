## 1. 检查点结论

已建立两类不改变库存数量的真实、不可变业务效果：责任调整台账与短缺运输损失台账。两类效果由纯策略分类、窄条件 Mapper 追加，并由要求既有事务的唯一效果所有者执行；它们不是财务总账，也没有接入执行入口。

执行入口继续默认关闭。即使两个 Gate 被误开，服务仍会最终无条件硬停止；新增效果所有者与 Mapper 均无入口、Controller、任务或其他生产调用点。

## 2. 成本与执行事实补强

- 执行边界新增裁决冻结的 `source_cost_price`，不从当前商品或库存重算。
- 差异总金额必须精确等于 `round(source_cost_price * discrepancy_quantity, 6)`。
- 成本快照进入事件指纹、执行事件、责任台账和短缺损失台账。
- 历史执行事件结果映射新增成本字段，并增加通用 JavaBean 可写属性一致性测试。
- 事件表滚动 SQL 对已存在的空表也使用幂等加列过程补齐成本字段。

## 3. 两类原子业务台账

责任台账只接受：

- `shortage` 或 `damaged` 差异；
- `responsibility_adjustment` 动作；
- `responsibility_ledger` 效果。

短缺损失台账只接受：

- `shortage` 差异；
- `transport_loss_write_off` 动作；
- `shortage_loss_ledger` 效果，并固定 `loss_type=transport_shortage`。

两张表均保存请求、事项/裁决/动作标识、事项和动作前后版本、三层前后状态、收发货与原调拨锚点、物料、数量、冻结成本、金额、责任方、决定/执行指纹、说明、证据、权限和操作者快照。请求 ID 与动作前版本均有唯一约束。

这些记录是差异处置的权威业务事实。未来会计集成只能从其派生独立凭证，不得回写或覆盖本台账。

## 4. 原子效果所有者

- 纯策略只接受 `dispatch`、`pending -> completed`、动作版本从 0 精确到 1、事项版本精确加一且无子流程引用的已准备执行事实。
- Mapper 只有两个 `INSERT ... SELECT`，会重新核对当前事项、裁决、动作的前状态、版本、数量、金额、责任、成本、决定指纹、权限和幂等条件。
- 两个插入的列数与 `SELECT` 投影数由测试固定，避免字段错位。
- 效果所有者使用 `Propagation.MANDATORY`，没有外层事务时必须拒绝。
- 每次只能选择一个台账插入，受影响行数不为 1 时失败关闭。
- 不更新执行事件、动作、裁决头、事项、库存、调拨单或财务表。
