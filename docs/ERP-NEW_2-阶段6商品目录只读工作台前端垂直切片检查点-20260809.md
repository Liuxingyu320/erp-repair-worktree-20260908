## 1. 本检查点完成内容

新增 `/inventory/products` 商品目录只读工作台，形成从后端权限发布到前端页面的完整安全竖向切片：

- 新增 `inventory.product.view`，后端仅在会话具备 `inv:product:list` 时发布；
- 路由与导航同时要求 feature 和精确列表权限，默认失败关闭；
- 真实 HTTP Gateway 读取 `/inventory/product/list`；
- 会话具备 `inv:category:list` 或 `inv:category:tree` 任一权限时读取 `/inventory/category/tree`，否则不发送分类请求；
- 支持关键词、分类、供应商名称、等级、状态和分页；
- 提供桌面表格、移动卡片、指标、组织不可用、初始加载、空数据、错误保留和分类权限降级；
- 隔离 Mock 使用 ERP-NEW_2 专属确定性商品与分类数据，不引用旧前端运行时代码。

## 2. 成本与缓存安全修复

### 2.1 服务端成本权限

旧行为在无 `inv:cost:view` 时只隐藏 `purchasePrice`，仍返回 `costPrice`。本检查点已修正：

- 商品列表和详情同时清空 `purchasePrice` 与 `costPrice`；
- 具有 `inv:cost:view` 的用户继续获得两个字段；
- 列表与详情均有正向和负向回归证据；
- 新前端 `ProductCatalogItem` 从类型层完全排除采购价、成本价、供应商电话和采购备注；服务端即使多返回字段，Zod 投影后也不会进入领域状态。

商品导出、导入和写操作不属于本只读切片，未借本次工作扩大修改范围；对应成本导出/写权限仍须在后续独立契约中冻结。

### 2.2 缓存与组织边界

- 商品列表、详情和分类树响应返回 `Cache-Control: no-store, max-age=0` 与 `Pragma: no-cache`；
- 前端商品与分类 HTTP Gateway 使用共享 `requireNoStore`，缺少 `no-store` 时拒绝成功响应；
- 请求只发送一个显式 `Dept-NumId` 组织头，GET 不发送 CSRF；
- 会话组织在请求前变化时由 HTTP Client 在 `fetch` 前拒绝；
- 公司层级页面不发商品或分类请求；组织范围和关联组织仍由服务端数据范围决定，前端不提交任意组织集合。

## 3. 运行时契约与异常状态

- Java `Long` 标识只接受安全整数或十进制字符串，并保存为字符串；
- 商品字段使用白名单投影，未知状态、空必填字段、越界标识失败关闭；
- 分类树限制 8 层、500 个节点，并拒绝重复 ID、循环引用和畸形 `children`；
- 分类读取失败不会清空成功商品页；已有分类树刷新失败时继续显示上一次结果并明确标记；
- 商品刷新失败保留上一次成功页和已应用筛选，不把异常伪装成空数据；
- 分类权限是 OR 语义，不被错误提升为商品路由的额外必需权限。

## 4. 界面与动效决策

本页按高频企业 ERP/SaaS 工作台处理，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 吸收用户列出的 21st.dev、React Bits、UI Prompt Library、Magic UI、Motion Primitives、Uiverse 和 MotionSites 的信息层级与交互提示，不复制外部代码、品牌、付费提示词或不明许可证资产；
- 分类、筛选、键盘提交和分页不播放装饰性入场；
- 只保留约 140ms 的按钮按压和悬停反馈，使用项目现有自定义 Bé塞尔曲线；
- 没有循环光效、弹跳、视差、大幅缩放、布局属性动画或全局 `will-change`；
- `prefers-reduced-motion: reduce` 下关闭页面非必要过渡；
- 自审补充筛选栏换行，避免分类侧栏存在时中等宽度主内容溢出。
