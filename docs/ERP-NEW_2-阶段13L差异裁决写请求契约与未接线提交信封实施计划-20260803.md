# ERP-NEW_2 阶段 13L：差异裁决写请求契约与未接线提交信封实施计划

## 1. 结果和范围

在阶段 13K 已完成服务端依据令牌原子消费之后，建立未来 HTTP 写边界两侧都可复用的浏览器安全契约：

- 后端增加 Bean Validation 请求 DTO，并把路径事项 ID、请求头幂等标识与请求体纯组装为阶段 13K 命令；
- 前端增加严格 Zod basis 响应、提交信封和创建结果契约，并能从已二次确认的本地草案纯生成一个 `transport=unwired` 信封；
- 继续保持 Controller、HTTP Writer、Gateway 写方法、页面提交调用、功能码和默认运行时关闭。

本阶段不会产生可调用的真实写接口，不签发或消费 token，不连接数据库，也不执行任何库存、物流、财务或差异处置动作。

## 2. 权威字段来源

未来 HTTP 边界必须保持以下单一来源：

- `requestId` 只来自 `X-Request-Id` 请求头，不在 JSON 请求体重复；
- `discrepancyCaseId` 只来自路径，不在 JSON 请求体重复；
- `selectedOrganizationId` 只来自现有组织请求头，不在 JSON 请求体重复；
- JSON 请求体只包含 `basisToken`、浏览器看到的 `caseVersion`、裁决说明、证据引用和 1 至 20 个动作；
- `factFingerprint`、确认事件 ID、决定指纹、动作金额、执行状态、裁决主键、用户和权限均不得由浏览器提交。

后端 DTO 的纯转换只能把路径和请求头提供的外壳与请求体合成 `InvTransferReceiptDiscrepancyAdjudicationCommand`；阶段 13K 服务仍是事实恢复、权限复核、组织隔离和事务写入的唯一所有者。

## 3. 后端契约

新增：

- `InvTransferReceiptDiscrepancyAdjudicationCreateRequest`；
- `InvTransferReceiptDiscrepancyAdjudicationActionRequest`。

结构门禁：

- basis token 必须满足 `adjb_v1_` 加 43 位 URL-safe Base64 字符；
- 版本必须是 Long 范围内的规范十进制字符串，避免浏览器安全整数截断；
- 说明必填且最多 500 字，证据必填且最多 2000 字；
- 动作 1 至 20 条、序号 1 至 20、数量为最多 14 位整数和 4 位小数的正数；
- 动作类型和责任方只接受裁决策略已知枚举；
- 嵌套列表防御性复制，字符串表示不得输出 token、说明、证据或动作正文。

Bean Validation 只负责传输结构。动作与差异类型兼容、数量守恒、事实版本、双方确认、用户、权限、组织范围和一次性 token 仍由既有服务端策略重新核验。

## 4. 前端未接线提交信封

新增严格契约但不新增 HTTP 调用：

- basis 响应要求服务端来源、事项/版本/组织一致、签发和过期时间为严格 5 分钟窗口；
- 创建结果要求服务端来源、相同事项、固定计划状态和合法时间；
- 提交信封把 `requestId`、路径事项、所选组织与请求体分层，固定 `transport=unwired`；
- 只允许 `ready_for_adjudication`、尚无计划且已经二次确认的本地草案组装信封；
- basis 必须未过期，并与草案事项、版本及当前所选组织完全一致；
- 信封及其日志表示不得持久化或输出原始 token。

契约不加入 `TransferGateway`，不导入页面或 `bootstrap.ts`，不创建 POST/签发 HTTP 模块，不使用 localStorage、sessionStorage、IndexedDB、Pinia 或 URL 保存 token。

## 5. 验证

后端：

- Bean Validation 正向和所有字段负向；
- 反射证明 DTO 不存在内部字段和重复权威字段；
- DTO 到领域命令的映射与防御性复制；
- token 和正文字符串脱敏；
- Controller 源码继续不引用 basis 签发服务、裁决创建服务或新 DTO。

前端：

- 严格 schema 拒绝未知内部字段、非法 ID、token、时间窗、来源、金额和执行状态；
- 拒绝未二次确认、事项/版本/组织漂移和过期 basis；
- 精确生成 header/path/body 分层信封；
- 源码门禁证明 Gateway、页面和默认 bootstrap 均未接线，且没有浏览器持久化调用；
- 运行完整 `npm --prefix erp-ui-next run verify`。

后端运行库存模块完整离线 Reactor，且不执行 MySQL 集成测试或迁移。

## 6. 风险和停止线

- 本阶段形成的是契约，不是可用 Writer；不得以契约测试通过宣称真实写流程已开放。
- 不新增或修改 Controller、`@PostMapping`、`@PersistentCommand`、权限菜单或功能开关。
- 不把 token 放入查询字符串、日志、异常正文、持久化存储或 Mock fixture。
- 不启动 Docker、服务或中间件，不连接数据库，不执行 DDL。
- 不删除旧前端，不合并、不推送。

只有后端和前端契约、脱敏及未接线 Gate 全部通过后，才可单独审查真实 HTTP 写边界；物理处置仍属于更后的独立 Gate。
