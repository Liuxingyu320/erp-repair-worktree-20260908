## 1. 目标与范围

在全新前端 `erp-ui-next/` 内新增 `/inventory/suppliers` 供应商主数据工作台，覆盖旧页面 `erp-ui/src/views/inventory/supplier/index.vue` 的列表、查询、详情、供货商品、新增、编辑、删除和导出能力，同时修复现有后端暴露出的成本越权、备注不落库和名称关联完整性风险。

本切片包括：

- 供应商名称、编码、合作状态、记录状态筛选以及服务端分页；
- 桌面表格与移动卡片的同等核心信息；
- 供应商详情及供货商品投影；
- 新增和编辑基础资料、结算方式、合作状态、记录状态与备注；
- 静态两步删除确认以及服务端引用阻断；
- 有明确范围、敏感字段说明和外发提醒的 Excel 导出确认；
- 独立 model、Zod 运行时契约、Gateway、真实 HTTP 适配器与隔离 Mock；
- 后端响应禁缓存、成本字段权限脱敏、输入归一化、引用安全和备注持久化；
- `inventory.supplier.view` 功能发布、精确权限、路由、导航和迁移证据。

本切片不包括供应商评分、准入审批、资质附件、状态专用权限/原因审计、批量导入、采购流程状态联动或真实浏览器 E2E。旧前端继续保留且不得修改或删除。

## 2. 审计结论与硬边界

### 2.1 接口与权限

| 动作 | 端点 | 精确权限 |
| --- | --- | --- |
| 列表 | `GET /inventory/supplier/list` | `inv:supplier:list` |
| 详情 | `GET /inventory/supplier/{supplierId}` | `inv:supplier:query` |
| 供货商品 | `GET /inventory/supplier/{supplierId}/products` | `inv:supplier:query` |
| 新增 | `POST /inventory/supplier` | `inv:supplier:add` |
| 编辑 | `POST /inventory/supplier/update` | `inv:supplier:edit` |
| 删除 | `DELETE /inventory/supplier/{supplierId}` | `inv:supplier:remove` |
| 导出 | `POST /inventory/supplier/export` | `inv:supplier:export` |

- 路由和导航同时要求 `inventory.supplier.view` 与 `inv:supplier:list`；
- 编辑入口必须同时具备 `inv:supplier:query` 和 `inv:supplier:edit`，避免旧页面“可见编辑按钮但详情接口 403”的权限错配；
- 详情供货商品中的采购价/成本价只在 `inv:cost:view` 下展示，前端隐藏不替代服务端脱敏；
- 保存、删除和导出在真正执行前重新核对权限及组织，不能只依赖按钮是否渲染。

### 2.2 组织与传输边界

- 供应商由当前门店或仓库及服务端相关组织范围管理；公司、缺失组织或未知组织类型不得发起请求；
- 前端只发送当前会话组织头和 `expectedOrganizationId`，不得提交 `shopDeptId`、店铺名称、数据范围或审计字段；
- GET 省略 CSRF；写操作和导出强制 CSRF、组织上下文和合法 `X-Request-Id`；幂等写同时发送同值 `Idempotency-Key`；
- 所有 JSON 成功响应必须声明 `Cache-Control: no-store`；Excel 响应也必须禁缓存；
- 新增通用二进制 HTTP 能力时必须复用现有同源路径、会话、CSRF、组织漂移、错误映射和请求 ID 边界，并限制响应 MIME、大小与文件名来源。

### 2.3 数据契约

- Java `Long` 标识在浏览器中保持十进制字符串，并限制为正数且不超过后端范围；
- 记录状态仅允许 `active/inactive` ↔ `0/1`；合作状态仅允许 `active/paused/terminated` ↔ `0/1/2`；未知值失败关闭；
- 名称必填且最多 128 字符；编码、联系人、电话、邮箱、地址、结算方式和备注使用与数据库/既有业务兼容的明确上限；
- 响应允许历史空值，写命令只接受白名单字段并统一 trim；邮箱写入时验证格式；
- 列表页码从 1 开始，单页上限 100；统计卡明确区分服务端总记录数和当前页状态分布，不能把当前页计数描述为全量；
- 供货商品只接受有限投影，采购价和成本价为可空精确十进制字符串，不用 JavaScript 浮点计算。

### 2.4 名称引用完整性

现有商品和采购退货仍以 `supplier_name` 关联，采购订单同时存在 `supplier_id` 与历史名称快照。普通改名若直接写入会让旧名称引用失联，随后删除保护也可能绕过。

本切片采用保守策略：

- 供应商名称未变化时允许普通维护；
- 名称变化前，由服务端在当前授权相关组织范围内检查商品、采购订单和采购退货引用；存在任一引用即拒绝改名，并提示停用或先治理引用；
- 删除使用同一范围化引用计数，存在任何当前或历史引用即拒绝；
- 不级联改写历史单据快照，不从客户端传入引用状态，也不依赖前端预判；
- 名称和非空编码在所属组织内做排除自身的重复检查，避免产生新的歧义主数据。

## 3. 设计与动效决策

这是高频 ERP/SaaS 主数据工作台，采用 Emil Kowalski 为主动效基线、Jakub Krehel 为辅：

- 参考 21st.dev、React Bits、UI Prompt Library、Magic UI、Motion Primitives、Uiverse 与 MotionSites 的信息层级和局部反馈思路，不复制外部代码、品牌或资产；
- 页面以“检索—审阅—维护”为主线，详情把联系方式、合作状态、结算信息和供货商品分组，避免营销落地页式装饰；
- 筛选、分页、键盘提交、表格替换、对话框内表单操作即时响应，不做页面入场序列、循环光效、视差、弹跳或布局动画；
- 仅低频按钮、链接和对话框提供 120～180ms、可中断的 `transform`、`opacity`、颜色或阴影反馈；
- `prefers-reduced-motion: reduce` 下关闭非必要过渡；加载、成功、失败、无权限、组织不可用和引用阻断均有非动效语义文本；
- 对话框提供初始焦点、Tab 焦点循环、Escape 关闭和清晰的保存中状态；删除与导出确认不使用会漂移的二次浮层。

## 6. 验证标准

- 未知状态、越界 Long、超限文本、畸形邮箱、负数/指数成本值和异常分页全部失败关闭；
- 响应不会把服务器字段带回写命令，保存 body 只含维护白名单；
- 无 `inv:cost:view` 时后端返回的供应商品成本字段为空，前端也不渲染成本列；
- 公司上下文不调用 Gateway；组织在确认后变化时请求在 fetch 前被阻止；
- 同一未变命令失败后人工重试复用请求 ID，表单变化后生成新 ID；
- 引用中的供应商不可改名或删除，非引用供应商可完整 CRUD；
- 导出明确显示当前条件、可能包含的联系方式等敏感字段和外发提醒，仅在确认后发起；
- 桌面表格与移动卡片共用同一数据和动作状态；权限不足时入口和执行均失败关闭；
- 完整前端 verify、相关后端单测、feature 发布测试、迁移生成器和确定性哈希通过；
- `erp-ui/`、受保护原项目、Docker、服务、数据库、端口、依赖和真实配置保持零改动。

## 7. 停止线

发现以下任一情况立即停止：

- 需要读取或修改受保护原项目，或修改旧 `erp-ui/`；
- 需要启动 Docker、前端/后端服务、连接数据库/Redis/Nacos、探测端口或安装依赖；
- 无法用当前工作树证据证明组织范围、引用关系或成本权限边界；
- 必须级联修改历史单据、创建新数据库约束或执行 SQL 才能继续；
- 需要删除旧前端、合并、推送或操作其他 worktree。

真实浏览器 E2E、视觉回归、数据库集成与生产等价验收在获得隔离运行环境后补做；缺失这些验证时 VIEW-0074 仍只能标记为“重设计 / 部分实现”。
