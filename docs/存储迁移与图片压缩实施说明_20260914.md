# 存储迁移与图片压缩实施说明（2026-09-14）

依据：[项目存储与图片上传规则](项目存储与图片上传规则.md)。本说明区分源码修复、本地验证、服务器准备和线上生效。当前没有停止生产服务，没有替换线上配置、切换版本或发布本轮图片代码。

## 图片实现与工程默认值

新上传的图片在服务端解码、核实扩展名与真实格式，压缩发生在最终文件长度、摘要、配额及证据绑定之前。通用上传、库存图片、云盘、报销图片、请假/剩余工作附件及新签名材料已接入。考勤照片保留既有解码、方向修正、重编码、水印和摘要流程；已归档文件与历史签署证据不重新压缩。

| 格式 | 处理方式 |
| --- | --- |
| JPEG | 保持原分辨率，按 EXIF 修正方向，质量默认 0.92，优化编码；体积增加时保留经校验原文件及方向元数据。 |
| PNG | 浏览器先解码验证，保留原字节，避免 Canvas 对半透明像素舍入；后端进行无损压缩，保留透明通道、方向及颜色元数据。 |
| WebP | 保留 WebP，默认质量 92；验证透明通道、帧数、动画时长/循环、方向及元数据。 |
| HEIC、HEIF | 保持文件扩展名与 HEIF 容器，不转成 JPEG；验证多图、主图、透明通道、方向及元数据。 |
| 复杂图片 | 含 HDR、深度/辅助图/缩略图的 HEIF，以及无法无损保留元数据或压缩后更大的候选，使用经解码验证的原文件。GIF 等多帧图片不丢帧。 |

这些数值是可调整的工程默认值，不是用户已确认的质量或目标体积标准。当前总像素上限 4000 万、帧数上限 200；通用处理器最多 50 MiB，具体业务原有的更小上限优先。库存入口与业务规则统一为单文件 5 MiB、请求 6 MiB。JPEG 后端可通过 `ERP_IMAGE_JPEG_QUALITY` 配置 0.85–1；浏览器默认质量见共享组件；扩展格式质量见内置 Python 处理器。

云盘的幂等请求仍绑定上传原始字节，最终存储摘要及配额绑定实际落盘字节。原文件重试返回同一回执，不重复建节点或占用空间。编解码子进程并发最多 2、处理超时 30 秒；Linux 增加内存、CPU 和输出文件限额。错误不返回文件路径或元数据。

扩展格式依赖独立 Python 3.10+ 环境，锁定 Pillow 12.2.0、pillow-heif 1.7.0；使用 `scripts/install-image-codecs.sh /绝对路径/python` 安装在 `/data/erp-new-runtime/image-codecs`，固定 `ERP_IMAGE_PYTHON=/data/erp-new-runtime/image-codecs/bin/python`。脚本拒绝覆盖已有环境。服务器已在数据盘安装独立 Python 3.12.14 和该环境，未替换系统 Python；服务器编解码测试通过不代表线上应用已发布。

## 回退步骤与数据边界

- **新目录尚未开放业务写入：**停止已启动消费者和 MySQL/Redis，恢复原配置、单元、链接与冷复制前目录，启动原活动服务并重新核实 JAR/健康/文件引用。不得在数据库进程存活时移动其目录。
- **已经开放新写入：**先重新冻结消费者并干净停库，为当前数据生成新的备份。优先仅回退程序/配置且继续使用数据盘最新数据；如必须恢复原物理布局，须在停库期间将数据盘最新数据反向完整冷复制、校验，再替换目录。绝不能直接指向切换前旧目录或恢复旧 SQL/RDB，这会丢失切换后的业务数据。
- 应用回滚始终使用同一上传根，禁止覆盖或删除新文件、归档签署包及证据摘要。记录回退前后所有路径和校验结果。

## 上线门禁与剩余验收

数据盘缺失、目录不可写、路径软链接逃逸、编解码依赖缺失或源状态漂移均应停止切换。当前挂载失败验证是本地隔离模拟，未在生产卸载数据盘。服务器上的恢复演练与依赖测试不等同于线上迁移验收。

本轮合成样例验证了格式、分辨率、透明通道、方向、多帧、重试和配额；真实票据细字、印章和手机 HEIC/HDR 样本仍需业务视觉验收。最终图片功能必须在包含本轮源码的标准候选发布后再验收，不能用存储基线候选替代。本地完整测试证据见 `output/storage-image-repair-20260914/修复与复测报告.md`。
