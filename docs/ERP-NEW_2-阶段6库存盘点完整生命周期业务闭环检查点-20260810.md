## 1. 本检查点结论

本阶段在 ERP-NEW_2 隔离工作树内，将原有库存盘点只读列表扩展为响应式完整生命周期工作台，并同步收紧后端缓存、成本、统一审批重提和深链边界。

本检查点证明以下代码与离线自动化结果成立：

- 门店或仓库可创建全仓、分类、指定商品和抽盘任务，并固定使用当前精确库存组织；
- 可查询盘点人候选、调整指派、录入实盘与复盘数量、保存、提交和重新提交；
- 提交结果准确区分零差异完成、有差异待审批和库存快照变化后失效；
- 旧审批引擎支持待我审批、同意、必填原因驳回和不可变审批轨迹；
- 统一审批引擎只提供准确审批中心入口、申请人撤回和多轮次串接，不在库存页伪造直接审批；
- 驳回、退回和失效任务可按状态机重新提交或重盘，草稿可删除，其余允许状态可受控取消；
- 盲盘编辑期不泄漏账面量、差异或成本，隐藏值不会被伪造成零；
- 列表、详情、创建、审批和导出均受当前组织、精确权限、CSRF、幂等与 `no-store` 契约保护；
- 待办与统一审批发起快照均深链到 `/inventory/stock-check/{checkId}`，不依赖旧前端运行时路径。

## 2. 后端闭环

### 2.1 缓存与成本边界

`InvStockCheckController` 的列表、详情、创建、候选、指派、录入、提交、重盘、审批待办、审批动作、审批轨迹、撤回、取消、删除和导出响应统一设置：

- `Cache-Control: no-store, max-age=0`；
- `Pragma: no-cache`。

无 `inv:cost:view` 时，详情明细中的 `costPrice` 由服务端清空，审批轨迹中的内部快照也在返回前执行成本字段掩码；页面隐藏成本不是安全边界。

### 2.2 状态与审批边界

- 移除统一审批 `rejected` 对编辑和重新提交的额外禁止，继续保留状态、组织、盘点人、快照和权限校验；
- 驳回后的新提交通过既有 `previousInstanceId` 形成新审批轮次，历史轨迹保持不可变；
- 旧审批引擎继续使用库存盘点专属同意/驳回接口；统一审批继续交由审批中心处理；
- 统一审批发起的桌面与移动路径统一为 `/inventory/stock-check/{checkId}`；
- 提交和审批仍以后端库存快照、事务和幂等状态机为最终权威，前端不计算最终库存结果。

## 3. 新前端闭环

### 3.1 页面与路由

- `/inventory/stock-check`：全部盘点、待我审批、筛选、分页、风险摘要、详情入口与受控列表导出；
- `/inventory/stock-check/new`：四种盘点范围、盲盘、阈值、盘点人、截止时间和商品选择；
- `/inventory/stock-check/:checkId`：详情、指派、录入、复盘、保存、提交、重盘、审批分流、撤回、取消、删除和轨迹。

工作台仅在“全部盘点”视图显示列表导出，避免把旧审批待办视图误导为可按待办范围导出；只有 `query`、`approve` 或 `submit` 任一精确权限时才显示详情处理入口，仅列表权限保持只读。

桌面使用高密度表格和并列任务区，窄屏使用逐项卡片与全宽操作。组织切换时清除旧数据并中止在途请求，失败时保留最近一次成功结果。

### 3.2 领域、命令与 HTTP 契约

- Long 标识始终按字符串处理并限制在服务端 Long 范围；
- 日期、日期时间、备注、审批意见、请求 ID 和十进制精度均有显式上限；
- 创建命令仅发送服务端白名单字段，指定商品只发送 `productId`；
- 录入命令仅发送 `detailId`、`actualQty` 和 `recountQty`，不回传账面量、差异、成本、商品或组织快照；
- 所有写请求携带 CSRF、`X-Request-Id` 与 `Idempotency-Key`，命令不会被前端自动重试；
- 所有响应验证请求业务 ID、当前组织 ID、状态和审批实例身份，并要求明确 `no-store`；
- Excel 导出要求合法 MIME、非空文件且不超过 25 MiB；
- 默认隔离 Mock 与真实 HTTP 适配器共享同一领域契约和状态矩阵。
