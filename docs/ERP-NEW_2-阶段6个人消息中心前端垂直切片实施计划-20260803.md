## 1. 目标与范围

重建旧 `erp-ui/src/views/system/userNotification/index.vue` 对应的“我的消息”，作为阶段 6“工作台、组织、统一待办和消息”首序列的下一条垂直切片。新页面应支持：

- 加载当前登录用户的个人业务消息；
- 全部/未读过滤、未读计数、刷新、逐条已读和有界批量已读；
- 仅对新前端已登记、且当前会话具有能力的目标进行安全深链；
- 加载失败、部分已读失败、空消息、无未读消息和目标尚未迁移的明确状态；
- 桌面和移动网页共用模型，在移动端保持单列与不低于 44px 的触控目标。

本切片不重建系统公告发布管理，不把公告与个人消息合并，也不接入 Capacitor、APNs/Firebase 或设备令牌。系统公告保留独立迁移条目和后续权限评审。

## 2. 权威契约证据

现有后端 `SysUserNotificationController` 提供：

- `GET /system/user-notification/list`：按 `SecurityUtils.getUserId()` 返回当前用户消息；
- `GET /system/user-notification/unread-count`：按当前用户统计未读；
- `POST /system/user-notification/{id}/read`：以“消息 ID + 当前用户 ID”标记已读；
- `POST/DELETE /system/user-notification/device-token`：设备能力，本切片排除；
- `POST /system/user-notification/inner/publish`：内部发布能力，本切片排除。

控制器只要求登录，没有业务权限标识；因此新路由使用 `messages.view` 已知功能门禁，不虚构 `messages:view` 权限。个人消息是用户级数据，HTTP 读取和已读写入不发送组织头；已读写入仍必须携带 CSRF 和请求标识。

当前列表接口未分页，逐条已读也不返回强结果；真实 HTTP 适配器只能按现有契约失败关闭，默认应用组合仍不注入该适配器。分页、批量已读和强写回执需要后续后端兼容性扩展，不能由前端假装已经存在。

## 3. 领域与安全设计

### 3.1 领域模型

- 消息 ID 始终以字符串保存，拒绝非正整数和超过 JavaScript 安全整数的数值 JSON；
- `readStatus` 只接受 `0/1` 并映射为 `unread/read`；
- 标题、正文、业务键、渠道和时间均经运行时 schema 校验；
- 服务端 `routeType/routeParams` 作为不可信数据处理，未知或尚未迁移的目标不得直接形成路由；
- Mock fixture 可以直接使用新前端强类型 `TaskDeepLink`，用于验证已有调拨任务的安全跳转。

### 3.2 Gateway

- `MessageGateway.loadInbox(signal?)` 返回用户消息列表；
- `MessageGateway.markRead(messageId)` 只改变当前用户消息状态；
- 默认 `createMockGateways()` 持有每个实例独立的可变消息副本；
- 真实 HTTP Gateway 使用同源 `/api`、Cookie 会话、GET 无 CSRF、POST 必须 CSRF，且显式省略组织头；
- 真实 HTTP Gateway 本切片不注入启动组合。

### 3.3 页面

- 页面通过 `useAppGateways().messages` 读取与写入；
- 逐条打开时先尝试标记已读，失败不伪造已读状态，但仍允许用户阅读或进入已验证目标；
- “全部已读”以固定批次执行 `Promise.allSettled`，只更新成功项并报告失败数量；
- 目标跳转复用 `resolveTaskDeepLink()`，权限或功能不满足时不导航；
- 键盘选择和高频过滤即时完成，不增加动画。

## 4. 导航与会话边界

- 在 `featureCatalog` 登记 `messages.view`；
- Mock 会话只增加该功能，不增加不存在的后端权限；
- `/messages` 路由要求登录和 `messages.view`，不声明 `requiredPermissions`；
- 导航目录允许“仅功能门禁”的项目，其他现有项目仍保持功能 + 权限双门禁；
- 侧栏、移动导航和 `⌘K/Ctrl+K` 命令面板由同一目录自动出现“我的消息”；
- 移动底栏列数改为按实际可见条目自适应，不硬编码 3 列。

## 5. TDD 顺序

1. 先新增领域 schema、深链映射和有界批处理测试；
2. 先新增 HTTP Gateway 的同源路径、用户级安全头、CSRF、非法 ID 和畸形响应测试；
3. 先新增 Mock Gateway 状态隔离和页面加载/过滤/已读/失败/导航测试；
4. 先扩展导航、路由与功能清单断言；
5. 运行定向测试并记录 Red；
6. 实现最小生产代码，定向测试转 Green；
7. 执行完整 `npm --prefix erp-ui-next run verify`；
8. 更新阶段 1 目标映射，连续两次生成清单并验证哈希一致。
