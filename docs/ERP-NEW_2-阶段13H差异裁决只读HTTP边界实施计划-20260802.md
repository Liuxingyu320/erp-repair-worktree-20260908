# ERP-NEW_2 阶段 13H：差异裁决只读 HTTP 边界实施计划

## 1. 目标

把阶段 13F 的浏览器安全只读投影暴露为精确权限、组织范围和 `no-store` 保护的 GET 边界，并在 `erp-ui-next/` 建立严格的同源 HTTP 读取适配器。

本阶段不把真实读取适配器注入默认运行时。阶段 13G 的编译期关闭功能码、无菜单状态和不可操作页面继续保持。

## 2. 后端边界

- 在既有 `/transfer` Controller 下新增：
  `GET /discrepancies/{discrepancyCaseId}/adjudication-planning`。
- 只允许精确权限 `inv:transfer:discrepancy:adjudicate`，不使用 OR 权限或管理员通配符替代。
- 从当前请求解析已选择组织，并调用阶段 13F 的 `InvTransferReceiptDiscrepancyAdjudicationPlanningService`。
- 响应设置 `Cache-Control: no-store`。
- 不标注 `@PersistentCommand`，不接收请求正文、CSRF、请求幂等键或写命令。
- 不新增或调用裁决创建服务。

## 3. 新前端 HTTP 适配器

- 新增 `transfer-discrepancy-adjudication.http.ts`，只实现 Gateway 的 `loadDiscrepancyAdjudicationPlanning`。
- `caseId` 必须是正整数，非法值在发起请求前拒绝。
- 只使用同源 GET：
  `/inventory/transfer/discrepancies/{caseId}/adjudication-planning`。
- 强制组织头，省略 CSRF 和请求正文。
- 使用阶段 13F 严格 Zod 契约解析 `AjaxResult.data`，拒绝未知或内部字段。
- 再次核对响应事项 ID 与请求一致，并要求 `dataSource=server`。
- 不新增 Writer、submit、simulate 或运行时调用。

## 4. 运行时继续关闭

- `bootstrap.ts` 不导入、不构造、不注入真实裁决 Reader。
- 非 Mock 模式继续使用 `unavailableGateways` 并标记会话不可用。
- 原型功能码继续 `disabled: true`；路由和深链继续失败关闭。
- 不新增导航、菜单、权限种子或环境开关。

## 5. 测试

- Controller 反射与源码测试：GET 映射、精确权限、`no-store`、所选组织传递、无 `@PersistentCommand`。
- HTTP Reader 测试：路径、GET、组织头、无 CSRF、AbortSignal、非法 ID 请求前拒绝、跨事项响应拒绝、Mock 来源拒绝、未知字段拒绝。
- 启动源码测试：默认运行时未注入真实 Reader。
- 复跑阶段 13G Gate 测试、前端完整门禁和库存模块离线 Reactor。

## 6. 停止线

若需要开放功能码、添加菜单/权限种子、注入真实运行时、启动服务、连接数据库、执行迁移、开放裁决写入或下载依赖，立即停止并保留独立检查点。
