## 1. 本检查点结果

阶段 13P14 已建立 `FIXED_RETURN` 发货的专属原子隔离收货骨架：

- 预期退回实收作为已裁决残损的正常履约处理，不重复创建残损差异；
- 预期退回实收只能进入目标仓 `quarantine` 库位、`damaged` 派生批次和隔离库存；
- 只有本次确认的意外短缺创建新的 `shortage` 差异事项；
- 发货明细和调拨明细的累计实收按预期退回实收数量推进；
- 批次与序列号均维持分配、来源、目标处置、成本和数量守恒；
- 多次部分收货继续使用来源分配版本、计划版本和条件更新拒绝漂移；
- 普通 V2 收货行为保持不变，并继续拒绝 `fixed_return` 来源分配。

现有收货、库存、批次、余额、流水、序列号、差异事项和生命周期写模型足以表达上述事实。本检查点没有新增 DDL 或迁移，也没有建立第二套库存写入顺序。

## 2. 原子边界与写入所有权

- 新增专属请求 DTO、逐分配请求、不可变校验命令、锁定边界包装和创建结果 VO；
- 新增纯请求策略，以 P13 权威计划为唯一允许集合，并生成稳定请求指纹；
- 固定锁序 Gateway 在锁定发货、调拨、明细、分配、来源批次、来源库位、目标库存和未收序列号后，重读并重算 P13 计划；
- `InvTransferShipmentReceiptMutationPlanner` 增加显式 `FIXED_RETURN` 语义；普通收货继续使用 `ORDINARY`；
- 明细写意图使用 `fulfillmentDelta`：普通收货传合格量，固定退回传预期退回实收量；
- `InvTransferShipmentReceiptMutationExecutor` 仍是唯一收货 DML 执行者，专属入口只复用其既有写顺序；
- 新专属 Service 使用 `Propagation.MANDATORY`，要求未来调用者提供同一根事务；
- 独立 Gate 的 `write-enabled` 与 `lifecycle-boundary-ready` 均默认 `false`，仓库配置中没有启用值；
- 主代码中没有 Controller、HTTP、任务、消息或其他生产调用点，当前骨架不可达。

## 3. 失败关闭与守恒校验

首条 DML 前会拒绝以下情况：

- 请求计划版本、固定依据、分配、数量或序列号不属于锁后 P13 计划；
- 合格处置、普通存储库位、`accepted` 库存/流水或残损差异混入固定退回语义；
- 来源分配不是 `fixed_return`，或来源批次不处于隔离且有效状态；
- 追踪策略缺失或不是 `lot` / `serial`；
- 预期退回、意外短缺、序列号处置、分配进度、履约增量、库存和成本不守恒；
- 目标批次、库位、余额、主键回填、版本或生命周期关系无法证明；
- 短缺缺少说明或附件证据，或无短缺时携带不应存在的短缺证据。

提交前复核补充了两个空值失败关闭点：P13 来源处置成员校验不再因 `null` 触发 NPE，P14 Mutation 对缺失追踪策略返回业务校验失败。
