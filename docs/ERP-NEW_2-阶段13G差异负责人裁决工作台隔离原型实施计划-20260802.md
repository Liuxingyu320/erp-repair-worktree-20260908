# ERP-NEW_2 阶段 13G：差异负责人裁决工作台隔离原型实施计划

## 1. 目标

在 `erp-ui-next/` 内建立收货差异裁决工作台的可测试前端骨架，承接阶段 13F 已冻结的只读投影契约，验证负责人审阅事实、双方确认和拟定裁决动作时的信息结构与交互质量。

本阶段只提供隔离 Mock 原型，不开放任何运行时入口，不连接后端，不产生写操作。

## 2. 硬边界

- 仅修改 `/Users/liuxingyu/.codex/worktrees/353b/ERP-NEW` 工作树。
- 不访问或修改受保护原项目。
- 不启动 Docker、前后端服务或中间件，不连接 MySQL、Redis、Nacos 或任何数据库。
- 不安装或升级依赖，不新增 HTTP 适配器，不调用真实 API。
- Gateway 只新增读取方法；禁止新增提交、执行、确认或模拟写入方法。
- 不删除旧前端，不合并、不推送。

## 3. 运行时入口必须保持关闭

新增功能码 `inventory.transfer.discrepancy-adjudication.prototype`，在功能目录中显式标记为编译期关闭。即使会话被人为加入该功能码和精确权限 `inv:transfer:discrepancy:adjudicate`，路由访问和任务深链仍必须被拒绝。

原型页面仅允许在组件测试中直接渲染。不得新增菜单入口；移动任务中的“处理差异”仍显示为未开放。

## 4. 页面信息结构

1. 页面标题与隔离原型提示。
2. 调拨单、商品、差异类型、数量、金额和处理时限摘要。
3. 收货事实、备注和附件引用。
4. 发出方与接收方的最新确认状态、人员、时间和意见。
5. 只读工作流状态与是否满足裁决条件。
6. 已存在时显示裁决计划及动作清单；不存在时显示不可操作的“裁决提交 Gate 未开放”。
7. 明确说明裁决计划不等于库存、财务或物理执行已完成。

## 5. 设计与动效原则

设计参考已确认的网站和组件思路：21st.dev、React Bits、UI Prompt Library、Magic UI、Motion Primitives、Uiverse 与 MotionSites.ai。只吸收其布局、信息层级、局部组件和提示词表达方式，不复制外部运行时代码，不引入依赖。

面向高频 ERP 后台，以 Emil Kowalski 的直接、快速、可中断交互为主，以 Jakub Krehel 的状态反馈与可访问性为辅：

- 页面仅在首次进入时使用约 `180ms` 的轻微透明度和纵向位移动画。
- 筛选、键盘操作和高频状态切换即时响应，不增加等待动效。
- 禁止循环动画、弹跳、视差、大面积光效、从 `scale(0)` 出现或会引起布局抖动的动画。
- 焦点态清晰，语义标题完整，移动端单列可读。
- `prefers-reduced-motion: reduce` 下关闭非必要动画。

## 6. 计划变更

- 扩展功能目录，支持显式关闭的原型功能。
- 注册受关闭功能码保护的裁决路由与严格任务深链。
- 扩展调拨 Gateway 的只读裁决投影方法，并为不可用 Gateway 与 Mock Gateway 提供实现。
- 新增就绪态与已规划态 Mock 数据。
- 新增 `TransferDiscrepancyAdjudicationPage.vue` 与组件测试。
- 扩展路由、深链和移动任务测试，证明运行时入口保持关闭。

## 7. 验收条件

- 就绪态页面可准确展示事实、证据、双方确认、金额与不可提交状态。
- 已规划态页面可准确展示动作清单和待执行含义，不宣称差异已解决。
- 返回的 `caseId` 与路由参数不一致时拒绝展示。
- 未知或内部字段继续由阶段 13F 严格契约拒绝。
- 即使伪造会话同时包含功能码与权限，路由和任务深链也不可访问。
- 移动任务仍无可点击的裁决入口。
- 桌面、移动、键盘焦点和减少动态效果均有验证。
- 前端完整验证通过；工作树隔离审计通过。

## 8. 停止线

若实现需要真实 API、数据库、服务启动、依赖安装、开放写操作、开放运行时入口或触及受保护原项目，立即停止并重新建立检查点。
