# ERP-NEW_2 阶段 6：OA 采购申请只读工作台前端垂直切片实施计划

> 日期：2026-08-03
> 基线：`4f70456f feat: add delivery notice workbench skeleton`
> 状态：实施中；只读“我的采购申请”列表切片，不代表 OA 或统一审批闭环迁移完成

## 1. 目标与范围

在 `erp-ui-next/` 内新增 `/oa/purchases` 采购申请工作台，覆盖当前登录申请人在当前店铺或仓库范围内的申请列表、标题与状态筛选、服务端分页、金额、申请组织、审批轮次、创建时间和响应式只读展示。

本切片只实现：

- `GET /oa/purchase/my`；
- 权限 `oa:purchase:list`；
- 当前登录申请人和当前店铺/仓库的双重严格数据范围，公司上下文不发请求；
- 标题与精确状态筛选；
- 服务端总记录数，以及当前页待处理、审批流转中、已通过和已结束数量；
- ERP-NEW_2 隔离 Mock 默认运行时和未注入的真实只读 HTTP Reader；
- 桌面表格、移动卡片、加载、错误、空状态和最近成功筛选语义。

以下能力明确留待后续独立切片：新建、编辑、保存草稿、提交审批、撤回、关闭、详情、审批轨迹、同意、退回、拒绝、导出、审批可用性、真实运行时注入和旧 OA 页面下线。

## 2. 审计结论与硬边界

### 2.1 接口与权限拆分

- 我的列表：`GET /oa/purchase/my`，权限 `oa:purchase:list`；
- 详情使用 `oa:purchase:query`、`oa:purchase:add` 或 `oa:todo:approve` 的 OR 权限；
- 保存、提交、撤回和关闭使用 `oa:purchase:add`；导出使用 `oa:purchase:export`；
- 本切片不得展示详情、审批轨迹、导出或任何写动作伪入口，也不得用列表权限调用其他端点。

### 2.2 申请人与组织范围

- 服务层强制把查询申请人设置为当前登录用户，前端不得发送 `applicantId`；
- 服务端叠加当前所选店铺/仓库的授权范围；新 Reader 只允许当前会话组织头，不接受 `shopDeptId`、`scopeDeptIds` 或 `dataScope` 查询参数；
- 新前端逐行验证 `applicantId` 与当前会话用户一致，并要求 `shopDeptId` 精确匹配当前叶子组织；任一越界记录整页失败关闭；
- 公司上下文不请求；默认 Provider 只注入隔离 Mock；真实 Reader 在版本化 OpenAPI、缓存策略和生产等价负向测试完成前保持未注入。

### 2.3 状态、金额与内部字段

- 状态闭集为 `draft`、`submitting`、`pending`、`approved`、`returned`、`rejected`、`withdrawn`、`terminated`、`cancelled`；未知状态失败关闭；
- `purchaseId`、`applicantId` 与 `shopDeptId` 必须经过 Java Long 边界；审批轮次必须是非负安全整数；
- 金额保持非负十进制字符串；旧数据金额为空时显式显示“金额待补充”，不伪造 0；
- `approvalInstanceId`、`rowVersion`、`lastApprovalEventKey`、内部创建/更新人和原始数据范围参数不进入列表模型；
- 当前列表端点没有显式 `Cache-Control: no-store` 证据，这是生产注入阻断项。

## 3. 设计与动效决策

这是高频 ERP/SaaS OA 工作台，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 使用“当前申请人与组织 → 总记录/当前页状态 → 明确筛选 → 申请事实”的层级；
- 标题、金额、申请人、申请组织、审批轮次、创建时间和状态在桌面与移动端保持等价；
- 搜索、状态筛选、键盘提交、分页和列表替换不播放动画；
- 只允许按钮按压的 140ms 可中断 `transform` 过渡；
- `prefers-reduced-motion: reduce` 下关闭所有非必要过渡；
- 不新增 React、Tailwind、Motion、GSAP、远程字体或外部组件依赖。

## 5. 测试驱动实施顺序

1. 固定安全 Long、可空金额、状态闭集、审批轮次、创建时间、有界筛选和字段丢弃。
2. 固定 Mock 的申请人/组织双重隔离、标题/状态筛选、分页和当前页统计。
3. 固定 HTTP Reader 的精确 URL、单一 `Dept-NumId`、无 CSRF、组织漂移、跨申请人和跨组织返回拒绝。
4. 固定页面的店铺/仓库加载、公司零请求、桌面/移动等价展示、显式筛选和失败后保留最近成功条件。
5. 固定 `oa.purchase.view`、`oa:purchase:list`、路由和导航双重门禁。
6. 实现最小领域、Mock、HTTP、页面、路由和导航，使测试转绿。
7. 更新迁移覆盖层为“重设计 / 部分实现”，明确所有延期动作和生产阻断项。
8. 运行完整 `verify`、阶段 1 生成器两次、确定性哈希和隔离审计；全部通过后只做本地提交。

## 6. 验证标准

- 不安全 Long、非法状态、负金额、无效创建时间和越界筛选全部失败关闭；
- 新模型不包含审批实例 ID、乐观锁版本、审批事件键、内部操作人或数据范围参数；
- HTTP Reader 只发送允许参数和一个旧组织头；组织漂移、跨申请人和跨组织记录都失败；
- 当前申请人只能读取当前店铺/仓库隔离 Mock；公司上下文不调用 Gateway；
- 页面明确区分服务端总记录和当前页状态，不把分页样本误报为全局统计；
- 筛选成功后才更新已应用条件，失败时保留最近成功标签并可重试最后请求；
- 页面没有详情、新建、编辑、保存、提交、撤回、关闭、审批或导出伪入口；
- 功能开关和列表权限同时满足才可见且可访问；
- 完整前端验证、迁移生成器、确定性哈希和隔离扫描通过；
- 旧 `erp-ui/`、受保护原项目、Docker、服务、数据库、依赖和真实配置保持零改动。

## 7. 停止线

发现以下任一情况立即停止：

- 需要读取或修改受保护原项目、连接数据库、启动服务或安装依赖；
- 需要修改旧 `erp-ui/`、注入真实 Reader 或绕过申请人/组织数据边界；
- 需要公司级汇总而当前响应不能证明逐行授权；
- 需要启用详情、写操作、审批动作或导出而没有独立计划；
- 不能证明全部文件、运行目录和测试只位于 ERP-NEW_2 隔离工作树。
