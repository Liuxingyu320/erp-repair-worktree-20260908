# ERP-NEW_2 阶段 13P13：退回发货专属隔离收货规划与普通收货阻断实施计划

> 日期：2026-08-03
>
> 分支：`codex/erp-new-2-rebuild`
>
> 基线：`e9eb7c62 feat: create adjudication return shipments atomically`
>
> 范围：建立只读、生产零调用点的退回专属收货规划，并阻止 `FIXED_RETURN` 发货进入普通 V2 收货边界

## 1. 目标与审计结论

P12 创建的差异退回发货来自已裁决残损隔离库存，目标仓收到后仍必须进入隔离库存。它不能复用普通 V2 收货语义：普通链允许浏览器把到货数量分类为合格、残损或短缺，其中合格数量进入可用库存，残损数量会创建新的差异事项，且调拨累计收货只推进合格数量。

若直接把 `FIXED_RETURN` 发货交给普通收货，将出现两类错误：

- 已裁决残损可能被错误分类为合格并进入可用库存；
- 即使分类为残损，也会再次创建差异事项且不推进退回子调拨的履约数量，形成重复裁决或无法完成。

P13 因此只建立退回专属只读规划和普通入口阻断，不创建真实收货写事务。后续 P14 再基于本规划实现“预期残损退回入隔离、仅意外短缺产生新差异”的原子写入。

## 2. 权威识别与新增事实

在现有收货规划来源分配事实中增加并持久化读取以下不可变证据：

- `allocationPolicy`：退回专属值必须精确为 `FIXED_RETURN`；
- `sourceReceiptDisposition`：来源批次必须为 `damaged`；
- `sourceLocationType`：来源库位必须为 `quarantine`；
- 调拨明细审批、累计发货和累计收货数量，用于证明退回履约进度。

锁定写边界同步携带并比较 `allocationPolicy`，避免普通写事务在锁定事实和规划事实之间遗漏退回来源标识。以上均复用现有列，不新增 DDL。

## 3. 退回专属只读规划

新增纯策略和只读 Service，要求：

- 调拨来源业务类型为 `transfer_discrepancy_return`，来源动作标识、审批轮次、返仓原因和方向均可核验；
- 发货批次为 `V2_DETAIL`、状态允许收货，并保存 P11 计划版本、封存修订和来源对账批次；
- 所有不可变来源分配均为 `FIXED_RETURN`，来自 `damaged` 批次和 `quarantine` 库位；
- 已累计合格收货必须为 0；已退回实收沿用现有 `damaged_received_quantity` 作为兼容存储，但在新契约中展示为 `returnedQuantity`；
- 剩余量等于分配量减已退回实收和已报告短缺；默认建议全部剩余量按“预期残损退回实收”进入隔离库位；
- 序列号必须仍与不可变发货审计一致并处于 `shipped`，只展示脱敏标签；
- 目标仓只要求启用的隔离库位，不要求普通存储库位；
- 目标仓明细库存权威模式和对账批次必须通过。

规划版本使用退回专属指纹，覆盖主单/发货状态、来源分配、累计进度、批次/库位属性、序列号、目标隔离库位和库存模式。任一事实漂移均产生新版本或失败关闭。

## 4. 普通收货阻断

扩展普通 `InvTransferShipmentReceiptPlanComposer`：任何来源分配的 `allocationPolicy` 为 `FIXED_RETURN` 时增加全局阻断原因，普通规划返回 `canCreateReceipt=false`。

普通写事务在固定锁序后仍会重算同一普通规划并通过请求策略校验，因此伪造普通 `receiptPlanVersion`、分类或库位也不能越过该阻断。锁定分配和只读分配的 `allocationPolicy` 必须精确一致。
