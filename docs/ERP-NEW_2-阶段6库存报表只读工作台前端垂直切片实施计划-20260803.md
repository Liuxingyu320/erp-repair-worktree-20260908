# ERP-NEW_2 阶段 6：库存报表只读工作台前端垂直切片实施计划

> 日期：2026-08-03
> 基线：`343f7063 feat: add stock check workbench skeleton`
> 状态：只读库存预警与经营汇总前端切片已实现；不代表报表或经营分析领域迁移完成

## 1. 目标与范围

在 `erp-ui-next/` 内新增 `/inventory/report` 库存报表工作台，覆盖当前门店或仓库的库存健康汇总、经营汇总、库存预警筛选、服务端分页和响应式只读展示。

本切片只实现：

- `GET /inventory/report/summary` 的受限旧 HTTP 兼容读取；
- `GET /inventory/report/stock-warning` 的只读列表；
- 权限 `inv:report:list`，成本显示附加要求 `inv:cost:view`；
- 当前门店或仓库的严格数据范围；
- 精确商品 ID、预警状态和经营日期区间筛选；
- ERP-NEW_2 脱敏 Mock 默认运行时，以及未注入的真实 HTTP Reader；
- 桌面表格、移动卡片、加载、错误、空状态和最近成功筛选语义。

以下能力明确留待后续独立切片：商品检索选择器、分类筛选、趋势图、指标钻取、导出、报表配置、成本服务端脱敏修复、版本化 OpenAPI、生产运行时注入和跨组织经营汇总。

## 2. 审计结论与硬边界

### 2.1 接口与权限

- 旧页面：`erp-ui/src/views/inventory/report/index.vue`；
- 旧 API：`erp-ui/src/api/inventory/report.js`；
- 后端：`InvReportController`、`InvReportServiceImpl`、`InvReportMapper.xml`；
- 汇总为 `GET /inventory/report/summary`，预警为 `GET /inventory/report/stock-warning`；
- 两个端点均只要求 `inv:report:list`；旧前端另用 `inv:cost:view` 隐藏库存成本、采购金额、销售成本和毛利；
- 当前没有导出、趋势、钻取或明细端点，本切片不得展示伪入口。

### 2.2 成本与敏感数据停止线

- 旧汇总端点始终返回 `totalStockCost`、`purchaseAmount`、`salesCost` 和 `grossMargin`；旧前端隐藏卡片不能阻止响应体泄漏；
- 新目标 Mock 将非成本汇总与成本指标分层，成本指标只有在 `inv:cost:view` 下才可进入页面模型；
- 旧 HTTP Reader 在没有 `inv:cost:view` 时不得请求 `/summary`，只读取库存预警，并明确标记“经营汇总因旧接口未脱敏而不可用”；
- 有成本权限时，旧 HTTP Reader 才可解析汇总；即便如此，Reader 仍不得进入默认启动路径；
- 生产接线前必须由后端按权限省略或拒绝成本字段，并补负向契约测试，前端字段丢弃不能替代服务端授权。

### 2.3 组织、查询与统计语义

- 有效库存组织只有 `store` 与 `warehouse`；公司上下文不得发送报表请求；
- 服务端依据 `Dept-NumId` 解析当前组织，前端不得发送 `scopeDeptIds`、`dataScope` 或任意可见组织集合；
- 请求必须携带 `expectedOrganizationId`，组织漂移在 `fetch` 前失败；预警记录若返回其他组织则拒绝整页；
- 分页字段为 `pageNum`、`pageSize`，商品筛选为安全 Long `productId`，预警状态闭集为 `low`、`empty`、`unconfigured`；
- 经营日期区间只影响汇总 SQL，库存预警是当前库存快照；新 UI 必须清楚区分，预警请求不发送无效日期参数；
- 汇总中的库存品项、预警项、缺货项和未配置阈值项是计数；跨商品单位的总数量字段不进入新模型；
- 金额保持十进制字符串，页面不得使用二进制浮点重新计算毛利或成本。

## 3. 设计与动效决策

这是高频 ERP/SaaS 报表页，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 使用“库存健康 → 经营摘要 → 明确筛选 → 预警明细”的层级；
- 无成本权限或旧端点未脱敏时，用静态说明代替隐藏失败或伪造 0 值；
- 筛选、分页、键盘提交、列表替换和指标更新不播放动画；
- 只允许按钮按压、聚焦和悬停阴影等 120～180ms 可中断 CSS 过渡；
- 只过渡 `transform`、颜色或 `box-shadow`，不动画布局属性；
- `prefers-reduced-motion: reduce` 下关闭所有非必要过渡；
- 不新增 React、Tailwind、Motion、GSAP、远程字体或外部组件依赖。

## 6. 验证标准

- 不安全 Long、畸形金额、无效日期、未知预警状态和反向日期区间全部失败关闭；
- 新模型不包含跨单位汇总数量、成本单价、Mapper 内部字段或未授权成本指标；
- 无成本权限的旧 HTTP Reader 不请求 `/summary`；有成本权限时才解析独立成本指标；
- 预警 Reader 只发送有效筛选和一个旧组织头；组织漂移与跨组织记录都失败；
- 公司上下文不调用 Gateway；门店和仓库均可读取各自隔离 Mock；
- 页面区分经营日期口径与当前库存快照，不把当前页预警类型计数伪装为全局汇总；
- 筛选成功后才更新已应用条件，失败时保留最近成功标签并可重试最后请求；
- 桌面表格和移动卡片核心信息等价，无写动作、导出、趋势或钻取伪入口；
- 功能开关和报表权限同时满足才可见且可访问；
- 完整前端验证、迁移生成器、确定性哈希和隔离扫描通过；
- 旧 `erp-ui/`、受保护原项目、Docker、服务、数据库、依赖和真实配置保持零改动。

## 7. 停止线

发现以下任一情况立即停止：

- 需要读取或修改受保护原项目、连接数据库、启动服务或安装依赖；
- 需要修改旧 `erp-ui/`、注入真实 Reader 或绕过成本权限；
- 组织范围、金额、日期或预警语义无法从当前工作树证据确定；
- 需要启用趋势、钻取、导出、配置或任何写动作而没有独立计划；
- 不能证明全部文件、运行目录和测试只位于 ERP-NEW_2 隔离工作树。
