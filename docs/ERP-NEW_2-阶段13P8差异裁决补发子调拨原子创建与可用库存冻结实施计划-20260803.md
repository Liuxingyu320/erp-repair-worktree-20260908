# ERP-NEW_2 阶段 13P8：差异裁决补发子调拨原子创建与可用库存冻结实施计划

> 日期：2026-08-03
>
> 分支：`codex/erp-new-2-rebuild`
>
> 基线：`b11a615c feat: bind adjudication async transfer evidence`
>
> 范围：实现未接线补发效果所有者；不开放差异执行入口，不实现退回，不启动运行环境

## 1. 复用结论

补发不应另写一套调拨建单和商品级冻结逻辑。现有标准提交链已经在同一事务内完成：

1. 校验组织方向、物料状态和调拨类型；
2. 创建草稿头、唯一明细和不可变修订；
3. 由 `InvTransferReservationService.reserveForSubmission` 按稳定顺序锁定来源商品库存；
4. 精确把可用库存转为锁定库存并追加调拨明细级预留台账；
5. 封存审批修订，把子调拨推进到 `submitted` 或自动审批后的 `approved`；
6. 任一步骤失败时由调用方外层事务整体回滚。

阶段 13P8 复用 `IInvTransferService.submitTransfer`，不复制上述 DML。标准提交仍保留物料启用、组织可见、调拨方向、返仓 Gate 和审批规则；补发不得绕过这些失败关闭条件。

## 2. 原子边界

新增 `InvTransferReceiptDiscrepancyReshipEffectOwner`，其 `dispatch` 方法使用 `Propagation.MANDATORY`，只能在未来差异执行外层事务中调用：

1. 校验请求、操作者权限和选择组织；
2. 锁定动作已有 P7 工作流关系；一致重放只返回原关系，不创建第二张子调拨；
3. 锁定短缺事项、裁决、补发动作、原调拨和原 V2 收货分配事实；
4. 纯策略再次推导原方向、原类型、业务来源和可用库存来源；
5. 调用标准提交链创建一张单明细补发子调拨并冻结精确数量；
6. 从数据库锁定回读子调拨头、唯一明细和当前审批轮次唯一 ACTIVE 预留；
7. 使用阶段 13P7 纯策略生成工作流指纹和效果引用；
8. 条件追加 P7 不可变唯一关系；
9. 返回关系，供未来外层事务随后生成 dispatch 执行事件并推进动作状态。

关系追加或后续执行事件失败时，子调拨、修订、审批发起 outbox、库存冻结和预留台账必须随同一外层事务回滚。

## 3. 补发子调拨规则

- 仅允许 `shortage/reship` 且动作为 `pending`、效果引用为空；
- 子调拨复制原调拨的原始组织/仓库字段，保持方向和调拨类型；
- `warehouse` 由原目标门店组织上下文提交；
- `store_return` 和 `cross_store` 由原来源组织上下文提交；
- 业务来源固定为 `transfer_discrepancy_reship` + 裁决动作 ID；
- 只创建一条物料、产品和数量完全匹配的明细；
- 参考成本使用裁决冻结源成本，但实际 V2 发货成本继续以后续批次库位分配的权威库存成本为准；
- 回读时必须只有一个明细、一个当前轮次 ACTIVE 预留，冻结数量等于动作数量，且尚无发货、收货或子差异。

## 4. 新增持久化读取

新增只读补发 Mapper，仅包含两个锁定查询：

- `selectSourceForUpdate`：锁定并投影短缺事项、裁决动作、原调拨和原 V2 收货分配；
- `selectCreatedChildForUpdate`：锁定刚创建的子调拨头、最小明细和预留，并统计明细、预留、V2/旧发货、收货和开放差异数量。

该 Mapper 不包含 `insert`、`update` 或 `delete`。唯一关系仍由阶段 13P7 Mapper 条件追加；标准提交的现有服务继续唯一拥有调拨和可用库存写入。

## 5. 验证

- 纯策略拒绝非短缺补发、方向/类型/原始组织字段漂移和错误选择组织；
- 效果所有者严格执行关系锁、来源锁、标准提交、子事实锁、纯策略关系、唯一插入顺序；
- 一致关系可重放，不一致关系在任何调拨/库存写入前失败；
- 标准提交返回空 ID、回读事实缺失、关系插入非单行均失败并声明由外层事务回滚；
- 新 Mapper XML 可解析、两方法全绑定、全部结果属性可写、只有锁定读取；
- 效果所有者和 Mapper 均无生产调用点；
- 定向测试与 inventory 完整离线 Reactor 通过。

## 6. 停止线

- 不修改阶段 13P6 同步事务，不把补发路由接入硬关闭执行入口；
- 不实现或模拟隔离库存退回；
- 不执行 SQL，不连接数据库、Redis 或 Nacos；
- 不启动 Docker、服务或中间件，不安装依赖；
- 不修改端口、配置、凭据或密钥；
- 不删除旧前端，不访问受保护原项目，不合并、不推送。
