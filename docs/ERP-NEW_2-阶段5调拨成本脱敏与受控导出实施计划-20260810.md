# ERP-NEW_2 阶段 5：调拨成本脱敏与受控导出实施计划

## 1. 目标

在 ERP-NEW_2 独立工作树内完成调拨查询、详情、版本历史和导出的成本权限闭环：

- 无 `inv:cost:view` 权限的用户在服务端响应中不得获取成本价、明细金额或参考总价；
- 有成本权限的用户保留现有成本可见能力；
- 处理中和历史记录分别使用真实服务端导出，继承当前组织、权限、数据范围和筛选条件；
- 同步导出上限为 10,000 行，超限明确拒绝，不发起无界查询；
- 所有相关敏感响应和文件下载都禁止缓存。

## 3. 实施范围

### 3.1 后端

- 新增小型调拨成本可见性策略，统一脱敏列表、详情及不可变版本快照，避免继续扩大已有巨型 Service。
- 新增专用调拨导出查询服务，仅调用 Mapper，不加载列表审批摘要；SQL 使用参数化 `limit 10001` 做超限探测。
- 导出使用显式列白名单；不导出跨单位可能误导的“总数量”，改为“明细行数”。
- 只对具有 `inv:cost:view` 的用户添加“参考总价”列，并在导出前再次执行数据脱敏。
- 为查询、详情、版本历史与导出统一设置 `Cache-Control: no-store, max-age=0` 和 `Pragma: no-cache`。

### 3.2 前端

- 在 `erp-ui-next/` 内新增独立的调拨导出 HTTP 适配器，使用组织头、CSRF、请求 ID、25 MiB 响应上限和 Excel MIME 校验。
- 工作台将“处理中”和“历史记录”导出作为两个明确范围，分别校验 `inv:transfer:export` 与 `inv:transfer:records:export`。
- 真实导出前展示二次确认，说明当前组织、筛选、上限和成本列可见性；确认后若组织或权限已变更则中止。
- 成功后使用 Blob URL 下载并及时 revoke；失败保留当前筛选状态并给出可恢复提示。
- 详情与版本历史 HTTP 读取端增加 no-store 响应合同校验。

## 5. 执行顺序

1. 先以单元测试固定成本脱敏、成本授权保留、组织范围和 10,000 行上限。
2. 实现后端成本可见性策略、专用导出服务和参数化查询上限。
3. 改造 Controller 的响应脱敏、no-store 和导出列白名单。
4. 先以前端 HTTP 契约测试固定端点、组织、CSRF、MIME、容量上限和 no-store。
5. 接入网关和工作台确认对话框，补齐权限、组织漂移、失败和成功下载测试。
6. 执行定向测试、后端模块全量测试、前端 `verify` 和生成器双跑一致性验证。
7. 更新检查点证据，只在当前专属分支创建本地提交。

## 6. 验收条件

- 无成本权限时，列表、详情、发货明细、版本头和版本明细的成本字段均为 `null`。
- 有成本权限时，上述字段保留；管理员按现有安全规则视为有权。
- 普通导出不包含“参考总价”，成本授权导出包含该列；两者均不包含“总数量”。
- 导出查询仅返回当前组织范围，参数化读取最多 10,001 行，超过 10,000 行不产生文件。
- 前端只在具有对应导出权限时提供操作，并在用户确认后请求正确范围。
- 相关响应均通过 no-store 契约检查，超大、空或非 Excel 文件均被拒绝。
- 全部新增和现有回归测试通过，工作树不包含真实秘密或运行时产物。

## 7. 风险与控制

- 风险：仅靠前端隐藏导致网络响应泄露成本。控制：服务端就地脱敏并以负向测试锁定。
- 风险：通用实体导出因新增 `@Excel` 字段意外扩大数据面。控制：使用 `showColumn` 显式白名单。
- 风险：无界导出造成内存和数据库压力。控制：SQL 端最多取 10,001 行，应用端拒绝超限。
- 风险：确认对话框打开后组织或权限变化。控制：确认时二次比对快照，不一致则中止。
