# 电脑端增量审计报告（2026-07-10）

> 目标：在《desktop-multi-account-store-audit-20260622.md》基础上，继续检查电脑端页面漏洞、页面 Bug、流程卡点、功能缺口和不人性化之处。本报告只把本轮新发现作为新增问题；已在旧报告记录、但本轮仍能复现的问题单独列为“仍未修复”。

## 1. 结论摘要

本轮只读/低风险抽查覆盖 13 个电脑端步骤，使用管理员会话，分别验证门店、仓库和未选择组织三种上下文，并在 1440×900、1280×720 两种桌面尺寸下检查页面。

新增确认问题：

- 2 个高优先级体验/流程问题：人事搜索分页口径错误；多个业务弹窗没有正确接管键盘焦点和错误字段语义。
- 4 个中优先级问题：入职管理没有创建/导入待入职人员的直接入口；采购弹窗在 1280×720 下关键列被裁到横向滚动区；访问令牌存放在 JavaScript 可读 Cookie；仓库内置 Nginx 配置缺少常见安全响应头。
- 2 个低优先级问题：仍有字符串形式 `setTimeout` 和 `eval`；生产依赖审计存在 4 个低危 Vue 依赖告警。

旧报告中至少 5 类问题仍未关闭：仓库路由组织守卫遗漏、公告富文本脚本风险、用户导入结果危险 HTML 渲染、菜单搜索 `v-html` 渲染点、调拨时间直接显示 UTC ISO 字符串。

## 2. 审计范围与限制

- 前端：`http://127.0.0.1:1026`；后端：本机 `8080` 服务。
- 账号：管理员；组织上下文：测试门店、主仓库、未选择组织。
- 页面：组织选择、首页、库存、销售、采购、采购退货、OA 待办、员工档案、入职管理、调拨、签署包。
- 尺寸：1440×900、1280×720。
- 为避免污染业务数据，本轮没有保存、提交、删除或导入业务数据；只执行页面打开、筛选、空表单校验、详情查看和组织切换。
- 未覆盖所有角色、82 个组织、真实生产反向代理、屏幕阅读器和完整 WCAG 测试；安全响应头结论仅基于仓库内可见 Nginx 配置，生产边缘网关可能另有配置。

## 3. 关键流程健康度

1. **登录后选择组织 — 良好**
   - 组织数量和层级表达清楚，选中态明显。
   - 82 个可选组织时树较密集，后续可增加“最近使用 / 仅门店 / 仅仓库”快捷筛选。

2. **电脑端首页 — 良好**
   - 当前组织、快捷入口、待办和库存/销售入口清楚，没有观察到阻塞性脚本错误。

3. **门店库存空态 — 良好**
   - 未选择物料类型时禁用物料搜索，空态能解释下一步。

4. **销售列表与新建表单 — 需改进**
   - 空列表和必填校验可用。
   - 弹窗打开后焦点未进入对话框；错误输入没有 `aria-invalid` / `aria-describedby` 关联。

5. **门店上下文进入仓库采购 — 阻塞**
   - 页面说明“请切换到仓库”，但没有就地“切换仓库”按钮，用户必须自己找到顶部组织切换入口。

6. **仓库采购列表与新建采购单 — 需改进**
   - 主流程和动作齐全。
   - 1280×720 下采购明细的右侧“操作”列被裁入横向滚动区，删除当前行需要额外横向滚动。

7. **OA 待办 — 基本可用**
   - 空态正常。
   - 表格直接展示“店铺 ID / 任务 ID”这类内部字段，业务人员更需要店铺名称、申请人、当前节点和等待时长。

8. **员工档案搜索 — Bug / 阻塞判断**
   - 输入确定不存在的关键字后，列表标题显示 0 条、正文显示无结果，但底部分页仍显示“共 152 条”和 16 页，用户会误以为后续页还有结果。

9. **入职管理 — 功能缺口**
   - 页面为 0 条待入职时，只有导出、搜索、筛选和列设置，没有“新增待入职人员”“从招聘转入”“导入待入职名单”等开始流程入口。

10. **仓库调拨列表与详情 — 需改进**
    - 流程阶段和当前责任人表达较好。
    - 详情直接显示 `2026-07-05T11:41:23.000Z`，同一单据在列表中却显示本地格式；详情弹窗焦点也仍留在底层“详情”按钮。

11. **员工签署包 — 基本可用**
    - 空态能说明依赖模板和员工；建议在空态中直接提供“去维护模板 / 去选择员工”的按钮。

12. **未选组织直接访问采购/采购退货深链 — 阻塞**
    - 路由没有统一跳转组织选择页；采购停在禁用业务页，采购退货只显示“请选择仓库”，二者都没有直接修复上下文的 CTA。

13. **1280×720 桌面适配 — 需改进**
    - 主导航和弹窗整体能容纳。
    - 宽度固定为 980px/920px/1080px 的大弹窗较多，表格关键操作列依赖横向滚动；应在常见 1366×768、1280×720 桌面尺寸做固定回归。

## 4. 本轮新增问题

### NEW-P1-01 人事搜索使用“服务端分页 + 当前页本地二次过滤”，产生幽灵分页

- **现象**：搜索 `__audit_no_match_20260710__` 后，员工摘要显示“共 0 条”，正文为空，但分页仍显示“共 152 条 / 16 页”。
- **证据**：[`12-hr-employee-empty-search.png`](audit-screenshots/desktop-20260710/12-hr-employee-empty-search.png)。
- **根因**：
  - `erp-ui/src/views/hr/components/HrEmployeeList.vue:101` 用 `filteredRows.length` 展示当前页本地过滤后的数量。
  - `:140` 的分页仍绑定服务端 `total`。
  - `:306-308` 对服务端当前页 `rows` 再执行 `matchesActiveTask` 和 `matchesLocalFilters`。
  - `:322-329` 把接口的 `response.total` 原样交给分页。
  - `SysUserMapper.xml:225-275` 的员工主列表 SQL 支持部分独立字段，但没有处理通用 `keyword`、`deptKeyword`、`completenessStatus`、`accountStatus`；前端因此只能过滤当前 10 条，不能对全量 152 条得到正确总数。
- **影响**：搜索结果、任务卡数字、分页总数和每页内容互相矛盾；用户可能翻完多页仍找不到人，也可能漏掉存在于其他服务端页的匹配员工。
- **修复**：把所有影响结果集的筛选下沉到服务端，并由同一个 SQL 返回准确 `total`；前端只渲染服务端当前页。若某些风险标签必须前端计算，应先把可计算字段结构化到 SQL/DTO，而不是过滤分页后的 10 条。
- **回归**：新增集成测试覆盖关键字命中第 2 页、完全无匹配、部门/完整度/账号状态组合筛选，并断言页头数量、分页总数和行数一致。

### NEW-P1-02 多个业务弹窗未接管焦点，表单错误缺少可访问关联

- **现象**：打开新建销售单、新建采购单、采购物料选择、调拨详情后，`document.activeElement` 分别停在 `BODY` 或遮罩层后面的触发按钮；空提交后虽然显示红字，但输入控件没有 `aria-invalid`、`aria-describedby`，可见标签也没有稳定关联到输入控件。
- **证据**：[`07-sales-validation.png`](audit-screenshots/desktop-20260710/07-sales-validation.png)；运行态 DOM/焦点检查。
- **代码线索**：`sales/index.vue:109-122`、`purchase/index.vue:119-149/201-218`、`transfer/index.vue:299-381` 的 `el-dialog` 没有 `@opened` 后的首焦点处理，也没有关闭后显式恢复触发点的逻辑。
- **影响**：键盘用户打开弹窗后仍可能操作背景页；屏幕阅读器不能可靠得知哪个字段出错。详情、保存、提交等高频动作会变得难以使用。
- **修复**：封装统一业务弹窗：打开后聚焦标题或第一个可操作字段，焦点限制在弹窗内，关闭后回到触发按钮；为表单控件生成稳定 `id`，通过 `label for` / `aria-labelledby` 关联标签，通过 `aria-invalid` 和 `aria-describedby` 关联错误文本。
- **回归**：至少覆盖 Tab/Shift+Tab 循环、Esc 关闭、关闭后焦点恢复、必填错误朗读、嵌套弹窗的焦点栈。

### NEW-P2-01 入职管理没有“开始办理”的写入口

- **现象**：0 条待入职时页面只有导出和筛选，没有新增、导入或从招聘/候选人转入的入口。
- **证据**：[`13-hr-onboarding.png`](audit-screenshots/desktop-20260710/13-hr-onboarding.png)。
- **根因**：`erp-ui/src/views/hr/onboarding/index.vue:1-10` 仅复用 `HrEmployeeList`，启用 `show-export`，没有启用导入/模板，也没有专用新增或候选人转入动作；后端 `HrOnboardingController` 也只有列表接口。
- **影响**：入职页只能消费已经被其他入口标成“待入职”的用户，但页面没有告诉用户应该去哪里创建这类人员；新环境会永久停在 0 条空态。
- **修复**：先明确入口模型：推荐提供“新增待入职人员”和“从候选人转入”；若只能从员工导入产生，则空态必须提供“导入待入职名单”并自动带模板和状态。

### NEW-P2-02 采购弹窗在 1280×720 下把关键操作列裁到横向滚动区

- **现象**：弹窗主体宽 980px，采购明细列的最小宽度合计超过可视区；右侧操作列首屏不可见，底部出现横向滚动条。
- **证据**：[`19-purchase-create-1280x720.png`](audit-screenshots/desktop-20260710/19-purchase-create-1280x720.png)。
- **根因**：`purchase/index.vue:119` 固定 `width="980px"`；`:155-191` 的物料、供应商、规格、单位、数量、进价、金额、操作列总宽度超过弹窗内容区，操作列没有固定在右侧。
- **影响**：用户添加明细后容易找不到删除动作；笔记本和窗口分屏场景受影响更明显。
- **修复**：弹窗宽度改为 `min(980px, calc(100vw - 32px))`；明细“操作”列固定在右侧；优先压缩次要列或把规格/编码放到物料副标题，不要让删除动作依赖横向滚动。

### NEW-SEC-01 访问令牌保存在 JavaScript 可读 Cookie，放大现有 XSS 影响

- **规则**：客户端令牌存储 / XSS 影响面。
- **严重度**：中；在已有可达脚本渲染点未修复的前提下应按高优先级处理。
- **位置**：`erp-ui/src/utils/auth.js:1-17`、`erp-ui/src/utils/request.js:43-55`。
- **证据**：`Admin-Token` 通过 `js-cookie` 写入和读取，没有 `HttpOnly` 能力；每次请求把它拼到 `Authorization: Bearer`。
- **影响**：任一同源脚本执行点都可以读取并外传当前管理员令牌；公告富文本、导入结果和菜单搜索的危险 HTML 渲染点因此不只是页面篡改风险。
- **修复**：中长期迁移到服务端设置的 `HttpOnly + Secure + SameSite` 会话/刷新 Cookie，并配置 CSRF 防护；短期先关闭所有可达 XSS 渲染点、缩短令牌寿命、支持设备/会话撤销，并限制高权限账号长期登录。
- **误报说明**：当前未主动注入或外传令牌；结论来自存储实现和已确认脚本渲染链路。

### NEW-SEC-02 仓库内置 Nginx 配置缺少常见安全响应头

- **规则**：浏览器安全响应头。
- **严重度**：中（防御纵深）。
- **位置**：`docker/nginx/conf/nginx.conf:32-60`、`docker/nginx/conf/nginx.host.conf:32-60`。
- **证据**：可见配置只设置缓存响应头，没有 CSP/`frame-ancestors`、`X-Content-Type-Options: nosniff`、`Referrer-Policy`、点击劫持保护；配置本身只监听 80。
- **影响**：不能通过 CSP 限制脚本执行和外传目的地，也没有在该层阻止 iframe 点击劫持或 MIME 嗅探。
- **修复**：先以 Report-Only 模式上线 CSP，清理字符串 `eval` 后逐步收紧；补 `frame-ancestors 'none'`（或明确白名单）、`nosniff`、合理的 `Referrer-Policy`。TLS/HSTS 如果由外部负载均衡提供，应在部署文档和自动化检查里明确。
- **误报说明**：生产 CDN、Ingress 或负载均衡可能另行添加这些头；上线前需对真实生产域名执行响应头复核。

### NEW-SEC-03 仍存在字符串代码执行写法，阻碍严格 CSP

- **严重度**：低。
- **位置**：`erp-ui/src/layout/components/Settings/index.vue:294` 的字符串 `setTimeout`；`erp-ui/src/utils/generator/js.js:143` 的 `eval(item.pattern)`。
- **影响**：当前 `setTimeout` 内容是常量，直接利用风险低；代码生成器的正则配置如果未来可导入或共享，则可能把配置变成代码执行点。两处都会迫使 CSP 保留 `unsafe-eval` 或造成兼容问题。
- **修复**：改成函数回调；正则配置用受限字符串构造 `new RegExp(pattern, flags)` 并验证长度和允许语法，不执行任意 JavaScript 表达式。

### NEW-SEC-04 生产依赖有 4 个低危告警，无中高危或严重告警

- **命令**：`npm audit --omit=dev --registry=https://registry.npmjs.org --json`。
- **结果**：0 critical、0 high、0 moderate、4 low。
- **主要告警**：Vue 2 `parseHTML` 的低危 ReDoS（GHSA-5j4c-8p2g-v4jx），并由 `element-ui`、`vuex`、`@riophae/vue-treeselect` 继承；当前依赖树没有直接兼容修复。
- **建议**：不要为消除数字强装不兼容版本；建立 Vue 2 到受支持框架/版本的迁移计划，并对富文本/大输入做长度限制和性能回归。

## 6. 修复顺序建议
