## 1. 本检查点结论

新前端已经具备真实 HTTP 模式的浏览器认证入口：读取 ERP-NEW_2 一次性验证码、提交账号与密码、通过 HttpOnly Cookie 建立会话、重新读取完整授权上下文、区分匿名与过期状态、保护站内返回路径，以及使用当前 CSRF 证明退出。完整会话校验通过前，业务 Gateway 始终保持 unavailable；任何失败都不会回退到原项目、共享服务或 Mock 数据。

本检查点只覆盖代码、契约测试、组件测试、网关测试和生产构建。没有启动前端或后端服务，没有进行真实 Cookie、浏览器、Redis 登录态或验证码图片端到端联调，因此不宣称真实运行环境验收完成。

## 2. 登录与验证码契约

- 新增 `/code` 验证码客户端契约；请求使用同源 `/api`、`credentials: include` 和 `cache: no-store`，明确省略 CSRF 与组织头。
- 验证码响应必须声明 `Cache-Control: no-store`，启用时必须同时返回受限格式的 `uuid` 与 Base64 JPEG；关闭时不得夹带一次性验证码材料。
- 网关验证码路由不再只接受 `text/plain`，现在可由明确请求 JSON 的新客户端命中；成功和生成失败响应都设置 `no-store, max-age=0` 与 `Pragma: no-cache`。
- 验证码生成异常只向浏览器返回通用错误，不返回内部异常消息；日志只记录异常类型，不记录验证码答案、Cookie、令牌或凭据。
- 登录只发送 `username`、`password` 以及验证码启用时的 `code`、`uuid`；用户名按后端 2–20 字符约束校验，密码兼容既有短密码但拒绝超过后端 20 字符上限。
- 登录响应严格要求 CSRF 证明和正会话期限，并递归拒绝 `token`、`access-token`、`access_token`、`accessToken`、Bearer 或 Authorization 等令牌字段命名变体。

## 3. 会话状态与路由

- 会话 Store 新增 `anonymous` 和显式 `beginLoading`；初次会话探测 401 进入匿名状态，已经就绪的业务会话收到 401 才进入过期状态。
- 新增顶层公开 `/login` 路由。匿名与过期用户访问受保护页面时跳转登录，并保留经过安全规范化的站内返回路径；后端或契约不可用仍进入独立的会话不可用页。
- 返回路径拒绝跨源 URL、协议相对 URL、反斜杠、控制字符、片段、登录页循环，以及 URL 规范化后形成的双斜杠路径。
- 已登录用户访问登录页会返回经相同规则校验的站内目标，再由既有权限守卫决定是否允许进入。
- 跨标签页同步新增 `session-cleared` 事件；明确退出在其他 ERP-NEW_2 标签页中表现为匿名，而不是误报为会话过期。

## 4. 登录与退出界面

- 新增响应式 Vue 3 登录页：账号、密码显示切换、可选验证码、验证码刷新、字段错误、通用认证错误、会话过期提示与加载状态。
- 输入具有显式标签、错误描述关联、键盘提交和首个错误焦点恢复；密码与验证码不写入 Local Storage、Session Storage、Cookie 或 URL。
- 认证错误不直接显示后端用户查询结果，避免根据文案区分账号是否存在；网络、服务与安全契约错误使用独立的无敏感信息提示。
- 登录成功后重新读取浏览器会话、用户权限、功能目录和授权组织树；只有四步完整通过才进入目标页面并安装真实业务 Gateway。
- AppShell 在真实 HTTP 模式显示安全退出入口。退出携带会话绑定的 `X-CSRF-Token`、省略组织上下文；网络失败不会假装退出，已失效的服务端会话则安全完成本地清除。

## 6. 代码审查修复

高风险自审没有遗留 P0/P1 发现，并在提交前修复：

- JSON 客户端无法命中只接受 `text/plain` 的旧验证码路由；改为精确 GET 路径且不限制 Accept。
- 验证码生成失败会走未声明 `no-store` 的通用异常路径；改为通用、不可缓存的失败响应。
- 初版返回路径校验未拒绝点段规范化后产生的 `//host`；补充规范化后路径检查与回归用例。
- 初版令牌字段扫描只覆盖少数字段拼写；改为去除分隔符、忽略大小写后匹配禁止集合。
- 验证码异常测试日志曾包含模拟堆栈；生产实现改为只记录异常类型，避免内部错误细节进入日志。
