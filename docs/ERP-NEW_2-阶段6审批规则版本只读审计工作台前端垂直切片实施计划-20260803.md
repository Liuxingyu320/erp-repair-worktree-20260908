# ERP-NEW_2 阶段 6：审批规则版本只读审计工作台前端垂直切片实施计划

> 日期：2026-08-03
> 基线：`851da8b2 feat: add approval validation audit skeleton`
> 状态：本只读规则目录与不可变版本审计切片已完成；不代表规则编辑、候选人预览、发布或统一审批闭环迁移完成

## 1. 目标与范围

在 `erp-ui-next/` 内新增 `/approvals/rules` 审批规则版本只读审计工作台，覆盖审批管理员跨组织查看适用规则、按真实 Mapper 条件筛选、服务端分页、当前页状态摘要，以及查看规则关联模板、全部版本、条件和节点策略。

本切片只实现：

- `GET /approval/rules`；
- `GET /approval/rules/{id}`；
- 列表权限 `approval:template:list` 与详情权限 `approval:template:query` 的双重失败关闭；
- 系统级管理员跨组织只读语义，请求不发送组织头；
- 模板 ID、规则编码、规则名称、范围类型、范围 ID、业务子类型和规则状态筛选；
- 规则、版本、条件和节点的安全审计投影；
- ERP-NEW_2 隔离 Mock 默认运行时和未注入的真实只读 HTTP Reader；
- 桌面表格、移动卡片、加载、错误、空状态和最近成功结果语义。

以下能力明确留待后续独立切片：规则新建/编辑、草稿创建/保存、候选人预览、配置检查执行、版本发布、规则停用、真实运行时注入和旧审批管理页面下线。

## 2. 审计结论与硬边界

### 2.1 当前后端契约

- 规则列表要求 `approval:template:list`，规则详情要求 `approval:template:query`；编辑、发布权限保持独立。
- 列表 Mapper 实际消费 `templateId`、`ruleCode`、`ruleName`、`scopeType`、`scopeId`、`businessSubtype` 和 `ruleStatus`。
- 详情响应为 `{ template, rule, versions }`；每个版本由 Service 补齐 `conditions` 与 `nodes`，版本按版本号降序。
- 规则状态为 `DRAFT | ACTIVE | DISABLED`，版本状态为 `DRAFT | PUBLISHED | RETIRED`，范围为 `ALL | AREA | STORE`。
- 条件和节点可能正处于发布前校验失败状态；新契约必须安全展示不受支持的字段、操作符或策略，而不是把需要审计的无效草稿静默丢弃。

### 2.2 敏感投影

- 原始 `strategyConfig` 不进入页面模型；固定用户策略只显示去重人数，不显示用户 ID。
- 定义快照、定义校验和、发布人用户 ID、规则/版本锁版本、内部操作人和创建/更新时间全部丢弃。
- 条件值属于管理员配置审计事实，按数据库上限保留；节点只保留受控策略摘要、动作策略和是否受支持的判定。
- 列表和详情成功响应必须显式声明 `Cache-Control: no-store`，否则 Reader 失败关闭。

### 2.3 跨组织与生产阻断

- Controller 和 Mapper 没有当前组织数据范围条件，属于审批管理员系统级配置视图；Reader 显式省略组织头与 CSRF。
- 当前端点没有 `no-store` 响应头证据，真实 Reader 继续保持未注入。
- 默认 Provider 只注入 ERP-NEW_2 自有脱敏 Mock，不读取任何真实或共享业务数据。

## 3. 设计与动效决策

这是高频 ERP/SaaS 配置审计界面，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 信息层级为“跨组织范围 → 当前页健康 → 精确筛选 → 规则列表 → 版本 → 条件与节点”；
- 桌面和移动端都提供等价的查看版本动作；
- 版本选择、筛选、键盘提交、分页和列表/详情替换不播放动画；
- 仅允许按钮按压的 140ms 可中断 `transform` 反馈；
- `prefers-reduced-motion: reduce` 下关闭非必要过渡；
- 外部参考站点仅提供后台审计层级和局部交互研究，不复制代码、品牌、素材或付费提示词；
- 不新增 React、Tailwind、Motion、GSAP 或其他依赖。

## 6. 验证标准

- 列表只发送 Mapper 实际消费的参数，不发送组织、数据范围、`params` 或旧向导写命令参数；
- 列表与详情不发送组织头或 CSRF，并都强制响应 `no-store`；
- `ALL` 范围不得携带范围 ID，`AREA/STORE` 必须携带有效 Long 范围 ID；
- 详情模板、规则、版本和当前发布版本关联一致；固定用户 ID、原始 JSON、快照、校验和、锁版本和内部审计字段不可到达页面；
- 发布前无效条件或节点仍可见，并明确标记“需复核”，不伪装为有效配置；
- 页面没有编辑、保存草稿、预览、检查、发布、停用、导出或新建伪入口；
- 功能开关、列表权限和详情权限全部满足才可见且可访问；
- 完整前端验证、迁移生成器、确定性哈希和隔离扫描通过；
- 旧 `erp-ui/`、受保护原项目、Docker、服务、数据库、依赖和真实配置保持零改动。

## 7. 停止线

发现以下任一情况立即停止：

- 需要访问或修改受保护原项目、连接数据库、启动服务或安装依赖；
- 需要修改旧 `erp-ui/`、注入真实 Reader 或把当前组织误当作管理员数据范围；
- 需要执行规则编辑、草稿、预览、检查、发布或停用命令；
- 不能证明双权限失败关闭或敏感策略配置已脱敏；
- 不能证明全部文件和测试只位于 ERP-NEW_2 隔离工作树。
