# ERP-NEW_2 阶段 6：审批配置检查执行命令前端垂直切片实施计划

> 日期：2026-08-03
> 基线：`4f980dac feat: add approval instance admin actions`
> 状态：本执行命令垂直切片已完成；不代表规则修复、发布、真实运行时或统一审批闭环完成

## 1. 目标与范围

扩展 `erp-ui-next/` 的 `/approvals/validation` 工作台，让具备独立执行权限的管理员按一个精确审批版本发起配置检查，并在成功后刷新批次列表、打开服务端返回的问题明细。

本切片实现：

- `POST /approval/validation/run`；
- `approval:validation:run` 的独立失败关闭门禁；
- 严格命令 `{ versionId, validationType }`，不复制旧页面失效字段；
- 必填版本 ID、受控检查类型、目标与后果复核、显式二次确认；
- CSRF 必需、组织头省略、成功响应 `Cache-Control: no-store`；
- ERP-NEW_2 隔离可变 Mock 中新增检查批次与明细；
- 成功后刷新当前列表并打开新批次明细；不确定网络结果下先刷新核对，不自动重试；
- 桌面与移动共享同一个权限门禁和对话框。

规则/版本编辑、自动修复、发布、停用、真实运行时注入、旧审批管理页面下线与组合容器合并留待独立切片。

## 2. 审计结论与硬边界

### 2.1 后端真实契约

- Controller 要求 `approval:validation:run`，DTO 的唯一必填字段是 `versionId`，并兼容别名 `ruleVersionId`；新 Writer 只发送规范字段 `versionId`。
- `validationType` 可选；Service 空值默认 `MANUAL`。前端使用闭集 `MANUAL | FULL | PUBLISH` 并显式发送，不依赖隐式默认值。
- Service 按版本查询规则与模板，读取条件和节点，创建 `RUNNING` 批次、写入问题，再把批次置为 `PASSED` 或 `FAILED`，响应为 `{ run, issues }`。
- Service 只校验版本、规则与模板存在，不校验版本状态；页面不得暗示只有已发布版本可检查。
- `templateId` 与 `ruleId` 虽存在于 DTO，但 Service 不消费请求中的两个值；新 Writer 不发送。

### 2.2 旧页面纠偏

- 旧 `ValidationPanel.vue` 执行请求发送 `businessCode`、`scopeMode`、`anchorDeptId` 和 `businessSubtype`，与当前 Controller/Service 不兼容。
- 新对话框只允许输入精确版本 ID并选择检查类型，不提供无效范围字段，也不把当前组织当成执行范围。
- 列表旧筛选偏差继续由既有 Reader 契约阻断，本切片不扩大筛选范围。

### 2.3 幂等、缓存与默认运行时

- 当前 POST 没有 `requestId` 字段、幂等注解或去重证据；前端不得伪造幂等协议，也不得在结果不确定时自动重试。
- 提交期间禁止重复触发；收到成功响应后关闭对话框并刷新。错误时保留草稿，但明确提示先刷新相同版本批次再决定是否重新执行。
- POST 必须携带 CSRF、不得携带当前组织头；成功响应必须显式声明 `Cache-Control: no-store`，否则失败关闭。
- 默认 Provider 只使用 ERP-NEW_2 自有脱敏可变 Mock。HTTP Writer 保持未注入，不连接真实后端、共享服务或数据库。

## 3. 设计与动效决策

项目属于高频 ERP/SaaS 管理工作台，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 页面主动作只在拥有执行权限时显示；只读用户仍完整保留列表与明细能力。
- 表单先说明检查会新增审计批次但不会修改、发布或修复规则，再要求版本 ID 和检查类型。
- 二次确认展示规范化版本 ID、检查类型、非幂等风险和无组织范围语义；确认标题获得焦点，Tab 留在对话框内，Escape 可安全取消。
- 列表、筛选、键盘操作、对话框打开和刷新不播放动画；按钮只保留 140ms 可中断 `transform` 按压反馈。
- `prefers-reduced-motion: reduce` 下关闭非必要过渡；不新增依赖、动态背景、光效或营销式动效。

## 6. 验证标准

- 无 `approval:validation:run` 时没有执行入口；有列表权限不会隐式获得写权限。
- 无效/超范围版本 ID、未知检查类型与额外字段在发送前失败关闭。
- 请求体只有 `versionId` 和 `validationType`，不发送旧范围字段、模板/规则 ID、组织头或伪造幂等键。
- POST 必须携带 CSRF；响应缺少 `no-store` 时即使状态为 200 也不接受结果。
- 对话框提交中禁用关闭和重复提交；失败不清空草稿，提示先刷新核对再重跑。
- 成功返回完整安全明细，隔离 Mock 新增记录后当前列表和新批次明细可见。
- 默认运行时不发起真实 HTTP，不启动服务、不连接数据库，不修改旧 `erp-ui/`。
- 完整前端验证、迁移生成器、确定性哈希和隔离扫描通过。

## 7. 停止线

发现以下任一情况立即停止：

- 需要访问或修改受保护原项目、连接数据库、启动服务或安装依赖；
- 需要修改旧 `erp-ui/`、注入真实 Reader/Writer 或绕过 CSRF；
- 需要伪造后端不存在的幂等、版本状态或组织范围保证；
- 无法证明执行权限独立、响应投影安全或默认 Mock 完全隔离；
- 需要删除旧前端、合并、推送或改动其他 worktree。
