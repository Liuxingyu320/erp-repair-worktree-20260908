## 2. 后端闭环

### 2.1 严格调整接口

新增 `POST /inventory/stock/{stockId}/adjust`，权限保持为 `inv:stock:adjust`。请求体仅接受：

- `expectedVersion`：非负 Long 版本；
- `adjustQuantity`：非零 `DECIMAL(18,4)` 差量；
- `reason`：2–500 字符的审计原因。

服务执行顺序为：按库存 ID 加行锁 → 校验当前选择组织精确归属 → 校验版本 → 校验当前量与可用量均不为负 → 按版本条件更新 → 校验恰好更新一行 → 写入结构化库存流水 → 校验恰好写入一行 → 返回最新库存详情。任何一步失败均由事务回滚。

既有 `POST /inventory/stock/adjust` 未删除、未改签名，继续作为兼容入口；新前端只调用严格接口。

### 2.2 查询、流水与成本边界

- 库存关键词查询补齐批次、序列号、库位编码和库位名称；
- 流水查询补齐关键词、业务单号和起止日期，并拒绝结束日期早于开始日期；
- 流水业务引用使用 `STOCK-ADJ-{stockId}-V{version}`，可关联库存记录与更新版本；
- `inv:cost:view` 是成本读取的唯一普通权限，管理员保持兼容；
- Controller 在 JSON 和 Excel 输出前统一执行成本脱敏，不依赖客户端隐藏列。

## 3. 新前端闭环

### 3.1 页面与路由

- `/inventory/stock`：库存现状、预警、授权可见范围、详情入口和受控导出；
- `/inventory/stock/:stockId`：库存详情、当前组织写边界、调整预览、二次确认和最近流水；
- `/inventory/stock/movements`：当前组织库存流水、筛选、分页、业务追溯和受控导出。

静态流水路由注册在动态库存详情路由之前。路由分别要求 `inv:stock:list`、`inv:stock:query` 和 `inv:stock:log`；调整、导出、成本显示继续按 `inv:stock:adjust`、`inv:stock:export` 和 `inv:cost:view` 独立判断。

### 3.2 契约与网关

- Long、版本、日期、日期时间和十进制数量均经过 Zod 严格校验；
- 当前库存必须等于锁定库存加可用库存；
- 成本单价与总成本必须同时出现或同时为空；
- 真实写请求拒绝 Mock 标识，只允许服务端 Long 库存和组织 ID；
- 调整命令不会自动重试；
- Excel 响应必须非空、MIME 合法、大小不超过 20 MiB 且明确 `no-store`；
- Mock 使用独立内存数据，按组织精确隔离，并模拟版本递增、幂等结果和新增流水。

### 3.3 交互与动效

页面按高频 ERP / SaaS 工作台设计，参考用户指定的 MotionSites、21st.dev、React Bits、UI Prompt Library、Magic UI、Motion Primitives 与 Uiverse 的结构和交互原则，但未复制第三方组件代码。

动效采用 Emil Kowalski 的克制与即时反馈为主、Jakub Krehel 的生产级细节为辅：高频筛选和分页不做装饰性动画；仅二次确认使用 180ms 进入、120ms 退出的 opacity/transform/filter 过渡。弹窗具备焦点进入、焦点陷阱、Escape、忙碌态阻断和焦点恢复；`prefers-reduced-motion: reduce` 下关闭非必要过渡与按压缩放。
