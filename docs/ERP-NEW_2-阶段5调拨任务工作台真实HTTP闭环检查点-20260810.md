## 1. 本检查点结论

本阶段在 ERP-NEW_2 隔离工作树内，将 `/inventory/transfer` 从 Mock-only 聚合视图升级为当前门店或仓库范围内、失败关闭的真实只读 HTTP 工作台。

本检查点证明：

- 列表与运营摘要使用同一精确组织上下文并并行读取；
- 服务端列表负责单号、状态、类型筛选及分页，页面不再对一页结果伪装全量筛选；
- 运营摘要回显组织标识，列表每行必须以当前组织为调出方或调入方，否则前端拒绝结果；
- 页面展示服务端真实生命周期、审批等待对象、下一步动作、明细行数和更新时间；
- 已移除 Mock 文案、跨单位“件”汇总、伪截止时间，以及使用调拨单 ID 构造的虚假收货入口；
- 默认 Mock 与真实 HTTP Gateway 共享同一查询接口，但真实运行组合器已明确接入 HTTP reader；
- 本阶段没有启动任何服务，也没有连接数据库或中间件。

## 2. 后端只读边界

### 2.1 列表投影与分页

- `InvTransferOrder` 新增只读 `detailLineCount` 投影，不参与持久化或数量计算；
- 列表 Mapper 对每个调拨单统计真实明细行数，保留既有组织范围和创建时间倒序；
- 前端冻结页码、1～100 的页大小、64 字符内单号、完整 12 状态枚举和 3 种调拨类型；
- 工作台不展示 `totalQuantity`，避免把不同计量单位汇总为虚假的统一“件”数。

### 2.2 运营摘要与缓存保护

- 摘要新增当前组织、待审批、待继续发货和待继续收货计数；
- `partial_delivered` 同时属于“仍可继续发货”和“存在在途待收货”，两个指标表达不同作业责任，允许交叠；
- `/list`、`/processing` 与 `/ops-summary` 均设置 `Cache-Control: no-store, max-age=0` 和 `Pragma: no-cache`；
- 空摘要也由 Service 回填已选择组织，前端不会把缺失组织当作安全默认值。

## 3. 新前端闭环

### 3.1 冻结契约与真实 HTTP Gateway

- Long 标识按字符串保留，并拒绝超出后端 Long 范围或已经不安全的 JavaScript 数字；
- 状态、类型、非负计数、日期时间、审批摘要归属、分页和查询均显式校验；
- 响应仅映射页面所需白名单字段，不向 UI 泄漏成本、总数量或审批内部候选标识；
- 两个 GET 请求均要求当前精确组织头、禁用 CSRF、支持同一取消信号并验证 `no-store`；
- 摘要组织漂移或任一列表行越出当前组织时，整个工作台请求失败关闭。

### 3.2 页面事实与失败处理

- 仅门店或仓库组织、且持有调拨列表权限时发起读取；公司或集团层级保持空状态；
- 组织切换中止旧请求并清除旧组织快照，防止响应串写；
- 查询失败保留最近一次成功快照，明确提示失败，不把旧数据标记为新结果；
- 分页、总数、本页条数和筛选条件均来自已应用的服务端查询；
- 只暴露可由权威 `transferId` 定位的详情、历史与发货规划；列表没有 shipment/task/case 标识时不伪造收货或差异深链；
- 本地导出明确限定“本页 CSV”，不冒充服务端全量导出。

### 3.3 设计参考边界

页面遵循 `docs/ERP-NEW_2-前端设计参考与使用约束.md`，吸收 21st.dev、React Bits、UI Prompt Library、Magic UI、Motion Primitives、Uiverse 与 MotionSites 对后台信息层级、状态连续性和局部反馈的启发，但未复制第三方代码、素材、提示词或品牌。交互保持克制，优先即时筛选提交、清晰状态和桌面/移动事实一致性。
