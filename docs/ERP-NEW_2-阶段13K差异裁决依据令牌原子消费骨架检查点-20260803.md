## 2. 已完成骨架

### 2.1 浏览器安全命令

新增 `InvTransferReceiptDiscrepancyAdjudicationCommand`，仅携带：

- 请求幂等标识；
- 不透明 basis token；
- 事项 ID 与浏览器看到的事项版本；
- 裁决说明、证据引用和动作列表。

该命令不包含 `factFingerprint`、双方确认事件 ID、决定指纹、裁决主键、内部金额分摊或执行状态。`toString()` 不输出 token、说明、证据或动作正文。

### 2.2 令牌核验和消费意图

- `issued` 路径核验 token 摘要、5 分钟窗口、用户姓名与 ID、权限、所选组织、规范化范围摘要、事项、版本、事实指纹和双方最新确认事件。
- `PreparedConsumption` 完整绑定 basis、请求、裁决、用户和消费时间；令牌摘要、事实指纹和范围摘要在字符串表示中脱敏。
- 消费时间必须位于 `[issuedAt, expiresAt)`。
- `consumed` 重放不以当前时间拒绝，但要求最初消费确实发生在有效期内，并且当前用户、权限、组织范围、事项事实、确认事件、请求和裁决锚点仍完全一致。

### 2.3 唯一事务与固定锁序

`InvTransferReceiptDiscrepancyAdjudicationCreationService` 在同一 `@Transactional(rollbackFor = Exception.class)` 内固定执行：

1. 校验登录快照和精确权限；
2. 解析有限组织范围；
3. 按范围锁事项；
4. 按请求标识锁裁决头；
5. 按用途域 token 摘要锁 basis；
6. 只从已锁服务端 basis 恢复内部事实指纹；
7. 条件写裁决头和完整动作；
8. 条件推进事项状态与版本；
9. 最后把 basis 条件推进为 `consumed`。

basis 消费不是精确一行时抛出异常，使此前的裁决头、动作和事项状态全部进入同一事务回滚边界。精确重放只读取原动作并返回原裁决，不执行任何新写入或二次消费。

### 2.4 持久化边界

- basis Mapper 只有一个条件签发 INSERT、一个摘要行锁 SELECT 和一个条件消费 UPDATE，无删除、续期、重置或重新启用方法。
- 条件消费再次匹配 basis 的全部绑定，并通过 `EXISTS` 匹配同事务写入的裁决 ID、请求、事项、前后版本、事实指纹、双方事件、裁决人、权限和计划状态。
- 原始 token 不进入 Mapper 参数、数据库列或日志字符串。
- 未执行的 MySQL 5.7 DDL 草案将 `consumed_request_id` 和 `consumed_adjudication_id` 分别设为唯一键，约束一次消费与一次裁决的一一关系。

## 3. 失败关闭覆盖

- 无权限时在组织解析与数据库访问前拒绝；
- 无效、未来签发、已过期、已消费或被篡改的 token 拒绝新写；
- 跨用户、所选组织、组织范围、事项、版本、事实、请求或裁决锚点拒绝；
- 裁决头零行、主键缺失、动作行数不完整、事项推进零行或 basis 消费零行均停止并抛出事务异常；
- 重放时动作、决定指纹、事项状态、版本、事实或确认组织漂移均拒绝；
- 已消费 token 只有原 token、原请求和原裁决的完整快照可在过期后安全重放。
