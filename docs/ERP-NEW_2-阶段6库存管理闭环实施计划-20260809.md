## 1. 结果定义

在不启动服务、不连接数据库、不使用 Docker、也不依赖旧前端源码的前提下，完成库存现存量、库存详情、手工调整、库存流水和受控导出的端到端代码闭环。该切片完成后：

- 库存列表支持当前组织与授权可见范围，并明确区分可写与只读记录；
- 用户可进入库存详情查看数量、批次、效期、序列号、库位和最近流水；

- 调整命令使用幂等请求标识、CSRF、组织头、服务端行锁和乐观版本校验；

- 缺少 `inv:cost:view` 时，列表、汇总、详情、流水和导出均由服务端清除成本值；
- 所有库存响应明确禁止缓存，前端继续校验 `no-store`；
- Mock 模式具有完全离线、可重复、按组织隔离的相同行为。

## 3. 关键约束与安全不变量

- 所有写入仅发生在 ERP-NEW_2 隔离工作树。
- 新前端不得 import、symlink 或在运行时引用 `erp-ui/src`。
- 当前组织是库存调整的唯一写边界；授权可见的其他组织库存只能读取。
- 前端权限仅用于体验控制，服务端权限、组织范围、版本和库存可用量仍是最终裁决。
- 成本脱敏必须发生在后端序列化/导出前，不能只依赖前端隐藏列。
- 调整数量按 `DECIMAL(18,4)` 业务上限处理：最多 14 位整数、4 位小数、不得为 0。
- 调减后当前库存和可用库存都不得为负数。
- 调整原因必填，规范化后长度为 2–500 字符；不得把秘密或文件内容写入请求日志。
- 写命令不自动重试；相同幂等键只能对应相同载荷。
- Excel 下载必须显式触发、校验 MIME、限制最大响应体并使用本地对象 URL 后立即释放。

## 4. 接口设计

### 读取

- `GET /inventory/stock/list`：库存分页列表，`inv:stock:list`。
- `GET /inventory/stock/summary`：当前筛选汇总，`inv:stock:list`。
- `GET /inventory/stock/{stockId}`：库存详情，`inv:stock:query`。
- `GET /inventory/stock/log/list`：当前组织库存流水，`inv:stock:log`。

### 命令

- `POST /inventory/stock/{stockId}/adjust`：严格库存调整，`inv:stock:adjust`。

请求体：

```json
{
  "expectedVersion": 7,
  "adjustQuantity": "-2.5000",
  "reason": "门店破损复核后调减"
}
```

服务端必须先按 `stockId` 加行锁，再验证记录属于当前选择组织、请求版本与当前版本一致，最后执行加减、写入库存流水并返回更新后的库存详情。既有 `POST /inventory/stock/adjust` 暂时保留，避免破坏其他模块的兼容调用。

### 导出

- `POST /inventory/stock/export`：按当前库存筛选导出，`inv:stock:export`。
- `POST /inventory/stock/log/export`：按当前流水筛选导出，`inv:stock:export`。

所有端点均返回或设置 `Cache-Control: no-store, max-age=0` 与 `Pragma: no-cache`。

## 9. 风险与回退

- **兼容风险**：不删除或改签名既有 `/stock/adjust`，新前端只调用新增严格接口。
- **成本泄露风险**：controller 在返回/导出前统一清空字段，并以不同权限上下文测试。
- **并发风险**：行锁后校验客户端版本，写 SQL 继续携带版本条件。
- **Mock 漂移风险**：HTTP 与 Mock 共用相同 Zod 命令/查询契约，测试同一不变量。
- **导出风险**：只在用户确认后下载；失败不产生空文件或无限大小响应。
- **回退方式**：本切片独立本地提交，可由用户未来在隔离分支内单独 revert；不触碰其他工作树。
