# ERP-NEW_2 阶段 6：配送通知只读工作台前端垂直切片实施计划

> 日期：2026-08-03
> 基线：`b99724fc feat: add sales return workbench skeleton`
> 状态：已完成只读配送通知前端切片；不代表销售发货闭环迁移完成

## 1. 目标与范围

在 `erp-ui-next/` 内新增 `/sales/delivery-notices` 配送通知工作台，覆盖当前销售门店或发货仓库可见通知的筛选、服务端分页、来源销售单、客户、销售门店、发货仓库、业务状态和响应式只读展示。

本切片只实现：

- `GET /inventory/deliveryNotice/list`；
- 权限 `inv:deliveryNotice:list`；
- 当前门店或仓库的严格数据范围，公司上下文不发请求；
- 通知单号、销售单号、客户、精确状态与待发状态组筛选；
- 服务端总记录数，以及当前页待发货、发货中、已发货和已取消数量；
- ERP-NEW_2 隔离 Mock 默认运行时和未注入的真实只读 HTTP Reader；
- 桌面表格、移动卡片、加载、错误、空状态和最近成功筛选语义。

以下能力明确留待后续独立切片：详情、从销售单生成通知、执行发货、仓库选择、取消、导出、发货明细、库存扣减、跨店调拨生成、真实运行时注入和旧配送通知页面下线。

## 2. 审计结论与硬边界

### 2.1 迁移顺序

- 正式方案阶段 6 第 3 项要求迁移客户、销售、退货和配送；
- 已冻结的销售订单状态中，`submitted` 可生成配送通知，通知完成后销售单进入 `delivered`；
- 执行发货还会扣减仓库库存、写出库记录与库存流水，跨店场景可能继续生成调拨收货单；
- 当前切片只冻结通知列表读模型，不把发货写流程、库存扣减或跨店调拨描述为已迁移闭环。

### 2.2 接口与权限拆分

- 列表：`GET /inventory/deliveryNotice/list`，权限 `inv:deliveryNotice:list`；
- 详情、生成通知、执行发货、取消和导出均使用独立权限或端点；
- 本切片不得展示详情、导出或任何写动作伪入口，也不得用列表权限调用其他端点。

### 2.3 组织与数据范围

- 旧桌面页面同时表达销售门店视角和发货仓库视角，移动发货入口只允许 `WAREHOUSE`；
- 列表 Mapper 按销售门店、通知仓库或销售明细计划仓库匹配组织范围，因此新切片支持门店和仓库两类叶子上下文，不提供公司级聚合；
- 门店上下文的每一行必须匹配 `shopDeptId`；仓库上下文的每一行必须匹配唯一 `warehouseId`；
- 多仓通知只返回聚合仓库名称且 `warehouseId` 为空，无法证明当前仓库逐行可见性，仓库 Reader 必须拒绝整页；
- Reader 只能发送当前会话组织头，不能接受 `shopDeptId`、`warehouseId`、`scopeDeptIds` 或 `dataScope` 查询参数；
- 请求携带 `expectedOrganizationId`，组织漂移在 `fetch` 前失败；默认启动只注入隔离 Mock，真实 Reader在版本化 OpenAPI、逐仓证明和缓存策略完成前保持未注入。

### 2.4 状态、数量与时间

- 分页字段为 `pageNum`、`pageSize`；筛选字段为 `noticeNo`、`salesOrderNo`、`customerName`、`status`，待发组合映射为 `statusGroup=deliverable`；
- 状态闭集为 `pending`、`delivering`、`completed`、`cancelled`；未知状态失败关闭；
- `noticeId`、`shopDeptId` 与可选 `warehouseId` 必须经过 Java Long 边界；
- `createTime` 是旧本地日期时间标签，新页面不伪造不存在的业务日期；
- Mapper 返回的 `noticeQuantity`、`deliveredQuantity` 与 `remainingQuantity` 可能跨“件、盒、罐”等单位聚合，新列表模型必须丢弃；
- 来源销售单 ID、详情、内部操作人、数据范围参数和更新字段不进入列表模型。

## 3. 设计与动效决策

这是高频 ERP/SaaS 发货工作台，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 使用“当前组织视角 → 总记录/当前页状态 → 明确筛选 → 配送通知事实”的层级；
- 销售单、客户、销售门店、发货仓库、创建时间与状态在桌面和移动端保持等价；
- 搜索、状态筛选、键盘提交、分页和列表替换不播放动画；
- 只允许按钮按压的 140ms 可中断 `transform` 过渡；
- `prefers-reduced-motion: reduce` 下关闭所有非必要过渡；
- 不新增 React、Tailwind、Motion、GSAP、远程字体或外部组件依赖。

## 5. 测试驱动实施顺序

1. 固定安全 Long、可选仓库 ID、状态闭集、真实创建时间、有界筛选和字段丢弃。
2. 固定 Mock 的门店/仓库隔离、单号/销售单/客户/状态筛选、分页和当前页统计。
3. 固定 HTTP Reader 的精确 URL、待发状态组、单一 `Dept-NumId`、无 CSRF、组织漂移、跨组织返回和多仓歧义拒绝。
4. 固定页面的门店/仓库加载、公司零请求、桌面/移动等价展示、显式筛选和失败后保留最近成功条件。
5. 固定 `inventory.delivery-notice.view`、`inv:deliveryNotice:list`、路由和导航双重门禁。
6. 实现最小领域、Mock、HTTP、页面、路由和导航，使测试转绿。
7. 更新迁移覆盖层为“重设计 / 部分实现”，明确所有延期动作与跨单位数量边界。
8. 运行完整 `verify`、阶段 1 生成器两次、确定性哈希和隔离审计；全部通过后只做本地提交。

## 6. 验证标准

- 不安全 Long、非法状态、无效创建时间和越界筛选全部失败关闭；
- 新模型不包含来源销售单 ID、跨单位数量汇总、详情、内部操作人或更新字段；
- HTTP Reader 只发送允许参数和一个旧组织头；组织漂移、跨组织记录与仓库视角多仓歧义都失败；
- 门店和仓库只能读取自身隔离 Mock；公司上下文不调用 Gateway；
- 页面明确区分服务端总记录和当前页状态，不展示不可解释的数量合计；
- 筛选成功后才更新已应用条件，失败时保留最近成功标签并可重试最后请求；
- 页面没有详情、生成、执行发货、取消或导出伪入口；
- 功能开关和列表权限同时满足才可见且可访问；
- 完整前端验证、迁移生成器、确定性哈希和隔离扫描通过；
- 旧 `erp-ui/`、受保护原项目、Docker、服务、数据库、依赖和真实配置保持零改动。

## 7. 停止线

发现以下任一情况立即停止：

- 需要读取或修改受保护原项目、连接数据库、启动服务或安装依赖；
- 需要修改旧 `erp-ui/`、注入真实 Reader 或绕过组织数据边界；
- 需要公司级汇总或多仓通知而当前响应不能证明逐行授权；
- 需要启用详情、生成通知、执行发货、取消或导出而没有独立计划；
- 不能证明全部文件、运行目录和测试只位于 ERP-NEW_2 隔离工作树。
