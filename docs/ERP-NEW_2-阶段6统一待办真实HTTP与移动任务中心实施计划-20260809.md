## 1. 目标与范围

将新前端 `MobileTasksPage` 从调拨 Mock 聚合迁移到服务端已存在的统一待办契约，完成一条可独立验证的阶段 6 竖向切片：

- 并行读取 `approval` / `inventory` / `oa` / `system` 四个技术提供方；
- 保留“技术提供方”与用户看到的 `inventory` / `oa` / `system` 业务来源两层语义；
- 提供分类、业务来源、组织范围、关键词和分页/加载更多；
- 任一提供方失败时保留其上次同组织、同查询的成功数据，显式标记陈旧或未知，不将未知伪装为 0；
- 待办只能通过新前端登记的深链白名单跳转，未迁移页面和不完整参数默认关闭；
- 为四组待办只读端点补齐 `Cache-Control: no-store` 与 `Pragma: no-cache`。

本切片不把待办中心扩张为业务写操作，不实现尚未迁移的 HR、合同、固定资产、采购退货页面，也不把工作台调拨概览伪装为已有真实聚合。

## 2. 权威契约证据

网关后的服务路径为：

| 技术提供方 | 摘要 | 列表 |
| --- | --- | --- |
| `approval` | `GET /approval/todo/summary` | `GET /approval/todo/list` |
| `inventory` | `GET /inventory/todo/summary` | `GET /inventory/todo/list` |
| `oa` | `GET /oa/todo/summary` | `GET /oa/todo/list` |
| `system` | `GET /system/todo/summary` | `GET /system/todo/list` |

共享 `TodoQuery` 限定：

- `type` 为大写类型码；
- `category` 只允许 `approval` / `execution` / `returned` / `risk` / `personal`；
- `source` 只允许 `inventory` / `oa` / `system`；
- `scopeMode` 只允许 `current_org` / `all_authorized`；
- `pageSize` 服务端上限为 100。

`TodoItem` 提供稳定 `todoKey`、业务来源、类型、分类、优先级、创建时间、组织上下文、`routeType`、`routeParams` 和 `requiredPermission`。服务端参数仅作为不可信输入，不允许直接生成 URL。

## 3. 领域与安全设计

### 3.1 运行时契约

- 使用 Zod 严格校验摘要和列表包装；兼容当前 `AjaxResult.data` 与 `TableDataInfo.rows/total` 结构；
- Java `Long` 标识在前端一律保存为字符串，对不精确 JSON number 失败关闭；
- `routeParams` 只接受有界的字符串键值，禁止对象嵌套、数组、URL 和原型链关键键；
- 列表必须按“紧急优先、同级最早创建、业务 ID、todoKey”确定性排序并全局去重。

### 3.2 聚合、分页与失败

- 全局第 `p` 页、每页 `s` 条需要每个提供方的前 `p*s` 条；提供方请求始终不超过 100 条；
- 全部前缀合并、去重、稳定排序后再切片，不把多个局部第 `p` 页直接拼接；
- 摘要缓存键包含 provider + category + source + scope + keyword + 组织；
- 列表缓存键在上述基础上再包含所需前缀，不得跨组织、跨筛选或跨页误用；
- 成功提供方标记 `fresh`，有同键缓存的失败提供方标记 `stale`，无缓存的失败提供方标记 `unknown`；
- 仅当所选提供方都成功、总数已知且未观测到跨提供方重复时才对外声明精确总数。

### 3.3 深链白名单

- 新增的待办目标只能指向新前端已登记的列表、调拨详情、审批、发货或收货路由；
- 处理前同时复核 `requiredPermission`、新前端 feature 开关和目标路由权限；
- `INV_TRANSFER_RECEIVE` 只使用 provider 返回的 `shipmentId`；
- 原生统一审批只在 `businessId + approvalTaskId + approvalInstanceId` 完整时生成审批目标；
- 未知类型、不完整参数和尚未迁移功能仅显示“处理页面待迁移”，不降级到旧前端。

## 4. 移动任务中心交互

- 页头保留当前组织、已知待办总数和数据新鲜度；
- 分类 chip 为高频操作，即时切换，不使用装饰性动画；
- 筛选提交、重试、加载更多和“去处理”触控目标不低于 44px；
- 仅对首次成功出现的状态区和卡片使用约 180ms 的 `opacity + translateY` 功能性入场，不使用循环、弹跳、大幅缩放或视差；
- `prefers-reduced-motion: reduce` 下关闭非必要动效；数据未知、缓存数据和处理页未迁移始终以文字呈现，不依赖动效或颜色。
