## 2. 权限、组织与传输边界

| 动作 | 精确权限 | 组织限制 |
| --- | --- | --- |
| 查看列表 | `inv:supplier:list` | 门店或仓库及服务端授权相关范围 |
| 查看详情与供货商品 | `inv:supplier:query` | 门店或仓库及服务端授权相关范围 |
| 新增 | `inv:supplier:add` | 当前门店或仓库 |
| 编辑 | `inv:supplier:query`、`inv:supplier:edit` | 当前门店或仓库的授权相关范围 |
| 删除 | `inv:supplier:remove` | 当前门店或仓库的授权相关范围 |
| 导出 | `inv:supplier:export` | 当前门店或仓库及当前筛选条件 |
| 查看采购价和成本价 | `inv:cost:view` | 服务端与前端双重裁剪 |

- 路由同时要求 `inventory.supplier.view` 和 `inv:supplier:list`；后端按列表权限显式发布 feature；
- 公司、缺失组织、未知组织类型或缺少列表权限时不读取数据；保存、删除和导出在执行瞬间再次核对组织和权限；
- 读取与写入均只发送当前 `Dept-NumId`；写命令与导出强制 CSRF、`X-Request-Id`，幂等 CRUD 同时发送同值 `Idempotency-Key`；
- 未修改表单的人工重试复用请求 ID，字段变化后生成新 ID；写操作不自动重试；
- Java `Long` 在浏览器中保持正十进制字符串；状态、合作状态、分页、文本、邮箱和非负十进制数均由白名单契约校验；
- JSON 与 Excel 成功响应必须声明 `Cache-Control: no-store`，否则真实 Gateway 失败关闭；
- 导出只接受 Excel 或通用二进制 MIME，最大 25 MiB，固定使用安全文件名，不信任服务端 `Content-Disposition`。

## 3. 后端完整性与隐私加固

- `InvSupplierController` 为列表、详情、供货商品、保存、删除和导出统一设置 `no-store`；
- 无 `inv:cost:view` 时，供货商品响应中的 `purchasePrice` 与 `costPrice` 在服务端置空，前端也不渲染对应列；
- 供应商查询、详情、供货商品、更新和删除在相关组织范围为空时失败关闭，不能通过省略 `IN` 条件扩大范围；
- 名称和非空编码在所属组织内排除自身检查重复；当前切片未新增数据库唯一约束，因此不声明并发下的绝对唯一性；
- 已被商品、采购订单或采购退货引用的供应商禁止改名和删除，引用检查限制在服务端授权相关组织范围内；
- 不级联修改历史单据名称快照；有引用时应停用供应商或进入后续主数据治理流程；
- 新增和更新检查数据库受影响行数，保存后必须能读取结果；更新 SQL 已补齐普通 `remark` 持久化。

## 4. 界面与动效决策

高频 ERP 工作台采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 吸收 21st.dev、React Bits、UI Prompt Library、Magic UI、Motion Primitives、Uiverse 与 MotionSites 的信息层级和局部反馈思路，不复制外部代码、品牌或资产；
- 筛选、分页、键盘操作和数据刷新即时完成，不使用页面入场序列、循环光效、弹跳、视差或布局动画；
- 仅按钮提供 140ms、可中断的按压和阴影反馈；`prefers-reduced-motion: reduce` 下关闭非必要过渡；
- 详情、编辑和导出确认均提供初始焦点、Tab 焦点循环与 Escape 关闭；删除和导出约束都有非动效文本说明；
- 统计卡明确区分服务端总数与当前页状态计数，桌面与移动端共用同一查询、命令和权限状态。
