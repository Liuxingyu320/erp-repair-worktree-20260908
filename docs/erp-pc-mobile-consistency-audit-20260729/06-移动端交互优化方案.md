# 移动端交互优化方案

> 设计日期：2026-07-29
> 设计目标：用户打开应用 10 秒内知道待处理事项；高频业务单手可完成；现场操作充分利用扫码、拍照和即时提醒；任何移动简化都不破坏业务闭环。

## 1. 当前体验诊断

当前移动端的优势：

- 已有 59 个可访问路由，覆盖人事、门店、仓库、OA、合同和系统管理；
- 多数核心单据已有移动动作配置，可完成草稿、提交、收货、质检、出入库、审批等操作；
- PC 与移动复用 API 模块，具备统一业务的技术基础；
- 已有门店、仓库、HR 工作台和移动“我的”入口。

当前核心问题：

1. 三套工作台和大量平铺入口导致一级导航不稳定；
2. 消息、通知、待办和独立审批页面职责重叠；
3. 后台管理页面占用移动信息架构，现场高频能力反而不突出；
4. 列表、详情、动作和长表单需要更统一的移动交互；
5. 扫码、弱网草稿、原生深链、相机权限和生产真机流程尚未完整落地；
6. “无数据”“无权限”“功能关闭”“接口失败”容易被用户理解成同一种空白状态；
7. 本人动作与管理动作在薪资、健康证、系统管理等页面需要更清晰分离。

## 2. 设计原则

| 原则 | 设计要求 |
|---|---|
| 任务优先 | 首页先显示需要行动的事项，不先展示装饰性图表 |
| 单一主动作 | 每个状态首屏最多一个强调主按钮 |
| 角色化内容、固定结构 | 五个一级入口不变，卡片和应用随角色权限变化 |
| 上下文可见 | 所有库存/采购/销售页始终显示当前门店或仓库 |
| 现场优先 | 扫码、拍照、快速确认优先于大表格编辑 |
| 渐进披露 | 先显示摘要，明细、附件、轨迹按需展开 |
| 可恢复 | 草稿、上传、弱网、并发冲突都告诉用户下一步 |
| 状态真实 | 部分失败不能显示为 0；客户端不提前宣告业务成功 |
| 安全默认 | 敏感信息脱敏，高风险动作默认不在手机开放 |
| 可访问 | 字体、对比度、触控尺寸、焦点和读屏标签符合移动使用 |

## 3. 信息架构

### 3.1 固定五栏

| 一级入口 | 用户问题 | 内容 | 红点/数字规则 |
|---|---|---|---|
| 工作台 | 今天最重要的是什么？ | 当前组织、今日任务、异常、快捷入口、最近业务 | 仅重大异常使用红点，不重复显示待办总数 |
| 消息 | 发生了什么？ | 系统、审批结果、任务提醒、业务消息 | 未读消息数，最大显示 `99+` |
| 待办 | 现在要我做什么？ | 待审批、待执行、退回、风险、个人事项 | 可执行待办总数 |
| 应用 | 我要主动发起什么？ | 按人事/OA/门店/仓库/查询分组的全部授权应用 | 默认无红点；应用内部可有任务角标 |
| 我的 | 与我本人有关的内容在哪里？ | 资料、组织、合同、工资、考勤、设置、帮助 | 仅资料缺失/安全风险提示 |

### 3.2 现有入口迁移

| 现有入口 | 新位置 |
|---|---|
| 店铺/仓库/HR 工作台 | 同一个“工作台”的角色化内容 |
| 手机通知 | “消息” |
| 我的待办、采购审批、调拨审批 | “待办”，独立路径保留为深链 |
| 手机个人资料、劳动合同、我的签约、工资 | “我的”及对应应用 |
| 销售、采购、库存、入职等 | “应用”并可作为工作台快捷入口 |
| 用户、角色、菜单、配置、字典、任务 | 普通移动应用移除；PC 管理 |
| 登录/操作日志、在线用户 | 管理员安全中心内条件只读开放 |

## 4. 工作台设计

### 4.1 首屏线框

```text
┌──────────────────────────────┐
│ 早上好，张三      华东一店 ▾ │
│ 数据更新于 09:42   [刷新]     │
├──────────────────────────────┤
│ 今日待办                      │
│ [待审批 12] [待执行 8]        │
│ [被退回 2]  [风险 5]          │
│ 有 1 个数据来源暂不可用 [重试] │
├──────────────────────────────┤
│ 需要关注                      │
│ ⚠ 3 个商品低于安全库存        │
│ ⚠ 1 个调拨存在收货差异        │
│ ⚠ 2 份健康证将在 7 天内到期   │
├──────────────────────────────┤
│ 快捷入口                      │
│ 审批  考勤  销售  查库存       │
│ 补货  盘点  员工  报修         │
├──────────────────────────────┤
│ 最近处理                      │
│ DB-20260729-003  调拨在途  >  │
└──────────────────────────────┘
 工作台   消息   待办   应用   我的
```

### 4.2 十秒感知标准

在正常网络下：

- 1 秒内显示骨架和当前组织；
- 3 秒内至少显示缓存的上次成功摘要并标注时间；
- 5 秒内完成主要实时摘要；
- 10 秒内用户可进入至少一个有效任务；
- 单一来源失败不阻断其他来源；
- 超过 10 秒显示明确的失败来源、上次更新时间和重试。

严禁：

- 用 `0` 替代尚未返回或失败的数据；
- 首屏放置不可操作的大幅轮播图；
- 快捷入口超过 8 个；
- 同一个待办同时出现在多个无关联区域并重复计数。

### 4.3 快捷入口排序

排序公式只影响展示，不影响权限：

1. 角色默认高频入口；
2. 当前组织可用入口；
3. 过去 30 天本人使用频率；
4. 当前有待办的应用；
5. 用户可固定最多 4 个入口。

最终结果先经服务端权限和组织条件过滤。

## 5. 消息中心设计

### 5.1 列表

- 顶部标签：全部、系统、审批、任务、业务；
- 卡片显示标题、摘要、时间、业务对象和未读状态；
- 重要业务消息可置顶，但过期后自动取消；
- 左滑仅提供“标记已读/未读”，不默认提供删除；
- “全部已读”二次确认，说明影响范围。

### 5.2 详情与深链

```text
点击消息
→ 先标记已读
→ 判断是否有业务引用
→ 有：校验权限并打开对应移动详情
→ 无：展示完整通知
→ 无权限：展示“权限已变化”，不泄露业务内容
→ 当前移动端不支持该管理动作：展示可解释的只读详情和 PC 处理提示
```

消息详情不能只给一个无法理解的业务 ID；至少显示业务类型、单号、组织、触发事件和时间。

## 6. 待办中心设计

### 6.1 分类和排序

| 分类 | 包含内容 | 默认排序 |
|---|---|---|
| 待审批 | 采购、请假/人事、付款类若未来接入、合同、调拨等审批 | 截止时间、优先级、等待时长 |
| 待执行 | 收货、质检、出库、收货确认、补资料、资产确认 | 截止时间、业务优先级 |
| 被退回 | 需要发起人修改重提的单据 | 最近退回时间 |
| 风险提醒 | 库存不足、到期、差异、接口补偿异常 | 风险级别 |
| 个人事项 | 本人合同、健康证、资料、考勤异常 | 截止时间 |

### 6.2 待办卡片

每张卡片只展示决策所需信息：

- 业务类型和状态；
- 单号/员工/商品等主要对象；
- 金额或数量；
- 发起人和组织；
- 已等待时长/截止时间；
- 下一动作；
- 风险标签。

同意、退回等操作原则上在详情页完成，避免用户未看详情就误操作。仅低风险“确认收到”类动作可在卡片上快捷处理。

### 6.3 审批详情

页面分四段：

1. **决策摘要**：申请人、组织、金额/数量、用途、风险；
2. **业务明细**：商品/人员/费用明细；
3. **附件**：图片缩略图、文件名、上传者；
4. **审批轨迹**：节点、处理人、意见、时间。

底部按钮按状态显示：

```text
[退回] [转交] [同意]
```

驳回等不可恢复动作放入“更多”，二次确认后执行。

## 7. 列表与筛选

### 7.1 列表规范

- 使用业务卡片，不横向压缩 PC 表格；
- 卡片左上是主对象，右上是统一状态标签；
- 关键数字采用等宽数字并带单位；
- 日期展示相对时间 + 可查看完整时间；
- 下拉刷新、滚动加载、回到顶部；
- 返回后保持搜索条件、滚动位置和已打开卡片；
- 超过 500 条不允许一次性下载到客户端。

### 7.2 筛选规范

首屏：

```text
[搜索单号/姓名/商品] [筛选]
[全部] [待处理] [已完成] ...
```

筛选抽屉：

- 状态；
- 日期范围；
- 组织；
- 负责人/发起人；
- 业务特有字段。

底部固定：

```text
[重置] [查看结果 28]
```

筛选项使用服务端同一字典和候选范围；不能由移动端维护一份静态枚举。

## 8. 详情与操作

### 8.1 详情页结构

```text
状态头：单号 + 状态 + 当前组织
风险条：仅有风险时出现
业务摘要
明细列表
附件
审批/操作轨迹
底部固定操作区
```

### 8.2 动作规则

- 主按钮只能有一个；
- 次级可恢复动作最多两个；
- 危险操作放入“更多”；
- 按钮文字使用业务动词，如“确认收货”，不用泛化的“确定”；
- 点击后立即进入提交中，阻止重复点击；
- 服务器未确认前不改变最终状态；
- 超时时先查询请求结果，再决定是否允许重试；
- 成功反馈包含结果，如“已收货 8 件，差异 1 件”。

### 8.3 状态变化

若详情打开期间状态被他人改变：

```text
提交动作
→ 服务端返回版本冲突/任务已处理
→ 页面顶部显示“数据已更新”
→ 禁用旧动作
→ 自动加载最新状态
→ 保留用户尚未提交的备注，供复制
```

## 9. 长表单与移动录入

### 9.1 分步结构

以入职为例：

```text
1 基本身份
2 联系与紧急联系人
3 任职与组织
4 证件与附件
5 确认提交
```

每步顶部显示 `2/5` 和当前主题；底部提供“上一步”和“保存并继续”。

### 9.2 表单规则

- 默认值说明来源，不静默替用户决定；
- 必填星号与提交校验一致；
- 人员、组织、商品使用可搜索选择器；
- 日期不允许手工输入歧义格式；
- 金额使用十进制输入，显示币种；
- 数量显示单位和精度；
- 身份证、手机号等使用合适键盘和格式提示；
- 服务端错误直接定位到字段；
- 页面离开、应用切后台和登录过期均保护未提交输入。

### 9.3 草稿策略

| 草稿类型 | 用途 | 真相来源 |
|---|---|---|
| 本地临时草稿 | 尚未创建业务 ID 时防止输入丢失 | 仅设备恢复辅助 |
| 服务端业务草稿 | 已有业务 ID，可跨端继续 | 业务真相 |
| 上传队列 | 附件传输状态 | 文件服务确认后才成为业务附件 |

本地草稿必须包含用户、组织、表单类型和版本，换账号或换组织不得自动恢复。

## 10. 扫码、拍照和现场执行

### 10.1 扫码入口

优先实施顺序：

1. 扫码查商品/库存；
2. 采购收货与质检；
3. 配送出库；
4. 盘点；
5. 调拨发货/收货；
6. 员工/资产二维码查询。

### 10.2 连续扫码

```text
开始任务
→ 显示任务组织和范围
→ 扫码
→ 震动/声音反馈
→ 商品合法：累计数量或打开数量确认
→ 商品不属于任务：红色提示，不计入
→ 重复扫码：按业务规则累计并可撤销最近一次
→ 显示已扫/计划/差异
→ 提交前汇总复核
```

支持手工搜索作为相机不可用的替代方案。

### 10.3 拍照上传

- 拍摄后允许裁剪、旋转和重拍；
- 默认压缩展示图，必要时保留原图；
- 显示每个文件的上传进度；
- 失败文件可单独重试；
- 未完成上传时禁止把表单显示为已提交成功；
- 相机权限被拒绝后提供相册/文件选择和设置引导；
- 客户、证件、合同照片必须按敏感文件处理。

## 11. 空、错、关、无权限四种状态

必须分别设计：

| 状态 | 标题示例 | 用户动作 |
|---|---|---|
| 真正空数据 | “还没有采购单” | 有权限时显示“新建采购” |
| 查询无结果 | “没有符合条件的记录” | 清除筛选 |
| 接口失败 | “暂时无法加载采购数据” | 重试、查看上次更新时间 |
| 部分来源失败 | “审批数据暂不可用，其他结果已显示” | 仅重试失败来源 |
| 无权限 | “你没有查看此内容的权限” | 返回、联系管理员 |
| 组织不匹配 | “请切换到仓库后继续” | 打开组织切换 |
| 功能关闭 | “该功能本期暂未开放” | 查看说明/返回 |
| 数据已变化 | “该任务已被处理” | 刷新最新状态 |

绝不能用空列表掩盖无权限或接口错误。

## 12. 弱网与失败恢复

| 场景 | 设计 |
|---|---|
| 首屏弱网 | 显示上次成功摘要和时间，后台刷新 |
| 列表超时 | 保留已加载内容，显示局部重试 |
| 表单断网 | 保留本地草稿，不声称已提交 |
| 提交超时 | 使用幂等键查询结果，避免用户重复建单 |
| 附件失败 | 逐文件重试，不重传成功文件 |
| 并发修改 | 展示冲突，不自动覆盖 |
| 应用切后台 | 保存临时输入，回来后检查会话和数据版本 |
| 组织/权限变化 | 清理受影响缓存，提示重新进入 |
| 原生版本过旧 | 明确最低版本并提供升级路径 |

最终库存记账、审批决策和签署结果不允许离线完成后静默同步。

## 13. 原生适配

### 13.1 布局

- 顶部导航避开刘海和状态栏；
- 底部操作与五栏导航避开安全区；
- 键盘弹出时当前字段和主按钮可见；
- 横屏不是必需，但扫描页可按设备评估；
- Android 返回键遵循：关闭弹层 → 返回详情 → 返回保留状态的列表 → 退出确认。

### 13.2 能力

- 相机/相册/文件；
- 推送通知到受控业务深链；
- 安全存储会话信息；
- 网络状态感知；
- 应用版本和环境诊断；
- 生物识别仅用于重新解锁本地会话，不替代服务端认证。

### 13.3 发布前真机矩阵

| 维度 | 最低覆盖 |
|---|---|
| iOS | 当前支持的最低版本 + 最新主版本，至少一台刘海屏 |
| Android | 最低支持版本 + 主流系统版本，至少两种屏幕尺寸 |
| 屏幕 | 320×568、390×844 及常见 Android 尺寸 |
| 网络 | Wi-Fi、4G/5G、弱网、断网恢复 |
| 权限 | 相机允许/拒绝、通知允许/拒绝、文件权限 |
| 账号 | 员工、经理、HR、门店、仓库、有限管理员 |

## 14. 视觉与组件规范

### 14.1 基础尺寸

- 主要触控目标最小 44×44 CSS px；
- 卡片间距 12—16 px；
- 页面左右安全边距 16 px；
- 正文不小于 14 px，关键数字 20—28 px；
- 状态不能只靠颜色，必须同时有文字/图标；
- 主按钮和危险按钮颜色稳定，不按模块随意变化。

### 14.2 统一组件

优先建立以下移动业务组件：

- `MobilePageShell`：标题、返回、组织、安全区；
- `MobileStatusHeader`：单号、状态、风险；
- `MobileFilterDrawer`：统一筛选；
- `MobileBusinessCard`：列表卡片；
- `MobileActionBar`：底部状态动作；
- `MobileTimeline`：审批与操作轨迹；
- `MobileUploadQueue`：拍照/文件与重试；
- `MobileScanSession`：连续扫码；
- `MobileErrorState`：空、错、关、无权限；
- `MobilePersonPicker`、`MobileOrgPicker`、`MobileProductPicker`。

## 15. 可访问性

- 所有图标按钮提供可读标签；
- 表单错误与对应字段关联；
- 焦点顺序与视觉顺序一致；
- 弹层打开后焦点进入弹层，关闭后回到触发按钮；
- 支持系统文字放大，不截断状态和主按钮；
- 颜色对比度满足可读要求；
- 上传进度、成功和失败通过文字而非仅颜色表达；
- 扫码成功提供声音、震动和文字三种反馈，可在设置关闭声音/震动。

## 16. 分阶段实施建议

### 阶段 A：结构统一
