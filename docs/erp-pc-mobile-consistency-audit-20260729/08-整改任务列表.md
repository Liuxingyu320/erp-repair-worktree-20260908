# ERP PC/移动一致性整改任务列表

> 编制日期：2026-07-29
> 当前状态：仅完成系统审计和设计文档，本清单中的代码、配置、数据和发布任务均未在本阶段执行。
> 执行原则：先确认页面和流程，再按共享基础 → 单模块 → 跨端测试 → 真实业务测试推进；禁止一次性大范围改造。

## 1. 优先级和规模

| 标识 | 定义 |
|---|---|
| P0 | 业务正确性、权限、安全、数据一致性或上线门禁 |
| P1 | 核心流程完整性和高频效率 |
| P2 | 体验增强、低频治理或后续能力 |
| S | 单一小改动，可独立验证 |
| M | 一个清晰子系统/页面族，需要集成验证 |
| L | 跨服务或跨多个页面，必须拆成多个交付批次 |

状态统一为：

- `待确认`：需要产品/业务评审；
- `待实施`：范围已确认，尚未开发；
- `实施中`；
- `待验收`；
- `已完成`；
- `阻塞`：必须写明外部依赖。

本文件初始状态均为 `待确认`。

## 2. 阶段与门禁

```text
阶段 0：文档评审与基线冻结
  ↓ Gate A：业务、产品、技术、测试共同签字
阶段 1：统一模型、权限、接口和移动壳
  ↓ Gate B：契约/权限/状态机测试通过
阶段 2：人事模块整改
  ↓ Gate C：人事跨端闭环通过
阶段 3：采购、销售、库存模块整改
  ↓ Gate D：库存与报表夹具通过
阶段 4：OA、资产、合同、签署整改
  ↓ Gate E：外部集成与异常补偿通过
阶段 5：系统管理入口收缩与全局体验
  ↓ Gate F：六角色回归通过
阶段 6：原生包与真实业务流程测试
  ↓ Gate G：生产上线评审
```

任何 Gate 未通过，不进入下一模块的大规模整改；可并行处理不影响状态机的小型 UI 一致性任务。

## 10. 推荐小批次拆分

为避免一次性修改大量代码，每个批次遵守：

- 一个明确业务目标；
- 最多涉及一个核心状态机；
- 先改共享契约和测试，再改 PC/移动呈现；
- 数据库迁移可独立回滚；
- 批次结束即用角色账号和隔离数据验收；
- 未通过不叠加下一个模块状态机改动。

推荐首批顺序：

## 11. 每个任务的完成定义
