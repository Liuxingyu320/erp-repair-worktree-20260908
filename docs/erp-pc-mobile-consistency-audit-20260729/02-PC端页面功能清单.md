# PC 端页面功能清单

> 基线日期：2026-07-29
> 页面口径：当前源码路由、后台动态菜单、视图组件、API 调用和最新桌面运行记录的并集。
> 验证口径：已有桌面审计以超级管理员只读巡检为主；下表中的写操作代表源码具备的产品能力，不代表已经完成多角色真实写入验收。

## 1. PC 端定位与通用规则

PC 端承担管理型工作：

- 配置业务规则、组织、权限和流程；
- 复杂查询、跨组织对比、批量操作、导入导出；
- 主数据维护、台账、数据分析和审计；
- 异常处理、流程监控、历史追溯；
- 需要大表格、多字段或多窗口协作的操作。

所有页面应遵守四层权限：

1. **登录权限**：必须为有效会话；
2. **功能权限**：由服务端权限标识决定按钮和接口；
3. **数据权限**：由角色数据范围、本人/本部门/本组织等规则决定；
4. **组织上下文**：库存、采购、销售等业务还必须校验当前门店/仓库。

前端按钮隐藏只用于体验，不能作为安全边界。

## 2. 页面功能模板

本清单的每一行均包含用户要求的六项内容：

| 字段 | 表达方式 |
|---|---|
| 页面名称 | “页面”列 |
| 页面定位 | “定位/业务问题”列 |
| 页面功能 | “主要功能”列 |
| 页面操作流程 | “主流程”列 |
| 页面权限 | “权限与数据范围”列 |
| 当前状态 | “状态/验收关注”列 |

通用 CRUD 流程为：`进入页面 → 查询/筛选 → 新增或选择记录 → 校验 → 保存 → 刷新列表 → 记录审计日志`。
通用导入流程为：`下载模板 → 填写 → 上传 → 预校验 → 查看逐行结果 → 确认导入 → 下载错误清单`。
通用审批流程为：`保存草稿 → 提交 → 生成统一审批实例 → 审批 → 回写业务状态 → 生成后续任务/消息`。

## 11. 页面级统一验收清单

每个 PC 页面整改或验收时必须回答：

### 功能

- [ ] 页面列出的查询、新增、编辑、删除、提交、撤回、导入、导出等动作是否真实可用？
- [ ] 服务端权限与页面按钮是否一致？
- [ ] 本人、本部门、本组织、全部数据范围是否分别验证？
- [ ] 空数据、加载中、无权限、接口失败、部分来源失败是否有不同状态？
- [ ] 删除、清空、强退、终止等高风险操作是否二次确认并审计？

### 流程

- [ ] 正常流程能否闭环到最终业务状态？
- [ ] 退回、驳回、撤回、取消、部分完成和重开是否可恢复？
- [ ] 是否存在处理到一半必须换到另一端才能完成的断点？
- [ ] 刷新、重复点击、并发修改是否保持幂等和版本一致？
- [ ] 待办、消息、业务详情和审批轨迹是否同步消失/更新？

### 体验

- [ ] 默认筛选、列宽、固定列和批量操作是否适合高频任务？
- [ ] 查询条件是否可以重置并准确反映当前组织？
- [ ] 表格数量/金额/时间/状态是否统一格式？
- [ ] 错误提示是否说明原因和可恢复动作？
- [ ] 导入导出是否提供明确进度、结果和错误明细？

## 12. 当前 PC 验证缺口

1. 最新记录覆盖了核心桌面页面的访问和只读检查，但没有在隔离数据中完成全部写流程。
2. 超级管理员不能代表员工、部门经理、HR、门店、仓库和有限管理员的真实体验。
3. 功能开关关闭或当前环境无数据的页面，尚不能据此判定业务不可用。
4. 报表、库存、薪资、权限等高风险领域必须使用固定测试数据验证结果，而不只检查页面无报错。
5. 所有页面最终验收应记录：账号角色、组织上下文、测试数据、前置状态、操作步骤、接口结果、业务结果和审计记录。
