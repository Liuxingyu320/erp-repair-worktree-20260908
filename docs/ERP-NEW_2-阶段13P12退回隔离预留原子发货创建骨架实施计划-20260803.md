# ERP-NEW_2 阶段 13P12：退回隔离预留原子发货创建骨架实施计划

> 日期：2026-08-03
>
> 分支：`codex/erp-new-2-rebuild`
>
> 基线：`0fd0d5e3 feat: add adjudication return shipment planning`
>
> 范围：建立默认关闭、生产零调用点的退回专属 V2 发货原子创建边界；不接 Controller、HTTP 或裁决执行链

## 1. 目标与结论

P12 将 P11 的只读固定来源计划推进为可回滚的写事务骨架。退回发货不能调用普通发货创建 Service：普通链从 `available_quantity`、普通调拨预留和 FEFO/FIFO 候选消费，而退回必须从 P9/P10 的唯一隔离预留、`locked_quantity`、固定残损批次库位和 `quarantine_reserved` 序列号消费。

可以复用的是已有 V2 发货批次、发货明细、不可变分配、序列号审计和明细库存流水结构，以及 P10 已验证的隔离预留消费事务；不能复用普通候选选择、普通库存扣减或普通预留消费。

## 2. 命令与关闭边界

- 新增退回专属创建请求：P11 `planVersion`、服务端固定来源标识和本批正发货数量；
- 支持正数且不超过当前隔离预留剩余量的分批发货；序列号由 P10 按冻结绑定顺序确定，不接受浏览器任意改选；
- 新增独立写开关，默认 `false`，且要求 V2 收货边界显式就绪；
- 创建 Service 使用 `Propagation.MANDATORY`，未来必须加入 `InvTransferCommandExecutor` 拥有的根幂等事务；
- 本阶段不接入 `InvTransferCommandService`、Controller、权限路由或前端适配器，因此生产零调用点。

## 3. 固定锁序与首个 DML 前校验

固定锁序：

1. 退回子调拨主单；
2. 当前已审批封存修订；
3. 唯一调拨明细；
4. 来源仓库存模式；
5. P10 隔离预留及其当前轮次归属事实；
6. 汇总库存；
7. 精确隔离余额；
8. ACTIVE 序列号绑定及物理序列号。

所有锁定完成后、首个 DML 前必须：

- 重算 P11 `planVersion` 并与请求精确匹配；
- 证明子调拨来源为当前裁决退回动作，状态允许发货且审批轮次一致；
- 证明当前修订为该轮次的 `approved` 封存版本；
- 证明唯一明细的物料、数量、累计发货与 P10 预留事实一致；
- 证明来源仓仍可权威读写明细库存且存在非空对账批次；
- 通过 P10 守恒规则验证本批数量不超量、成本不漂移、序列号仍在固定隔离位置。

任一事实变化均在写入前失败关闭，不降级到普通库存、共享库存或旧发货入口。

## 4. 原子写入顺序

验证通过后在同一外层事务内：

1. 创建 `V2_DETAIL` 发货批次，保存根请求、P11 计划版本、封存修订和仓库对账批次；
2. 创建唯一发货明细；
3. 调用 P10 已锁定消费边界，扣减汇总/精确冻结库存，迁移序列号并追加消费事件；
4. 写汇总库存日志；
5. 写固定隔离来源分配和发货序列号不可变审计；
6. 写明细库存不可变流水；
7. 以旧数量、旧状态、旧版本和审批轮次为条件推进累计发货量与子调拨状态；
8. 写子调拨状态日志并返回 JavaScript 安全结果。

任一生成键缺失、影响行数异常、唯一冲突或回读/条件冲突均抛错，由根事务整体回滚；不执行补偿 SQL。

## 5. 预计代码变更

- `domain/dto/InvTransferReceiptDiscrepancyReturnShipmentCreateRequest`：未接线创建请求；
- `domain/vo/InvTransferReceiptDiscrepancyReturnShipmentCreationVo`：JavaScript 安全结果；
- `domain/transfer/InvTransferReceiptDiscrepancyReturnShipmentCreationPolicy`：纯命令、审批、来源和数量策略；
- `service/impl/InvTransferReceiptDiscrepancyReturnShipmentWriteGate`：独立默认关闭开关；
- `service/impl/InvTransferReceiptDiscrepancyReturnShipmentCreationService`：原子创建编排；
- `mapper/InvTransferReceiptDiscrepancyReturnShipmentCreationMapper` 及 XML：只保存退回专属条件推进语句；
- P10 生命周期 Service：增加同事务“先锁定并校验计划、后绑定真实发货标识消费”的内部协作缝，不改变现有公开消费行为；
- 复用现有 V2 发货 Mapper 的不可变分配、序列号和明细流水插入语句，不修改普通发货规划或普通库存 DML。

本阶段不新增 DDL。现有 V2 发货结构和 P10 消费事件已经保存所需归属证据。
