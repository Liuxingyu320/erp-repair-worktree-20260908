# 项目存储与图片上传规则

确认日期：2026-09-14。

用户原话：**“之后的存储都放到数据盘，包括图片，但是上传图片要压缩。”**

本文是后续开发、部署和运维需要遵守的项目规则。规则已确认；记录到文档不代表相关改造已经实现或上线。

## 1. 后续项目存储统一放数据盘

- 后续新增或调整的项目存储统一使用实际挂载于 `/data` 的数据盘，包括图片、附件、签署文件、考勤照片、报销材料、网盘文件、生成文件、导出文件、数据库持久化数据、项目日志、落盘缓存、临时处理文件、发布包、解包目录和备份。
- 操作系统本身仍使用系统盘；项目持续增长的文件不得再积累在系统盘或发布目录的相对路径中。
- `/opt/erp-new` 等既有程序入口可以保留为兼容软链接，实际存储位置必须在数据盘。更新程序、切换版本或回滚不得隐藏、覆盖或删除业务文件。
- 服务启动及部署时检查数据盘挂载、路径和读写权限。数据盘未挂载或目录不可用时，应明确失败，不得自动回退到系统盘写入。
- 将现有数据库、正在使用的目录等迁到数据盘时，需保留备份和回退办法，并完成程序路径适配及验证；本次文档记录没有执行这些迁移。

## 2. 保留现有上传目录约定

生产上传根保持为 `/data/erp-new-data/uploadPath`，不得因后续改造另建一套分叉上传目录。

| 用途 | 固定目录 |
| --- | --- |
| 通用上传根 | `/data/erp-new-data/uploadPath` |
| 公共图片与附件 | `/data/erp-new-data/uploadPath/public` |
| 私有签署文件 | `/data/erp-new-data/uploadPath/private/sign-package` |
| 考勤照片 | `/data/erp-new-data/uploadPath/private/attendance` |
| 报销附件 | `/data/erp-new-data/uploadPath/private/reimbursement` |
| 网盘文件 | `/data/erp-new-data/uploadPath/private/drive` |

前后端读取地址、数据库中的文件引用、服务环境变量和部署挂载必须保持一致。私有文件继续经原有鉴权接口访问。

## 3. 上传图片必须经过压缩处理

- 图片上传流程统一接入压缩，包括电脑、手机、拍照及各业务上传入口；最终存入数据盘的是经过压缩处理并校验的图片。
- 压缩以业务可用为前提：照片可辨识、文字和票据可读，印章及签名保留必要细节，透明图片保留必要透明度，显示方向正确。
- 统一处理尺寸、编码质量及文件体积，避免压缩后反而增大。后端需要校验最终图片，不能仅依赖某个前端页面的压缩逻辑。
- 压缩应在最终文件摘要、签署或证据绑定之前完成；不得重新压缩、覆盖已经归档的签署文件或历史证据。
- 最大宽高、编码格式、质量系数、单张目标体积和超限处理方式尚未确定，后续实施时明确，并用代表性图片验证；不得把自行假设的数值写成用户已确认要求。

## 4. 补充确认：云盘特殊图片格式

2026-09-14 用户确认：**WebP、HEIC、HEIF 保留原格式，另补对应压缩支持**。不得为了压缩统一改成 JPG/PNG，必须保留透明度、方向及多帧内容。具体实现与验证结果另行记录。
