## 1. 本检查点交付

- 新增 `/inventory/stock` 库存现状路由、桌面侧栏、移动导航和命令检索入口；入口同时要求功能开关 `inventory.stock.view` 与旧后端已存在的读取权限 `inv:stock:list`。
- 新增库存领域模型、Zod 响应解析、Long 安全校验、精确十进制数量、库存状态推导、Gateway 和只读 HTTP 适配器。
- 新增 ERP-NEW_2 隔离 Mock 库存数据，覆盖当前组织和服务端授权可见两种范围，以及商品、运营耗材、礼赠品、正常、偏低、无可用库存、批次和库位。
- 新增品项/预警/无可用库存/组织数指标、明确提交的关键词/类型/状态/范围筛选、分页、错误、空状态、桌面表格与移动卡片。
- 公司级组织不会发起库存请求，而是提示切换到门店或仓库；前端没有任意组织 ID 筛选入口，也不把不同单位相加为总库存数量。

## 2. 契约与隐私边界

- 本切片只覆盖 `GET /inventory/stock/list` 与 `GET /inventory/stock/summary`；分类树、指定门店筛选、详情、调整、变动日志、导出和成本视图均未迁移。
- 旧库存端点读取 `Dept-NumId`，新 HTTP Client 默认仍使用 `X-ERP-Organization-Id`；仅显式配置的旧库存 Reader 使用 `Dept-NumId`，且不会双发两个组织头。
- 组织在请求确认后变化时会在 `fetch` 前失败关闭；GET 请求不发送 CSRF，路径保持同源。
- 当前后端库存响应可能包含 `costPrice`、`totalCost`，但普通库存角色未必具备 `inv:cost:view`。新领域契约会直接丢弃这些字段，页面和 Mock 都不保留成本。
- 客户端丢弃不能代替服务端脱敏。服务端按权限移除成本字段并补齐负向契约测试之前，真实库存 Reader 不得注入生产运行时。
- 默认启动仍只注入隔离 Mock；本检查点没有发出真实 HTTP 请求，也没有接线任何后端服务。
