## 1. 目标与范围

把 `erp-ui-next` 当前只有列表、筛选和分页的库存盘点只读切片，扩展为可在门店或仓库组织内完成下列业务闭环的响应式生产工作台：

1. 创建全仓、分类、指定商品或抽盘任务；
2. 查询并指派当前库存组织内具有盘点提交权限的盘点人；
3. 查看盘点详情，录入实盘与必要的复盘数量；
4. 保存草稿、提交盘点，并准确呈现“零差异直接完成 / 有差异进入审批 / 快照变化失效”结果；
5. 处理旧审批引擎的待我审批、通过、驳回和不可变审批轨迹；
6. 对统一审批引擎提供正确的审批中心入口、撤回和多轮次关联，不在库存页面伪造统一审批动作；
7. 对驳回、退回、失效、待审批和草稿提供符合状态机的重新提交、重新盘点、取消和删除动作；
8. 导出当前组织和当前筛选范围内的盘点数据；
9. 将 Mock 与真实 HTTP 网关收敛到同一份领域契约、状态矩阵、幂等与组织隔离规则。

本切片不启动 Docker、MySQL、Redis、Nacos 或任何服务，不连接任何数据库，不删除旧前端，不修改或读取受保护原项目目录。

## 3. 审计发现与必须修正的契约差异

1. **缓存边界缺失**：盘点控制器尚未像库存、商品、采购等控制器一样对业务响应设置 `Cache-Control: no-store, max-age=0` 和 `Pragma: no-cache`。前端真实网关必须验证 no-store，后端所有 JSON 响应和导出均需补齐该头。
2. **成本字段边界不完整**：详情内的 `costPrice` 是库存调整内部快照，不是盘点录入所需字段。控制器必须按 `inv:cost:view` 权限隐藏明细成本；审批轨迹中的内部 JSON 快照也不得向无成本权限用户泄漏成本。
3. **统一审批驳回后不可编辑与正式设计冲突**：正式设计和统一审批多轮次方案要求退回/驳回后可修改并生成新轮次，但 `requireMutableApprovalResult` 当前禁止修改统一审批 `rejected` 盘点单。应删除这条引擎特例，保留状态、当前盘点人/管理员、组织和快照校验，让下一次提交通过 `previousInstanceId` 串接新审批轮次。
4. **统一审批路由快照仍指向旧路径**：`desktopPath=/inventory/stockCheck`、`mobilePath=/mobile/inventory/stock-check` 与新前端路由不一致。统一改为响应式新前端详情路径 `/inventory/stock-check/{checkId}`，不保留运行时旧前端依赖。
5. **盲盘列表字段可为空**：后端会在可编辑盲盘状态隐藏差异计数，新前端现有列表 schema 却强制计数非空。契约需把“未披露”与真实零值分开，禁止把隐藏值伪造成 0。
6. **审批引擎边界不同**：`approval/todo`、库存页直接通过/驳回和 `approval-track` 只适用于旧引擎；统一审批必须使用审批中心实例和任务。前端根据 `approvalEngine` 与 `approvalInstanceId` 明确分流。

## 4. 固定业务状态机

| 当前状态 | 可执行动作 | 结果/限制 |
| --- | --- | --- |
| `draft` | 指派、录入、保存、提交、取消、无审批历史时删除 | 提交前所有实盘及必需复盘数量必须完整 |
| `returned` | 指派、录入、保存、重新提交、取消 | 新提交创建新审批轮次，历史不可变 |
| `rejected` | 指派、录入、保存、重新提交、取消 | 旧/统一引擎均按正式设计生成新审批轮次 |
| `pending_approval` | 查看；旧引擎有效候选人通过/驳回；统一引擎申请人撤回；允许取消的旧引擎任务可取消 | 审批前再次校验库存快照；重复动作幂等 |
| `invalidated` | 调整指派、重新盘点、取消 | 重盘重新抓取账面快照并清空实盘、复盘和差异 |
| `completed` | 查看、导出、查看审批轨迹 | 终态，不可再写 |
| `cancelled` | 查看、导出、查看审批轨迹 | 终态，不可再写 |
| `checking` | 兼容旧数据只读展示 | 不新增该状态路径 |

提交时：库存快照变化进入 `invalidated`；快照有效且无差异直接进入 `completed`；存在差异进入 `pending_approval`。审批通过时必须在同一事务内再次核对快照并写库存流水；审批驳回保留原因、自批标记和不可变历史。

## 5. 前端领域与安全契约

### 5.1 模型

扩展 `stock-check.model.ts`：

- 盘点详情、明细、盘点人候选、旧审批轮次/任务；
- `approvalEngine`、`approvalInstanceId`、`approvalRound`、提交/审批/驳回/失效事实；
- 可空账面量和差异量，用于准确表示盲盘未披露；
- 创建、指派、保存、提交、审批、撤回、重盘、取消、删除和导出命令；
- 由权限、用户身份、引擎和状态共同推导的动作能力，不仅依赖页面按钮隐藏。

### 5.2 输入与响应验证

在 `stock-check.contract.ts` 和新增命令契约中：

- Long 标识保留为字符串并限制在后端 Long 范围；
- 十进制禁止科学计数法、负数、非有限值和超精度；
- 日期、截止时间、备注、审批意见、筛选和请求 ID 有长度/格式上限；
- 创建命令只允许服务端接受的字段白名单；指定商品范围只发送 `productId`；
- 保存/提交只发送 `detailId`、`actualQty`、`recountQty`，禁止回传账面量、差异、成本、商品或组织快照；
- 每个详情、列表、候选、审批和命令响应验证请求 ID、业务 ID、当前组织 ID、状态及审批实例身份；
- 未知服务端字段可读取但不会进入领域模型，成本与内部事件键不进入前端对象。

### 5.3 HTTP 边界

- 所有业务请求携带当前 `Dept-NumId`；写请求要求 CSRF；
- 每个写动作携带 `X-Request-Id` 与 `Idempotency-Key`；
- 列表、详情、候选、审批轨迹、动作结果和导出都验证 `no-store`；
- 导出限定 Excel MIME、非空文件和 25 MiB 上限；
- 组织上下文切换期间请求失败关闭，不接受旧组织响应；
- 不连接旧前端，也不在运行时引用 `erp-ui/src`。

## 6. 页面与交互

### 6.1 路由

- `/inventory/stock-check`：列表工作台；
- `/inventory/stock-check/new`：创建盘点；
- `/inventory/stock-check/:checkId`：状态驱动的详情、录入与审批页。

列表路由保持 `inv:stockCheck:list`；创建路由要求 `add`；详情路由以列表能力进入，页面再按 `query/submit/approve/edit/remove/export` 精确开放动作，后端继续执行最终授权。

### 6.2 工作台

- 保留风险摘要、筛选、分页和移动卡片；
- 增加“全部盘点 / 待我审批”视图、创建入口、详情入口和精确行级动作；
- 盲盘未披露指标显示“待揭示”，绝不显示伪造零值；
- 导出使用当前成功应用的筛选条件；
- 请求失败保留最近一次成功数据，避免空白覆盖。

### 6.3 创建页

- 当前库存组织固定且不可由请求体覆盖；
- 支持全仓、分类、指定商品和抽盘四种范围；
- 支持盲盘、复盘阈值、盘点人、截止时间、日期和备注；
- 分类与商品选择复用新前端已存在的分类/商品只读网关，不复制旧前端源码；
- 创建成功进入详情页。

### 6.4 详情与录入页

- 顶部展示状态、组织、范围、盘点人、截止时间和审批轮次；
- 明细在桌面为高密度表格，在窄屏为逐项录入卡片；
- 盲盘编辑态不显示账面量和差异；达到复盘阈值时显式要求复盘数量；
- 保存、提交、重新提交、指派、重盘、撤回、取消和删除均显示动作后权威服务端状态；
- 旧引擎审批使用二次确认和必填驳回原因；统一审批展示“前往审批中心”并链接准确实例；
- 审批轨迹按轮次展示，自批、退回、失效、撤回和终态可区分。

## 9. 风险与回滚

- **统一审批与旧审批并存**：前端按引擎显式分流，不能把旧引擎动作发给统一审批实例；后端保持引擎校验。
- **盲盘泄密**：盲盘编辑态任何账面、差异和成本字段都按“缺失”处理；测试对序列化结果做负断言。
- **重复提交/审批**：前端双幂等头 + 后端 `@IdempotentSubmit` + 状态机/行锁共同保护。
- **组织切换竞态**：AbortSignal、`expectedOrganizationId` 和响应组织校验共同失败关闭。
- **库存快照竞争**：不在前端计算最终库存结果，提交和审批均以后端锁定快照为权威。
- 本切片全部改动局限于专属分支，可通过回退本地检查点提交恢复；不触碰原项目，也不执行 push、merge 或旧前端删除。
