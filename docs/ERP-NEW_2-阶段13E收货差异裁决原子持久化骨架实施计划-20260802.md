# ERP-NEW_2 阶段 13E：收货差异裁决原子持久化骨架实施计划

> 日期：2026-08-02
> 分支：`codex/erp-new-2-rebuild`
> 基线：`620f566b feat: add independent discrepancy adjudication plan`
> 范围：唯一事务所有者、固定锁序、幂等重放、计划头/动作写入和事项条件推进；不开放接口、不启用 Gate、不执行物理处置

## 1. 目标与边界

阶段 13E 把 13D 的 `PreparedAdjudication` 接到一个未来可调用、当前不可达的本地事务。事务只证明“裁决计划已原子记录”，不会执行补发、退回、报损、责任调整、运输损耗核销，也不会把事项推进为 `resolved`。

允许的唯一业务变化为：

1. 写入一条 `inv_transfer_receipt_discrepancy_adjudication` 计划头；
2. 写入该计划的一至二十条 `inv_transfer_receipt_discrepancy_adjudication_action` 动作；
3. 将同一事项从 `awaiting_confirmation`、版本 `N` 条件推进为 `adjudication_planned`、版本 `N+1`。

任何一步行数不符合预期都抛出异常，由 Spring 本地事务整体回滚。

## 2. 权限与职责分离

- 服务端从登录快照读取用户标识、用户名和权限集合，不接受客户端提交操作者或权限。
- 必须显式拥有 `inv:transfer:discrepancy:adjudicate`；本阶段不创建菜单、不授予角色、不开放 Controller。
- 继续由 13D 纯策略校验：裁决人不能是当前调出方或调入方确认操作者，双方确认事件必须匹配当前事项版本和事实指纹。
- 不接受组织选择作为裁决权限替代；独立裁决权限与双方业务组织身份是不同边界。

## 3. 固定锁序与权威读取

所有新裁决事务使用固定顺序：

1. 按 `discrepancy_case_id` 锁定并读取事项、调拨关系、收货差异事实和双方最新确认事件；
2. 按 `request_id` 锁定既有裁决头；
3. 若存在完全一致的历史请求，读取不可变动作并返回重放结果；
4. 若不存在，调用 13D 纯策略形成服务端计划；
5. 条件插入计划头；
6. 批量插入全部动作；
7. 条件推进事项状态和版本。

13C 的双方确认写事务同样先锁事项。因此，一旦裁决取得事项锁，新的确认事件不能在本事务核验与提交之间穿插。

## 4. 幂等语义

- `request_id` 是全局幂等键；重放只允许同一事项、同一裁决前版本、同一事实指纹、同一说明、同一证据、同一裁决人和同一组语义动作。
- 客户端动作输入按 `sequence` 排序后比较，输入列表顺序不影响重放。
- 重放必须验证存储头、动作数量、连续序号、动作类型、数量、服务端金额、责任方、说明、待执行状态和决定指纹；任何不一致都按幂等键冲突失败关闭。
- 重放不会再次插入或更新事项，响应保留原计划创建时间并标记 `replayed=true`。

## 5. 数据库条件防线

计划头采用 `INSERT ... SELECT`，数据库层再次核验：

- 事项仍处于 `awaiting_confirmation`，版本和事实指纹完全一致；
- 两个指定确认事件属于同一事项，角色/组织正确，均为当前版本的 `confirmed`；
- 两个事件仍分别是该事项调出方与调入方的最新事件；
- 裁决人不是任一确认操作者；
- 同一请求和同一事项前置版本尚无计划。

事项更新只能命中同一事项、前置版本、事实指纹和 `awaiting_confirmation`。更新值固定来自服务端计划：`status='adjudication_planned'`、`case_version=N+1`。

## 6. 运行时停止线

- 不新增 Controller、路由、OpenAPI、菜单、权限种子或功能 Gate。
- 不把阶段 13D SQL 复制到 Docker 初始化目录，也不执行任何迁移。
- 不连接数据库、MySQL、Redis、Nacos，不启动服务或 Docker，不安装依赖。
- 不修改库存余额、批次、库位、序列号、物流单、财务凭证或旧差异表。
- 物理动作执行、失败补偿和最终 `resolved` 状态留给独立后续检查点。

新增测试覆盖 Mapper 绑定与 DML 白名单、固定锁序、权限、职责分离、成功原子计划、完全一致重放、幂等冲突、生成键、动作行数和条件状态推进失败。完成后运行库存模块、后端 28 模块及 `erp-ui-next` 完整验证，并进行 Controller/Gate/运行配置/Docker/连接字符串隔离审计。
