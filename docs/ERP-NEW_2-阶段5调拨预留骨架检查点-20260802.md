## 2. 已建立的不变量

库存聚合行始终满足：

```text
available_quantity = current_quantity - locked_quantity
```

调拨预留归属行始终满足：

```text
remaining_quantity = reserved_quantity - consumed_quantity - released_quantity
remaining_quantity >= 0
```

核心原子更新：

1. 提交冻结：`locked += quantity`，`available -= quantity`，`current` 不变。
2. 发货消耗：`current -= quantity`，`locked -= quantity`，`available` 不变。
3. 驳回/撤回/取消释放：`locked -= quantity`，`available += quantity`，`current` 不变。
4. 每次更新均校验库存版本、台账版本、非负数量和足够的可用量/锁定量。
5. 同单全部物料先按稳定顺序锁定并完成校验，再执行首个库存更新；任一物料不足时不产生部分冻结。
6. 预留按审批轮次分代保存；旧轮释放记录不会被新轮覆盖，驳回后可重新提交并形成新轮台账。

## 3. 已接入的业务路径

- 提交调拨：保存明细后、创建审批实例前，在同一事务冻结全单库存。
- 旧审批驳回：先释放当前审批轮次未发库存，再进入草稿、驳回记录或关闭状态。
- 原生审批退回、撤回、拒绝、终止：回调事务中先释放，再更新业务状态。
- 旧审批中的未发取消：先释放当前轮库存，再取消归档。
- 分批发货：只能消耗本调拨明细、本审批轮次拥有的冻结数量；不再直接扣减共享可用量。
- 差异补发：先重新冻结补发数量，再回退累计发货数量，保证后续发货有明确预留来源。
- 销售发货自动生成的已出库调拨继续绕过预留，因为其来源库存已由销售事实扣减。
