# 手机端 QA 数据治理操作清单

## 安全边界

本轮只交付候选数据的只读审计和测试环境门禁，不包含生产清理命令，也不授权直接修改业务数据。`sql/erp_mobile_qa_data_audit_20260710.sql` 必须使用只有 `SELECT` 权限的账号运行。

自动化真实写测试必须同时满足：独立 QA 数据库、独立测试组织、每次运行唯一 `ERP_QA_RUN_ID`。运行任何写测试前先执行：

```bash
ERP_QA_DATABASE=erp_qa \
ERP_QA_ALLOWED_ORG_ID=900001 \
ERP_QA_RUN_ID=mobile-20260710-001 \
scripts/qa/require-isolated-qa-env.sh
```

门禁未通过时不得降级绕过，也不得把生产数据库名称改成别名规避检查。

## 只读审计

1. 由数据库管理员使用只读账号执行候选审计 SQL。
2. 将结果导出为带日期的 CSV，记录数据库实例、执行时间和执行人，但不记录连接凭据。
3. 按 `source_table + source_id` 核对账号、客户、销售、采购、退货、盘点和调拨候选。
4. 补查明细、库存流水、审批、文件及组织授权等关联关系。
5. 无法确认归属的记录只做标记，不进入清理范围。

## 清理评审

候选记录只有同时具备以下材料才可进入单独的清理变更：

- 清理前完整备份及可验证的恢复位置。
- 候选清单、关联关系、业务负责人和数据负责人签字。
- 明确的人工审批单号、执行窗口和影响组织。
- 单独评审的事务化脚本；脚本必须先在同版本 QA 数据副本演练。
- 每个表的预期影响行数、事务失败后的回滚步骤和执行日志留存方式。

生产清理不与应用发布同批自动执行。任何实际清理都必须由授权人员在维护窗口内手工确认，影响行数与审批不一致时立即停止并回滚。

## 清理后复核

1. 重新运行同一份只读审计，确认已审批候选不再出现。
2. 复核关联单据数量、库存汇总、审批链、账号授权和审计日志。
3. 抽查手机端销售、采购、库存和退货列表，确认正式数据可见且无跨组织变化。
4. 保存清理前后 CSV、事务执行结果、回滚验证和人工复核记录。
5. 若仍有候选，形成例外清单并注明保留原因，不追加未经审批的处理。
