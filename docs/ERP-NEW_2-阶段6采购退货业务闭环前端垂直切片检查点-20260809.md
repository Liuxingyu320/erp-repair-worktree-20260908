## 2. 路由、能力与权限

| 路由或动作 | Feature / 权限 | 关键约束 |
| --- | --- | --- |
| `/inventory/purchase-returns` | `inventory.purchase-return.view` + `inv:purchaseReturn:list` | 当前精确仓库列表与筛选 |
| `/inventory/purchase-returns/new` | `inventory.purchase-return.create` + `inv:purchaseReturn:add` | 来源采购单由服务端筛选 |
| `/inventory/purchase-returns/:returnId/edit` | `inventory.purchase-return.create` + `inv:purchaseReturn:query` + `inv:purchaseReturn:add` | 仅草稿且来源单不可变 |
| `/inventory/purchase-returns/:returnId` | `inventory.purchase-return.view` + `inv:purchaseReturn:query` | 只读权威详情与证据 |
| 保存并提交 | `inv:purchaseReturn:add` + `inv:purchaseReturn:submit` | 同时满足两项权限 |
| 提交已有草稿 | `inv:purchaseReturn:submit` | 只接受退货单 ID，不夹带内容修改 |
| 确认退货 | `inv:purchaseReturn:confirm` | 二次确认；会扣减当前仓库库存 |
| 取消 | `inv:purchaseReturn:remove` | 仅草稿或已提交；二次确认 |
| 导出 | `inv:purchaseReturn:export` | 当前筛选、有界 Excel、显式确认 |
| 上传附件 | `file:upload` | 最多 5 个、单个不超过 10 MiB、格式白名单 |

编辑继续使用服务端现有的 `inv:purchaseReturn:add` 权限，这是本切片的兼容性选择；如后续引入独立 `edit` 权限，必须同时调整菜单、后端和前端的权限契约，不在此处虚构新权限。

## 3. 后端契约与数据完整性

- `GET /purchaseReturn/list`、`GET /purchaseReturn/my`、详情、来源单、保存、提交、确认、取消和导出共 11 个端点统一返回 `Cache-Control: no-store, max-age=0` 与 `Pragma: no-cache`；
- 新增 `GET /purchaseReturn/source-orders` 和 `GET /purchaseReturn/source-orders/{orderId}`，只接受当前仓库且非草稿/非取消、仍有正可退数量的采购单；
- 可退数量只扣除 `submitted` 与 `returned` 的历史退货明细；草稿不提前占用，提交时在服务端重新校验；
- 列表和“我的退货”均使用当前精确仓库；“我的”按 `applicant_id` 过滤，不扩展到子组织；
- 供应商、采购单号、商品/物料、单价、金额、申请人及仓库字段由服务端从来源单重建，浏览器输入不能成为权威快照；
- 主题、日期、原因、责任归属、正数量明细、附件数量和安全 URL 统一验证；更新草稿时禁止更换来源采购单；
- 保存、提交、确认、取消、库存日志和明细写入均检查受影响行数；确认与取消在行锁后复核仓库及状态；
- 内容更新 SQL 与状态更新 SQL 已分离，状态迁移不会清空原因、责任、附件或备注；
- `/file/upload` 与 `/file/delete` 同步补齐禁缓存响应。附件从表单移除只解除单据引用，不自动物理删除共享文件。

## 4. 前端契约与交互

- Java `Long` 全程保持正十进制字符串；数量和金额使用十进制字符串与 `decimal.js` 计算；
- 真实 Gateway 强制同源、Cookie、CSRF、`Dept-NumId`、组织漂移检查、`X-Request-Id`、幂等标识和 `no-store`；
- JSON 响应若缺少禁缓存头、返回其他仓库数据或不满足白名单契约，立即失败关闭；
- 导出只接收 Excel 或通用二进制 MIME，最大 25 MiB，并使用前端固定安全文件名；
- 编辑器支持来源单远程筛选、逐行数量、全部填入、清空、附件、备注及实时权威金额汇总；
- 工作台和详情页在动作执行前再次核对当前会话权限、组织和实时状态；确认退货、取消与导出均有显式确认检查点；
- 未修改表单的失败重试复用请求 ID，字段变化后生成新 ID；写命令不自动重试。

## 5. 状态机

| 当前状态 | 允许动作 | 结果 |
| --- | --- | --- |
| `draft` | 更新草稿 | 保持 `draft`，不占用来源可退数量 |
| `draft` | 提交 | 进入 `submitted`，占用来源可退数量 |
| `submitted` | 确认退货 | 进入 `returned`，写入实际退货数量并扣减库存 |
| `draft` | 取消 | 进入 `cancelled` |
| `submitted` | 取消 | 进入 `cancelled`，释放来源可退数量 |

任何其他状态迁移均失败关闭；重复请求只允许通过同一幂等请求标识重放已有结果。

## 6. 界面与动效决策

- 设计参考 21st.dev、React Bits、UI Prompt Library、Magic UI、Motion Primitives、Uiverse 与 MotionSites 的信息层级和局部反馈方法，仅作原则学习，不复制外部代码、品牌或资产；
- 高频筛选、分页、输入和键盘操作即时响应，不使用页面入场编排、循环光效、视差或布局动画；
- 只对按钮、可交互卡片和状态反馈使用短时、可中断的 transform/color/shadow 过渡；
- `prefers-reduced-motion: reduce` 下关闭非必要过渡；危险动作的含义始终由文本和焦点状态表达，而非依赖动效。
