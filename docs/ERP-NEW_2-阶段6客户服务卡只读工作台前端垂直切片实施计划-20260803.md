# ERP-NEW_2 阶段 6：客户服务卡只读工作台前端垂直切片实施计划

> 日期：2026-08-03
> 基线：`c225bb2b feat: add inventory report workbench skeleton`
> 状态：只读客户服务卡列表前端切片已实现；不代表客户与销售领域迁移完成

## 1. 目标与范围

在 `erp-ui-next/` 内新增 `/customers/service-cards` 客户服务卡工作台，覆盖当前门店的服务卡筛选、服务端分页、客户偏好、注意事项、人均预算、最近到店和响应式只读展示。

本切片只实现：

- `GET /inventory/customer/service-card/list`；
- 权限 `inv:customerCard:list`；
- 当前门店的严格数据范围；
- 姓名/手机/编码/茶饮偏好关键字、使用状态和单个偏好标签筛选；
- 服务端总记录数，以及当前页使用中、已归档、含注意事项数量；
- ERP-NEW_2 隔离 Mock 默认运行时和未注入的真实只读 HTTP Reader；
- 桌面表格、移动卡片、加载、错误、空状态和最近成功筛选语义。

以下能力明确留待后续独立切片：服务卡详情、受控照片、审计与运营汇总、新建、编辑、追加服务、归档、客户候选选择、销售单联动、真实运行时注入和旧客户接口下线。

## 2. 审计结论与硬边界

### 2.1 当前入口不是旧客户财务档案

- 当前页面源码为 `erp-ui/src/views/inventory/customer/index.vue`，但已经重写为“客户服务卡”；
- `sql/erp_inventory_customer_service_card_20260713.sql` 保留原菜单 ID，同时把名称和页面权限切换为 `inv:customerCard:list`；
- 旧 `inv:customer:list/query/add/edit/remove/export` 仅保留兼容端点，不再作为新页面目标；
- 新切片不得重新暴露信用额度、已用额度、账期、电子邮箱、地址或旧导出能力。

### 2.2 接口与权限拆分

- 列表：`GET /inventory/customer/service-card/list`，权限 `inv:customerCard:list`；
- 详情与照片：`inv:customerCard:query`，不属于列表权限；
- 审计与运营汇总：`inv:customerCard:audit`，不属于列表权限；
- 新建、编辑、追加服务和归档分别使用独立写权限，并受 `feature.inventory.customer-service-card.enabled` 控制；
- 本切片不得展示详情、照片、审计或写动作伪入口，也不得用列表权限调用其他端点。

### 2.3 组织与 PII 边界

- 后端 `selectList` 使用 `requireStoreContext`；只有门店可以读取，仓库和公司上下文不得发送请求；
- Reader 只能发送当前会话组织头，不能接受 `shopDeptId`、`scopeDeptIds` 或 `dataScope` 查询参数；
- 请求携带 `expectedOrganizationId`，组织漂移在 `fetch` 前失败；解析后任何跨门店记录都拒绝整页；
- 列表包含姓名、联系人、手机号、偏好、注意事项和预算，属于受授权服务资料；成功响应必须带 `Cache-Control: no-store`，缺失时失败关闭；
- 契约只保留服务卡字段，把照片节点转换为 `hasPhoto` 布尔值，并丢弃信用、账期、邮箱、地址、服务记录、请求键和内部版本字段。

### 2.4 查询与字段语义

- 分页字段为 `pageNum`、`pageSize`；
- 关键字字段为 `keyword`，服务端匹配姓名、手机、编码和茶饮偏好；
- 状态只允许后端 `0`（使用中）和 `1`（已归档），新领域模型使用 `active` / `archived`；
- 偏好标签是单个精确标签，禁止逗号拼接多个值；
- 客户 ID 与照片节点必须经过 Java Long 边界；预算使用非负十进制字符串，并验证最低预算不高于最高预算；
- 最近到店允许后端日期或本地日期时间，领域模型统一为 `YYYY-MM-DD`。

## 3. 设计与动效决策

这是高频 ERP/SaaS 客户服务台，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 使用“门店范围 → 服务卡总量/当前页状态 → 明确筛选 → 服务资料明细”的层级；
- 注意事项始终用静态文字与警示样式展示，不依赖 hover、颜色或动画；
- 搜索、状态/标签筛选、键盘提交、分页和列表替换不播放动画；
- 只允许按钮按压与悬停阴影等 120～180ms 可中断 CSS 过渡；
- 只过渡 `transform`、颜色或 `box-shadow`，不动画布局属性；
- `prefers-reduced-motion: reduce` 下关闭所有非必要过渡；
- 不新增 React、Tailwind、Motion、GSAP、远程字体或外部组件依赖。

## 6. 验证标准

- 不安全 Long、非法状态、畸形预算、最低预算高于最高预算、无效日期和多标签筛选全部失败关闭；
- 新模型不包含信用、账期、邮箱、地址、照片节点 ID、服务记录、请求键或内部版本；
- HTTP Reader 只发送允许参数和一个旧组织头；组织漂移、跨门店记录和缺失 `no-store` 都失败；
- 仓库和公司上下文不调用 Gateway；门店只能读取自身隔离 Mock；
- 页面明确区分服务端总记录和当前页指标，注意事项与偏好在桌面和移动端都可直接读取；
- 筛选成功后才更新已应用条件，失败时保留最近成功标签并可重试最后请求；
- 页面没有详情、照片、审计、导出或写动作伪入口；
- 功能开关和列表权限同时满足才可见且可访问；
- 完整前端验证、迁移生成器、确定性哈希和隔离扫描通过；
- 旧 `erp-ui/`、受保护原项目、Docker、服务、数据库、依赖和真实配置保持零改动。

## 7. 停止线

发现以下任一情况立即停止：

- 需要读取或修改受保护原项目、连接数据库、启动服务或安装依赖；
- 需要修改旧 `erp-ui/`、注入真实 Reader 或绕过门店/PII 缓存边界；
- 需要复活信用、账期或旧客户导出能力；
- 需要启用详情、照片、审计、新建、编辑、追加服务或归档而没有独立计划；
- 不能证明全部文件、运行目录和测试只位于 ERP-NEW_2 隔离工作树。
