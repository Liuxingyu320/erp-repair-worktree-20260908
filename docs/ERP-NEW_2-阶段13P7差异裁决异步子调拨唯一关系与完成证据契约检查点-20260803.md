## 1. 本检查点结果

本阶段已冻结补发和退回两个异步裁决动作共用的不可变关系与完成证据契约：

- 补发保持父调拨方向和类型，使用 `available_stock`，业务来源为 `transfer_discrepancy_reship`；
- 退回反转父调拨方向，按仓店类型互换规则推导子调拨类型，使用 `quarantine_detail`；
- 退回关系必须锚定 V2 残损收货形成的隔离余额、批次和库位；
- 一个动作、一个子调拨、一个效果引用、一个业务来源和一个工作流指纹均由数据库唯一键约束；
- 只有子调拨达到 `received`、明细全量发货、发货全部为 `V2_DETAIL`、至少形成一次收货且不存在未解决 V2 差异，纯策略才返回完成证明；
- 创建时间在生成工作流指纹前统一截断到 MySQL `datetime` 的秒精度，保证写入后回读可重新核验。

## 2. 新增骨架

1. 纯策略：唯一推导方向、类型、库存来源、业务来源和效果引用，并校验派发/完成事实。
2. 不可变关系表：只追加关系快照，不复制或更新子调拨生命周期。
3. 映射对象：把数据库关系和子调拨完成事实转换为纯策略输入。
4. 三方法 Mapper：锁定动作关系、条件追加关系、锁定并读取子调拨完成事实。
5. SQL/Mapper/策略测试：证明结构可解析、DML 仅有关系插入、生产代码没有调用点。
