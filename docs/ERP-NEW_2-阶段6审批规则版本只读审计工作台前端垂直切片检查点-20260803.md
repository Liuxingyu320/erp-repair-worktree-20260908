## 1. 本检查点结论

`erp-ui-next/` 已新增 `/approvals/rules` 审批规则版本只读审计工作台，使用 `approval.rule.view` 功能开关，以及 `approval:template:list` 与 `approval:template:query` 双权限失败关闭。页面提供管理员跨组织规则列表、精确筛选、服务端分页、当前页状态摘要，并可查看规则关联模板、不可变版本、条件和节点策略。

本切片没有提供规则新建/编辑、草稿创建/保存、候选人预览、配置检查执行、版本发布、规则停用、导出或任何写操作入口。真实 HTTP Reader 仍未注入应用运行时。

## 2. 契约审计与纠偏

- 列表端点：`GET /approval/rules`；详情端点：`GET /approval/rules/{id}`。
- 列表只发送后端 Mapper 实际消费的 `templateId`、`ruleCode`、`ruleName`、`scopeType`、`scopeId`、`businessSubtype` 和 `ruleStatus`，以及标准分页参数。
- 详情响应按 `{ template, rule, versions }` 校验；模板、规则、版本和当前发布版本必须关联一致，版本按版本号降序。
- 规则状态固定为 `DRAFT`、`ACTIVE`、`DISABLED`；版本状态固定为 `DRAFT`、`PUBLISHED`、`RETIRED`；范围固定为 `ALL`、`AREA`、`STORE`。
- 发布前不受支持的条件字段、操作符或节点策略仍安全显示并标记“需复核”，不会把需要审计的无效草稿静默丢弃。
- 原始 `strategyConfig` 不进入页面模型；固定用户策略只显示去重人数，不显示用户 ID。
- 定义快照、定义校验和、发布人用户 ID、锁版本、内部操作人和创建/更新时间均被丢弃。

## 3. 权限、数据范围与缓存

- 路由与导航必须同时满足 `approval:template:list` 和 `approval:template:query`，只持有任一权限都失败关闭。
- 当前 Controller 与 Mapper 没有当前组织过滤，页面明确标注“管理员跨组织只读”；Reader 不发送组织头，也不发送 CSRF。
- 列表和详情的成功响应都必须声明 `Cache-Control: no-store`，缺失时 Reader 失败关闭。
- 当前后端没有该响应头证据，因此真实 Reader 保持未注入，这是生产接线阻断项。
- 默认 Provider 只注入 ERP-NEW_2 自有脱敏 Mock，不读取真实或共享业务数据。
