## 3. 单服务停止验收

测试先验证旧实现失败，再完成最小修改。当前行为：

- `stop inventory` 只读取当前端口组合的 inventory PID 文件。
- 没有 PID 文件时返回 `SKIP` 和成功状态，具备幂等性。
- 没有 PID 文件但目标端口仍被占用时返回 `REFUSE`，不误报为已停止。
- `stop unknown-provider` 返回状态 2，并打印有效服务集合。
- 不匹配 PID、完整命令或端口组合时仍拒绝停止。
- 无参数 `stop` 保持原有反向依赖顺序。
- 脚本仍不含 `pkill`、`killall` 或 Docker 调用。

原生运行态使用备用端口 19201、19200、19204、19205、18080、11025：

1. 六服务全部启动并监听。
2. `stop inventory` 后 inventory 为 `STOPPED`，system、auth、OA、gateway、UI 均保持 `RUNNING`。
3. `restart inventory` 后 inventory actuator 返回 HTTP 200 + `UP`。
4. 六服务 L1/L2 全部通过。
5. 未提供登录令牌，L3 三 Provider 业务探针明确跳过，不计为已通过。
6. 最终按反向依赖停止全部服务，六个端口均恢复可用。

## 4. 发布脚本安全门禁

### 4.1 apply 目标库确认

`--apply` 现在必须同时满足：

1. `ERP_UNIFIED_TODO_APPLY_CONFIRMATION=APPLY_UNIFIED_TODO_20260714`；
2. `ERP_UNIFIED_TODO_MYSQL_DATABASE` 与 `ERP_UNIFIED_TODO_EXPECTED_DATABASE` 字符串完全一致；
3. 连接后 `SELECT DATABASE()` 与期望库名完全一致。

缺期望库名、库名包含非字母数字下划线或配置/期望不一致时，在连接数据库前失败。连接库不一致时，在迁移流开始前失败；真正承载七个 SQL 的迁移连接还会在取得命名锁前再次核对。比较遵循 `@@lower_case_table_names`：大小写敏感服务器使用 `BINARY DATABASE()`，大小写不敏感服务器比较规范化名称，避免正确库名被误拒绝，也避免把独立预检连接的结果误当成迁移连接事实。

### 4.2 postflight 覆盖

`--postflight` 是独立只读模式，`--apply` 成功后也会自动调用。当前核验：

- 9 张迁移新增或备份表；
- 26 个迁移字段；
- 20 个迁移索引；
- `idx_stock_check_counter_due` 精确列序；
- `uk_hr_health_user_current` 唯一索引及精确列序；
- 4 个配置键无重复及 3 个关键 fail-closed 值；
- 仓储父菜单、6 个活动子路由、7 个退役重复路由及其授权；
- OA 采购菜单全部退役且角色授权为 0；
- inventory 正常采购锚点保留、调拨活动路由唯一；
- 6 个健康证权限菜单唯一、自助权限和审核权限继承完整；
- OA submitted、运行任务、运行实例均为 0；
- 收货质检数量关系无异常；
- 盘点缺责任人/截止时间只输出治理信息，不擅自修改。

测试同时扫描 postflight 函数，禁止出现建表、改表、插入、更新、删除、截断或删库语句。
