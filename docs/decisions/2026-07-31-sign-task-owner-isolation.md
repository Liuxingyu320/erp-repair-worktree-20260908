# 签约任务负责人隔离决策

日期：2026-07-31

适用范围：合同签约任务中心、统一待办、任务关联签约包、通知失败处理、入职签名优先公司工作区。

## 决策

普通 HR 查看或处理任务绑定的签约业务时，必须同时满足：

1. 持有对应的签约业务权限；
2. 任务位于其授权的签约组织范围；
3. `oa_sign_task.assigned_hr_user_id` 等于当前用户。

任务负责人字段既用于路由、通知和审计，也属于服务端业务授权边界。前端传入的负责人筛选值不能扩大该边界。

## 明确例外

- 系统管理员可跨负责人查看和处理任务，但仍沿用既有高权限审计与业务校验。
- 仅持有 `oa:signTask:technicalEvidence` 的人员可在授权组织范围内只读验真，不获得确认、发送、重试、取消、盖章或异常处理权限。
- 尚未绑定任务的历史入职记录和应急手工签约包继续按授权组织范围处理；一旦绑定任务，即切换到负责人隔离。
- 任务、签约包或入职行之间的绑定不一致时失败关闭，管理员也不能绕过证据绑定完整性。

## 实施边界

- 任务列表和指标由服务端强制写入当前负责人条件；管理员不写入该条件。
- 五类 HR 签约待办和通知失败待办在 SQL 层按当前负责人过滤。
- 任务详情及确认、发送、重试、取消、拒签/逾期处理等动作在读取后、产生副作用前校验负责人。
- 任务关联签约包的列表、详情、验真、文件读取、编辑、发送、撤回和盖章入口复用同一负责人边界。
- 批量发送和批量选公司盖章逐项失败关闭，不因一个无权任务中断其他合法任务，也不回显无权任务的包号和状态。
- 入职公司工作列表在 SQL 和投影层双重过滤；资料审核和生成动作再次校验当前负责人。

## 回归要求

- 同组织其他 HR：任务不可见、详情不可读、动作不可执行，且下游写入或文件处理不得发生。
- 跨组织 HR：继续由组织范围首先拒绝。
- 系统管理员：保留跨负责人业务能力。
- 技术证据人员：保留跨负责人只读验真，但所有业务动作拒绝。
- 历史未绑定记录：在授权组织范围内继续可用。
