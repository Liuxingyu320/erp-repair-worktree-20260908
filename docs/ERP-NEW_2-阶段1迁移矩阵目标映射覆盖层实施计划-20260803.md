# ERP-NEW_2 阶段 1：迁移矩阵目标映射覆盖层实施计划

> 日期：2026-08-03
>
> 分支：`codex/erp-new-2-rebuild`
>
> 基线：`78ffb311 feat: add discrepancy mobile task action bar`

## 1. 结果目标

让现有阶段 1 功能迁移矩阵能够持续吸收 `erp-ui-next/` 的实际迁移结果，而不是每次运行 `scripts/erp-new-2/build_phase1_inventory.py` 都把 173 条目标处置重新覆盖为“待确认 / 待设计”。

本切片新增一个人工维护、机器校验的目标映射覆盖层。生成器继续从隔离工作树内的旧页面、路由、SQL、API 和后端 Controller 生成源能力证据，再按旧页面源码键合并覆盖层中的目标处置、新路由、新组件、测试、确认状态、实施状态和目标证据。

## 2. 当前证据

- 阶段 1 已有 173 条页面/组件迁移矩阵、526 条前端 API、623 条后端端点和 238 个权限标识；
- 现有矩阵 173 条 `target_disposition`、`new_route`、`new_component` 和 `confirmation_status` 全部仍为占位值；
- 新前端已经有工作台、统一待办、调拨工作台、新建、审批、发货、收货、差异裁决、版本历史、401 替代页和 404 页及其自动化测试；
- 当前实现多数仍为 Mock-only 或显式依赖接线，不能因页面存在就宣称整个旧能力迁移完成。

## 3. 文件与结构

新增 `docs/erp-new-2-migration/target-mapping-overrides.csv`，字段为：

- `old_page_source`：稳定键，必须精确匹配矩阵中的旧页面源码；
- `target_disposition`：只允许“保留 / 重设计 / 合并 / 下线”；
- `new_route`、`new_component`、`automated_tests`：目标实现和验证证据；
- `confirmation_status`：原型验收与领域最终确认必须区分；
- `implementation_status`：只允许“未开始 / 部分实现 / 已实现”；
- `target_evidence`：新前端源码、契约或检查点证据；
- `notes`：明确 Mock、未接线、缺失动作或后续工作。

修改 `scripts/erp-new-2/build_phase1_inventory.py`：

- 严格校验覆盖层表头、稳定键、枚举、重复项和必填证据；
- 拒绝不存在于 173 条源矩阵中的孤儿覆盖项；
- 将覆盖项合并到生成矩阵，并增加 `implementation_status` 与 `target_evidence` 两列；
- 在生成摘要中报告已判定目标处置、部分实现、已实现和剩余未决数量；
- 保持输出顺序、编号和源证据哈希可重复。

新增 `scripts/erp-new-2/test_build_phase1_inventory.py`，使用 Python 标准库单元测试覆盖合法覆盖项、重复键、非法枚举、缺失证据和孤儿键。

## 4. 首批回填范围

只回填当前已有明确源码与测试证据的能力，不猜测其余领域：

- 桌面工作台；
- 桌面统一待办与移动待办；
- 调拨主工作台及新建、审批、发货、收货、差异裁决入口；
- 调拨记录/版本历史的部分迁移；
- 调拨审批进度组件的时间线重设计；
- 401 无权访问与 404 页面。

所有首批条目均标记为“重设计”。没有任何“合并”或“下线”决定，也不删除或修改旧页面。Mock-only、缺少导出、未接真实运行时等边界必须保留在 `implementation_status` 和 `notes` 中。

## 5. 测试顺序

1. 先新增覆盖层校验单元测试并运行，记录缺少校验函数的 Red；
2. 实现覆盖层加载、校验和合并，重跑单元测试；
3. 运行生成器两次，第二次必须不产生额外差异；
4. 核对 173 条源能力一条不少，首批目标映射准确，未决条目继续保留；
5. 执行 `erp-ui-next` 完整 `verify`，证明矩阵工具没有破坏新前端；
6. 执行 Git、路径、分支、危险引用和隔离审计。

## 6. 停止线

- 不启动 Docker、Vite、后端或浏览器服务；
- 不连接 MySQL、Redis、Nacos 或任何数据库；
- 不安装或升级依赖；
- 不生成伪造 OpenAPI，不把静态端点候选宣称为冻结契约；
- 不修改旧 `erp-ui/` 源码，不下线、合并或删除旧能力；
- 不访问受保护原项目，不合并、不推送、不操作其他 worktree。
