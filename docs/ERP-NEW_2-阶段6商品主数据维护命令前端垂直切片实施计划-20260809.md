## 1. 目标与范围

在已提交的商品目录与详情只读闭环之上，新增可独立验证的商品主数据维护命令：

- `/inventory/products/new` 新增商品；
- `/inventory/products/:productId/edit` 编辑商品并可显式启用或停用；
- 商品详情页提供受 `inv:product:remove` 保护的两步删除确认；
- 目录与详情按权限、当前组织类型显示新增和编辑入口；
- 通过真实 `POST /inventory/product`、`POST /inventory/product/update`、`DELETE /inventory/product/{productId}` 执行命令；
- 通过真实 `GET /inventory/supplier/list` 加载已启用且合作中的供应商选项；
- Mock Gateway 以独立内存状态模拟新增、编辑和未被引用商品删除，不接触任何数据库。

本切片仍不实现图片/附件、导入导出、分类维护、供应商维护、采购价或成本价编辑。删除只实现代码、契约和隔离 Mock 验证，不会向真实服务发送请求。

## 2. 组织与权限边界

- 门店和仓库均可按既有权限读取商品；只有当前组织为仓库时开放维护动作；
- 新增要求 `inv:product:add`、分类树读取与供应商列表读取能力；
- 编辑要求 `inv:product:query`、`inv:product:edit`、分类树读取与供应商列表读取能力；
- 删除要求详情读取权限与 `inv:product:remove`，并要求用户二次确认精确商品编码和名称；
- 路由守卫负责 feature 与精确权限，页面组件再次检查权限和仓库上下文，脱离路由挂载时不得发出命令；
- 当前组织在 fetch 前变化时失败关闭，所有命令只发送一个 `Dept-NumId`；
- 后端允许仓库读取上级共享商品，因此读取和编辑响应的所属组织不强制等于当前组织，数据范围以服务端授权校验为准；新增响应必须属于当前仓库；
- 修正上一检查点中把“授权范围”误写成“响应组织必须等于请求组织”的过窄表述与前端校验。

## 3. 命令字段白名单

允许提交：

- 商品名称、分类 ID、等级、SKU、规格、尺寸、单位；
- 销售参考价、250g/500g 售价；
- 安全库存上下限；
- 供应商名称、内部名称、商品描述、条码、普通备注；
- 启用/停用状态；
- 编辑时的商品 ID，以及命令组织 ID 和幂等请求 ID。

禁止提交：

- 商品编码（由后端按分类生成）；
- `shopDeptId`、组织名称和任何数据范围字段；
- `purchasePrice`、`costPrice`；
- 供应商电话、供应商采购备注；
- 图片/附件 URL、删除标记、审计字段及任意未知扩展字段。

所有文本执行统一 trim 和长度限制；价格与安全库存只接受有限非负十进制字符串，安全库存上限不得低于下限。HTTP 适配层重新解析命令并从白名单重新构造请求体，不能直接透传页面对象。编辑命令对五个可选销售/库存数值生成独立的 `clear*` 布尔标记：留空时显式清空数据库值，旧客户端未发送标记时仍保留原有动态更新语义。

## 4. 后端契约加固

- 商品新增、编辑和删除响应统一声明 `Cache-Control: no-store` 与 `Pragma: no-cache`；
- 无 `inv:cost:view` 时，在进入服务前清空请求中的采购价和成本价，防止绕过前端写入；保存结果返回前再次清空成本字段；
- 有成本权限时保留既有后端能力，但本切片前端仍不暴露成本编辑；
- 商品更新 SQL 补齐普通 `remark` 持久化，不改动省略字段；
- 商品写入服务拒绝负价格、负安全库存、上下限倒置和非法状态；部分更新按“显式清空标记 / 请求新值 / 数据库原值”的优先级校验最终安全库存范围；
- 供应商列表响应声明 `no-store`；前端只投影供应商 ID、名称和编码，丢弃电话、邮箱、地址、结算及其他字段；
- 前端命令同时发送已校验的 `X-Request-Id` 与 `Idempotency-Key`，同一份失败后未修改的表单重试复用请求 ID；不自动重试写操作。

## 5. 页面与交互

本页属于高频企业 ERP/SaaS，沿用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 使用“基础身份、规格库存、销售参考、供应与说明、提交边界”分组的单页响应式表单；
- 桌面双列，窄屏单列；错误摘要与字段错误同时可见，提交失败保留用户输入；
- 不使用分页入场动画、循环光效、弹跳、视差或大幅缩放；
- 高频字段切换即时完成，仅按钮按压/悬停使用 140–180ms 可中断过渡；
- `prefers-reduced-motion: reduce` 下关闭非必要过渡；
- 删除确认保持静态、明确且可取消，不使用自动倒计时或动态干扰。

## 6. TDD 与实施顺序

1. 为命令 Schema 写失败测试，冻结字段白名单、长度、十进制、状态、请求 ID 和新增/编辑/删除标识；
2. 为 HTTP Gateway 写失败测试，冻结精确路径、请求体、CSRF、组织头、双幂等标识、no-store 和响应一致性；
3. 为后端 Controller/Service 写失败测试，冻结成本写入阻断、响应脱敏、no-store、数值/状态校验和备注持久化；
4. 为路由、目录、详情删除及编辑页写失败测试，冻结权限、仓库上下文、成功/失败/重试和响应式入口；
5. 实现后端加固、前端契约、真实/不可用/Mock Gateway、编辑页和页面入口；
6. 更新上一详情检查点的组织语义及阶段 1 迁移覆盖层，仍保持商品页“部分实现”；
7. 运行前后端定向测试、完整前端 `npm run verify`、迁移生成器单测与连续生成、隔离扫描和差异自审；

## 8. 验收与停止线

- 新增、编辑、停启用和删除命令只能在仓库、精确权限与当前组织未漂移时发送；
- 请求体不包含成本、采购、供应商联系方式、图片、组织归属、商品编码或未知字段；
- 无成本权限的直接后端请求不能写入或读取成本字段；
- 同一失败提交的人工重试复用幂等请求 ID，表单变化后生成新 ID；
- 删除必须明确确认，已被业务引用时保留错误并建议停用；
- Prettier、ESLint、TypeScript strict、OpenAPI 门禁、Vitest、Vite 构建及相关 Maven 测试全部通过；
- 不启动服务、不安装依赖、不执行 SQL、不修改端口/运行数据/旧 `erp-ui/` 或受保护原项目；
- 不删除旧前端，不连接数据库，不合并、不推送。
