# ERP-NEW_2 阶段 13D：收货差异独立裁决计划契约实施计划

> 日期：2026-08-02
> 分支：`codex/erp-new-2-rebuild`
> 基线：`c4378563 feat: add atomic discrepancy confirmation append`
> 范围：独立角色裁决的惰性数据结构、纯动作计划、数量金额守恒和状态机；不写裁决、不更新事项、不执行物理处置、不开放接口

## 1. 结果目标

正式方案要求调出方与调入方都确认同一差异事实后，才由独立“库存差异处理”角色选择补发、退回、报损、责任调整或运输损耗核销。阶段 13D 建立该独立裁决的可信计划边界，但不会把“计划已形成”误报为“差异已解决”。

本阶段的状态只从双方推导的 `ready_for_adjudication` 形成 `adjudication_planned` 计划；未来必须由对应物理库存、物流或财务动作成功后，才能推进到 `resolved`。

## 2. 职责分离

- 新裁决权限契约固定为 `inv:transfer:discrepancy:adjudicate`，与旧 `inv:transfer:discrepancy:handle` 分离；本阶段只验证权限字符串，不创建菜单、不授予角色。
- 裁决人必须是有效登录用户，且不能与当前调出方或调入方确认事件的操作者相同。
- 两方最新事件必须都匹配当前事项版本与事实指纹，且决定均为 `confirmed`。
- 客户端不得声明双方角色、事项金额、裁决状态或是否已解决；这些全部由服务端权威边界推导。

## 3. 裁决动作与兼容性

一个事项允许由一到多个有序动作完整覆盖，支持真实业务中同一差异拆分处置：

- `reship`：补发，仅适用于 `shortage`。
- `return_to_source`：退回来源，仅适用于 `damaged`。
- `damage_write_off`：残损报损，仅适用于 `damaged`。
- `responsibility_adjustment`：责任调整，适用于残损或短缺。
- `transport_loss_write_off`：运输损耗核销，适用于残损或短缺。

每个动作必须保存连续序号、动作类型、数量、服务端金额、责任方和说明。责任方只能是 `source|target|carrier|company`。裁决头必须保存非空说明和证据引用快照。

## 4. 数量、金额与尾差守恒

- 动作数量全部为正、最多四位小数，且总和必须严格等于事项差异数量；阶段 13D 不允许部分裁决。
- 客户端不提交动作金额。服务端使用 13A 来源成本计算六位小数金额。
- 除最后一行动作外，各行按 `source_cost_price × action_quantity` 四舍五入到六位；最后一行取得事项总金额减去前面金额的余额，以确定性吸收微小舍入尾差。
- 各行动作金额必须非负且总和严格等于事项差异金额。
- 动作按连续 `sequence=1..N` 排序后计算，输入列表顺序不得影响计划或决定指纹。

## 5. 惰性结构

新增独立迁移源码 `sql/erp_inventory_transfer_discrepancy_adjudication_v2_20260802.sql`，只创建：

- `inv_transfer_receipt_discrepancy_adjudication`：裁决计划头，保存请求幂等标识、事项版本/指纹、双方确认事件锚点、数量金额、决定指纹、说明证据、独立权限快照、操作者与 `adjudication_planned` 状态。
- `inv_transfer_receipt_discrepancy_adjudication_action`：动作行，保存序号、类型、数量金额、责任方、说明和 `pending` 执行状态。

同一 `discrepancy_case_id + case_version_before` 只能形成一个计划。迁移不执行、不写种子、不复制到 Docker 初始化目录。

## 6. 纯策略输出

纯策略输出不可变 `PreparedAdjudication`：

- 锚定事项标识、版本、事实指纹和双方当前确认事件标识；
- 保存服务端排序和计价后的动作；
- 保存决定指纹、数量金额合计、独立权限、操作者和时间；
- `caseVersionAfter = caseVersionBefore + 1`；
- `caseStatusBefore = awaiting_confirmation`，计划状态为 `adjudication_planned`；
- 不执行 DML，不声称物理动作已完成。

## 7. 验证与停止条件

定向测试覆盖双方确认、职责分离、权限、动作类型兼容性、连续序号、数量守恒、金额尾差、输入顺序确定性、指纹变化和惰性迁移。随后运行库存、后端、前端完整验证与隔离审计。

若需要写裁决、更新事项、执行补发/退回/报损、调整库存或财务、增加 Controller/Gate/权限授予、连接数据库或接线旧差异处理器，立即停止并留待后续检查点。
