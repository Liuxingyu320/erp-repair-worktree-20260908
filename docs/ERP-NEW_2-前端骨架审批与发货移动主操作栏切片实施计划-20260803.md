# ERP-NEW_2 前端骨架：审批与发货移动主操作栏切片实施计划

> 日期：2026-08-03
>
> 分支：`codex/erp-new-2-rebuild`
>
> 基线：`65ac64e8 feat: add mobile ERP task action bar`
>
> 范围：扩展独立 `erp-ui-next/` 的既有操作栏契约，仅使用现有 Mock Gateway 和前端依赖

## 1. 问题与目标

正式方案要求审批、发货、收货在手机浏览器形成闭环，每个详情页突出唯一下一步操作，并满足固定主操作、移动触控与弹窗焦点管理。上一切片已经建立 `ErpTaskActionBar`，并接入新建调拨和收货；调拨审批与发货规划仍在长决策面板内使用普通按钮。

两个页面都已经在进入二次确认时把焦点交给确认标题，但取消确认后，原按钮节点已被重新创建，焦点没有恢复。两个页面在窄屏还会把决策面板移动到页面顶部，因此固定操作栏的原位占位无法保护长页面末尾内容。

本切片把统一操作栏扩展到审批和发货，补齐进入/退出确认态的双向焦点管理，并在固定主操作可见时为页面末尾提供等高安全留白。审批决定、发货规划、阻断规则、请求标识和 Mock-only 提交行为全部保持不变。

## 2. 交互与动效决策

- 项目属于高频 ERP 生产力工具，采用 Emil 为主、Jakub 为辅的交互判断；
- 审批与发货主操作不增加 animation、transition、keyframes、滑入、弹跳或循环光效；
- 操作栏出现、撤下和确认态切换即时发生，键盘路径不等待视觉动画；
- 进入确认态后，命名主操作组卸载，焦点移动到 `alertdialog` 标题；
- 点击“返回修改/返回检查”后，操作栏重新出现，焦点恢复到其中第一个可用主动作；
- 移动固定主操作继续使用不低于 48px 的触控高度和既有 safe-area/底部导航偏移。

## 3. 组件契约扩展

- `ErpTaskActionBar` 暴露 `focusPrimary()`，只在自身主动作插槽中寻找第一个未禁用按钮、链接或可聚焦元素；
- `embedded` 变体的直接主动作在桌面与移动端都填满可用宽度，避免从原满宽操作退化成内容宽度；
- 不增加领域 props，不让设计系统组件知道审批、发货或收货模型。

## 4. 页面接入

### 调拨审批

- 使用可访问名称“审批任务主操作”的 `embedded` 操作栏包装“继续确认”；
- 进入二次确认时撤下操作栏，保留原动作选择、意见校验与确认对话框；
- 返回修改后恢复焦点；
- 只在主操作可见时添加移动底部安全留白。

### 发货规划

- 使用可访问名称“发货规划任务主操作”的 `embedded` 操作栏包装“继续 Mock 确认”；
- 保留 `canCreateShipment` 阻断和服务器建议命令契约；
- 进入确认时撤下操作栏，返回检查后恢复焦点；
- 只在主操作可见时添加移动底部安全留白。

### 收货回归

- 复用新的 `focusPrimary()`，让既有收货确认在返回检查后恢复到“复核”主动作；
- 不改变收货分类、证据门禁或命令结构。

## 6. 实施顺序与验证

1. 先补三个页面的命名主操作组、确认态撤下、标题聚焦和取消后焦点恢复断言；
2. 运行页面定向测试，记录操作组缺失和焦点恢复缺失的 Red；
3. 扩展设计系统组件的主动作聚焦与 embedded 满宽契约；
4. 接入审批、发货与收货返回焦点，添加动态页面安全留白；
5. 定向测试转 Green 后，执行完整 `npm run verify`；
6. 执行 `git diff --check`、依赖/配置变更检查、外部地址/旧前端/受保护路径扫描和无新增动效扫描；
7. 保存检查点并只提交本切片精确文件。
