## 1. 检查点结论

已修正异步补发/退回的子流程引用生命周期，并建立仍未接线的事项、计划、动作和执行事件持久化契约。该契约冻结未来物理效果事务必须使用的锁序、请求重放读取、事件追加和三层条件状态推进，但不会单独运行，也不代表补发、退回、报损、责任调整或运输损耗核销已经发生。

执行入口继续默认关闭；即使两个 Gate 被误开，服务仍无条件抛出“持久化与物理效果边界尚未实现”。

## 2. 已修正的不变量

- 异步 `dispatch` 必须携带服务端创建并核验的 `reship_transfer:<id>` 或 `return_transfer:<id>`；动作从 `pending` 进入 `in_progress` 时立即绑定该引用。
- 异步 `complete` 必须与动作已绑定引用完全一致，不能替换或跨动作复用子流程。
- 原子效果不得绑定子流程引用。
- 动作行新增惰性字段 `execution_effect_reference`，非空值全局唯一。
- 执行事件对效果引用使用普通索引，同一引用可以依次追加调度和完成事件；请求 ID 和动作前版本仍保持唯一。
- 事件指纹纳入全部动作的当前效果引用，引用分布变化会改变指纹。

## 3. 惰性持久化契约

新增 Mapper 的固定顺序接口：

1. 锁定差异事项；
2. 锁定事项与指定裁决头的一致边界；
3. 按动作序号和动作 ID 锁定全部动作；
4. 锁定请求 ID 对应的历史执行事件；
5. 追加一个执行事件；
6. 以事件指纹、精确前状态和前版本条件推进一个动作、一个计划头和一个事项。

Mapper XML 只有 4 个 `SELECT`、1 个 `INSERT` 和 3 个 `UPDATE`，没有 `DELETE`，不读取或写入库存、余额、批次、库位、序列号、预留、调拨单、库存台账或财务表。

新增的边界、动作和历史事件模型只用于未来事务组装与精确重放；当前生产 Java 源码中，Mapper 名称只出现在 Mapper 接口自身，没有 Service、Controller、Gateway、任务或配置调用点。

## 4. 物理效果审计结论

- 受损品的权威位置是 V2 收货生成的目标隔离库存、受损余额/批次/库位及相关序列号；受损报损必须在同一事务扣减这些明细并追加损失台账。
- 短缺未进入目标库存；短缺运输损耗只应追加独立损失台账。
- 补发必须创建受动作唯一约束的 V2 子调拨并重新冻结明确来源库存。
- 退回必须创建反向子调拨；旧 V1 直接增加来源聚合库存的实现不满足 V2 明细语义。
- 当前不存在证据充分的 V2 责任调整台账与运输损耗台账，后续需要新增不可变台账，不能复用旧差异字段冒充效果。

因此本检查点刻意不实现或调用任何物理效果。
