- 仓库和公司上下文零请求；门店数据严格隔离。

## 2. 契约与安全边界

- 只覆盖 `GET /inventory/customer/service-card/list`；真实 Reader 保持未注入，默认启动仅使用 ERP-NEW_2 脱敏 Mock。
- 请求只发送 `pageNum`、`pageSize`、`keyword`、`status`、`preferenceTag` 和一个 `Dept-NumId`；GET 不发送 CSRF，也不接受门店 ID 或数据范围查询参数。
- 请求前校验当前组织未漂移，解析后逐行校验门店归属；任一跨门店记录都会拒绝整页。
- 成功响应必须包含 `Cache-Control: no-store`，否则以 `INVALID_RESPONSE` 失败关闭，避免客户服务资料进入可缓存状态。
- 领域模型保留服务所需的姓名、联系人、手机号、门店、茶饮/冲泡偏好、注意事项、预算和最近到访，把照片节点缩减为布尔值。
- 信用额度、已用额度、账期、邮箱、地址、服务记录、请求键、照片节点 ID 和内部版本全部在契约边界丢弃。
- 详情、受控照片、审计、运营汇总、新建、编辑、追加服务、归档、销售联动、旧客户导出和生产接线均未迁移。

## 3. 设计与动效结果

- UI Prompt Library 与 21st.dev 只影响“门店范围 → 指标 → 筛选 → 服务提示”的信息层级；Motion Primitives 只影响成功/失败状态连续性。
- 页面由 Vue 3、现有设计系统和普通 CSS 独立实现，没有复制外部代码、提示词正文、素材或品牌组合。
- 未引入 React、Tailwind、Motion、GSAP、远程字体或新依赖；没有动态背景、光效、循环、列表入场或布局动画。
- 只保留 140ms 可中断按钮反馈，`prefers-reduced-motion` 会关闭过渡；注意事项始终有文字，不依赖颜色、hover 或动画。
