### 你特别关心的几类（从 68 项里抽出）

**消息与待办（W1 / MN\*）**

- 签约通知必须带：姓名、门店、事项/文件、截止时间、下一步。
- 旧消息也要可读、可按姓名搜索，不能只改新模板。
- “签约超时”与“劳动合同到期”必须分开说。
- 点击消息不能只变已读、原地不动；要进正确办理位置或给清原因。

**合同与人员（W2 / C\*）**

- 合同资料自动回写档案；当前工资与历史工资分清。
- 员工档案与用户管理的公司/门店/配置状态口径统一。
- 工资入档与合同生成反馈脱节要修（失败也要说清已完成哪步）。

**账号角色店铺（W3 / B\* C\*）**

- 新增用户不能卡在向导；资料+角色+店铺尽量同页完成。
- 建角色 → 选成员 → 配店铺不要来回跳；支持批量应用并说清增减范围。
- 调店后角色/管理范围要联动；未读到授权时不能拿所属部门冒充已授权。

**日常便利（W4 / U\* N\*）**

- 调岗少填、连续入职沿用门店岗位、入职步骤少切页。
- 请假/补卡能按姓名找人；补卡时间语义正确；假种空值不能自动变 1。
- 考勤预检期间改条件不能串提交范围。

## 四、你后来单独拍板的规则：离职顺序（L01）

你明确选择：

补充文件：`docs/plans/L01-离职先签署后办结停号-用户确认补充-20260915.md`

要点：

1. 发起离职时账号先不停，员工仍可用原账号签完本人文件。
2. 三份文件：**《离职申请审批表》《离职交接表》《离职证明》**；全部签署并归档后，人事在同一办理记录里一次办结，同时停号。
3. 少签/拒签/归档失败不能当办结；办结后旧会话失效、新登录拒绝。
4. 不新增离职专用完整登录权限，不自动恢复历史已停账号。
