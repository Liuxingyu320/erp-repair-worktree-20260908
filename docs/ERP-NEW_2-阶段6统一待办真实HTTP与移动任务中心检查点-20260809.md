## 1. 本检查点结论

新前端移动任务中心已经从调拨 Mock 概览切换到统一待办真实 HTTP Gateway，能够聚合 `approval`、`inventory`、`oa`、`system` 四个技术提供方，并保留 `inventory`、`oa`、`system` 三个业务来源语义。页面支持分类、来源、组织范围、关键词和加载更多；提供方失败时只使用同组织、同查询、同前缀的上次成功数据，并明确区分 `fresh`、`stale` 与 `unknown`。

所有服务端导航数据仍按不可信输入处理。只有经过运行时契约、目标白名单、服务端声明权限、前端功能开关、路由权限和授权组织共同校验的任务才可打开；未知类型、原始 URL、不完整参数和未迁移页面默认关闭。

本检查点只验证代码、契约、单元/组件测试和生产构建。没有启动前端或后端服务，没有连接数据库或中间件，因此不宣称真实数据端到端联调已经完成。

## 2. 统一待办领域与 HTTP 聚合

- 新增独立 `todos` 领域的 model、Zod contract、aggregation、target resolver、Gateway 与 HTTP 实现，并接入 `AppGateways` 的真实和 Mock 装配。
- Java `Long` 标识保持字符串精度；不精确 number、越界计数、嵌套路由参数、原型链关键键、未知枚举和摘要计数不一致均失败关闭。
- HTTP Gateway 使用同源 `/api` 下的四组 `summary` / `list` 端点；GET 请求省略 CSRF，按查询范围要求或附带当前组织，并通过 `expectedOrganizationId` 阻止陈旧组织请求。
- 每个提供方单次最多读取 100 条；全局第 `p` 页先读取每个提供方前 `p*s` 条，再全局去重、稳定排序和切片，未直接拼接各提供方局部分页。
- 缓存键包含提供方、分类、业务来源、组织范围、关键词、查看组织和所需前缀；缓存总量有界，不跨组织、查询或页前缀复用。
- 取消请求始终向上抛出，不允许降级为陈旧缓存；快速切换筛选时，只有最新请求可以结束当前 loading 状态。
- 仅在全部列表新鲜、全部总数已知且未观测到跨提供方重复时声明精确总数；否则只展示已知数据和估算范围。

## 3. 导航、权限与组织安全

- 新增采购、库存、盘点、销售、销售退货、配送通知、OA 采购和调拨详情等新前端深链登记；登记只返回具名 Vue Router 目标，不接受服务端 URL 或任意 path。
- 原生调拨审批必须同时具有 `businessId`、`approvalTaskId`、`approvalInstanceId`；旧审批只在缺少统一实例且任务 ID 完整时形成 legacy 目标。
- 调拨收货只使用服务端明确返回的 `shipmentId`，不根据业务 ID 猜测或拼接收货任务标识。
- 打开任务前同时验证待办 `requiredPermission`、目标 feature、目标 permission 和待办所属组织是否仍在当前授权组织树中。
- 需要跨授权组织处理时先切换 ERP-NEW_2 会话组织；路由失败会恢复原组织。未授权组织不会触发导航。
- 尚未迁移的 HR、合同、固定资产、采购退货和差异裁决操作页保持关闭，不回退到旧前端。

## 4. 移动任务中心与动效约束

- 页面显示当前组织、已知待办总数、实时/部分/未知状态、分类 chips、来源/范围/关键词筛选、任务卡片和加载更多。
- 任一提供方失败时以文字显示其上次成功数据或未知状态；所有提供方未知时不把结果伪装成“0 条待办”。
- 按钮、筛选控件和重试操作的最小触控高度为 44px；状态不只依赖颜色表达。
- `design-motion-principles` 技能影响了本次交互：高频筛选即时响应，只对状态区和任务卡首次出现使用 180ms 的轻量 `opacity + translateY(8px)`，没有循环、弹跳、视差或大幅缩放。
- `prefers-reduced-motion: reduce` 下关闭入场和按压缩放；未新增 GSAP、React、Tailwind、远程素材或其他依赖。

## 5. 服务端缓存控制

- `approval`、`inventory`、`oa`、`system` 四个待办控制器的摘要和列表响应均设置 `Cache-Control: no-store, max-age=0` 与 `Pragma: no-cache`。
- 新前端同时强制校验 `no-store`；缺失该响应头的数据被视为提供方失败，不会进入成功缓存。
- 只修改响应缓存头和控制器测试，没有改变审批候选、组织范围、查询条件、排序、分页或服务层业务逻辑。
- 审批提供方继续沿用服务端既定的 `all_authorized` 语义；本检查点没有擅自增加当前组织锚点过滤。

## 6. 代码审查修复
