# ERP-NEW_2 前端设计参考与动效规范

> 日期：2026-08-02
> 适用目录：`erp-ui-next/`
> 技术基线：Vue 3 + TypeScript；不得 import、symlink 或运行时引用旧 `erp-ui` 源码

## 1. 设计参考源纳入长期目标

以下站点作为界面结构、组件形态、视觉层级和动效提示词的参考库。免费情况来自用户提供的候选清单；实际采用某个组件或素材前，仍须逐项复核当时的许可证、归属要求和商业使用范围。

| 优先级 | 参考源 | 在 ERP-NEW_2 中的用途 |
| --- | --- | --- |
| 1 | [21st.dev](https://21st.dev/) | 观察可运行组件的视觉效果，提取布局、状态和 AI 提示词思路 |
| 2 | [React Bits](https://reactbits.dev/) | 参考高质量动态背景、文字、卡片和局部交互；优先吸收普通 CSS 思路 |
| 3 | [UI Prompt Library](https://www.itoolverse.com/generator/ui-prompts) | 参考登录页、后台首页、侧边栏和数据看板的完整结构提示词 |
| 4 | [Magic UI](https://magicui.design/) | 为少量关键状态、引导和品牌区域参考渐变、光效与动态边框 |
| 5 | [Motion Primitives](https://motion-primitives.com/) | 参考克制、专业、可访问的后台交互动效 |
| 6 | [Uiverse](https://uiverse.io/) | 参考按钮、输入、加载和空状态等局部细节 |
| 补充 | [MotionSites](https://motionsites.ai/) | 参考页面动效提示词和动效编排，不复制与 ERP 任务无关的营销页效果 |

这些来源多数面向 React 或 Tailwind，而 ERP-NEW_2 当前是 Vue。不得为了复制示例而引入 React 运行时，也不得把来源站点代码未经审查直接粘贴进生产代码。采用过程必须是“观察模式 → 提炼设计意图 → 用本项目 design tokens 和 Vue 组件独立实现 → 测试可访问性与性能”。

## 2. ERP 界面取向

1. 首要目标是让用户快速判断当前状态、责任人、风险和唯一下一步动作，而不是制造展示型动画。
2. 信息密度适合桌面后台，同时保证 640px 以下的任务处理页面可用。
3. 颜色只表达品牌、语义状态和差异；不得靠颜色单独传达审批或库存结论。
4. 调拨、审批、收货、差异和库存历史优先使用时间线、状态徽标、差异表和审计摘要。
5. 科技感只允许出现在低频品牌区域、关键成功反馈或空状态；常用表格、表单和任务按钮保持克制。
6. 所有外部参考都必须回落到 ERP-NEW_2 自有 token、组件、文案和权限/组织边界，不形成运行时外部依赖。

## 3. 动效预算

本规范采用 `design-motion-principles` 的 ERP SaaS / productivity dashboard 权重：Emil Kowalski 的可感知速度与直接操控原则为主，Jakub Krehel 的状态连续性为辅。

- 页面首次进入可使用一次 `opacity + translateY(6px)`，时长约 200ms，使用项目自定义标准 easing。
- 高频操作（版本切换、表格筛选、分页、选项切换）必须即时更新，不增加等待型过渡。
- 按钮按下可使用轻微 `scale(0.98)`；不得使用 bounce、弹簧过冲、闪烁或无限循环。
- 只动画 `transform` 与 `opacity`；不得动画布局尺寸、位置或阴影扩散来制造大面积重绘。
- 所有非必要动效必须在 `prefers-reduced-motion: reduce` 下关闭。
- 动效不得掩盖权限失败、数据校验、库存不足、审批拒绝或哈希完整性错误。

## 4. 引入外部模式的验收门槛

每个参考模式进入业务页面前必须回答并验证：

1. 它是否让 ERP 用户更快完成任务或更准确理解状态？
2. 它是否能用现有 Vue、CSS 和 design tokens 独立实现？
3. 它是否满足键盘、焦点、对比度、减弱动效和移动端要求？
4. 它是否引入不必要的依赖、遥测、远程资源、许可证或供应链风险？
5. 它是否有单元/组件测试，并通过 `npm run verify` 的格式、Lint、类型、OpenAPI 门禁、测试和构建？

任一问题无法证明时，该模式不得进入正式页面。

## 5. 2026-08-02 只读核验与阶段 9 采用结果

- 21st.dev 当前仍定位为 React 社区组件注册表，支持实时预览与复制 AI 提示词；因此只提炼结构和设计意图。
- React Bits 同时提供 TypeScript/JavaScript 与普通 CSS/Tailwind 变体，但核心实现仍面向 React；阶段 9 不引入其运行时或源码。
- UI Prompt Library 的后台结构包含指标卡、侧栏、三栏和主从详情模式；阶段 9 采用其中“摘要 + 主清单 + 详情/确认区”的信息架构。
- Magic UI 提供大量光效、动画列表和卡片模式；仓库作业只借鉴清晰的状态层次，不采用光效背景或持续运动。
- Motion Primitives 是基于 Motion 与 Tailwind 的开源动效组件集合；阶段 9 只借鉴确认面板、披露和状态连续性原则。
- Uiverse 的公开元素覆盖按钮、输入、加载、卡片和提示等局部控件；进入项目仍需逐个复核许可证与可访问性。
- MotionSites 当前主要提供 AI 网站模板；仅作为提示词和动效节奏参考，不作为 ERP 页面或代码来源。

核验不会改变既有门槛：任何外部模式都必须使用 Vue、项目 token 和本地代码独立实现，通过可访问性、减弱动效、性能和完整门禁后才能保留。
