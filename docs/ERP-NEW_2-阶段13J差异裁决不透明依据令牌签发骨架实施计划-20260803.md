# ERP-NEW_2 阶段 13J：差异裁决不透明依据令牌签发骨架实施计划

## 1. 目标与审计结论

阶段 13I 已证明浏览器可以建立严格本地草案，但阶段 13F 的浏览器安全投影有意不返回内部 `factFingerprint`；阶段 13E 的裁决写事务仍必须以该指纹、事项版本和双方最新确认事件为权威依据。

仓库内 OA 模块存在签名 JWT 确认令牌，但 JWT 的载荷可被客户端解码，且该实现不提供服务端一次性消费状态。差异裁决属于库存和金额相关高影响操作，本阶段不复用该模式，也不让库存模块依赖 OA。

本阶段采用真正不透明的服务端令牌：

- 使用 `SecureRandom` 生成 256 位随机 bearer token；
- 浏览器只收到一次原始令牌，数据库只保存 SHA-256 摘要；
- 令牌有效期固定为 5 分钟；
- 令牌绑定用途、裁决人、所选组织、当前组织范围摘要、事项、版本、事实指纹和双方确认事件；
- 预留 `issued/consumed` 状态、消费请求和裁决结果锚点，支持后续同事务一次性消费；
- 不依赖 JWT 密钥、Redis、共享缓存或客户端可构造的内部摘要。

## 2. 本阶段实现范围

### 2.1 纯安全策略

新增纯策略负责：

- 规范化并校验组织范围；
- 生成带固定版本前缀的 Base64URL 不透明令牌；
- 计算令牌摘要和组织范围摘要；
- 只在双方当前确认一致、事项处于待裁决状态且裁决人与双方确认人相互独立时准备签发；
- 对数据库中的服务端绑定进行常量时间比较；
- 对篡改、过期、未来签发、已消费、跨用户、跨组织、跨范围、跨事项、跨版本或事实变化统一失败关闭。

### 2.2 服务器签发服务

新增尚无业务入口的 Spring 事务服务：

1. 在访问数据库前验证登录快照和精确权限 `inv:transfer:discrepancy:adjudicate`；
2. 通过 `ShopScopeService` 解析有限、非空、全为正数的组织范围；
3. 锁定权威差异事项并复用既有事实、确认与独立职责校验；
4. 生成令牌并条件插入签发记录；
5. 仅返回浏览器安全的事项、组织、签发/过期时间和原始令牌，不返回事实指纹、确认事件内部标识或数据库主键。

### 2.3 加法持久化

新增 ERP-NEW_2 专属数据库未来 roll-forward 使用的独立表和窄 Mapper：

- 表只保存令牌摘要，不保存原始令牌；
- 唯一约束阻止摘要重复；
- 当前阶段 Mapper 只允许一条条件 `INSERT ... SELECT`；
- SQL 在插入时再次核对事项状态、版本、事实指纹、双方最新确认、独立裁决人、精确权限和组织范围；
- 不修改库存、物流、财务、裁决计划或事项状态。

DDL 只作为独立环境的未来迁移源码提交，本阶段不连接或执行任何数据库。

## 4. 验证

- 纯策略覆盖令牌熵、格式、摘要、上下文绑定、过期和消费状态；
- 服务测试证明权限先于数据库访问、锁序固定、原始令牌不进入持久化对象、条件插入失败即停止；
- Mapper 测试证明只有授权表的一条插入，没有更新、删除或业务表写入；
- SQL 测试证明表保存摘要而非原文，并具备一次性消费所需字段和约束；
- 运行库存模块离线 Reactor、新前端完整门禁、`git diff --check` 和隔离扫描。

## 5. 停止线与下一 Gate

本阶段不新增 Controller、HTTP/RPC、前端 Reader/Writer、运行时注入、权限菜单或真实裁决调用点，也不修改阶段 13E 写事务的浏览器请求模型。

下一阶段必须把“令牌锁定、核验、裁决写入、事项推进和令牌消费”纳入阶段 13E 唯一事务，完成精确幂等重放语义后，才可以继续设计 HTTP 写边界。若无法保证同事务一次性消费，不开放真实提交。
