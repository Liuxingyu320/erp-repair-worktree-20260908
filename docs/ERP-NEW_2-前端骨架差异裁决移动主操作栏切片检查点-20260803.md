## 1. 本切片结果

- 差异裁决草案使用“差异裁决草案主操作”命名操作组承载唯一“检查裁决草案 / 检查 Mock 草案”动作；
- 操作栏采用既有 `ErpTaskActionBar` 的 `embedded` 变体，767px 以下固定在移动导航上方，并由组件宿主预留等高正文空间；
- 二次确认出现时撤下主操作栏，避免同时暴露草案复核与最终确认两个竞争动作；
- 打开确认层后焦点进入确认标题；按 Esc 或点击“返回修改”后，焦点都恢复到重新创建的草案复核按钮；
- 默认运行时仍只允许不持久化的本地 Mock 草案演练，显式协调器路径仍只创建待执行计划；
- 已形成裁决计划时不再出现草案主操作，物理执行 Gate 继续保持关闭；
- 没有改变差异覆盖校验、双方事实确认、提交次数、一次性依据、Gateway 或库存、财务、物流执行契约；
- 本切片没有新增 animation、transition 或第三方 UI/动效依赖。

## 2. 设计取舍

- 采用 Emil Kowalski 的高频工具交互取向：唯一下一步持续可见，状态切换直接，不添加装饰动画；
- 采用 Jakub Krehel 的可访问性取向：确认态与编辑态双向焦点可预测；
- 参考 Motion Primitives 的状态连续性，但复用项目已有 Vue/CSS 设计系统，不引入 React、Tailwind 或 Motion 运行库；
- 21st.dev、React Bits、Magic UI、Uiverse、UI Prompt Library 与 MotionSites 只作为结构和质感参考，没有复制站点代码或素材。
