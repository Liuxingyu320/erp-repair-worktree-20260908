## 1. 问题与目标

正式方案要求移动核心任务使用大触控区域和固定主操作，并在批量页面建设前建立移动底部操作栏。当前新建调拨只有普通页尾操作区，收货页面的主操作位于长页面末端；手机用户必须滚到末尾才能继续。同时应用已经有固定移动主导航，页面若自行固定按钮会与导航及 iPhone 安全区重叠。

本切片建立 `ErpTaskActionBar` 设计系统组件，并新增共享的移动导航/操作栏高度令牌。组件在桌面保持普通页内布局，在移动端固定到主导航上方并为页面预留等高空间。首批接入新建调拨与收货两个原型，保持原有校验、二次确认和 Mock 提交逻辑不变。

## 2. 已确定契约

- `ErpTaskActionBar` 使用带可访问名称的 `role="group"`，提供上下文、次要动作和主动作插槽；
- `footer` 变体负责完整表单页尾表面，`embedded` 变体用于已有决策面板内部；
- 桌面端保持静态布局，不改变页面栏宽、决策面板 sticky 或按钮顺序；
- 移动端通过 `position: fixed` 固定，底部偏移由共享的移动主导航高度令牌与 `env(safe-area-inset-bottom)` 共同计算；
- 组件自身在文档流中预留操作栏高度，最后一段内容能够滚动到固定栏上方；
- 固定操作栏 z-index 低于移动主导航且空间不重叠；
- 主动作与次要动作维持至少 48px 移动触控高度；
- 新建调拨在三步流程中始终提供取消、上一步和唯一下一步动作；
- 收货页面在规划可操作且尚未进入二次确认时显示固定“复核”动作；进入二次确认后立即撤下固定栏，由确认区接管焦点和最终操作；
- 动作栏固定/撤下、步骤变化、按钮出现/消失均不使用 animation、transition、keyframes、滑入或弹跳；
- 不复制外部组件库或提示词网站代码，不新增第三方依赖。

## 4. 实施顺序

1. 先用组件测试锁定可访问操作组、插槽、变体和移动固定开关；
2. 新增共享高度令牌，并让 AppShell 移动导航使用同一令牌；
3. 实现无领域依赖、无动效的 `ErpTaskActionBar`；
4. 替换新建调拨页尾操作区，保留三步流程与 Mock 演练；
5. 包装收货“复核”动作，并在进入二次确认后卸载固定栏；
6. 增加两个页面的操作组、动作切换与原有成功路径回归测试；
7. 执行定向测试、完整 `npm run verify`、源码隔离扫描与 Git 隔离复核。

## 5. 验证门禁

- 组件测试证明操作组名称、三个插槽、footer/embedded 变体和固定/静态类正确；
- 新建调拨每一步只有一个明确的下一步主动作，原有就地校验与 Mock 成功路径继续通过；
- 收货进入二次确认前存在命名主操作组，进入确认后固定组消失且确认标题获得焦点；
- 主导航和任务操作栏使用同一个移动导航高度令牌，不存在第二份数字偏移；
- `npm run verify` 必须通过 Prettier、ESLint、Vue TypeScript strict、OpenAPI 门禁、Vitest 与 Vite 构建；
- `git diff --check` 与源码隔离测试必须通过；
- 静态扫描必须证明无新依赖、无旧前端引用、无真实网络请求和无运行配置变化。

## 6. 停止线

- 不启动 Vite/Playwright web server、Docker、MySQL、Redis、Nacos 或后端服务；
- 不执行 `npm install`、`npm ci` 或任何联网依赖命令；
- 不修改真实 Writer、`.env.local`、端口、凭据或运行数据；
- 不访问受保护原项目，不删除旧前端，不合并、不推送。
