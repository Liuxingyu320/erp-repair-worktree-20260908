# ERP-NEW_2 阶段 13L：差异裁决写请求契约与未接线提交信封检查点

## 1. 检查点结论

阶段 13L 已建立未来差异裁决 HTTP 写边界两侧可复用、但尚未接入运行时的安全契约：

- 后端增加浏览器安全 Bean Validation 请求 DTO，可把未来请求头中的 `requestId`、路径中的差异事项 ID 与严格 JSON 正文纯组装为阶段 13K 领域命令；
- 前端增加服务端 basis、浏览器正文、未接线提交信封和创建结果的严格 Zod 契约；
- 草案只有在服务端规划仍处于待裁决状态、事实字段未漂移且 basis 与事项、版本、当前组织和有效期完全一致时，才能生成固定 `transport=unwired` 的内存信封；
- Controller、HTTP writer、TransferGateway 写方法、页面、bootstrap、功能码和默认运行时均继续关闭。

本检查点不是可调用接口，也没有签发或消费真实 token，更没有执行差异处置。

## 2. 已落实的边界

浏览器 JSON 正文只允许：

- `basisToken`；
- Long 范围内的规范十进制 `caseVersion` 字符串；
- `adjudicationNote`；
- `evidenceRefs`；
- 1 至 20 个仅含序号、动作类型、正数量、责任方和说明的动作。

以下字段不允许由浏览器正文提供：`requestId`、`discrepancyCaseId`、`selectedOrganizationId`、事实指纹、双方确认事件 ID、决定指纹、动作金额、执行状态、裁决主键、用户或权限。

数量前后端统一限制为最多 14 位整数和 4 位小数。前端标识与版本按字符串比较限制在 Java `Long` 范围，避免 JavaScript 安全整数截断。后端 DTO、命令和前端摘要均不输出原始 token 或正文文本。

## 3. 审查结果

聚焦自审覆盖了请求字段来源、后端策略枚举、幂等请求格式、VO 响应形状、Long/Decimal 边界、未知字段拒绝、令牌日志与浏览器持久化风险，以及运行时接线状态。

未发现阻断性缺陷。审查中补充了两类测试：

- Jackson 同时拒绝根级内部权威字段和嵌套动作金额字段；
- 前端创建结果只接受服务端来源及不早于计划时间的响应时间。

剩余验证缺口是刻意保留的运行时停止线：本阶段没有真实 Controller、HTTP writer、数据库集成测试或端到端写入验证。
