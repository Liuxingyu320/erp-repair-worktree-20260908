## 1. 本检查点结论

新前端已具备从统一待办深链进入的移动优先调拨审批任务页，并以阶段 7 的不可变封存修订作为商品、数量、组织、原因、凭证和哈希上下文。页面按旧库存审批与统一审批两种执行引擎展示各自允许的动作，在发送真实决策前校验任务、实例、调拨单、封存版本和当前节点归属。

默认应用仍使用 ERP-NEW_2 隔离 Mock；页面演练结果明确标记 `persisted: false`，不会伪装为真实审批成功。真实 HTTP 适配器只冻结未来联调边界，本检查点没有启动服务或连接数据库。

## 2. 双引擎审批边界

- 旧库存审批读取 `GET /inventory/transfer/{transferId}/approval-track`，只开放 `approve/reject`，提交到 `POST /inventory/transfer/approve`。
- 统一审批读取 `GET /approval/instances/{instanceId}`，开放 `approve/return/reject`，提交到 `POST /approval/tasks/{taskId}/{action}`。
- 旧引擎路由不得携带统一实例 ID；统一引擎路由必须携带实例 ID。
- 真实 HTTP 路由只接受正整数标识；Mock 固定标识只存在于隔离 Gateway，不会进入真实请求路径。
- 真实写请求要求组织上下文、CSRF 和调用方生成的请求标识，不启用自动重试。
- 审批页在一次确认周期内复用同一个请求标识；网络结果不确定后的重试继续使用原标识，修改动作、意见或主动取消才生成新命令标识。

## 3. 失败即关闭校验

只有以下条件同时成立，页面才会开放审批动作：

1. 最新不可变修订存在且状态为 `SUBMITTED`。
2. 旧审批轨迹的调拨 ID、单号、运行状态和当前节点与封存历史一致，并且轨迹完整度为 `complete`。
3. 统一审批实例业务类型为 `INV_TRANSFER`，实例、任务、调拨 ID、当前节点顺序和可用节点名称一致。
4. 统一审批实例仍为 `RUNNING`，目标任务仍为 `PENDING`。
5. 拒绝或退回原因去除首尾空白后至少 4 个字符；所有审批意见不超过 500 个字符。

后端旧审批入口同步增加 Jakarta Bean Validation 和服务层防御校验，覆盖绕过 HTTP Controller 的内部调用。
