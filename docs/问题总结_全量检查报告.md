## 二、🔴 严重问题（Critical）

### 1. 登录页硬编码默认账号密码
- **位置**: `erp-ui/src/views/login.vue:183-184`
- **问题**: `username: "admin"`, `password: "admin123"` 作为表单默认值硬编码在前端代码中
- **影响**: 安全风险，任何可以查看前端源码的人都能看到默认凭据；生产环境可能被暴力破解利用
- **建议**: 移除默认值，改为空字符串

### 2. 调拨页面引用未定义方法（运行时崩溃风险）
- **位置**: `erp-ui/src/views/inventory/transfer/index.vue`
- **问题**: `handleTransferActionError` 方法在第 934, 965, 976, 1020, 1090, 1107 行被调用，但该方法在整个组件中从未定义
- **影响**: 当调拨操作的 API 调用失败时，会抛出 `xx.handleTransferActionError is not a function` 错误，导致页面的错误处理逻辑完全失效
- **建议**: 定义该方法或改为通用的错误处理逻辑

### 3. 创建用户后店铺授权页面跳转传参缺失
- **位置**: `erp-ui/src/views/system/user/index.vue:501-505`
- **问题**: 新增用户时，`createdUser` 是在 `addUser` 调用前捕获的 `Object.assign({}, this.form)`，此时还没有 `userId`。后续 `confirmShopScopeAfterCreate` 中 `handleShopScope` 读取 `row.userId` 将是 `undefined`
- **影响**: 创建用户后自动跳转到店铺授权页面时，URL 为 `/system/shop?userId=undefined&userName=xxx`，授权功能无法正常工作
- **建议**: 在 `addUser` 成功后从响应中获取真正的 userId，再传递

### 4. 排序事件处理器签名不匹配
- **位置**: `erp-ui/src/views/system/logininfor/index.vue:268`, `erp-ui/src/views/system/operlog/index.vue:253`
- **问题**: `handleSortChange(column, prop, order)` 接收三个参数，但 Element UI 的 `sort-change` 事件回调签名是 `({ column, prop, order })`（单个对象），导致 `prop` 和 `order` 为 `undefined`
- **影响**: 登录日志和操作日志页面的排序功能完全不生效
- **建议**: 改为 `handleSortChange({ column, prop, order })` 解构接收

## 三、🟠 高优先级问题（High）

### 5. 字典数据页面缺少 `isDefault` 字段
- **位置**: `erp-ui/src/views/system/dict/data.vue`（表单和表格均缺失）
- **数据库**: `sys_dict_data` 表有 `is_default` 字段（Y/N）
- **问题**: 用户无法在界面上设置或查看字典项的"是否默认值"
- **建议**: 在表单和表格中增加该字段

### 6. 菜单管理-状态筛选 v-model 缺失
- **位置**: `erp-ui/src/views/system/menu/index.vue`
- **问题**: 搜索表单中有 `status` 下拉框（第14-21行），但 `queryParams` 的 `data()` 中没有定义 `status` 属性（第357-359行只有 `menuName` 和 `visible`）
- **影响**: 状态筛选下拉框选择后不会传递给后端，筛选无效
- **建议**: 在 data() 的 queryParams 中增加 `status: undefined`

### 7. OA-待办审批无法查看采购原因
- **位置**: `erp-ui/src/views/oa/todo/index.vue`
- **数据库**: `oa_purchase` 表有 `reason`（采购说明）字段
- **问题**: 待办列表中不显示 `reason` 字段，审批弹窗只显示意见输入框，审批人看不到采购申请的具体内容就需决定是否通过
- **影响**: 审批流程名存实亡，审批人无法做出合理判断
- **建议**: 在待办表格中增加"采购说明"列，在审批弹窗中显示详情

### 8. OA-考勤"全部"视图缺少员工信息列
- **位置**: `erp-ui/src/views/oa/attendance/index.vue`
- **数据库**: `oa_attendance_record` 表有 `user_name`, `nick_name`, `dept_name`, `shop_dept_name`
- **问题**: 切换到"全部"视图时，表格中不显示员工姓名、部门等字段，无法区分每条记录属于谁
- **影响**: 管理员查看全员考勤时完全无法使用
- **建议**: 在表格中增加员工姓名、部门等列，增加员工姓名搜索筛选

### 9. 采购/待办/已办页面显示店铺ID而非店铺名称
- **位置**: `erp-ui/src/views/oa/purchase/index.vue`, `todo/index.vue`, `done/index.vue`
- **数据库**: `oa_purchase` 表有 `shop_dept_name`
- **问题**: 表格中显示的是 `shopDeptId`（数据库ID），而非人类可读的 `shopDeptName`
- **建议**: 改为显示 `shopDeptName`

### 10. OA待办/已办页统计数据仅统计当前页
- **位置**: `erp-ui/src/views/oa/done/index.vue:221-226`
- **问题**: 顶部的"已通过 X"、"已驳回 X"计数仅统计当前分页的10条数据，并非全量统计
- **影响**: 误导用户以为只有X条已通过/已驳回
- **建议**: 从后端获取全量统计数字，或在响应中包含 total count

### 11. 工资参数配置缺少店铺选择
- **位置**: `erp-ui/src/views/oa/salary/index.vue`
- **数据库**: `oa_salary_config` 表有 `shop_dept_id`
- **问题**: 打开工资参数弹窗时，`getSalaryConfig({})` 不传 `shopDeptId`，`defaultSalaryConfig()` 的 `shopDeptId` 固定为 `undefined`
- **影响**: 多店铺场景下，不知道配置的是哪个店铺的考勤工资参数
- **建议**: 在配置弹窗中增加店铺选择器

### 12. 销售管理客户为自由文本输入
- **位置**: `erp-ui/src/views/inventory/sales/index.vue`
- **数据库**: 已有 `inv_customer` 客户主数据表
- **问题**: 销售单中的客户字段是 `el-input` 自由文本，而非从客户主数据中选择，无自动补全，无校验
- **影响**: 数据完整性风险——可以录入不存在的客户名，导致客户数据分散且无法追溯
- **建议**: 改为下拉选择器，支持筛选和新增

## 七、业务流程问题

### 41. 采购流程：质检与收货的顺序矛盾
- **现状**: 采购单提交后 → 质检 →（通过后）→ 收货。但 `canReceivePurchase` 要求 `qcStatus !== "pending"`
- **问题**: 未收货前如何质检？质检是对已收货商品的质量检验
- **建议**: 明确业务流程：方案A（先收后检）或方案B（先检后收），当前是方案B，需确认业务是否合理

### 42. 调拨流程：审批规则中"按金额"条件被禁用
- **位置**: `erp-ui/src/views/inventory/transfer/rules.vue:125`
- **问题**: 审批规则的"按金额"条件类型的 option 标记为 `disabled` 且提示"暂不可选"
- **建议**: 实现该功能或移除禁用选项

### 43. 劳动合同流程：签署后无同步通知
- **观察**: 合同发送→员工签署→状态更新，但缺少签署完成后的通知机制（如站内信/邮件）
- **建议**: 增加签署完成后的通知推送

### 44. 固定资产维修流程：超额维修无审批链
- **观察**: 维修金额超出可用额度时，通过"异常批准"处理，但异常批准是直接管理员操作，无多级审批
- **建议**: 考虑引入金额分级审批机制

## 八、人性化/UX 改进建议

1. **全局无批量操作**: 所有列表页都不支持批量选择/批量操作（批量删除、批量导出、批量状态变更）
2. **无列可见性定制**: 所有表格都不支持用户自定义显示/隐藏列
3. **无保存的筛选条件**: 搜索条件不支持保存为预设
4. **无表单草稿自动保存**: 复杂表单（如劳动合同、调拨单）不支持自动保存草稿
5. **无键盘快捷键**: 全系统缺少键盘快捷键支持
6. **无操作撤销**: 所有操作都是不可逆的，无撤销/回收站机制
7. **弹窗模式不统一**: 有的页面用 `el-dialog`，有的用 `el-drawer`
8. **按钮风格不一致**: 有的用 `text-danger` class，有的用 inline style
9. **供应商详情加载两路数据时无统一loading**: `Promise.all` 失败时详情页显示空白
10. **响应式设计不完整**: 桌面端页面在平板/小屏幕下体验较差
11. **无趋势图表**: 库存报表只有表格数据，无折线图/柱状图等可视化
12. **无打印布局**: 采购单、销售单、调拨单等无打印友好的样式
