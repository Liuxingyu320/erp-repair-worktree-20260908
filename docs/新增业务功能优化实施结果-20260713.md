## 3. 关键业务结果

### 3.1 健康证与团队

- 健康证续证保留历史，审核通过后只保留一条当前证件。
- 员工本人不能通过传入其他 `userId` 查看或修改他人证件。
- 员工档案、团队列表和团队详情统一读取健康证当前投影，不重复维护到期日期。
- 店长只查看当前选择门店的员工；普通主管只查看直属员工。
- 团队详情继续使用精简模型，不跳转或放开完整人事档案。

### 3.2 OE 与仓库补货

```text
员工提交 OE 上报
  ├─ 超额：上报失败 → 展示同款购买参考 → 员工自行购买，无需上报
  └─ 额度内：维修单 + 额度流水 + OA 发件箱同事务写入
                 ↓
             库存幂等创建补货需求
                 ↓
             仓库查看上报内容并创建 OE 调拨
                 ↓
             审批 → 发货 → 门店收货/差异处理 → 补货完成
```

- 预检结果只用于页面提示，不能替代正式提交时的加锁复核。
- 同一维修上报只创建一个补货事实；库存短暂不可用时由发件箱重试。
- 永久失败进入死信，不会静默丢失；管理员可查看错误并受控重投。
- 仓库无库存时可标记缺货，不能直接把补货需求标为完成。

### 3.3 调拨与返仓

- `warehouse`：仓库发往当前门店，即门店要货。
- `store_return`：当前门店发往目标仓库，即门店返仓。
- `cross_store`：沿用现有异店调货范围。
- 返仓审批继续使用现有调拨审批规则，不建设第二套审核流程。
- 只增加实际验收进入目标组织的库存；差异数量留在差异流程中处理。

### 3.4 客户服务卡

- 新建服务卡仍生成可供销售单使用的原客户 ID。
- 普通员工可共同维护本店客户服务资料，但不能访问其他门店客户。
- 客户照片通过业务鉴权接口预览；移动端支持新建、编辑、追加服务记录、查看照片和完整历史。
- 修改使用幂等请求键和乐观锁，变更日志记录操作人、门店、来源端和摘要。
- 归档权限仅授予店长/经理及原有高权限角色，不向普通员工开放物理删除。

## 6. 上线步骤

1. 备份目标数据库，并记录当前服务与前端版本。
2. 在独立测试库先执行 8 份迁移两次，确认第二次执行无结构冲突，再执行脚本末尾的预检/对账查询。

4. 发布共享 API 和后端服务，建议顺序为：`erp-file`、`erp-system`、`erp-inventory`、`erp-oa`、网关。
5. 发布前端 `erp-ui/dist`，清理角色菜单缓存并让使用人员重新登录获取新权限。
6. 使用真实角色 UAT 手册完成两门店、两仓库的 API 与浏览器验收，并通过候选提交绑定的证据校验。
7. 先灰度一个门店和一个仓库，再增加第二个门店和第二个仓库做跨组织隔离验证；确认告警已实际加载、对账零异常并完成回滚演练。
8. 灰度稳定后再执行性能阶段，使用同一脱敏数据快照比较前后 P95；观察健康证提醒、OA 发件箱、补货需求、返仓差异和客户卡变更日志后再全量开放。

## 7. 必须完成的真实角色验收

- 员工：提交健康证；额度内上报 OE；超额只看到同款自购参考且不产生上报。
- 人事：审核、驳回、续证、查看历史和到期待办；确认受控附件不能越权访问。
- 店长：只查看当前门店员工和完整手机号；不能看到工资、银行卡等完整人事信息。
- 仓库：看到 OE 上报内容并创建补货调拨；接收门店返仓；处理短少、残损和拒收差异。
- 门店员工：共同新增和编辑本店客户服务卡、追加服务记录；无法访问另一门店客户。
- 管理员：查看并重投 OE 补货死信；核对成功上报数、发件箱数、库存需求数和关联调拨数。

验收配置、运行命令和证据格式见 [`20260714-new-business-uat-runbook.md`](./releases/20260714-new-business-uat-runbook.md)。源码测试或管理员账号冒烟不能替代真实角色验收。
