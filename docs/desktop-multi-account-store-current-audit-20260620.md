## P1 高优先级问题

### P1-01 店长 `dz` 角色仍包含过多高风险能力

现象：单门店和多门店店长账号可见并具备以下高风险入口：

- `/inventory/stock`：`库存调整`
- `/oa/salary`：`计算本月工资`、`工资参数`、`导出`
- `/oa/labor-contract`：`验 hash`、`发起签约`
- `/inventory/transfer`：`发起要货`、`导出`
- `/oa/attendance`：`上班打卡`、`导出`

数据库权限复核显示 `dz` 拥有 `inv:stock:adjust`、`inv:transfer:deliver`、`inv:transfer:receive`、`inv:deliveryNotice:deliver`、`oa:salary:calculate`、`oa:salary:config`、`oa:laborContract:add`、`oa:laborContract:query` 等。

影响：门店店长账号同时覆盖库存手工调整、工资计算/参数、合同发起、调拨出入库等职责，权限边界过宽。即使部分按钮依赖上下文隐藏，权限码本身仍会放大后端越权风险。

建议：拆分店长、库存调整、仓库发货、门店收货、薪资管理员、HR 合同管理员等角色。普通店长默认保留门店销售、要货、盘点、门店库存查看；高风险接口后端按组织类型和流程节点再次校验。

### P1-02 门店账号暴露工资与劳动合同敏感字段

现象：`qa144822s` 和 `qa144822m` 可进入 `/oa/salary`、`/oa/labor-contract`。

- 工资页表头暴露：基本工资、迟到扣款、早退扣款、缺勤扣款、加班费、其他奖金、其他扣款、实发工资。
- 合同页表头暴露：手机号、岗位、店铺、社保、期限、工资合计、发送时间、签署时间。
- 合同页还显示 `发起签约`。

代码位置：`erp-ui/src/views/oa/salary/index.vue:16` 到 `:44`，`erp-ui/src/views/oa/laborContract/index.vue:27` 到 `:58`。

建议：工资和劳动合同默认归总部 HR/财务权限。门店账号若确实需要，只提供本人/本店只读摘要，隐藏工资合计、扣款明细、合同发起、发送、作废等能力。

### P1-03 门店账号可打开 `/cangku/product` 但页面弹无权限并抛全局错误

现象：`qa144822s`、`qa144822m` 访问 `/cangku/product` 时页面主体能渲染商品列表，但同时出现“当前操作没有权限”，并记录 `pageerror: error`。这在单门店和多门店两个组织下都复现。

影响：用户看到数据但又收到无权限错误，容易误判是系统坏了；全局 `pageerror` 也会影响自动化回归和真实错误定位。

建议：统一商品资料入口和权限。若门店可只读商品资料，应使用门店端路由/菜单名并让查询接口无错误降级；若门店不可访问仓库商品页，则菜单不要下发该路由。前端对 401/无权限分支不要抛全局 `pageerror`。

## P2 中优先级问题

### P2-01 用户管理“配置状态”在运行实例中显示不准

现象：用户列表 API 返回的 `setupStatus`、`roleCount`、`shopScopeCount` 为 `undefined`，导致前端把已有角色/组织授权的用户显示成“未分配角色”。截图中 `admin`、`ry` 等账号都出现该误导。

证据：

- 前端依赖字段：`erp-ui/src/views/system/user/index.vue:344` 到 `:348`
- Mapper 已有查询字段：`erp-modules/erp-system/src/main/resources/mapper/system/SysUserMapper.xml:64` 到 `:71`
- 当前运行 API 实测字段未返回，可能是运行 jar 未重建或字段序列化/映射未生效。

建议：先确认运行包和源码是否一致；再补接口回归，确保列表返回 `roleCount`、`shopScopeCount`、`setupStatus`。配置状态是多账号开通闭环的核心提示，不能误报。

### P2-02 劳动合同页列表加载即提示企业章失败

现象：门店账号进入 `/oa/labor-contract` 时提示“加载企业章失败，请稍后重试或联系管理员”。用户只是看签约列表也会看到章加载失败。

代码位置：`erp-ui/src/views/oa/laborContract/index.vue:640` 到 `:644`。

建议：企业章只在“模板/章配置”或发起签约需要时加载；无权限或未配置时给出明确设置入口/权限说明，不要在列表页打扰普通查看流程。

### P2-03 选择组织仍允许公司/集团作为最终上下文

现象：选择组织页文案已经提示“库存、采购、调拨建议选择门店或仓库”，但 `handleConfirm` 仍接受 `COMPANY`、`GROUP`，`isSelectableDeptType` 也允许公司/集团。

代码位置：`erp-ui/src/views/select-shop/index.vue:302` 到 `:313`，`erp-ui/src/utils/shopContext.js:20` 到 `:25`。

建议：普通业务账号只允许门店/仓库作为进入系统的最终上下文。公司/集团可作为树节点或只读汇总工作台，不应进入会触发库存/采购/调拨重选的上下文。

### P2-04 组织上下文仍出现裸技术 ID

现象：调拨发起要货和库存调整表单仍显示 `组织ID：103`、`ID: 103` 这类技术信息。

代码位置：`erp-ui/src/views/inventory/transfer/index.vue:95` 到 `:98`、`:457` 到 `:458`，`erp-ui/src/views/inventory/stock/index.vue:237` 到 `:240`。

建议：业务主界面展示“组织类型 + 组织名称 + 上级路径”，技术 ID 放在 tooltip 或详情调试区。多店铺操作时，直接展示 ID 不利于一线人员确认。

### P2-05 店长账号导出入口偏多，敏感导出需再收口

现象：店长账号在销售、客户、销售退货、调拨、发货通知、库存、盘点、库存日志、待办、已办、考勤、工资等页面均可见 `导出`。其中工资、考勤、客户、库存日志属于敏感数据。

建议：按数据敏感级别拆分导出权限。导出确认文案应统一展示当前组织、筛选条件、字段范围和敏感字段提示；工资/合同/客户类导出默认不授予门店店长。

## P3 低优先级体验问题

### P3-01 门店账号看到“商品资料”但实际路由仍是 `/cangku/product`

现象：门店账号侧边栏显示“商品资料”，实际地址和面包屑仍进入仓库域 `/cangku/product`。再叠加无权限提示，会让用户分不清是商品资料、仓库商品，还是权限问题。

建议：门店只读商品资料改为独立路由和菜单，例如 `/inventory/product-info`；仓库商品维护保留 `/cangku/product`。

### P3-02 仓库管理员产品维护权限需业务确认

现象：`ck` 仓库账号可见商品 `新增商品`、`编辑`、`删除`、`导入`、`导出`，同时可做 `库存调整` 和调拨 `发货`。

建议：若仓库管理员只负责库存和收发货，商品主数据新增/删除应由商品管理员维护；仓库最多可补充库位、批次、安全库存等仓库属性。

## 建议处理顺序

1. 先收窄 `dz` 店长角色：移除库存调整、工资计算/配置、合同发起/查询、调拨发货/收货、发货通知执行等高风险权限。
2. 修正 `/cangku/product` 对门店账号的菜单/接口/错误处理，消除“页面可见但无权限 + pageerror”。
3. 修复用户管理配置状态字段，保证多账号开通闭环能正确看到“未分配角色 / 未授权店铺仓库 / 已完成”。
4. 收口 HR/薪资/合同页面对门店账号的可见范围。
5. 调整组织选择页，普通业务账号只允许门店/仓库进入业务工作台。
6. 清理裸 ID、导出权限和仓库商品维护权限等体验与权限边界问题。
