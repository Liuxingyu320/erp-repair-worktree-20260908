# ERP-NEW_2 阶段 6：库存盘点只读工作台前端垂直切片实施计划

> 日期：2026-08-03
> 基线：`9f257b20 feat: add purchase order workbench skeleton`
> 状态：实施中；只读盘点列表切片，不代表库存盘点业务闭环迁移完成

## 1. 目标与范围

在 `erp-ui-next/` 内新增 `/inventory/stock-check` 库存盘点工作台，覆盖当前门店或仓库的盘点单筛选、服务端分页、盘点范围、状态、盘点人、截止时间、差异项数和响应式只读展示。

本切片只实现：

- `GET /inventory/stockCheck/list`；
- 权限 `inv:stockCheck:list`；
- 当前门店或仓库的严格数据范围；
- 盘点单号、状态、盘点日期区间筛选；
- 服务端总记录数，以及当前页待审批、需重盘、差异项数量；
- Mock 默认运行时和未注入的真实只读 HTTP Reader；
- 桌面表格、移动卡片、加载、错误、空状态和最近成功筛选语义。

以下能力明确留待后续独立切片：详情、新增、盘点范围选择、盘点人候选与指派、盲盘录入、复盘、提交、统一/旧审批、撤回、快照失效后重盘、取消、删除、导出、库存调整、审批轨迹和真实运行时注入。

## 2. 审计结论与硬边界

### 2.1 接口与权限

- 旧页面：`erp-ui/src/views/inventory/stockCheck/index.vue`；
- 旧 API：`erp-ui/src/api/inventory/stockCheck.js`；
- 后端：`InvStockCheckController`、`InvStockCheckServiceImpl`、`InvStockCheckMapper.xml`；
- 列表为 `GET /inventory/stockCheck/list`，权限为 `inv:stockCheck:list`；
- 详情为 `GET /inventory/stockCheck/{checkId}`，使用 `inv:stockCheck:query/approve/submit` 的 OR 权限，不属于本切片；
- 候选人、指派、实盘录入、提交、审批待办、审批轨迹和所有状态变更均是独立能力，本切片不得展示伪入口或复用列表权限。

### 2.2 组织与传输边界

- 旧前端的有效库存组织只有 `STORE` 与 `WAREHOUSE`；公司上下文不得发送盘点列表请求；
- 服务端通过 `appendShopScope` 计算范围，前端不得接受任意组织 ID 或 `scopeDeptIds/dataScope` 参数；
- 当前旧端点通过 `ShopHeaderUtils` 读取 `Dept-NumId`，真实 Reader 只能显式使用该兼容头，不与默认 `X-ERP-Organization-Id` 双发；
- 请求携带 `expectedOrganizationId`，组织漂移必须在 `fetch` 前失败；解析后的记录必须与当前门店/仓库一致，否则拒绝整页；
- GET 不发送 CSRF，保持同源 Cookie；真实 Reader 不进入默认 Mock 应用启动路径。

### 2.3 查询、状态与字段

- 分页字段为 `pageNum`、`pageSize`；
- 文本筛选为 `checkNo`；
- 日期区间必须使用 `params[beginCheckDate]`、`params[endCheckDate]`；
- 状态闭合集合为 `draft`、`checking`、`pending_approval`、`returned`、`rejected`、`invalidated`、`completed`、`cancelled`；
- 盘点范围闭合集合为 `all`、`category`、`selected`、`sample`；
- ID 必须通过安全 Long 边界，日期必须是真实 `YYYY-MM-DD`，数量和阈值保持十进制字符串；
- `itemCount`、`profitItemCount`、`lossItemCount` 是可相加的项数；`totalDiffQuantity` 可能混合不同单位，不进入新领域模型和页面；
- 列表响应中的审批实例、事件键、失效快照和其他内部字段不进入新领域模型。

## 3. 设计与动效决策

这是高频 ERP/SaaS 工作台，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 使用“服务端总量 → 当前页风险 → 明确筛选 → 数据明细”的层级，避免把当前页指标误报为全局统计；
- 状态徽标以静态文字和颜色双重表达，不依赖动画或 hover；
- 查询、状态/日期筛选、键盘提交、分页和列表替换不播放动画；
- 只允许按钮按压和悬停阴影等 120～180ms 可中断 CSS 过渡；
- 只过渡 `transform`、颜色或 `box-shadow`，不动画布局属性；
- `prefers-reduced-motion: reduce` 下关闭所有非必要过渡；
- 不新增 React、Tailwind、Motion、GSAP、远程字体或外部组件依赖。

1. 先固定安全 Long、真实日期/时间、精确十进制、状态/范围闭集、内部字段丢弃与查询区间。
2. 固定 Mock 的门店/仓库隔离、状态、单号、日期闭区间、分页和当前页风险计数。
3. 固定 HTTP Reader 的精确 URL、`Dept-NumId`、无 CSRF、组织漂移预拒绝和跨组织返回拒绝。
4. 固定页面的门店/仓库加载、公司零请求、桌面/移动等价展示、显式筛选和失败后保留最近成功条件。
5. 固定 `inventory.stock-check.view`、`inv:stockCheck:list`、路由和命令导航的双重门禁。
6. 实现最小领域、Mock、HTTP、页面、路由和导航，使测试转绿。
7. 更新迁移覆盖层为“重设计 / 部分实现”，记录所有延期动作和旧页面缺陷不继承项。
8. 运行完整 `verify`、阶段 1 生成器两次、确定性哈希和隔离审计；全部通过后只做本地提交。

## 6. 验证标准

- 不安全 Long、负数/畸形十进制、无效日期时间、未知状态/范围、反向日期区间全部失败关闭；
- 新模型不包含 `totalDiffQuantity`、成本、审批实例、事件键或失效明细快照；
- HTTP Reader 只发送允许参数和一个显式旧组织头；组织漂移与跨组织记录都失败；
- 公司上下文不调用 Gateway；门店和仓库均可读取各自隔离 Mock；
- 页面明确区分服务端总记录与当前页指标，差异使用“项数”而非跨单位数量；
- 筛选成功后才更新已应用条件，失败时保留最近成功标签并可重试最后请求；
- 桌面表格和移动卡片核心信息等价，无动作列和 hover-only 信息；
- 功能开关和权限同时满足才可见且可访问；
- 完整前端验证、迁移生成器、确定性哈希和隔离扫描通过；
- 旧 `erp-ui/`、受保护原项目、Docker、服务、数据库、依赖和真实配置保持零改动。

## 7. 停止线

发现以下任一情况立即停止：

- 需要读取或修改受保护原项目、连接数据库、启动服务或安装依赖；
- 需要修改旧 `erp-ui/`、注入真实 Reader 或执行盘点写动作；
- 组织范围、状态或日期语义无法从当前工作树证据确定；
- 需要启用详情、新增、指派、录入、提交、审批、撤回、重盘、取消、删除或导出而没有独立计划；
- 不能证明全部文件、运行目录和测试只位于 ERP-NEW_2 隔离工作树。
