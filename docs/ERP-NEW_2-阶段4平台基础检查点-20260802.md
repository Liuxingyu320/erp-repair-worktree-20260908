# ERP-NEW_2 阶段 4 平台基础检查点

> 日期：2026-08-02
>
> 分支：`codex/erp-new-2-rebuild`
>
> 结论：平台基础切片通过；阶段 4 尚未整体完成

## 1. 本检查点范围

本检查点只建立不依赖真实后端的安全平台边界：

- 统一成功、分页、问题详情、字段错误和追踪编号类型；
- 对遗留 `AjaxResult`、`TableDataInfo` 返回结构做运行时校验和显式适配；
- 建立同源、Cookie、CSRF、操作组织和请求编号约束的 HTTP 客户端；
- 建立 Decimal、业务日期、带时区时刻和枚举未知值处理；
- 建立 Mock 会话、多组织上下文、跨标签页组织/失效同步；
- 建立功能开关、权限与路由的默认拒绝门禁；
- 建立正式 OpenAPI 输入清单、哈希、路径、服务器和 `operationId` 门禁；
- 在桌面浏览器验证组织切换，在移动浏览器回归待办和差异收货原型。

本检查点没有接入真实身份服务、业务 API、文件服务、消息服务或用户偏好服务。

## 2. 安全与隔离结论

- 运行模式仍为 ERP-NEW_2 Mock；未连接 MySQL、Redis、Nacos 或业务后端。
- 未启动 Docker、后端服务或中间件。
- 浏览器回归只绑定重新审计后空闲的 `127.0.0.1:24620`，测试结束后已关闭，端口恢复空闲。
- HTTP 客户端拒绝跨源 URL；状态变更默认要求内存中的 CSRF 令牌和已授权操作组织。
- 跨标签页消息只使用 `erp-new-2:session:v1`，只传播组织标识或会话失效事件，不传播 Cookie、CSRF 或完整会话快照。
- 未使用、修改或连接受保护原项目及其容器、数据、配置、密码或密钥。

## 3. OpenAPI 结论

版本库当前没有满足证据门槛的正式 OpenAPI，因此：

- `npm run test:openapi-gate` 的合法与负向 fixture 全部通过；
- `npm run openapi:check` 因正式 `manifest.json` 不存在而返回失败；
- 此失败是预期的 fail-closed 结果，证明前端不会根据静态端点盘点猜测契约或生成伪类型；
- 只有后续从 ERP-NEW_2 独立流程得到带提交 SHA、文件 SHA-256、同源路径和唯一 `operationId` 的契约后，才能运行类型生成。

## 5. 尚未完成

阶段 4 只有在以下能力以真实隔离服务和真实浏览器负向场景验收后才能标记完成：

1. HttpOnly Cookie 登录、刷新、401/403、会话超时和 CSRF 真实联调；
2. 后端数据范围和组织权限的服务端强制校验；
3. 正式 OpenAPI 契约冻结、生成类型和逐模块适配；
4. 文件上传、下载、预览、取消、重试和错误恢复；
5. 消息、待办深链、统一错误页和追踪查询；
6. 标准表格、筛选、导出、用户偏好和弱网恢复；
7. 完整角色切换、越权、过期、冲突、限流和服务错误浏览器测试。

在这些条件满足前，页面只能继续使用可识别的 Mock 网关，不得把 Mock 结果描述为真实业务提交。
