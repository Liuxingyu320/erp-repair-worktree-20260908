# ERP-NEW_2 阶段 13P1：差异裁决动作执行硬关闭入口骨架实施计划

> 日期：2026-08-03
>
> 分支：`codex/erp-new-2-rebuild`
>
> 基线：`bc2db52a feat: define adjudication execution lifecycle`

## 1. 目标

在阶段 13O 的纯执行生命周期之后，先建立一个无法误触发物理处置的服务端入口骨架。该骨架冻结浏览器之外的内部命令字段、独立执行权限和双条件启用语义，但不读取案件、不获取数据库锁、不写执行事件，也不调用补发、退回、报损、责任或运输损耗效果。

## 2. 本阶段交付

1. 新增内部执行命令，字段只包含请求、案件、裁决、目标动作、版本、命令和异步效果引用，不接受操作者、权限、效果类型、数量、金额或责任方。
2. 新增双条件 Gate，仓库默认值全部为 `false`：
   - `erp.inventory.transfer-discrepancy-execution-v2.write-enabled`
   - `erp.inventory.transfer-discrepancy-execution-v2.effect-boundary-ready`
3. 新增无 Mapper、无 Gateway、无事务注解的服务骨架：先检查 Gate；即使两个条件被外部误设为 `true`，仍固定抛出“持久化与物理效果边界尚未实现”。
4. 增加离线测试，证明默认关闭、双条件顺序、最终硬停止、无数据库依赖和无事务所有权。

## 3. 安全不变量

- 13O 的 `inv:transfer:discrepancy:execute` 仍是唯一执行权限，但本阶段不创建角色、菜单或权限种子。
- 客户端不能声明 `effectKind`；未来只能由 13O 策略根据权威差异类型与裁决动作推导。
- 客户端不能声明操作者；未来只能从服务端登录快照读取。
- 客户端不能声明数量、金额、责任方或聚合状态；未来只能从锁定后的裁决计划读取。
- 入口不得注入 Mapper、数据库模板、消息生产者、HTTP 客户端或任何真实效果执行器。
- 入口不得添加 Controller、RPC、消息消费者、定时任务、前端 Writer、路由或 Gateway 接线。

## 4. 明确不做

- 不实现案件/裁决/动作锁、幂等重放、执行事件写入或条件状态推进。
- 不实现补发调拨、退回调拨、隔离库存核销、责任台账或运输损耗台账。
- 不执行阶段 13O SQL，不连接 MySQL、Redis、Nacos 或任何数据库。
- 不启动 Docker、容器、后端或前端服务，不安装或升级依赖。
- 不修改 `.env`、Compose、Nacos、Redis、数据库配置、端口、上传、日志或运行目录。
- 不删除旧前端，不访问受保护原项目，不合并、不推送。

## 5. 后续检查点

13P2 只有在先冻结每种效果的事务所有者、固定锁顺序、回滚语义、幂等重放和精确 DML 白名单后，才可增加 Mapper 与本地事务。任何物理库存、物流或财务效果必须与动作状态和追加事件同事务完成；不能把动作先标记为完成，再异步补写业务事实。
