## 1. 本检查点结果

阶段 13P10 为差异退回的专属隔离预留建立了独立生命周期：

- `ACTIVE -> PARTIAL -> CONSUMED` 支持合法 V2 退回发货分批消费；
- `ACTIVE -> RELEASED` 和 `PARTIAL -> CLOSED` 支持将全部未消费余量释放回隔离库存；
- 消费同时扣减汇总库存和精确批次库位余额的当前量、冻结量与来源成本；
- 释放保持当前量和成本不变，将冻结量完整转回隔离量；
- 批次和序列号物料分别执行精确守恒校验，序列号按收货单件稳定排序并执行版本化状态迁移；
- 消费、释放分别追加不可变事件，主预留只允许版本化累计数量和状态迁移；
- P7 异步子调拨完成证据改为实时读取实际普通/隔离预留，只有全量消费且从未释放才能完成。

## 2. 事务与持久化边界

新增 `InvTransferReceiptDiscrepancyReturnReservationLifecycleService`，消费和释放均要求 `Propagation.MANDATORY`，只能加入未来专属外层命令事务。锁序固定为：预留及归属事实、汇总库存、精确余额、序列号绑定及物理序列号。

纯策略在首个 DML 前验证请求身份、裁决动作、子调拨、审批轮次、工作流关系、成本锚点、数量守恒、维度、版本和序列号事实。任一条件更新影响行数不为一、事件唯一冲突或回读漂移均抛错，由外层事务整体回滚，不执行补偿 SQL。

加法迁移仅新增：

- `inv_transfer_quarantine_reservation_consumption`；
- `inv_transfer_quarantine_reservation_release`；
- P9 序列号绑定的生命周期状态、事件归属、发货归属、版本和审计列。

迁移文件只位于仓库顶层 `sql/`，未进入自动初始化目录，也未执行。

## 3. 完成证据与接线边界

异步裁决子调拨完成现在必须同时证明：

```text
child.status = received
reservation.status = CONSUMED
reservation.consumed_quantity = reservation.reserved_quantity = action_quantity
reservation.released_quantity = 0
存在 V2_DETAIL 发货与收货
不存在旧发货和开放差异
```

创建工作流关系时仍要求实际预留为 `ACTIVE` 且消费、释放均为零。普通补发读取普通预留台账，差异退回读取隔离预留台账，不能用关系表中的历史快照替代实时事实。

本阶段保持以下入口关闭：

- 生命周期 Service 在生产主代码中零调用点；
- 未修改普通发货创建、普通预留、调拨命令、Controller、审批回调或裁决执行事务；
- 未把 P9 退回效果所有者接入 P6 执行链；
- 未开放退回发货消费、审批/取消释放或裁决完成入口。

## 6. 后续风险与停止线

1. 新 DDL、联合锁、生成键和条件 DML 仍需未来在 ERP-NEW_2 专属 MySQL 5.7 中验证；
2. 退回发货必须由专属规划/创建适配器在同一事务中先形成合法 `V2_DETAIL` 发货，再调用消费边界并同步子调拨交付量；
3. 审批拒绝、撤回、取消或终止必须由专属适配器调用释放边界，不能复用普通预留释放逻辑；
4. 释放后重新裁决必须创建新的显式动作，不能绕过终态唯一约束重新激活旧预留；
5. 在专属退回发货、释放和完成适配器均闭合并通过真实隔离数据库验收前，裁决执行链继续硬关闭；
6. 用户当前要求不使用 Docker，因此不启动或配置任何容器化运行环境。
