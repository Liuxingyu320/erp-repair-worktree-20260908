## 检查点 7：真实浏览器 Provider 中断与恢复

目标：证明部分 Provider 故障时，已知数据不误显示为 0，不串用不同优先级缓存，恢复后自动回到实时数据。

执行矩阵：

1. 使用全新浏览器会话，只预热 `priority=urgent` 的精确缓存。
2. 运行 `stop inventory`：
   - inventory 显示 stale/暂不可用状态；
   - 已预热 urgent 数据可回退但明确标识陈旧；
   - 切到未预热 `important` 必须是 unknown，不能复用 urgent 数；
   - OA 和 system 继续实时工作，顶部总数不把 inventory 当作 0。
3. 运行 `restart inventory`，等待端口、actuator、业务探针恢复，页面状态恢复 live。
4. 对 OA、system 重复同一流程；system 停止时使用已登录页面和现有令牌，不把认证/用户资料请求故障误判为 Provider 缓存缺陷。
5. 每个 Provider 同时验证一次晚返回旧请求不会覆盖新优先级结果。
6. 验收结束执行无参数 `stop`，确认六个端口全部释放且未停止其他工作树进程。

页面尺寸：

- 桌面：1440 × 900；
- 移动：390 × 844；
- 极窄：320 × 568；
- 均为真实网页响应式视口，不使用设备模拟器。

证据要求：

- 记录 `navigator.userAgent`/可获得的浏览器引擎信息；如果无法获得完整版本，明确写“工具未提供”，不虚构。
- 每个 Provider 保存停止前、stale/unknown、恢复后三组脱敏截图。
- 记录 console error 数；预期业务中断可有受控网络错误，但不得有未处理异常、无限重试或敏感信息泄露。
- 记录请求时间、Provider、组织范围、优先级、live/stale/unknown 状态，不保存认证头和 Cookie。

完成门：三个 Provider 均可单独中断和恢复；其他 Provider 不受影响；缓存只按精确组织/优先级键回退；恢复后无须重新登录即可回到 live。
