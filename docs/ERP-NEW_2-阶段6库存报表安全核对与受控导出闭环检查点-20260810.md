## 1. 本检查点结论

本阶段在 ERP-NEW_2 隔离工作树内，将 `/inventory/report` 从受限只读切片扩展为可安全读取经营摘要、发现当前组织商品、核对业务来源、精确进入库存记录并受控导出预警的响应式工作台。

本检查点证明：

- 普通报表角色也能读取完整非成本经营摘要，成本字段由服务端按 `inv:cost:view` 脱敏；
- 汇总、预警、商品候选和导出响应均强制 `no-store`，客户端缺失指令即失败关闭；
- 商品候选仅来自当前精确门店或仓库的库存事实，不依赖商品主数据权限；
- 预警行按精确 `stockId` 进入库存详情，汇总区域只呈现用户有权访问的库存、采购和销售核对入口；
- `inv:report:export` 独立控制只含安全字段的预警 Excel，默认不自动授予任意角色；
- 导出只使用最近一次成功查询的商品和预警状态，不读取尚未提交的草稿筛选；
- 默认 Mock 与真实 HTTP Gateway 共享同一领域契约，当前仍未连接任何服务或数据库。

## 2. 后端安全闭环

### 2.1 缓存与成本

`InvReportController` 的 `summary`、`stock-warning`、`product-options` 和 `stock-warning/export` 统一设置：

- `Cache-Control: no-store, max-age=0`；
- `Pragma: no-cache`。

`summary` 在返回前执行服务端字段级授权：管理员或持有 `inv:cost:view` 的用户保留库存成本、采购净额、销售成本和毛利；其他报表角色收到这些字段的 `null` 值。前端隐藏不再承担成本安全边界。

### 2.2 报表专属商品候选

- `GET /inventory/report/product-options` 继续使用 `inv:report:list`，不借用 `inv:product:list/query`；
- Service 要求精确库存组织、规范化 100 字符内关键词，并限制 1～50 条；
- Mapper 使用参数绑定，只返回商品 ID、编码、名称、规格和单位；
- 查询同时约束当前 `shopDeptId` 与 `warehouseId`，不会返回其他组织或成本、供应商、图片和内部版本。

### 2.3 安全预警导出

- `POST /inventory/report/stock-warning/export` 使用独立 `inv:report:export` 和导出审计；
- `InvReportWarningExportRow` 是专属白名单 DTO，不直接导出宽泛 `InvStock`；
- 字段只覆盖商品、组织、批次/效期/序列号/库位、当前/可用量、安全下限、缺口、状态和最近变动；
- 权限 SQL 幂等新增报表子按钮，但不向任何现有角色自动授权；本阶段只创建 SQL 文件，没有执行数据库迁移。

## 3. 新前端闭环

### 3.1 领域与 HTTP 契约

- Long 标识保持字符串并限制在服务端 Long 范围；日期、十进制、关键词和请求 ID 均有显式格式与长度门禁；
- 所有报表读取都验证 `no-store`，预警响应还拒绝任一跨组织记录；
- 无成本权限时仍请求 summary，但只解析安全字段并把成本模型设为 `null`；
- 商品候选最多读取当前组织前 20 条，规范化关键词后再发送；重复商品、非法标识和缓存响应均失败关闭；
- 导出使用 POST、CSRF、当前组织头和请求 ID，不自动重试；只接受合法 Excel MIME、非空且不超过 25 MiB 的响应。

### 3.2 页面与交互

- 组织切换时中止报表和商品候选在途请求，清除旧组织数据；公司层级不发送任何报表请求；
- 商品搜索只在明确按钮或 Enter 后执行，选择框展示编码、名称、规格和单位，实际查询保存服务端商品 ID；
- 商品候选失败独立提示并保留已选商品和最近成功报表；报表查询失败也保留最近成功条件和数据；
- 有 `inv:stock:query` 时，桌面表格和移动卡片都可按精确库存 ID 打开详情；
- 库存、采购和销售核对入口分别受 `inv:stock:list`、`inv:purchase:list` 与 `inv:sales:list` 控制，并明确不暗中传递筛选；
- 仅 `inv:report:export` 显示导出按钮；确认弹窗展示当前组织、最近成功条件和服务端预警记录数，成功后显示实际文件名并恢复焦点。

### 3.3 设计与动效约束

页面只吸收用户指定的 21st.dev、React Bits、UI Prompt Library、Magic UI、Motion Primitives、Uiverse 与 MotionSites 的后台层级和状态连续性思路，没有复制第三方代码、素材或品牌。
