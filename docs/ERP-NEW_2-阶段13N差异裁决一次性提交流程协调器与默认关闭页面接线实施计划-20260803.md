# ERP-NEW_2 阶段 13N：差异裁决一次性提交流程协调器与默认关闭页面接线实施计划

## 1. 目标

在阶段 13M 已具备真实 HTTP Reader/Writer 之后，建立不持久化 token 的前端提交协调器，并让差异裁决页面可以通过显式依赖注入使用该协调器；默认路由、Gateway、bootstrap 和 Mock 继续不注入真实 Writer。

协调器固定编排：

1. 重载服务端权威规划；
2. 将二次确认草案与当前事项、版本、类型和数量重新绑定；
3. 为当前事项和当前组织签发一次性 basis；
4. 用唯一请求 ID 立即组装严格提交信封；
5. 提交裁决计划，网络不确定时只用相同 token/requestId 重放一次；
6. 结束独立写入函数栈，使局部 basis 和信封引用离开作用域；
7. 重载并核对服务端裁决计划。

本阶段不执行物理补发、退回、报损、核销、库存或财务动作。

## 2. 协调器边界

新增 `TransferDiscrepancyAdjudicationSubmissionCoordinator`：

- 依赖阶段 13M Reader/Writer、当前组织 getter、请求 ID factory 和时钟；
- 公共 `submit(draft, signal?)` 返回不含 token 的创建结果、请求 ID、验证状态和可选最新规划；
- 所有阶段回调只暴露固定枚举，不暴露 basis、信封、正文或 token；
- basis 和提交信封只存在于独立写入函数的局部变量；写响应返回后该函数栈结束，再进入投影验证；
- 类实例不得保存 token、basis、信封或草案正文；
- 当前组织缺失、变化、规划漂移或 basis 过期全部失败关闭。

并发和重试：

- 同一协调器只允许一个 in-flight 提交；重复点击在 Reader/Writer 调用前抛出稳定 `ADJUDICATION_SUBMISSION_BUSY` 错误；
- basis 签发不自动重试，避免因响应丢失无界签发新 token；
- 只有 `ErpApiError.retryable=true` 且请求未取消时，裁决提交才使用完全相同信封重放一次；
- 验证重载失败或计划锚点不一致时返回 `reload-required`，不重新提交命令；
- AbortSignal 在每个网络阶段透传，已取消请求不自动重试。

## 3. 页面默认关闭接线

草案面板新增：

- `submissionEnabled` 和 `submitting` 只读属性；
- 二次确认后发出 `confirmed-draft` 事件；
- 未启用时继续完成原有本地 Mock 演练；
- 启用时不在面板保留“完成草案”副本，由父页面协调提交；
- 提交期间禁用审阅、编辑和确认，防止双击或草案漂移。

页面新增可选 `submissionCoordinator` prop：

- 路由仍只传 `caseId`，因此默认值为空且真实提交不可达；
- 只有测试或未来显式运行时组合传入协调器时，才处理 `confirmed-draft`；
- 提交成功且服务端规划已核验时，用最新只读规划替换页面状态；
- `reload-required` 或结果未知错误会锁定草案操作，只保留“重新读取计划状态”，避免用新请求 ID 人工重发；
- 错误不清空草案字段，组织/路由变化或组件卸载会取消当前提交。

页面和面板不得直接 import HTTP Writer factory，不得保存 basis token。

## 4. 测试

协调器：

- 精确顺序、服务端规划再确认、请求 ID、当前组织、同一信封提交和最终计划锚定；
- 双击在任何第二次网络调用前拒绝；
- retryable 提交只重放一次且 token/requestId 完全相同；
- 非 retryable、取消和 basis 签发失败不重试；
- 成功后重载失败或计划锚点不一致返回 `reload-required`；
- 结果、阶段回调和错误均不含 token；
- 源码 Gate 拒绝 Storage、URL、Pinia 和实例 token 字段。

页面：

- 默认无协调器时维持本地 Mock 草案且不调用 Writer；
- 显式注入时只在二次确认后调用一次协调器；
- 提交中禁用重复确认；
- 验证成功切换到服务端只读计划；
- 失败和 `reload-required` 显示可理解状态并锁定再次提交；
- 路由/组件清理取消进行中的提交。

运行 `npm --prefix erp-ui-next run verify`。

## 5. 停止线

- 不把真实 Writer 加入 `TransferGateway`、providers、Mock 或 bootstrap；
- 不启用功能码、菜单、默认路由或真实会话；
- 不在 localStorage、sessionStorage、IndexedDB、Pinia、URL、日志、遥测或异常正文保存 token；
- 不启动 Docker、服务、MySQL、Redis 或 Nacos，不连接数据库或执行迁移；
- 不新增依赖、锁文件、`.env`、端口或真实秘密；
- 不删除旧前端，不合并，不推送，不访问其他 worktree。

只有真实隔离会话、服务端 CSRF/Origin、防越权组织边界和独立数据库迁移均验证后，才可以把该协调器注入默认运行时。
