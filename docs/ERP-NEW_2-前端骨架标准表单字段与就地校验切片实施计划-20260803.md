## 1. 问题与目标

正式方案要求先建立统一表单基础组件，并明确规定“错误直接定位字段和步骤，不能只在页面顶部显示失败”。当前新建调拨已经按三步组织，但基本信息缺失、路线相同或商品数量无效时只显示一个页顶错误，具体控件没有 `aria-invalid`、错误关联或自动聚焦。

本切片建立 `ErpFormField` 设计系统组件，将标签、必填提示、说明、错误、控件标识和 `aria-describedby` 契约统一起来；随后让新建调拨的四个基本信息字段与每个商品数量字段具备就地错误、首错聚焦和输入后即时清除。页面继续持有业务校验规则和 Mock 提交流程。

## 2. 已确定契约

- `ErpFormField` 接收稳定 `controlId`、标签、可选说明、可选错误、必填和紧凑/宽字段布局；
- 默认作用域插槽提供 `controlId`、`describedBy` 和 `invalid`，由真实原生控件绑定 `id`、`aria-describedby` 与 `aria-invalid`；
- 标签使用原生 `for` 关联；说明和错误拥有稳定 ID，错误使用 `role="alert"`；
- 视觉隐藏标签仍保留可访问名称，适用于表格中的数量输入；
- 基本信息校验为每个缺失字段给出专属错误；调出方与调入方相同时错误定位调入方；
- 商品数量校验将错误定位到具体商品行，不制造通用占位错误；
- 校验失败保持当前步骤，并在 DOM 更新后聚焦第一个无效控件；用户修改对应字段后即时移除该字段错误与页顶汇总；
- 页面仍保留简短页顶汇总，作为步骤级错误提示，但不再是唯一错误来源；
- 输入、校验、错误出现/消失与焦点移动均不使用 animation、transition、keyframes、抖动或滚动动画；
- 不复制外部组件库或提示词网站代码，不新增第三方依赖。

## 4. 实施顺序

1. 先用组件测试锁定标签、必填文案、说明/错误关联、作用域插槽和视觉隐藏标签；
2. 实现无领域依赖、无动效的 `ErpFormField`；
3. 为新建调拨建立基本字段错误与商品行错误状态；
4. 将四个基本字段和数量控件接入组件，保留现有三步流程和 Mock Gateway；
5. 增加基本信息缺失与商品数量超限的首错聚焦、ARIA 和恢复测试；
6. 执行定向测试、完整 `npm run verify`、源码隔离扫描与 Git 隔离复核。

## 5. 验证门禁

- 组件测试证明 label/control、说明、错误和作用域插槽 ARIA 值一致；
- 基本信息缺失时仍停留步骤 1，对应字段标记无效并获得焦点；
- 修改字段后对应错误和汇总即时消失；
- 商品数量超限时仍停留步骤 2，具体商品数量字段标记无效并获得焦点；
- 原有三步 Mock 演练成功测试继续通过；
- `npm run verify` 必须通过 Prettier、ESLint、Vue TypeScript strict、OpenAPI 门禁、Vitest 与 Vite 构建；
- `git diff --check` 与源码隔离测试必须通过；
- 静态扫描必须证明无新依赖、无旧前端引用、无真实网络请求和无运行配置变化。

## 6. 停止线

- 不启动 Vite/Playwright web server、Docker、MySQL、Redis、Nacos 或后端服务；
- 不执行 `npm install`、`npm ci` 或任何联网依赖命令；
- 不修改真实 Writer、`.env.local`、端口、凭据或运行数据；
- 不访问受保护原项目，不删除旧前端，不合并、不推送。
