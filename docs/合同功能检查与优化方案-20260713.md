# 合同功能检查与优化方案

日期：2026-07-13

## 检查范围

- HR 签约任务中心：指标、筛选、列表、详情、确认和异常处理。
- 签约包与签约方案：新建、续签场景、文件生成、预览和历史数据兼容。
- 员工移动端签署：文件切换、阅读确认、场景和状态展示。
- 待办和权限边界：HR 待办、员工本人待办、技术证据只读权限。
- 后端状态机、MyBatis 查询、单元测试和前端生产构建。

## 发现的问题与处理

| 优先级 | 问题 | 用户影响 | 处理结果 |
| --- | --- | --- | --- |
| P0 | 本地运行库未执行 2026-07-13 的调岗/离职合同迁移，`sys_hr_lifecycle_action.actual_confirm_time` 等字段缺失 | 合同事件补偿扫描持续 SQL 报错；后续调岗、离职动作也可能因字段或签约包快照列缺失而失败 | 先完整备份本地库，再执行仓库内两份幂等迁移；补齐生命周期动作、任务、签约包字段和权限同步过程，运行态健康检查恢复为 `UP` |
| P0 | 续签场景同时使用 `renew`、`RENEWAL`、`renewal` | 续签方案可能匹配不到，筛选和显示不一致 | 新增前后端共享规范，新数据统一存储，查询仍兼容历史 `renew` 数据 |
| P1 | “即将逾期”指标卡可点击但不会筛选 | HR 以为已筛选，实际看到全部数据 | 增加三天内到期的精确后端筛选，并显示选中态 |
| P1 | “本月已完成”实际列出所有已签任务 | 指标数和列表对不上 | 增加当月完成时间边界筛选，与指标统计口径一致 |
| P1 | 任务仅显示数字员工 ID | HR 定位员工慢，容易选错 | 列表显示员工姓名+账号，支持按姓名或数字账号搜索 |
| P1 | 受保护文件下载完成后才打开预览窗口 | 容易被浏览器当成异步弹窗拦截 | 点击时先保留窗口，文件到达后再导航；失败时自动关闭 |
| P1 | 移动端阅读确认使用旧文档 hash | 文档刷新后可能被后端拒绝，或确认语义不准确 | 重新校验后提交最新文档 hash |
| P1 | 移动端快速切换文件时存在异步竞态 | 旧文件返回较晚时会覆盖当前预览 | 增加请求序列和当前文档校验，过期结果立即释放 |
| P1 | 续签方案混入“入职日期、试用期”字段，手工续签包反而隐藏合同起止日期 | HR 容易填错资料，续签草稿可能缺少新合同期限或夹带旧试用期资料 | 按场景统一控制字段：续签保留合同期限和薪资，隐藏入职与试用期；保存前清理所有隐藏字段 |
| P1 | 历史 Word 合同被直接放进 `iframe`，手机端只出现空白预览框 | 员工会误以为合同文件损坏或不存在 | PDF 继续内嵌预览；Word 文件改成明确说明和“下载 Word 合同”入口，不再展示空白框 |
| P2 | 移动端“已撤回”分组也包含失败状态 | 用户容易误判业务结果 | 改为“异常/撤回” |
| P2 | HR 待办显示英文场景码，失败待办文案过窄 | 理解成本高，非发送阶段失败也被称为发送失败 | 待办改为“姓名（账号）·中文场景”，失败统一为“合同任务异常” |
| P2 | 历史合同弹窗标题为“验 hash”，签署记录空态没有说明从哪里选择签约包 | 非技术人员看不懂术语，也不知道下一步 | 改为“合同文件验真 / SHA-256 哈希”，空态明确提示回到签约包列表点击“详情” |
| P2 | 前端测试门禁被两个重复 SQL 副本误伤 | 与业务无关的重复文件导致整体测试失败 | 删除与正式文件完全相同的忽略副本 |

## 已实施的便利性改进

1. 指标卡现在是可反馈、可取消的真实筛选器，并增加键盘焦点样式和 `aria-pressed` 状态。
2. HR 可直接输入员工姓名或数字账号，列表优先展示人的姓名。
3. 桌面端方案、签约包、任务详情、确认弹窗和移动端使用同一套场景字典。
4. 续签现在可在方案和手工签约包中正常选择，后端统一存储且兼容历史别名。
5. 文件预览、移动端文件切换和阅读确认都增加了对应的失败/并发保护。
6. 新建方案和手工签约包会按场景只展示相关字段，隐藏字段在切换场景和提交前都会清理，避免脏数据被带入合同快照。
7. 历史 Word 合同会说明浏览器无法内嵌预览并给出明确下载动作；PDF 和完成证明仍保留在线预览能力。
8. 验真和签署记录空态已改成业务文案，降低首次使用成本。
9. 本地数据库已与当前合同代码的调岗、离职迁移对齐，避免“页面可用但后台事件链路因缺列失效”。
