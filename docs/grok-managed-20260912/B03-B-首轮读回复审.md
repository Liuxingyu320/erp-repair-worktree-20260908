# B03-B 首轮读回复审

Codex 已读首轮 save/submit/merge 与表单入口，以下仍需核对并补测试。沿用原四项允许范围，不改全局组件/后端。

1. `mergeSavedStockCheck(remoteData, snapshot)` 目前 remoteData 缺失时以 emptyForm 替换，可能把单据ID/全部数量清空并误报保存成功。确认响应有正确 checkId、有效明细数组且属于提交单据后才合并；异常响应保留输入并提示无法确认，不允许继续 submit。返回明细缺少某提交行时不能静默抹掉该行的新输入，应保留并提示核对，不凭猜测补成功。验证空data、错单ID、缺行。
2. `beginFormSession()` 只清busy但不使旧表单不可提交。已有A表单时触发openInput(B)，B读取pending期间仍显示A；若此时保存A，B读取与A保存归同一新session，可能响应交错覆盖B。加载新目标需绑定目标ID/加载态且禁止旧表单参与写入，应用保存结果还需核对冻结ID。测试 B加载未回时A保存不可发，B接纳后旧A响应不回写。
3. 当前只有beforeDestroy，没有keep-alive失效边界。核对路由离开/重入时，旧读写不应在重新激活后被接纳，也不能启动新的保存/提交；恢复可继续使用，并保留未保存编辑或明确未确认状态。不要把deactivated永远标destroyed。
4. 统一取消关闭入口应立即失效会话，不能只依赖异步watch(formOpen)；校验或确认延迟期间换单/关闭须不发请求。确认期间重复submitActualQty应只存在一个有效确认操作，旧确认不得在新保存完成后再把旧快照写回。补可控校验和confirm promise的乱序测试。

已正确的按detailId合并、初盘使复盘失效、必复盘保护、盲盘、保存期间继续输入、正式提交阶段锁定需保留。以上先真实验证再修，不降低断言或把错误响应当成功。
