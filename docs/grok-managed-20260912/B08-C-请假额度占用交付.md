# B08-C 请假申请额度与审批联动交付

本段在 A 额度规则/账户与 B 主管已日结加班转休基础上，连接员工草稿、提交占用、审批消费/释放，以及发起结果未知后的原键恢复。授权32路径（原31加已批准Controller预览接线），根项目经理另行负责 D 前端。没有部署、线上写库或自动分配角色权限；ATT-U1/D22 全项需 C/D 合并验收。

## 最终行为与边界

申请天数由用户明确填写，保存 requestedDays，起止范围仍独立保留 totalMinutes。DAY 要求整天，HALF_DAY 要求半天步长；MINUTE 保留已有分钟流程，MIXED 可填天数。非额度按天类型的每日分钟必须由 HR 配置，额度类型沿唯一匹配规则；没有默认法规天数或默认每日8小时。

政策快照冻结假种版本、单位、规则/映射版本、公司和每日换算。首次或换型由服务自动匹配；同类型旧草稿即使省略期望快照，也会与原保存快照比较。政策漂移需通过本人/原门店/原rowVersion绑定的policy-preview读取完整拟保存内容对应的新政策；明确确认后仍走原save，省略快照继续保留旧快照防绕过。预览不保存、不重算、不发放；预览后政策再变化仍拒绝。不能让旧天数悄悄配新换算。ANNUAL/COMPENSATORY 强制需要余额；九标准假种以及其他额度类型强制 HR 审批。新标准类型仅作为禁用占位，不擅改已有类型。

草稿不占用。提交时自动沿 A 已配置规则准备额度，然后按到期日和桶ID从有效来源分配；申请、额度分配、流水及发起出站记录同事务。余额不足、附件不足、出站写入失败均整体回滚。重复创建请求键、同一提交轮次及审批事件不会二次占用或消费。

待审同意将原占用转为消费；退回、驳回、撤回以及待审终止释放原占用。已批准后的终止才反向冲回原消费，进入工资或抵扣/转休后的业务期间不自动改写。释放/冲回始终回原来源、原年份；已到期金额转为过期记录，不创造新可用额度。历史已提交且没有新额度快照的申请不追溯补扣；历史额度型/按天草稿必须先明确保存。

发起未知结果保留占用并显示 REVIEW。超时、HTTP 错误、缺ID/错轮次成功回执，以及远端成功而本地关联失败均使用同一请求键重试。只有第一次认领、远端从未尝试且本地快照无效时，才能证明没有发起并原子释放、退回可编辑状态。远端成功已固化时只重试本地关联。没有额外远端查询接口，未将“暂时查不到”当作未发起证明。

## 事务与锁

公共身份和门店范围仍由原业务入口校验；内部额度桥要求实际 READ_COMMITTED 事务。申请锁后，按门店/月排序锁金融期间，再按日结ID锁来源和目标，随后锁员工/规则、账户/桶、分配/事件。沿与实际日结失效一致的已发布排班时间相交选择业务日，LEFT JOIN覆盖未有日结，预先锁前一日期可能所在月；工资核对实际业务月，月锁等待后重读目标日集合，账户锁后核对加班来源集合，来源变化要求重试。回调先核对实例、轮次、事件和状态，额度变动后的业务 CAS=0 抛错回滚，不提交“仅额度成功”。

A 自动规则计算在当前已授权员工的同一事务调用，不伪造管理员或登录身份。Callback/Outbox 由原内部入口执行，不新增 HTTP 越权写链。B 月锁、来源版本及已确认调岗审计继续生效。

新额度/政策 Long 对 Jackson2 与 Spring Boot4 默认 Jackson3 都按十进制字符串输出，并通过默认 MockMvc 的大于 JS 安全整数样本核对；没有以单独 ObjectMapper 代替真实 MVC 合同。

## 迁移与回退

先备份并执行原考勤/草稿幂等迁移、A 余额与 B 转休迁移，再执行 sql/erp_oa_attendance_leave_quota_20260912.sql，最后发布对应服务。迁移新增申请独立天数/快照/额度状态、假种每日换算和两张额度分配/事件表，可重复执行；不回填旧申请、不改旧类型、不向已有角色授予权限。A 自动发放 Job 仍沿专用默认关闭开关及原迁移启用顺序。

已有新轮次产生分配后不能仅回退旧 jar 或删表，否则旧服务无法维护占用。回退前先停止新提交并核对所有 RESERVED/REVIEW/CONSUMED 轮次，通过原审批/恢复链收束或完成数据级迁移；本段只提供代码补丁和本地证据，没有执行线上回退。
