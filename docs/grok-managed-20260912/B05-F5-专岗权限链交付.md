## 修复后的权限链

保留原角色与权限码，不给任何角色自动增加授权，不把完整查询权限附加给专岗。完整详情旧 query 路线继续独立存在。

| 操作 | 权限及接口 | 范围和状态 |
| --- | --- | --- |
| 采购编辑已存草稿 | add → GET /purchase/draft/{id} | 原仓库可见性、必须当前仓库、仅草稿 |
| 采购收货准备 | receive → GET /purchase/receive-context/{id} | 原仓库范围、submitted；不因最新余量为零丢弃既有恢复命令 |
| 采购供应商/商品/OE/礼盒选择 | add → 原已存在 /purchase/catalog/* | 复用原目的目录及物料/供应商过滤，PC/H5 不再隐含通用主数据 list 权限 |
| 采购退货/销售退货编辑草稿 | 对应 add → GET /purchaseReturn/draft/{id}、/salesReturn/draft/{id} | 当前仓库/门店、仅草稿 |
| 销售退货原单选择与读取 | salesReturn:add → GET /salesReturn/source-orders、/{id} | 当前门店、实际有可退物料；独立于 sales:list/query |
| 手机端提交已保存的三类草稿 | 对应 submit → POST /purchase/submit/{id}、/purchaseReturn/submit/{id}、/salesReturn/submit/{id} | 只提交已存 ID；不先 query，不回传或重写客户端表单 |
| 待办深链最小单据摘要 | 真实专岗操作任一 → GET /三类业务/action-context/{id} | 服务重新核对实际存在单据及当前仓库/门店，无完整详情 |

上表路径省略网关 /inventory 前缀。采购 action-context 权限 OR 为 add/submit/receive/qc/remove；两类退货为 add/submit/confirm/remove。list 或 query 本身不授予此操作摘要入口，普通查看仍使用旧 query 接口。新 action-context、draft、receive-context 和销售退货 source 接口返回 no-store。

新增销售退货按 ID 提交入口先锁原销售单、再锁退货单及当前明细，校验已保存主题/客户、草稿状态、当前门店及每行和同物料的历史占用，只 CAS 更新状态，不删除重建明细、不把新输入混入旧单。旧带表单的 /salesReturn/submit 本身会保存内容，因此改为 add AND submit，和采购/采购退货原带表单入口一致；原路径继续保留。

## 待办摘要与完整资料的边界

最小 VO InvSpecialistActionContext 不继承完整业务实体，明确列出字段：字符串 orderId 或 returnId、orderNo 或 returnNo、status、字符串 shopDeptId；采购另有 qcStatus、receivedQuantity、remainingQuantity 供原按钮条件判断。没有金额、客户、供应商、申请人资料或 details，固定标记 _specialistSummaryOnly=true。

H5 待办聚焦先读摘要。进入草稿编辑时，以 add 权限读 draft；进入收货时，以 receive 权限读 receive-context；仅提交/确认/取消专岗保留摘要并调用已存 ID 操作。不能拿摘要伪装完整草稿来保存；完整资料读取失败则继续沿用原页面禁止写操作的保护。H5 页面同时显示专岗摘要提示。PC 采购/采购退货待办回调已接 purpose API；PC 销售退货相同回调由 root 在 F7 文件中接 getSalesReturnActionContext，本批不覆盖其页面。

## 销售退货原单接口合同

GET /salesReturn/source-orders 支持 keyword（单号或客户，最多100字符）、orderNo（64）、customerName（128）、startDate/endDate（严格 YYYY-MM-DD，包含起止业务日期）、pageNum（默认1）、pageSize（默认20，1至100）。多个条件组合生效，非法日期、反向日期、过长条件和非法分页在进入 Mapper 前拒绝；组织来自认证后的当前组织头，不接受查询参数覆盖。

SQL 在分页之前排除没有实际可退数量的单据：按明细已出库数量扣除 submitted/returned 退货占用，并应用同类型物料总量上限；兼容历史未记录 sales_detail_id 的行，不混算同数值 ID 的商品和礼盒。不会只看“已发货”状态而漏掉已有实际出库的其他可退状态。排序 create_time DESC、order_id DESC 稳定；超出最后一页返回空页，不钳回最后页。

关键词用参数化 LOCATE 实现字面包含，%、_、!、引号和反斜杠不会扩大查询或拼接 SQL。PageHelper 6.1 默认偏移量存在 int 乘法溢出，本新接口显式按 long 计算 start/endRow，最大有效 int 页码也不会生成负数 LIMIT。

返回列表保持 {rows,total} 与原销售单展示字段。源单及新目的详情使用专用 VO 将 Long 身份序列化为字符串（包含明细 ID），旧 domain JSON 数字行为保留。GET /source-orders/{id} 附带可退明细和 returnableQuantity，保存/提交仍在后端锁内重新校验数量，页面展示不代表预留。
