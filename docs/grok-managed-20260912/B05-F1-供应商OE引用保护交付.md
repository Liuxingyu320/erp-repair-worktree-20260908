# B05-F1：供应商 OE 引用保护交付

日期：2026-09-12。状态：源码与本地隔离验收通过；未部署，未连接现用数据库，不代表线上验收。对应原清单 INV-F1。

## 已实现的业务规则

沿用供应商原有“存在引用时禁止改名、禁止删除”的规则，补入未删除的 OE 引用。启用和停用 OE 都保护供应商名；已逻辑删除 OE 不参与占用。产品、采购及采购退货历史占用判断保留，供应商非名称资料仍可修改。没有做 OE 名称批量同步，也没有改历史记录。

当前 OE 仅存供应商名，没有 supplierId 或组织归属。为避免破坏可恢复的引用，同名供应商在不同组织存在时采取保守保护：任一未删除 OE 引用了这个名字，都阻止此名字对应供应商的改名与删除。后续如果要解除这种跨组织同名限制，需单独治理稳定引用 ID，本批不猜测归属。

## 并发与事务

供应商修改和删除先锁定当前供应商行，再校验原有组织范围及引用；批量删除按去重后的供应商 ID 升序锁定，任一占用则整批回滚。OE 保存和导入先通过原有当前组织/上级供应商目录选择，再锁定同一供应商行，重新核对名称、组织、启停与合作状态，最后写 OE；因此不会在供应商已经改名或删除后，把先前读到的旧名字重新写入。

双方遵循供应商行 → OE 行的锁序。OE 引用检查使用 FOR UPDATE 当前读，不使用事务旧快照。供应商名索引 idx_inv_oe_item_supplier 已在原 OE 发布 SQL 中，本批不新增迁移、不改 bootstrap。

导入仍按原规则统计普通行数据错误；Spring 翻译后的 ConcurrencyFailureException（包括锁等待/死锁）向外传播，使事务异常不会被吞掉并误报前面行已成功。两版真实数据库验证了第一行实际 INSERT 后第二行锁异常导致整次导入回滚。
