# B08-A 规则匹配与可追溯额度核心交付

2026-09-12，Codex 直接实施 ATT-U1 / D22 的 A 段，精确 21 路径（准备清单原第 20 项含两份文档），基线为相邻 output/grok-managed-20260912/review-b08a-balance/before-manifest.json。没有改全局台账或现有请假/审批/工资链。

## 已实现

- HR 维护法人主体、归属组织、明确工作地文本映射和发布版本规则。员工基础资料只读必要字段，不读取工资、证件、银行或整份签约快照；工作地仅统一首尾空白，不猜城市/省份。缺资料、缺映射、同优先级多规则、未知在职状态都给可读待配置状态，可用额度为未知而不是伪造 0。
- 规则提供固定额度、基础日期年资档位、来源核定三种受控计算方式，以及明确的显示单位、每日分钟换算、发放步长/舍入、整年或按自然日折算、预发或逐日累积、结转/到期配置。没有内置全国统一天数或每日工时。调休来源类别只能使用 SOURCE_ONLY，本段不会把普通超时打卡或原早退抵扣计作调休。
- 使用百万分之一分钟的 long 整数统一内部额度，非精确转换拒绝；对前端传输的 Long 使用十进制字符串。存储最多六位小数的档位或换算数值不能由数据库静默舍入。规则计算从 workStartDate / entryDate 出发，不解析展示工龄。
- 年度来源按员工/假种/年度唯一；规则应发部分 ruleGrantedUnits 和含 HR 调整的 grantedUnits 分开。新版本或员工来源变化只记差额，保留调整、占用和消耗，不另赠一整年度；回到先前规则上下文也重新调和当前状态。规则/来源快照、动作、操作者、理由、请求身份及载荷指纹进入追加流水。
- 当前事务先锁员工和基础档案，再读取匹配来源并锁定规则/工作地记录；核对当前组织授权，之后串行锁额度账户及分桶。同次计算冻结一个服务端日期，跨年时不会用旧年度金额写入新年度桶。Job 使用独立事务入口，不伪造登录用户，也没有对应的无权限 HTTP 路由。
- 并发发放不重复，调整不能使可用额度低于 0；同请求身份、同载荷返回原结果，不同载荷拒绝。规则下调不能抹掉已有占用、消耗或已到期/结转事实。
- 到期按原规则和原桶身份处理。结转有独立来源桶和对应转出/转入记录，错过原结转到期日不会重新获得可用额度。仍有占用时保留原桶并返回 WAITING_RESERVED / EXPIRY_HAS_RESERVATIONS，等待审批结算，不静默删掉余额。
- 提供本人余额/按规则重算、HR 所辖余额/分页流水/审计调整、规则草稿与发布版本、工作地映射维护 API。服务层同时校验功能权限和当前组织范围；空范围不能解释为全量。SQL 来源组织类型沿现有 GROUP/COMPANY/STORE/WAREHOUSE 范围；停用或删除的当前组织不能匹配规则/工作地，也不能由 Job 继续发放，恢复组织后才能重新计算。新迁移不自动授权现有角色。

## 自动计算与上线顺序

自动 Job 额外受 `oa.attendance-v2.leave.balance.accrual-enabled` 控制，默认 false；既有 ATTENDANCE_V2 开关仍必须开启。默认每 60 秒处理下一批最多 100 名员工，循环按服务端日期调和已配置规则。幂等核心使多实例和重复扫描不会重复入账，员工不需要每次手工申请发放；D 段也可在自助打开时自动调用本人重算接口。

顺序必须是：单独执行本批迁移 → HR 配置工作地映射、规则版本及明确权限 → 核对合成/岗位流程 → 开启自动计算。仅部署 jar 不会由默认关闭的 Job 查询尚未迁移的新表。本批没有修改全局配置、bootstrap-files.list 或运行中的服务，没有执行线上迁移。

新增权限均以 `oa:attendance:leave:balance:` 为前缀：self、read、rule、adjust。迁移仅插入菜单/按钮，角色授权需管理员明确配置。
