# 07B 调岗与同时调薪验收

2026-09-12，Codex 直接实施。本地定向验收通过，待整体验收；未部署、未操作现用数据库；菜单 SQL 已在隔离合成 MySQL 中验证。

## 最终行为

- 普通调岗不要求工资，不展示“工资不变”提示；请求省略工资，后端使用锁定档案保留原金额。未勾选时，即使夹带旧客户端工资字段也不用于覆盖。
- “同时调整工资”独立使用 `hr:employee:salary:edit`。真实 controller AOP 仍要求 `hr:employee:transfer`，实际服务再检查调薪写权限、当前配置 HR 本人、源/目标店范围与日期；敏感查看、旧薪资编辑、签约发送权限均不能替代调薪写权限。
- 明确调薪才按原规则校验四项组成与合计，掩码不转成 NaN 或默认 0。服务器保留当前展示版本，五项金额按数值比较；同额不同小数 scale、只改版本字符串不算实际调薪。
- 仅实际金额变化调用原工资来源变更服务，保留其来源锁、前序一致性和历史日期防覆盖规则。普通调岗与同额调整不移动工资来源指针。原 profile 锁、动作幂等、历史调岗确认与 outbox 保留；不能通过省略调薪标志重放并掩盖已记录的调薪动作。
- D18 只限制 `TRANSFER_SALARY_CONFIRM`。工资不变时保留调岗确认、岗位职责等其他文书；仅工资模板方案返回 NO_ACTION，实际调薪缺少工资模板进入方案待处理。
- 生成规则与 PackageService 重新取模板均按冻结 task 前后金额过滤。最终发现任务中心可直接发送已经准备好的文件，因此 `sendPreparedPackage` 同样在写入发送状态前检查工资确认书；工资未变或快照证据缺失则拒绝，不删除旧文件。已经发送的包保留既有幂等返回。HR 手动发送时点不变。

## 菜单迁移边界

新增 `sql/erp_hr_employee_salary_edit_permission_20260912.sql`，仅在唯一有效员工档案父菜单下新增一个功能权限；检查既有同名权限是否唯一、所属父菜单正确，重入不重复新增。没有角色、角色菜单或用户授权写入，不恢复旧签约 HR 自动授权过程，也不恢复旧薪资模块写入口。SQL 附只针对本迁移新增且无角色绑定菜单的回退条件。

SQL 已在无网络、无端口映射、无宿主挂载且数据位于 tmpfs 的 MySQL 5.7.44 与 8.0.36 容器串行执行，每版本 14 项，共 **28 通过、0 失败、0 跳过**。覆盖首次/重复执行、既有用户角色映射不变、既有规范权限保留、重复或异形权限与父菜单阻断、仅回退本迁移且无绑定行，以及无 route_name 列兼容。当前 SysMenuMapper 使用 route_name，新增 F 功能不需要路由名，因此 INSERT 省略该列，无需额外兼容 DDL。两个完成验收的容器均已按其确切 ID 删除。首轮曾在 MySQL 初始化临时服务切换时中断，9 项阶段通过不计最终总数；等待 PID 1 为 mysqld 后完整重跑通过，原日志留存。部署时需要由管理员通过现有角色管理明确分配新权限，不能把目前已有查看/发送权限推断为调薪授权。
