# 02A 最终请求错误边界补充

14个行为场景及4组既有回归已经由Codex通过。但最终源码核对发现：用户API没有silentError，过期getUser/getUserPii或保存请求会先由公共拦截器弹旧错误，组件会话catch拦不住；getUser基础读取链也缺catch。不能把mock绕过拦截器的通过等同于这个边界已解决。

项目经理批准在原02A范围上精准新增 erp-ui/src/api/system/user.js：仅给getUser、getUserPii、addUser、updateUser、updateUserPii、previewUserDerivedProfile增加可选silentError参数/配置，位置不破坏现有签名。默认其它调用不变，不能接受任意options覆盖URL/方法/身份/载荷；仅读取silentError。

本页有会话判断的受控请求传silentError=true，在当前会话失败处明确提示；过期错误静默。保留PII部分成功的准确提示、新建后只重试PII、真实失败不关闭、不报成功。基础getUser失败也要消费拒绝并能再次打开重试；不能全局静默或忽略当前有效错误。派生预览是已有可选辅助读取，仍可按既有语义安静失败。全局登录失效/权限控制不改。

同一新增 userSaveTargetIsolation.test.js 补API调用默认与可选silent配置合同、旧基础读取失败与当前失败可重试反例。测试使用真实API配置和组件方法，不用测试级全局unhandledRejection屏蔽。禁止改公共request拦截器、其它API函数或既有测试。完成并更新02A交付后停止。
