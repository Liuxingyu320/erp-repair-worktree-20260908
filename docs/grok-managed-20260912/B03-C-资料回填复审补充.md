# B03-C 资料回填复审补充

Codex 已读取首版。继续限定 userInfo.vue、必要时原已许可的父组件、新 profileSaveRoundTrip.test.js 与交付文档，不改公共 API 或其他页面。

1. watch.user 的 `user === syncedUser && profileRef === syncedProfile` 会永久忽略同一对象里的真实外部资料变更，实际上削掉 deep watcher 功能。要按“确实是本次已同步值”区分自身保存回写，不能只按对象引用跳过所有以后变化。补真实 Vue nextTick 场景：初载后外部原地更新 user.nickName / user.profile.emergencyContact，表单正确接收；保存后再原地权威更新也正常。正常新对象替换继续通过。
2. 保存 pending 时外部权威资料替换或改变后，当前回调仍把 submitted 写到可变 this.user，会覆盖新的权威资料。捕获此次资料/表单代次；新的权威输入应使旧回调不再污染当前对象、输入、成功/失败与 busy。补 pending save -> 外部新资料 -> 新输入 -> 旧响应成功/失败的真实响应式测试。销毁和离开同样不应弹旧成功。
3. `Object.assign(this.user.profile, patch)` 对原先不存在的键在 Vue2 无法保证响应式；必要字段用响应式回填或整体更新，同时保留只读字段。补初始 profile 无 currentAddress/emergencyContact 的真实父子源更新场景。
4. 确认在异步校验阶段和保存期间重复调用 submit 不会产生并发覆盖；同一保存后新增输入保留，并让用户可见还有修改未保存，不能笼统误认为整个当前表单都已保存。

现有银行卡边界、错误保留、再次提交值、五组场景不得删减。不要以永久关 watcher 或冻结整个保存期间表单来规避问题。所有新增场景必须真实跑完再输出计数，Grok 不自行声称测试通过。
