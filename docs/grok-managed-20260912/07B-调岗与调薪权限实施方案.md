# 07B 调岗与同时调薪

2026-09-12，Codex 直接实施。主项目经理已确认 D18 只限制 `TRANSFER_SALARY_CONFIRM`，保留调岗确认、岗位职责等其他文书，并批准生成与发送两处使用冻结金额判断。07A 已冻结验收，本批另行保存基线与证据至相邻 `output/grok-managed-20260912/review-b07b`。

## 已核实的权限链

`HrEmployeeProfileController.confirmTransfer` 使用 `hr:employee:transfer` 注解；真实 `PreAuthorizeAspect` 调用 `AuthUtil`。`HrLifecycleServiceImpl.confirmTransfer` 另要求当前配置 HR 本人、源和目标店范围、有效员工与业务日期。权限来自当前登录上下文，服务端不接收前端自报的写权限。

敏感查看使用独立 `hr:employee:sensitive:view`；Excel 工资入档为现有 `oa:signTask:send`。旧 `system:salary:edit` 指向的旧薪资写服务已停用。这三者都不替代新的调薪写权限。

旧迁移包含签约 HR 自动授权过程，但当前 `SysConfigMapper.xml` 的 `syncSignHrPermissions` 已为 compatibility no-op，明确由普通角色管理权限。不能重新接通旧自动授权。

## 实施行为

1. 新增独立 `hr:employee:salary:edit` 功能权限。有此权限才显示“同时调整工资”。服务端在 `adjustSalary=true` 时再次检查该权限，仍需原调岗权限、配置 HR 与店范围；保留现有 AuthUtil 管理员语义，不新设旁路。
2. 普通调岗默认不调薪，不显示“工资不变”提示，也不要求工资或版本。DTO 工资字段取消全局必填；普通请求的工资值不用于覆盖服务器工资，后端以锁定员工快照保留。若请求夹带工资但未明确调薪，按普通调岗保留服务端工资。
3. 明确调薪才校验五项金额（四项组成与合计、非负、精度及范围）；金额显示为掩码时不转成数字或默认 0。原工资版本由服务端快照保留，不要求用户为了普通调岗填写技术版本。五项金额数值比较不受小数 scale 或版本字符串影响。
4. 保留 profile 锁、工资来源锁和事务、动作 requestId 幂等、历史调岗二次确认、outbox。只有实际金额变化才调用已有工资来源变更服务。普通调岗不挪动工资来源指针；重放请求仍核对冻结前后与当前快照，不能以省略金额掩盖此前实际调薪动作。
5. OA 规则仅过滤 `TRANSFER_SALARY_CONFIRM`。工资不变时保留其他调岗模板；仅含工资模板的方案可 NO_ACTION。真实调薪应有适用工资模板，否则作为方案待处理，不能假装已发工资确认书。既有 HR 手动发送时点保持原样。
6. 发送模板会重新按方案取全量，所以发送选择处也按关联 task 的冻结前后五项金额过滤。任务中心直接发送已准备文件的 `sendPreparedPackage` 同样检查所含工资确认书；草稿实际金额未变则在发送写入前拒绝，不自动删除或重写文件，已发送任务保留既有幂等返回。任务关联、员工或快照缺失时不能默认允许工资模板。使用持久化 task 快照，不信任前端标志或当前可能已再次变化的员工工资。
