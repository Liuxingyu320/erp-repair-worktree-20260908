# 任务02B 交付说明

## 当前代码

OE `erp-ui/src/views/inventory/oe/index.vue` 与礼盒 `erp-ui/src/views/inventory/gift/index.vue`：

- 编辑/详情请求绑定目标 ID、模式、会话代次。切换、新建、关闭开始立即失效；`handleEditorClose` 在抽屉已重新打开时不处理，避免关闭动画误伤同一条记录。
- 保存捕获点击时的会话；成功、失败、`finally` 仅作用于仍匹配的会话。
- 详情未就绪不渲染编辑表单（`v-else-if="formReady"`），抽屉内显示「资料加载中」，不是整页阻断。保存按钮仅在 `formReady` 时出现。
- 加载失败写入 `formLoadError`，抽屉内 `role="alert"` 与页脚提供「重新加载」。`retryEditorLoad` 对当前记录发起新会话请求；旧成功/失败不能覆盖新请求或后打开的记录。
- 新增路径仍立即 `formReady`。图片仍用 `imageUrls` 与既有 `image-upload` 契约。OE 供应商补全和延迟聚焦也绑会话。

## 测试场景

`erp-ui/test/oeGiftEditorIsolation.test.js` 用真实组件方法与可控 Promise，OE/礼盒参数化：

1. A 后回时 B 的描述、图片、ID 与保存参数不变。
2. 编辑 A 未完成时关闭或新增，旧响应不重开抽屉、不向新增填 A 的 ID。
3. 只读详情 A/B 逆序，最终为 B 及 B 的图片顺序。
4. 保存 A 期间打开 B，A 的完成/失败不关闭、替换或清除 B 的忙碌状态。
5. 加载失败后窗内重试：新会话、仍是当前 ID、成功后图片顺序保留。
6. 旧成功与旧失败分场景：重试后仍保留第一条 pending，旧成功不能填表，旧失败不能把新请求标失败；打开 B 时 A 的 pending 失败不能污染 B。
7. validate 绑点击会话；关闭后重开同一条；保存失败可重试；新增图片可用；OE 供应商与聚焦不串台。

图片比较先 `Array.isArray` 再 `Array.from`，只统一跨 VM 原型，缺失字段不能当成空数组通过。未删场景，未改既有测试。源文件断言覆盖 `@close`、`formReady`、`retryEditorLoad`、`formLoadError`、`重新加载`。
