# B08-B 主管核定已日结加班转调休：白名单与实施准备

2026-09-12，Codex 直接接续 B08-A。本文33个精确路径已由根项目经理在2026-09-12明确批准；A 完成的是额度核心，ATT-U1 / D22 的 B/C/D 仍需逐段实现。未调用 Grok，未写线上或宿主业务库。

## 已有事实与写入口

- `AttendanceTimeCreditService.apply/reverse`：`POST /attendance-v2/time-credits` 及撤销，所辖门店、同员工、同工资月，追加早退抵扣 APPLY/REVERSE。先锁 `oa_attendance_time_credit_period_lock(shop_id,salary_month)`，再按日结 ID 排序锁来源/目标；原撤销还锁原调整记录。同请求身份的相同内容重放、不同内容拒绝。
- `OaSalaryServiceImpl.calculateSalary`：保留代码的 `LegacySalaryWriteGuard.reject()` 仍禁用实际工资新增；以下仅描述未启用的保留实现和现有工资读预检。先取得同一门店/月锁，再读 `AttendancePayrollMapper.selectPublishedDayResultsForPayroll`，从原加班分钟扣早退净抵扣；已有工资记录阻止后续重新分配来源。需接入净转休分钟，不能仅在新转休接口限制。
- `AttendanceDaySettlementService.settle`：按排班逐个锁排班、日结，写 `upsertDayResult` 并推进版本；不取得上述月锁。新转休与它通过同一日结行锁串行，不能反向去锁排班而制造锁环。
- 打卡重算、补卡/请假审批回调及撤回、剩余工作确认都可能写日结并使 `settled_at=null`。已转休的来源不能随这些动作静默删除，也不能再按旧版本继续提供可用余额。

## B 段行为与锁顺序

1. 主管只提交日结 ID、预览版本、假种、核定分钟、原因和请求身份；服务端核对门店、员工、真实已日结、排班及版本。规则必须是该员工当前匹配的 COMPENSATORY/SOURCE_ONLY，单位沿 A 的精确微分钟与规则换算；不把普通超时打卡自动入账。
2. 独立转休来源台账追加 APPLY/REVERSE，记录来源日结/版本/业务分钟快照、核定人、原因、规则和分桶。可用源 = 日结可转加班 - 早退净抵扣 - 转休净分钟。旧抵扣候选/新增路径和工资聚合同时读取另一用途，不能双花。
3. 写顺序固定为：门店/月锁 → 日结 ID 升序 → 原核定记录（撤销）→ 员工/档案/匹配规则与工作地 → 额度账户/分桶 → 追加核定/额度流水。工资读写持同月锁并冻结所用日结，防读取期间来源重算。A 自动额度不反向锁日结；C 在占用前沿 B 顺序冻结涉及的转休来源。
4. 同一请求/载荷返回原核定结果；同键不同载荷拒绝，流水写失败整笔回滚。撤销追加反向记录并收回原分桶，不删除原核定；已占用、消费、结转或无法完整收回的来源不能撤销后再次用于抵扣/计薪。
5. 来源失效或日结版本改变后保留原金额和审计事实，显示待核对并禁止新转休、请假占用和工资使用该错误来源。重算结果不自动替换核定快照；未占用/消费时主管可审计撤销，再按新来源版本核定。已占用/消费的修复需要 C 的审批/考勤/工资边界协作，不静默造负数。
6. 仅新增按钮权限 `oa:attendance:leave:balance:convert`，不自动赋给现有角色。使用现有功能与所辖门店授权，不伪造登录身份。新表迁移必须先于接线部署；缺失迁移明确失败，不按未扣转休的金额继续抵扣/计薪。A 自动 Job 默认关闭开关保持。

## 必须验证

双核定竞争；核定与旧抵扣竞争；工资先后与同月锁；已日结预览版本过期；来源变人/变店/失效/重算；异店权限；精确单位；同请求重试/键冲突；额度流水或核定失败整笔回滚；重复撤销及已占用/消费/结转的拒绝；工资排除净转休且撤销恢复来源。新真实 Mapper + Spring 事务测试在隔离 MySQL 5.7/8.0 运行，原核心/抵扣/工资场景继续保留并分别统计。浏览器/岗位/部署未验收。

根补充约束：来源员工调岗或跨公司后，不能把旧店日结静默记入新公司账户；必须核对日结时的合法归属与当前规则，不能匹配时明确拒绝。已消耗来源失效不伪造撤销、不造负数。

## 真实事务验证发现与修正

第一轮隔离 MySQL 5.7 保留失败证据：16个场景中，双核定竞争和等待月锁后检查已有工资2个失败。来源提示读取在默认 REPEATABLE_READ 中先建立旧快照，取得月锁后普通聚合仍看不到前一事务新提交结果。仅持锁不能修复该旧快照。

新核定/撤销、旧抵扣/撤销、保留工资 calculateSalary 共5个写入口明确 READ_COMMITTED，保留原月锁和日结锁。运行时同时拒绝加入已有非明确 READ_COMMITTED 事务，避免 REQUIRED 传播加入外层旧快照后方法注解失效。实际 HTTP 控制器调用服务代理时新建 RC 事务；B 调用额度桥接方法沿同一事务写入，桥接方法拒绝无事务调用。当前源码没有其他生产 calculateSalary 调用者；旧工资禁写守卫保持。测试单独模拟其守卫通过仅验证保留聚合逻辑，不代表启用了工资写入。

回归新增确定性旧抵扣等待核定提交、显式外层 RR 拒绝两项，MySQL 组为18个真实方法。工资月锁读取用生产锁 Mapper/工资 Mapper 在 RC 事务中证明等待转休提交后读取净分钟；不把测试内插入工资夹具当生产工资端到端。
