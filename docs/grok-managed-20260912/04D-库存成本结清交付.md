## 修复行为与范围

`InvStockCostAllocator` 从已经 FOR UPDATE 锁住的库存行分摊扣减金额：部分扣减按成本单价乘数量并 HALF_UP 到两位；本次数量等于 currentQuantity 时，使用整个剩余 totalCost。耗尽 availableQuantity 而仍有锁定库存时不结清成本池。

五处扣减共用这个结果：发货通知、采购退货、盘亏、按库存 ID 手动调减、按物料手动调减。库存 SQL、出库记录、库存流水和发货通知明细累计额使用同一金额；采购退货明细的原采购价和单据金额不作为库存成本，也不被改写。发货与盘点补齐流水/出库零行写入失败检查，失败回滚本次事务。

库存成本单价及总成本必须已知、非负、可精确表示为两位；未知值、负值、超出两位且非零的精度不转为零或静默舍入。部分金额超过剩余成本池也拒绝。SQL 保留 version 和 availableQuantity 保护，另要求正数量、足够 currentQuantity/成本余额，最后一笔的金额必须等于剩余总成本。零成本是合法值。

手调/盘点共享流水函数仅在扣减分支传入本次精确成本，避免以扣减后的均价反算金额。正向手调/盘盈保留原金额计算和流水行为，不把原未知历史成本写成确定金额。采购退货原单 → 退货单 → 明细/原入库事实/占用 → 库存锁链保持 04C 验收版本。
