## 费用身份

保存草稿、保存并提交、上传前建草稿、上传识别后自动保存统一进入受控保存方法。请求载荷与提交快照独立复制；保存期间当前表单编辑不会改变已发出的对象。

服务端每次保存按提交顺序赋予 sortNo、生成 itemId，再按 sourceInvoiceId 绑定发票。前端用冻结提交行顺序核对返回 sortNo、费用字段和发票关联，随后按原行对象或旧持久 itemId 找到当前仍存在的行；不按响应时数组位置猜配。返回服务端身份，保留提交之后发生的字段修改、增行、删行和排序。只改标题不会保留全部旧 itemId。

费用数、sortNo、持久 ID 或发票关联无法核实时保留原草稿和原版本，显示最新对照并阻止继续写入，不猜配。服务器明确返回空费用数组时保持为空，避免删票后通过默认空白行重新引入费用。

## 冲突与未知结果

两端都保存最近一次权威详情快照，并提供“本地草稿/最新记录”对照面板。明确版本冲突保留本地原版本、金额和未保存字段；保存、提交、上传以及识别写入被阻断。用户可重新读取对照，或明确放弃本地修改并重新读取最新记录。读取期间又有新输入时仍保留草稿，要求再次核对；不会覆盖确认之后的新输入。

删除响应丢失或缺少完整详情时，只有权威记录满足原版本恰好 +1、目标发票不存在、被绑定费用按预期移除、其他费用身份/字段及标题事由和剩余发票集合不变，才自动确认删除并保留无关本地修改。其他并发变化、发票仍在、版本不符、读取失败都保留原草稿/版本和待核对状态，不声称成功，也不自动重试写入。保存网络结果未知时也阻止盲目重试；无记录 ID 的新建未知结果明确要求先在记录列表核对，避免重复新建。

后续普通刷新若发现远端费用集合改变且本地有未保存内容，同样进入核对状态；不会用新版本搭配旧费用继续覆盖。正常上传/识别刷新若费用未变，则更新持久身份并保留本地编辑。
