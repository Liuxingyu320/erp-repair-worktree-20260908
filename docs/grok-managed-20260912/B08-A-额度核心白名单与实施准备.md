## 已定规则与本段结果

HR 按稳定法人主体 ID 和明确工作地映射维护结构化、版本化规则；缺档案、缺映射或同优先规则歧义返回可读待配置状态，未知不当 0。只使用 workStartDate / entryDate 计算年资，员工不选择地区。年假由配置自动计算；调休只接主管核定已日结加班来源，本段不把打卡超时或旧早退抵扣直接入账。

A 段提供规则/映射维护、本人或所辖员工余额及追溯查询、规则计算与幂等发放/审计调整核心 API。B/C 将通过明确内部额度服务接口接日结转休、申请占用与审批结算；本段不解除旧 LEAVE_BALANCE_POLICY_NOT_CONFIGURED，不宣称九类申请已闭环。前端接线仍在 D 段。

## 表与数据白名单

新增 7 表，仅这些表可写：

- oa_attendance_leave_balance_rule：法人主体、组织归属、工作地规则码、假种、优先级、不可变发布版本、生效区间、年资基础、受控计算方式、单位换算、折算/发放/结转/到期配置。
- oa_attendance_leave_balance_tier：按完成年资区间的配置额度；区间不得重叠或不连续地误匹配，边界按明确计算规则核对。
- oa_attendance_leave_work_location：法人主体 + 原档案工作地文本到规则工作地码的显式映射，保留版本/审计。
- oa_attendance_leave_balance_account：员工/假种唯一锁头和版本，B/C 在同一锁顺序接占用与消耗。
- oa_attendance_leave_balance_bucket：按规则期间或外部来源分桶的发放、可用、占用、消耗、到期身份；重算按同一期间差额调整，不能每换规则版本再赠送一份。
- oa_attendance_leave_balance_ledger：追加发放/调整/结转/到期流水与规则/源版本、操作者和原因；不覆盖历史事实。
- oa_attendance_leave_balance_command：请求/来源身份 + 载荷指纹与结果，重放同载荷返回原结果，不同载荷拒绝。

只读已有表：sys_user（ID/组织/启停状态）、sys_user_profile（user_id/dept归属关联、legal_entity_id/work_location/work_start_date/entry_date/在职状态等必要字段）、sys_dept（组织层级和主体）、sys_user_shop（授权范围）、sys_legal_entity（主体有效性）、oa_attendance_leave_type（假种/单位/启用状态）。不读工资、证件号、银行或完整签约快照。日结/timecredit/salary 留 B 段，此段不读写。

## API 白名单

新根路径 /attendance-v2/leave/balance：

- GET /my：从登录用户取身份，只读本人匹配状态与分桶余额；忽略/拒绝其他员工身份。
- POST /my/recalculate：按服务器日期、员工档案及已发布规则计算本人应发差额，幂等入账；请求不接金额/地区。页面 D 段可在自助打开时调用，Job 提供无人打开时的自动计算。
- GET /employees/{userId} 与 /employees/{userId}/ledger：有 read 权限且服务端组织授权内。
- POST /employees/{userId}/recalculate：有调整权限且组织授权内，按服务端规则调和。
- POST /employees/{userId}/adjustments：有调整权限且组织授权内，必填原因/请求身份；正负调整追加流水，不能使可用不足或覆盖消费。
- GET/POST /rules，GET /rules/{ruleId}，PUT /rules/{ruleId}/draft，POST /rules/{ruleId}/publish：规则维护权限及主体归属组织范围，发布后不可原位修改，新版本继承稳定规则身份。
- GET/POST /locations，PUT /locations/{mappingId}：规则维护权限及主体范围，显式映射版本/原因。

新增权限：oa:attendance:leave:balance:self、:read、:rule、:adjust。SQL 仅创建本段菜单/按钮，不给任何现有角色自动授予权限；权限展示/路由 D 段接线。HTTP 中 userId/地区/金额都不能取代服务端身份、组织授权或应发计算。

## 锁与验证顺序

先验证 feature / 功能权限 / 员工组织范围，再匹配规则。账户锁固定在分桶、命令与流水之前；规则发布版本只读，调和冻结规则/档案基础来源。相同年度或来源重复计算只写差额，已占用/消耗部分不可直接抹掉或变负。结转/到期必须用配置的原桶身份追加对应流水，反向还原不得跳到错误年度。

必要本地证据：缺资料/多规则歧义、生效边界/年资边界、单位折算/舍入、规则版本切换差额、重复发放/不同载荷重放、并发同账户调和/调整、到期/结转且已有占用、失败整事务回滚、本人越权/HR跨组织/空范围拒绝、最小字段不含敏感资料、迁移重复运行和历史申请不动。MySQL 5.7/8.0 均为隔离合成夹具，运行前协调 Maven 时段。浏览器/岗位/部署验收继续单独记录。

## 根项目经理补充授权

精确范围已批准。迁移仅新增菜单/按钮，不为现有角色自动授予权限。自动计算使用专用默认关闭开关，先迁移再配置规则/权限再启用；只部署 jar 不触碰新表。员工无需反复手工申请发放。内部统一为百万分之一分钟的精确整数单位，保存原规则换算和显示单位。档案读取在发放事务内锁定基础员工与档案记录，规则与映射来源也锁定/冻结版本；不按旧上下文发至新组织。到期/结转遇已有占用需保留并提示，不能抹掉。Job 使用独立受控内部入口，不伪造登录身份。Maven 与 R07 协调。

## 实施细化

工作地映射只规范首尾空白并保持其余文本精确匹配；金额单位为微分钟，传输 Long 使用十进制字符串。年度桶分别保存规则应发 ruleGrantedUnits 和含 HR 审计调整的 grantedUnits，避免重算抹去调整。账户、档案与规则匹配的同次服务器日期均冻结。匹配来源组织类型仅沿既有 GROUP/COMPANY/STORE/WAREHOUSE。余额查询会返回已匹配规则名称、单位和换算；配置缺失时可用为未知。

MySQL 8.0 故障注入测试采用仅临时容器生效的 log-bin-trust-function-creators=1，允许非 SUPER 合成账号创建回滚测试触发器；宿主/线上配置不变。
