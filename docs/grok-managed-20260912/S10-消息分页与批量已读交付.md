## 接口契约

保留旧 `/list`、`/unread-count`、`/{id}/read`、`/inner/publish`、设备令牌接口，以及原通知 domain 的 JSON 类型和全部推送实现。本批新增：

- `GET /user-notification/page`：keyword ≤100，routeType ≤64，readStatus 为空/0/1，startDate/endDate 为严格 YYYY-MM-DD；pageNum 默认1且为正整数，pageSize 默认20且为1至100；snapshotMaxId 可选，为非负Long范围的规范十进制整数。
- 首次未传快照时，先查询当前登录账号全部消息的最高ID；筛选和分页后仍用客户端传入的原上限。刷新不传上限即可取新快照。新到的更高ID不会进入旧快照。最大ID上限不冻结消息已读状态或内容。
- `AjaxResult.data={rows,total,unreadCount,snapshotMaxId,routeTypes,pageNum,pageSize}`。`snapshotMaxId` 和新 page 行的 `notificationId` 始终为字符串；仅新 Row VO 做ID序列化，旧 domain/旧list保持原类型。`unreadCount` 是该账号全部未读，`routeTypes` 是该账号已有的非空类型字符串列表，两者都不跟随页面/筛选缩小。
- `POST /user-notification/read-all` 请求示例：`{"snapshotMaxId":"123"}`。以一条 SQL 更新当前登录账号、ID≤上限、原未读的消息，不受页面/关键字/类型/日期影响。返回 `data={changed,snapshotMaxId字符串,unreadCount}`。重复请求可返回 changed=0，新到更高ID保留未读。

两个入口均 RequiresLogin，Controller 仅从 SecurityUtils 取当前用户，DTO没有可用来改变账号范围的userId。Service也拒绝空/非正账号。没有新增或自动授予角色权限。快照、页码、长度、枚举、非法日期/反向范围与Long溢出在读写前验证；字符串快照保留大整数精度，分数/指数/布尔/负数不能变成合法上限。

## 查询与事务边界

分页与count共用相同 WHERE，始终带 user_id 和 snapshotMaxId；标题/正文按字面关键字匹配，参数化SQL并以 `!` 转义 `%`、`_` 与 `!`，不把用户输入当SQL片段。排序为 create_time DESC、notification_id DESC，时间相同也稳定。offset使用long计算。

日期按上海业务日 `[start 00:00, end+1日 00:00)` 查询，向 DATETIME 绑定上海日历的 LocalDateTime，避免JVM默认时区转换。现有 system 数据源声明 serverTimezone=Asia/Shanghai、BaseEntity输出GMT+8（仅相关片段存 timezone-source.log）。9999-12-31 是 MySQL DATETIME 最后一天，其结束条件由列本身最大值保证，不构造溢出日期。此约定是项目业务时间语义，不声称已经检查现用数据库会话时区或历史数据。

分页在只读事务内取快照上限、count、rows、账号全部未读和类型。read-all 的单条更新与随后未读统计在同一事务内；统计阶段抛错也回滚更新。高于快照的新消息始终不被本次更新选中；返回未读数反映本次查询可见的账号数据，后续新到消息由再次查询刷新。
