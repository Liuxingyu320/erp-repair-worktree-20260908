# B08 额度闭环分段实施准备

2026-09-12 Codex 项目管理准备，尚未派发或验收。不包含真实 HR 规则数据，也不定义统一法定天数。以用户最终问答与 `B08-规则与数据来源核对.md` 为依据。

## 已定产品行为

员工选择年假、调休、病假、事假、婚假、丧假、产假、陪产假或育儿假，填写起止、天数、原因和按规则需要的证明；HR 确认，通过后影响考勤。HR 按法人主体和工作所在地维护额度规则，系统按档案匹配，员工不选省份。年假自动计算；调休以主管核定的已日结加班转入，系统自动累积。历史假种、已有申请和审批事实必须兼容。

## 分段交付建议

### A：规则匹配与可追溯额度核心

- 用稳定法人主体 ID 匹配公司；工作所在地当前是文本，HR 需维护明确映射。员工档案缺失或多条同优先规则命中时返回可读待配置状态，不能把未知当0或猜省份。
- 限定结构化规则字段与受控计算方式，不引入任意脚本执行。规则需版本、生效区间、年资基础、发放/折算、结转/到期，以及单位换算配置；所需数值由 HR 配置，不植入未确认的全国统一值。
- 从基础参加工作日期/入职日期计算年资，不能解析展示的“几年几月”。只读取所需上下文，不能为额度拉取整份工资/证件/签约快照。
- 发放与调整以可追溯流水/批次记录；同员工、假种、规则版本、额度期间/来源具备幂等身份。重算规则不能重复赠送，也不能直接覆盖已占用/已消费历史。
- 本段需提供自助查询本人以及有权限 HR 查看、维护规则、审计调整能力；只看本人/所辖组织，不能靠客户端 userId 或地区参数决定权限和金额。

### B：主管核定加班转调休

- 来源必须是所辖门店同一员工真实已日结记录，记录核定人、来源日结/版本、分钟、原因、所用规则、流水身份。不能把普通打卡超时全部自动入账。
- 可用源 = 日结可转加班 - 已抵扣早退净分钟 - 已转调休净分钟；抵扣和转休两条路径都必须读取对方占用，在一致锁顺序下并发核验。只在新接口检查不足以防原抵扣接口继续超用。
- 复用现有工资月锁/日结锁语义；已有工资生成状态下不得偷偷重新分配同一加班来源。计薪应排除已经转调休的来源分钟，避免同一分钟同时加班计薪和形成调休额度。
- 核定未知结果重试必须返回同一结果，重复键不同载荷拒绝；撤销为可审计反向动作，不能删除原核定。已占用/消耗额度、日结失效重算等必须有明确约束，不把错误额度静默变负数。
- 本段要同时验证新转休、旧早退抵扣、工资聚合三方关系，不能只写新表或新按钮。

### C：请假申请、余额占用与 HR 审批

- 独立申请天数与起止时间写入持久数据/版本/审批快照，按配置校验单位与时长；不能继续把起止的自然时差直接当作已支持的申请天数。
- 草稿不消耗；提交时按申请与业务轮次原子占用，SUBMITTING/PENDING 的重复调用不得重复占用。审批通过将占用转消耗；退回/驳回/撤回释放一次，重新提交使用新轮次。远端审批已成功但本地未知时保留占用等待权威结果，不擅自释放。
- 现有回调还支持 APPROVED 后 TERMINATE，须按已生效的政策和考勤/工资边界处理反向流水，不能忽略这一终态路径。回调实例、轮次、eventKey 校验继续保留；旧回调不能影响新一轮额度。
- 同员工并发两张申请不能超占额度；同次申请跨不同额度发放批次/到期日时，分配与恢复必须可还原，不能释放到错误年份或已经过期来源。
- 九类申请统一可用流程、HR 确认与材料规则接已有审批和私有附件；老申请缺新字段按明确兼容分支处理，不批量改写历史。

### D：界面与集成验收

- 员工页显示已匹配规则、可用/占用额度及单位、未配置原因；无需选省份。主管从日结进入核定，能看到可转/已抵扣/已核定来源。HR 维护规则并查看追溯记录。
- 保存及上传期间可以继续填写，正式提交必须以已保存且验证通过的快照为准，继承 B03-E 行为。
- 余额规则与天数应进入审批可读摘要；状态、金额/分钟及错误不得依赖仅客户端判断。
- 最后才接入 SQL bootstrap，真实隔离 MySQL 5.7/8.0 验证事务、并发与回调，不连宿主或线上数据库。迁移需重复运行/旧数据兼容验证。

## 核心验收门槛

逐项覆盖：缺失与歧义规则、规则生效边界、年资边界、重复发放、重复请求键不同载荷、两申请超占、双核定竞争、转休与早退抵扣竞争、同月工资锁、审批重放/旧轮次、失败回滚、撤回重交、终止已批准申请、失效/重算来源、权限越界、PC/H5真实角色及新旧请求兼容。源码和本地测试通过后仍保留浏览器、岗位和部署验收未完成标记。
