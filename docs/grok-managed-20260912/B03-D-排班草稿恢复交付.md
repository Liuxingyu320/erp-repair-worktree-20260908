# B03-D 排班草稿与冲突恢复交付

实施目录：当前 Grok 实施工作副本。仅改 WeeklySchedule.vue、weeklyScheduleDraftRecovery.test.js 与本说明。未改 02C 已验收测试、后端或请求层。

## 首轮返工对应修复

1. `draftItems` 先消费 `draftEdits` 再可见单元格；保留本地后单元格/提交都使用 `remoteRowVersion`。不断言降级。
2. `confirmPersistedDrafts` 只清理本次提交且 stamp 未变的键，并按门店/周过滤。保存门店 20 不会删门店 10 草稿。测试回到门店 10 时服务端仍返回原始班次 1，本地仍为 9。
3. 草稿记住最初 `rowVersion`。刷新若远端 version 变化则进入核对，禁止用远端新 version 提交旧班次。保存成功且期间又改过的行，才把基线更新为本次保存结果。
4. `searchEpoch` 与 `loadEpoch` 分离。搜索不打断整周 loading；刷新不覆盖更新的搜索员工；乱序回包不丢排班。
5. 核对文案含本地/远端班次与地点及状态。`setCell`/`rememberDraft` 不再自动清除未核对；只有采用远端或保留本地会解除。已发布/已删除仍不可覆盖。
6. 重读失败只标记当前冻结门店/周草稿；`conflictReadFailed` 按店周隔离；重读成功会清 `remoteUnavailable`。
7. 发布链保存成功同样 `confirmPersistedDrafts`；发布遇版本冲突走重读核对且不发布。
8. 删除冻结门店、周、员工、日期、ID、版本和 loadEpoch。切店后不刷新页、不把旧错误弹到新店，只忘掉被删的那一格。

新建本地行远端不存在时不当成已删除。

## 复审补充（cells 回读）

`applyDraftOverlays` / `syncDraftAgainstServer` 的远端基线改为只从 `this.schedules` 映射，不再读已覆盖的 `this.cells`。保留本地把 version 改成 4 后不会被单元格上残留的 3 再判成冲突。核对文案用 `localShiftId`/`localSiteId` 对 `remote*`；已发布时选择器可显示远端快照，对照栏仍保留本地草稿，不会两栏都是远端。
