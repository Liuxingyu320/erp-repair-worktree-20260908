## 数据和界面合同

保留现有 PERSONAL=事假、SICK=病假；新增标准code ANNUAL=年假、COMPENSATORY=调休、MARRIAGE=婚假、BEREAVEMENT=丧假、MATERNITY=产假、PATERNITY=陪产假、CHILDCARE=育儿假。不重命名已有自定义假种或历史。新增政策不默认法律额度、工资比例、证明阈值或每日分钟；未配置额度型明确阻止，新类型启用须有HR配置。B按匹配规则的COMPENSATORY/SOURCE_ONLY判定，保留自定义typeCode兼容。

SaveDraft增加 requestedDays（十进制，服务端BigDecimal）及可选 quotaPolicySnapshot。详情和列表返回同名独立天数；原totalMinutes继续表示起止覆盖时间，不能拿它显示或反算天数。MINUTE未填天数保留原分钟路径；DAY/HALF_DAY新申请需显式天数，MIXED可选。LeaveType新增可选minutesPerDay；非额度按天必须HR明确配置，额度按天沿匹配规则换算。天数不可按自然跨度猜测。

服务端保存并返回 quotaUnits（精确微分钟十进制字符串；非额度不占用）、quotaStatus、quotaPolicySnapshot。快照冻结假种ID/版本、单位模式、请求单位、是否需余额、规则ID/版本、工作地映射ID/版本、公司、额度显示单位与minutesPerDay。首次选型未带快照由服务端自动匹配；传入快照只作期望条件，绝不信任其金额/权限。编辑沿原草稿版本和已读快照核对；新选型可重新自动匹配。提交在锁内重读依据，改变时要求核对新草稿，不悄悄以旧输入配新换算。

quotaStatus固定 NOT_REQUIRED / NOT_RESERVED / RESERVED / CONSUMED / RELEASED / REVIEW / LEGACY_NO_QUOTA；REVIEW仍保留真实占用或消费。既有pending/approved缺新快照按历史兼容，不回填或凭空追扣；旧草稿进入新额度/按天流程需重新核对保存。九标准假种新申请要求HR审批；既有自定义小时流程不擅自强改计量。

## 三条写链与一致性

1. 草稿仅冻结，不占用。提交按申请ID/业务轮次原子分配，先按到期日/桶ID从有效额度来源分配，再与SUBMITTING/审批出站记录同事务提交。重复PENDING/SUBMITTING不重复占用；同员工两申请不能超占。SOURCE_ONLY不自动赠送，年假按A已配置规则自动对账准备，员工不需要每次手工发放。
2. 已校验实例、轮次和eventKey的HR通过把原占用转消费，退回/驳回/撤回释放原分配一次。释放回原桶和年份，已过期来源保留到期身份，不释放成新可用年度。旧回调不能影响新轮次。APPROVED后TERMINATE检查原审批、考勤和工资边界，允许时追加反向流水；已参与工资/抵扣/转休等不可自动冲回的来源保留消费待核对，不造负数。
3. 出站发起失败分开处理：能够证明尚未发起的本地校验失败释放并回可编辑；调用超时、成功坏回执、远端已成功但本地关联失败均保留占用，用原同键请求取得权威结果。不能仅凭FAILED状态释放。既有RemoteApprovalService无按请求键查询API，本段先复用同键start重试；如仍需查询再列扩围，不擅改远端公共API。

申请锁后，额度写入统一按所有相关门店/月排序→来源及目标日结ID升序→员工/档案/规则→账户/桶→分配和事件。先探测来源，锁内复核集合与版本，出现新来源则拒绝重试，不能漏锁后使用。沿B READ_COMMITTED规则，拒绝加入旧快照事务；日结重算不反向锁排班。真正写额度的内部桥拒绝无事务调用，不伪造登录身份、不另造HTTP越权通道。

新增 oa_attendance_leave_quota_allocation 保存申请/轮次/来源桶分配与状态，oa_attendance_leave_quota_event 保存幂等动作。既有申请表新增独立天数和只读额度快照/状态，假种表新增每日分钟。余额仍使用A账户/桶/追加流水/命令，不另建另一套可用数。迁移可重复，不给既有角色自动赋权限，不批量改写旧申请。
