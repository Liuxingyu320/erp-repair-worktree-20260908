## 最终行为

D23 的历史补签保存合同当时工资，当前档案工资仍由现行来源和正式调薪控制。沿用现有过去合同开始日与历史标记识别；自动同步在生成操作保存历史确认之前发生，因此服务端直接读取已有 Excel 快照日期，即使 historical_supplement 尚为 false，也不会先覆盖档案。使用现有业务时区日期，不新增天数阈值；坏日期类型拒绝处理。

历史分支仅向现有来源表追加 `HISTORICAL_CONTRACT_EXCEL` 不可变记录，工资金额从服务端 Excel 快照读取，适用日期保留合同开始日。保留员工、批次、行、行版本、原文件哈希、请求号/请求哈希和操作人证据；不执行 updateSalary、不推进 current source、不写代表现行工资入档的旧 audit。appendHistorical 仅允许完整、已验证的历史来源；普通 append 明确拒绝该类型进入现行工资。

预览能识别已留存的同一历史工资；未知响应通过原请求号查询并恢复，不重复写入。混合批次中普通行照常同步，历史行只追加证据；后续行失败时，前面历史证据及普通写入共享事务回滚。Result.updated 兼容原接口，表示本次完成的来源记录行数，历史行不表示更新员工档案。

生成保留原有历史确认与原因要求。历史工资来源校验员工、批次、源行、文件哈希、五项金额和合同日期；行版本允许生成 claim/完成动作递增。已生成合同优先重用原包绑定来源，另一份等价确认不会把已生成合同改绑。

绑定和发送还通过真实 SQL 校验源行、任务、包的员工及来源关联、任务源版本、历史确认/原因、包与行的冻结合同日期和金额，关联不完整就拒绝。文件哈希用 binary 精确比较，兼容既有表不同排序规则。持有 task → profile 锁后读取历史关联，保留原事务次序。当前工资后来变更不会阻止有效历史合同发送；其他合同不能借此绕过来源校验。

普通 Excel 合同保留自动同步、当前来源锁、并发变更拦截和原 HR 手动发送时点。既有已准备历史签字优先的严格兼容边界保持，没有增加全局历史豁免。未改前端、合同 Excel 解析、Lifecycle、菜单权限或数据库 DDL。
