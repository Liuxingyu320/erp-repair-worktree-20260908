# B06-P 个人资料显示与手机离页准备

2026-09-12 Codex 准备；等 B03-C 验收释放 PC userInfo.vue 与 user API 后重新冻结基线，尚未派发。范围为 S03、S09、V01，对应 D10/D11。

## 已读当前事实

- PC `system/user/profile/userInfo.vue.display` 和 H5 `mobile/profile/index.vue.displayProfileValue` 都用 includes("T") 截前10字，普通职位/公司名也被截断。
- H5 当前“基本资料”包含全部可编辑内容以及身份、社保、任职、合同只读区，保存按钮在整个长表末尾；缺少离页保护。
- H5 saveProfile 将 payload 整体复制到 user/profile，包括提交的银行卡明文；保存返回还无条件清空当时银行卡输入。此处必须随保存/离页衔接保留仅提交内容已保存语义和银行卡边界，不能在加上dirty后仍把后续输入当作已保存。
- 当前页面自己的query切换用于密码页；须区分真正离开导致草稿丢失与只切标签仍保留草稿，避免为无损标签切换反复确认。

## 用户已定行为

手机个人可编辑资料与HR只读档案分开；保存随滚动可见。离开有未保存内容时可选保存后离开、放弃修改、继续编辑；保存失败继续留在原处，保留输入。日期显示只处理可确定的日期值，普通名称原样显示。

## 验收条件

- 长职位/公司名含大写T保持完整；标准ISO日期时间可显示日期；空值、普通中文、带T非日期文本、只日期均正确，不依赖时区误移日。
- 手机先看可编辑信息，HR身份/任职/合同仍可清晰查看；保存按钮在390×844等窄屏滚动时可用，不遮挡最后输入、底部导航或安全区，键盘焦点可达。
- 返回工作台、底栏、快捷入口、浏览器前进后退、关闭入口等都接统一路由保护；只有真正未保存变更才提示。明确3个选项，不用难发现的关闭叉暗代“继续编辑”。
- 保存并离开要等待真实保存成功；失败留页/保留值，可再试；保存期间的新修改未保存时不能继续离开。并发触发离开/重复保存只有一个有效决策，取消后不残留导航。
- 保存10/旧值期间的新输入保留并dirty，已保存权威源与当前草稿分开；外部新资料、离开/重入、旧响应不覆盖新页面。银行卡留空保持原值，提交明文不进公开user/profile，只有仍等于已提交卡号才清输入；不把密码/银行卡草稿写进持久浏览器存储。
- query标签切换如不丢草稿可以直接切，返回编辑标签仍保留；真正浏览器刷新可用原生未保存提醒，但不能承诺原生关闭支持异步保存。
- 新增行为测试运行真实组件与可控请求；有意义的视觉验收使用本地合成资料，记录视口和证据。已有mobileProfileMaintenance及B03-C测试回归，不能把方法测试称为真实设备/岗位或线上验收。
