## 1. 检查点结论

阶段 13P6 已建立一个没有生产调用点的同步执行事务所有者，首次把已有执行策略、不可变执行事件、三类同步效果所有者和动作/计划/事项状态推进组合成固定顺序的单事务骨架。

本骨架只接受已具备权威实现的同步效果：

- 责任调整台账；
- 短缺运输损失台账；
- 受损隔离库存写销与损失台账。

补发和退回仍缺少 V2 子调拨工作流，任何新请求都在执行事件或效果 DML 前失败关闭。原执行入口仍只持有双 Gate，并在 Gate 之后无条件抛出异常，因此该事务骨架不可从 Controller、HTTP、RPC、任务、消息或前端到达。

## 2. 已冻结的事务顺序

一次非重放同步执行固定为：

1. 校验服务端登录用户与 `inv:transfer:discrepancy:execute`；
2. 解析当前组织授权集合；
3. 锁定差异事项；
4. 只读校验原调拨来源/目标组织命中授权集合；
5. 锁定裁决头；
6. 稳定排序锁定全部动作；
7. 锁定同请求执行事件；
8. 使用纯策略重算边界、覆盖维度、效果和前后状态；
9. 追加不可变执行事件；
10. 唯一路由并执行一个同步效果所有者；
11. 条件推进动作；
12. 条件推进裁决计划；
13. 条件推进差异事项。

所有条件 DML 必须精确影响一行。任何异常都会由外层 `@Transactional(rollbackFor = Exception.class)` 回滚事件、效果和状态，效果所有者继续使用 `Propagation.MANDATORY`，不能脱离外层事务单独提交。

## 3. 重放与防篡改

执行事件读模型现在可转换为纯策略快照。完全一致重放会同时核验：

- 请求、事项/动作前版本、裁决和动作；
- 当前权威计划中的动作序号、类型、覆盖维度、数量、金额和责任方；
- 事件中的前后版本、前后聚合状态和动作状态；
- 差异类型推导的效果类型与同步/异步转换矩阵；
- 效果引用格式、决定指纹、事件指纹格式、权限和同一操作者。

重放成功只返回原事件结果，不追加事件、不重复效果、不推进状态。请求 ID 被不同命令、引用、事项、动作、版本或操作者占用时失败关闭。

## 4. SQL 与组织边界

- 责任与短缺损失两个条件插入现与受损写销一致，要求同事务中已存在完全匹配的执行事件；
- 组织锚点使用仓库既有的 `inv_transfer_order.transfer_id`，来源和目标均按仓库优先、部门回退规则计算；
- 组织校验查询不带 `FOR UPDATE`，避免把原调拨头加入本执行锁序；
- 执行事件与三层状态 DML 不读取或修改 `inv_transfer_order`；
- 本阶段没有新增或执行迁移 SQL。
