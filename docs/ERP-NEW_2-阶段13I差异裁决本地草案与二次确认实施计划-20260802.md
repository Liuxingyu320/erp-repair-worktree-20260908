# ERP-NEW_2 阶段 13I：差异裁决本地草案与二次确认实施计划

## 1. 审计结论

阶段 13F 的浏览器安全投影刻意不返回内部 `factFingerprint`，而现有裁决写服务要求该值校验并发事实。浏览器当前没有安全、完整的真实写入依据，不能诚实构造后端提交命令。

本阶段不泄露内部指纹、不猜测依据、不生成幂等请求标识，也不新增 Writer。只建立明确标记为非持久化的本地裁决草案和二次确认交互。

未来真实写握手应由服务端提供与用户、组织、事项版本和确认事实绑定的短期不透明依据令牌，并在独立安全检查点设计、签发和消费。

## 2. 本地草案契约

草案包含：

- 只读事项 ID、版本、差异类型与差异总量；
- 裁决说明和证据引用；
- 1 至 20 个动作；
- 每个动作的连续序号、动作类型、数量、责任方和说明。

严格校验：

- 仅允许对 `readyForAdjudication=true` 且尚无计划的事项建立草案；
- 动作类型必须与短少或破损兼容；
- 数量必须为正、最多 4 位小数，动作数量合计必须完整覆盖差异总量；
- 责任方只能是调出方、调入方、承运方或公司；
- 说明、证据和动作说明非空且受长度限制；
- 未知字段拒绝。

草案不包含金额分摊、内部事实指纹、确认人内部 ID、服务端决定指纹、requestId 或执行状态。

## 3. 交互

- 在阶段 13G 工作台的就绪事项中显示独立草案编辑区；已形成计划的事项不显示编辑器。
- 默认建立一个覆盖全部差异数量的空白动作，但不预选裁决类型或责任方。
- 支持新增、移除和调整动作，校验即时清除旧错误但不自动提交。
- “检查 Mock 草案”通过严格契约后打开二次确认面板，并把焦点移动到确认标题。
- `Escape` 或“返回修改”关闭二次确认；确认后只在内存中显示“本地草案演练完成”。
- 编辑后使既有确认结果失效，避免把旧草案误当当前结果。

## 4. 明确禁止

- 不调用任何 Gateway 方法，不新增 simulate/submit/Writer；
- 不生成 requestId，不伪造 `factFingerprint`；
- 不调用阶段 13E 写服务，不新增 POST Controller 或 HTTP Writer；
- 不开放功能码、路由、深链、菜单、权限种子或默认运行时注入；
- 不启动服务、不连接数据库、不执行迁移。

## 5. 设计与动效

继续使用高密度、专业后台布局；动作列表使用清晰编号、标签和错误关联。新增/删除/键盘输入即时响应，不增加列表动画。只复用页面既有一次性 `180ms` 进入动效；减少动态效果继续生效。

## 6. 测试

- 纯契约：就绪边界、短少/破损动作兼容、连续序号、数量精度与守恒、严格字段、证据长度。
- 页面：草案填写、二次确认、焦点、Escape、Mock 完成、编辑后结果失效、已规划事项无编辑器。
- 无写证明：完整交互后 Transfer Gateway 除一次只读加载外没有任何方法被调用。
- 复跑阶段 13G/13H Gate、前端完整门禁和库存模块离线 Reactor。

## 7. 停止线

若需要真实写依据、后端 POST、Writer、权限/菜单启用、运行时注入、依赖变更、服务启动或数据库连接，立即停止并建立不透明依据令牌的独立安全设计检查点。
