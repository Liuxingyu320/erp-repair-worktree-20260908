## 二、本阶段已实施内容

### 2.1 五场景统一

- 建立唯一场景编码：`onboard`、`regularize`、`transfer`、`renewal`、`offboard`。
- 方案、模板、任务、签约包、待办和前端筛选统一使用同一套规范化逻辑，兼容现有大小写/历史别名输入。
- 模板类型目录扩充到五场景，服务端会校验“模板类型—登记场景—方案场景”一致性。
- 批量建包明确只允许入职场景；转正、调岗、续签、离职继续走人员生命周期任务，防止绕过业务状态机。
- 前端模板选择、方案编辑、签约包详情和任务中心均显示规范化场景名称。

### 2.2 法律主体保护

- 签约方案和不可变方案版本新增法律主体 ID、名称。
- 签约包冻结法律主体 ID、编码、名称快照，不再用门店/部门名称冒充合同公司。
- 文档渲染、签署证据和验真凭证均使用法律主体名称快照。
- 方案发布前扫描模板正文：允许 `${companyName}` 或与方案一致的主体；如仍包含其他“某某有限公司”固定文字则拒绝发布。
- 已启用的 20260713-v2 入职模板仍保留，不被脚本替换；若其固定公司名称与方案主体不一致，服务端会阻断发布。
- 前端方案编辑页要求录入稳定主体 ID 和主体名称，发布确认页明确展示主体并给出不可逆发布提示。

### 2.3 续签安全快照

签约包新增并持久化以下字段：

- `previous_contract_end_date`：原合同结束日。
- `previous_employment_type`：原合同/用工类型。
- `previous_legal_entity_id_snapshot`：原法律主体 ID。
- `previous_renewal_count`：原续签次数。
- `renewal_count`：本次续签次数。
- `legal_entity_id_snapshot`、`legal_entity_code_snapshot`、`legal_entity_name_snapshot`：本次法律主体快照。

续签发送前会校验原合同结束日、前后用工类型、前后法律主体、续签次数递增、新合同起止日和模板所需字段；续签模板已暴露相应占位符。

### 2.4 统一发送前检查

新增服务端签约包预检，覆盖：

- 场景合法性与方案/模板场景一致性。
- 模板是否启用、员工可见、需阅读、需签字等交付策略。
- 劳动合同与劳务合同组合互斥及人员类型匹配。
- 法律主体快照完整性。
- 合同起止日期、试用期、入职/转正/调岗/离职生效日期。
- 薪酬分项和合计一致性。
- 续签前后类型、主体、次数和期限连续性。
- 模板必填占位符是否有值。

任务工作流生成签约包时以服务端任务快照为准；前端传入的同名关键字段不能覆盖任务权威数据。

### 2.5 模板防误启用

- 服务端对状态只接受 `0`（启用）和 `1`（停用）。
- 所有新建模板无论客户端传什么状态，首次保存都强制为 `1`（停用）。
- 编辑现有模板时未传状态则保持原状态，不会被空值误改。
- 前端新建模板默认停用，并显示“审核后再启用”的提示。
- 28 份新草案均有数据库停用状态；转正、调岗、续签、离职草案页眉/正文带红色“系统测试草案”警示。
- 离职通知书、离职证明按公司单方出具处理，不要求员工签字。

### 2.6 使用体验优化

- 签约包表单按场景显示相关字段，续签时自动带出“原次数 → 本次次数”。
- 列表和详情直接展示法律主体快照，避免用户根据门店猜合同主体。
- 方案发布增加可读性检查清单，缺主体、无模板、存在不兼容模板时禁止确认。
- 任务中心、签约包列表和模板列表统一场景筛选与中文标签。
- 签署凭证无公司印章时明确写“未加盖”，不再生成容易被误解为已盖章的证明。

## 六、仍存在的问题与优化顺序

### P0：正式启用前必须完成

1. **HR/法务审稿**：15 份非入职文件目前是系统字段与链路草案，不是法律定稿；13 份入职 v3 也需逐份确认主体替换后语义。审核前保持停用。
2. **法律主体主数据**：当前界面允许录入主体 ID/名称并在发布时阻断空值，但项目内尚无唯一法律主体主表和选择器，服务端无法证明 ID 与名称是一对。应建立主体主表、门店/员工绑定关系和只读选择器，禁止自由输入。
3. **公司印章治理**：现有 `oa_company_seal_config` 是全局配置，未与法律主体绑定；新签约链路没有安全地选择实体印章。应改为“法律主体—印章版本—有效期—授权人”配置，完成前禁止自动盖章，凭证保持“未加盖”。
4. **正式方案审批**：目前方案和版本均为 0。需在专用验收库为每个主体建立五场景方案，执行 HR、法务双人复核后再发布，不能直接用 SQL 绕过发布服务。
5. **专用合同 HR**：`sign.hr.user-id=1` 仍可能指向通用管理员。上线前必须配置专用合同 HR，验证角色、门店/主体数据范围、离职替岗和审计追踪。

### P1：自动发送前完成

1. 限制或下线遗留“手工直接建签约包”入口；该入口由有权限 HR 提交快照，而生命周期任务路径由服务端冻结权威数据。自动发送只应接受任务路径。
2. 建立员工档案到法律主体、合同类型、续签次数的权威查询，前端只展示，不允许手工改关键快照。
3. 增加方案发布审批流、四眼复核、模板差异预览、签约包发送前最终 PDF 预览与二次确认。
4. 建立模板版本下线/替换台账，正式 v3 启用后再有序停用固定主体 v2，不能先停旧再审新。
5. 在真实的非虚拟化 MySQL 5.7 验收库补跑迁移和全链路回归（如生产仍为 5.7）。

### P2：运营与可用性

1. 补充按主体/场景统计的待签、逾期、失败、续签临期看板。
2. 增加模板占位符可视化检查、缺值定位和测试数据预览。
3. 为表单布局表格提供屏幕阅读器专用说明，正式模板审稿时处理剩余 4 个中级可访问性提示。
4. 增加印章/模板/方案/发送动作的独立审计导出和定期验真任务。
