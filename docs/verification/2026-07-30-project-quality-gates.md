## 统一入口

仓库提供不绑定 GitHub、GitLab 或 Jenkins 的统一入口：

```bash
./scripts/ci/verify.sh --install
```

该命令按顺序执行：

1. 检查 Git 跟踪文件，拒绝构建目录、Python 字节码、部署压缩包和 Finder 编号副本。
2. 校验 Docker MySQL 自动/手工 SQL 清单、双份 SQL 字节一致性和关键依赖顺序。
3. 校验 MySQL 集成测试仍以 `*IT.java` 命名、Failsafe 从普通编译输出加载应用类，且 Docker 不可用时不会静默跳过。
4. 使用仓库 Maven Wrapper 和 `-fae` 运行后端测试，使一个模块失败后其余模块仍继续验证。
5. 在干净环境使用 `npm ci`，运行全部前端 Node 测试。
6. 自动使用当前 Git HEAD 和 UTC 时间注入构建元数据，执行生产构建与体积预算。

后端、前端测试或前端构建即使发现失败，入口也会继续执行其余可运行阶段，最后统一返回失败，避免一次执行只暴露一个门禁问题。若干净安装失败，则跳过依赖状态不可信的前端测试和构建。

只检查仓库与数据库清单：

```bash
./scripts/ci/verify.sh --checks-only
```

在具有 Docker daemon 的隔离测试机上追加 MySQL 5.7/8.0 集成门禁：

```bash
./scripts/ci/verify.sh --install --with-mysql
```

MySQL 集成门禁只能连接 Testcontainers 创建的临时数据库，不得指向生产或共享业务库。
调用方未显式设置 `DOCKER_HOST` 时，门禁会读取当前 Docker CLI context；对于
Colima、Docker Desktop 等非默认 Unix socket，会自动设置 Testcontainers
容器内 socket 映射。调用方显式提供的远程或 CI 配置保持优先。
