## 1. 本检查点交付

- 新增 `/inventory/purchase` 采购订单路由、侧栏、移动导航和命令检索入口；同时要求 `inventory.purchase.view` 与 `inv:purchase:list`。
- 新增采购领域模型、Zod 契约、Long 安全校验、有效日期、精确十进制金额/数量、业务阶段投影与回退、Gateway 和只读 HTTP Reader。
- 新增 ERP-NEW_2 仓库专属 Mock，覆盖待收货、部分收货、待质检和已完成订单，以及供应商、状态、采购日期筛选与分页。
- 页面明确区分服务端总记录与当前页阶段计数，提供桌面表格、移动卡片、加载、错误、空状态和最近成功筛选语义。
- 公司和门店上下文不会发出采购请求，只提示切换到仓库；页面没有动作列或任意组织 ID 入口。

## 2. 契约与运行边界

- 只覆盖 `GET /inventory/purchase/list`；详情、新建、保存、提交、收货、质检、上架、取消、删除、导出和采购退货均未迁移。
- HTTP Reader 显式使用旧端点所需的 `Dept-NumId`，不与 `X-ERP-Organization-Id` 双发；GET 不发送 CSRF。
- `expectedOrganizationId` 在 `fetch` 前阻止组织漂移，解析后再次拒绝任何其他仓库记录。
- 日期参数严格为 `params[beginOrderDate]`、`params[endOrderDate]`；前端不发送任意 Mapper 参数。
- 金额和数量保留为十进制字符串并通过 Decimal 处理；页面不把不同单位数量相加或展示为“总件数”。
- 默认启动只注入隔离 Mock；真实 Reader 没有进入默认运行时，本检查点没有发出真实 HTTP 请求。

## 3. 设计与动效结果

- UI Prompt Library 和 21st.dev 只影响“全局总量 → 当前页阶段 → 筛选 → 明细”的信息层级；Motion Primitives 只影响成功/失败状态连续性。
- 页面使用 Vue 3、现有设计系统和普通 CSS 独立实现，没有复制外部代码、提示词正文、素材或品牌组合。
- 未引入 React、Tailwind、Motion、GSAP、远程字体或新依赖；没有动态背景、光效、循环、列表入场或布局动画。
- 只保留 140ms、可中断的按钮 hover/press 反馈；`prefers-reduced-motion` 会关闭过渡。
