> 日期：2026-08-02

## 1. 已完成结果

- 新增共享 `InvTransferReceiptDiscrepancyBoundaryPolicy`，只读服务与写事务现在使用同一套关系事实、金额、指纹、双方组织和最新事件验证，消除读写规则漂移。
- 新增唯一 `InvTransferReceiptDiscrepancyConfirmationCreationService` 本地事务，固定执行：组织/用户校验 → 事项单行锁 → 权威关系读取 → 幂等事件锁 → 条件追加 → 影响行数与生成键校验。
- 新增窄化确认 Mapper，只有两个 `SELECT ... FOR UPDATE` 和一个 `INSERT ... SELECT`；没有事项更新、确认历史覆盖、删除或其他业务表 DML。
- 条件追加重新核验事项标识、版本、事实指纹、`awaiting_confirmation` 状态、收货/调拨归属、服务端推导的调出或调入组织、决定、说明、操作者和幂等标识。
- 全局 `request_id` 已存在时，只允许同一事项、版本、指纹、角色、组织、决定、说明和操作者完全一致的回放；不同载荷或不同用户复用会拒绝。
- 精确回放返回原事件标识和锁内重新计算的当前双方状态，不把较旧的回放事件重新提升为最新意见。
- 新事件只有影响行数严格为 1 且生成键为正才成功；0 行、多行或缺失生成键均抛出异常并由本地事务回滚。
- 创建响应只包含事件/事项标识、服务端角色、决定、当前确认状态、裁决前提、回放标记与时间，不返回内部指纹、成本、操作者用户标识或幂等载荷。
