## 1. 实际结果

已建立阶段 12C 的分段实施计划，并完成 12C1 的不可执行结构骨架：

1. 新增加法迁移源码，定义多次部分收货所需的收货头、逐来源分配、序列号处置、逐来源累计进度和目标派生批次维度。
2. 汇总库存与批次库位明细库存同时增加隔离数量，未来 V2 写入统一保持 `current = available + locked + quarantine`。
3. 新增独立锁事实与 Mapper 契约，按调拨明细、发货明细、来源分配、目标模式、物料策略、汇总库存、来源批次、目标库位、派生批次、目标余额和序列号稳定排序锁定。
4. 条件写 SQL 同时约束版本、业务归属、正数增量、非负数量、金额和库存公式；没有无条件库存更新。
5. 现有 `InvTransferShipmentReceiptCreationService` 未修改，仍只持有 `InvTransferShipmentReceiptWriteGate` 一个字段，没有注入或执行新 Mapper。默认 Gate 关闭；即使测试构造双 Gate 为真也继续硬拒绝。

旧 `inv_transfer_discrepancy` 处理器没有接入 V2。12C1 的收货分配只能作为未来的不可变差异证据；V2 专属差异裁决、真实写事务和专属数据库验证完成前，Gate 不能启用。
