# ERP-NEW_2 阶段 9：调拨分批发货与批次库位规划骨架检查点

> 日期：2026-08-02
> 分支：`codex/erp-new-2-rebuild`
> 基线提交：`807efacb feat: add dual-engine transfer approval flow`

## 1. 本检查点结论

审批后的“待发货”任务现已具备一个独立、移动优先且失败即关闭的新前端骨架。页面组合封存版本、服务端建议来源、库存读取模式、余额时点、FEFO/FIFO/序列号策略、批次、库位、可分配量和建议量，并允许用户在两步确认后完成一次非持久化 Mock 命令演练。

页面没有接入现有真实发货写接口。原因是现有接口只承载调拨明细和数量，尚未表达批次、库位、序列号、计划版本、人工改选权限、原因与证据。骨架明确把这种能力差距显示出来，不用前端计算或假成功掩盖。

## 2. 发货规划契约

- 所有数量使用非负十进制字符串和 Decimal 校验，不使用 JavaScript 浮点数承担守恒判断。
- 每行要求“审批数量 = 已发数量 + 剩余待发数量”。
- 本批建议量不得超过剩余量；所有批次库位建议合计必须等于本批建议量。
- 每个分配的建议量不得超过服务端返回的可分配量。
- 同一物料行不得重复余额和策略排序；整个命令不得重复消费余额或序列号。
- FEFO 建议必须携带有效期依据；FIFO 保留入库时点；序列号建议要求逐件整数数量与可用序列号一一对应。
- 可执行标识必须与全部物料建议及全局阻断项一致。
- 页面验证返回规划的调拨 ID 必须等于当前路由调拨 ID。
- Mock Gateway 重新派生预期命令并逐项比对，不接受调用方手工构造的“形状合法但内容被改写”命令。

## 3. 新前端入口与页面

- 新增功能 `inventory.transfer.ship` 和权限 `inventory:transfer:deliver`。
- 新增 `inventory-transfer-ship` 待办深链与受保护的发货规划路由。
- 统一待办新增“发货”筛选，待发货任务由占位状态变为授权路由。
- 调拨工作台的待发货行新增“发货规划”入口。
- 页面提供调拨方向、封存版本、建议总量、库存读取模式、计划版本、余额时点、快照哈希、数量守恒、分配优先级和逐件序列号摘要。
- 右侧/移动端前置确认区只提供“接受服务器建议”这一安全动作；人工改选保持关闭，并说明所需权限、原因和证据前置条件。
- 成功结果明确标注 Mock 非持久化，没有调用后端、扣减库存、创建在途批次或改变数据库。

## 4. 设计参考采用结果

阶段 9 对用户指定参考站点进行了只读核验，并将结果补充到前端设计规范：

- 采用 UI Prompt Library 的“摘要 + 主清单 + 详情/确认区”后台信息结构。
- 采用 Motion Primitives 所体现的克制确认与状态连续性原则。
- 21st.dev、React Bits、Magic UI、Uiverse 和 MotionSites 只作为结构、局部细节或提示词灵感，不复制 React/Tailwind 源码，不引入运行时外部依赖。
- 页面只使用一次 180ms `opacity + translateY(4px)` 进入动效；高频状态即时切换，按压反馈轻微，并支持 `prefers-reduced-motion`。
