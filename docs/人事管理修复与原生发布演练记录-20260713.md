# 人事管理修复与原生发布演练记录

> 日期：2026-07-13
> 范围：员工口径、缺档初始化、部门负责人稳定身份、主数据 readiness、资源级门禁、健康证受理与迁移
> 约束：仅使用本机原生 MySQL，不使用虚拟机、Docker、Testcontainers，不写业务数据库

## 1. 本次完成内容

1. 统一员工档案访问集合与在岗治理集合，排除内置管理员，并为缺失档案提供显式、幂等的初始化入口。
2. `sys_dept` 增加 `leader_user_id` 稳定负责人身份；姓名继续作为快照，旧文本负责人不自动猜测或回填。
3. 新增纯 `HrMasterDataReadinessEvaluator`；服务只负责按数据范围加载快照、过滤和汇总。
4. `affectedEmployeeCount` 改为员工 ID 并集数，新增 `affectedOccurrenceCount` 表示问题覆盖人次。
5. Java 评估器与 `scripts/hr-master-data-readiness.sql` 在同一隔离快照完成自动对账，问题键、严重度和行级影响人数一致。
6. 修正合法根 `GROUP` 被误报 `COMPANY_NODE_MISSING` 的永久 P0；嵌套集团节点仍按组织路径异常处理。
7. `hr.master-data.enforce-on-enable` 已接入组织变更和在用岗位停用/删除的资源级写入门禁，拒绝发生在写入前，且不受其他组织存量问题误伤。
8. 健康证使用统一 `BusinessFeatureGate` 严格解析新受理开关；配置缺失、非法或不可用均失败关闭。关闭时仍允许历史查询、已有审核和已审核当前证件提醒。
9. 新增健康证能力接口、桌面/移动提示、原生草稿→提交→审核→续证流程测试及数据库名称硬保护。
10. 迁移不再覆盖已有运行开关，角色授权改为 `WHERE NOT EXISTS` 幂等写法，并新增两份只读预检脚本。
11. 部门修改可区分“请求未携带负责人 ID”与“显式传空清除负责人”；只修改电话、邮箱或排序时保留原负责人，不误触发负责人治理。
12. 健康证后端补齐与表结构一致的发证机构和驳回原因长度校验，过长输入在写库前返回明确业务错误。

## 5. 正式发布门禁

1. 正式环境先执行健康证表/列/索引和负责人字段只读预检。
2. 按演练顺序执行三份迁移，禁止多个实例并发执行 `MAX(menu_id)+1` 初始化段。
3. 明确确认 `feature.hr.health-certificate.enabled=false`、`hr.master-data.enforce-on-enable=false`；配置调整必须作为独立变更，不得依赖迁移覆盖。
4. 由 HR/组织管理员处理全部 P0，并对 2 个历史负责人逐一选择真实员工身份；禁止批量猜测姓名。
5. P0 清零后重新执行 Java/DBA 对账，并连续观察至少一个完整工作日。
6. 健康证表结构、权限和流程复核通过后，可单独启用健康证新受理。
7. 只有 P0=0、对账一致且观察完成后，才可单独启用主数据强制门禁。

## 6. 未关闭风险

本机只有 MySQL 8.0.45。迁移和 SQL 已避免 CTE、窗口函数、`ADD COLUMN IF NOT EXISTS` 等 MySQL 5.7 不兼容写法，但这不能替代真实 MySQL 5.7 验证。如果正式目标仍是 MySQL 5.7，发布前必须在同版本非业务测试实例再执行一次迁移双跑、预检和原生测试；在此之前该兼容风险保持未关闭。
