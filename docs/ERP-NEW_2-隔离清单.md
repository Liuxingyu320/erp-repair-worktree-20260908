## 1. 文件系统与 Git 边界

- 唯一允许写入目录：`/Users/liuxingyu/.codex/worktrees/353b/ERP-NEW`
- 受保护原项目：`/Users/liuxingyu/Desktop/备份/ERP-NEW`
- 专属分支：`codex/erp-new-2-rebuild`
- 禁止修改、删除、格式化、暂存、提交或运行任何会写入受保护原项目的命令。
- 禁止访问或清理其他 Git worktree；禁止主动合并、推送、变基或删除分支。
- 每次执行写操作前必须确认 `pwd` 等于唯一允许写入目录，并确认当前分支正确。

## 2. 方案与代码隔离

- 正式实施依据仅使用本工作树副本：`docs/ERP前端全量重建与库存调拨实施方案-20260801.md`。
- 新前端只允许在 `erp-ui-next/` 中从全新目录和文件建立。
- `erp-ui-next/` 禁止 import、symlink、复制生成或运行时引用旧 `erp-ui` 源码、样式和组件。
- 旧 `erp-ui` 只作为功能迁移盘点输入；任何删除必须展示精确清单并再次取得用户批准。
- 后端 API 原则上保持稳定，只实施已确认的业务逻辑修复。

## 3. 运行环境隔离

- 当前决定：暂不使用 Docker，运行基础设施整体延期。
- 延期期间禁止改用本机共享 MySQL、Redis、Nacos 或其他已有业务服务作为替代。
- 后续运行环境无论采用何种方式，都必须拥有独立实例、配置、端口、数据和生命周期，可独立启停。
- MySQL 应用数据库名预留为 `erp_new_2_app`，Nacos 持久化数据库名预留为 `erp_new_2_nacos`；两者必须使用彼此独立且仅属于 ERP-NEW_2 的账号。
- Redis 必须使用独立实例和独立持久化目录，不得通过共享 Redis 的 DB index 模拟隔离；业务 key 前缀为 `erp:new2:`。
- Nacos 必须使用独立实例；namespace 预留为 `erp-new-2-local`，group 预留为 `ERP_NEW_2`。
- 所有宿主端口必须在实际启动前重新只读检查；发现冲突时只更换 ERP-NEW_2 端口，不得停止或修改现有进程。
- 禁止连接、复用、迁移或修改 `BossERP_NEW`、原项目实例、已有容器/网络/数据卷、共享业务库或生产环境。

## 4. 路径与数据隔离

- 专属运行根目录预留为本工作树内 `.runtime/erp-new-2/`。
- 上传、日志、缓存和临时目录分别位于该根目录下的 `uploads/`、`logs/`、`cache/` 和 `tmp/`。
- MySQL、Redis、Nacos 的数据目录必须位于 ERP-NEW_2 专属运行目录或专属数据卷，禁止映射受保护原项目路径。
- 测试数据必须带 ERP-NEW_2 标识，并且只能写入 ERP-NEW_2 专属数据库或实例。

## 5. 凭据与配置隔离

- 禁止读取或复用原项目 `.env`、密码、密钥、令牌或连接串。
- 仓库仅保留不含真实秘密的 example 模板。
- 真实本地凭据必须随机生成、只保存在已 gitignore 的 ERP-NEW_2 本地配置中，并且不得在终端输出、日志或回复中回显。
- 浏览器会话 Cookie 固定使用 ERP-NEW_2 专属名称 `ERP_NEW_2_BROWSER_SESSION`，不得复用原项目 Cookie；默认采用 `HttpOnly`、`SameSite=Strict` 和 `Secure` 属性。
- 浏览器会话 CSRF 密钥仅从 `ERP_NEW_2_BROWSER_SESSION_CSRF_SECRET` 注入，必须独立随机生成且不少于 32 字节；不得复用 JWT、Nacos、数据库、Redis 或原项目的任何密钥。
- 浏览器会话功能默认关闭；只有认证服务与网关同时显式启用且通过密钥校验后才可接受 Cookie 会话，否则必须失败关闭。
- 任何配置一旦出现受保护原项目路径、`BossERP_NEW`、共享服务地址或生产地址，必须停止执行并报告。

1. 阶段 0 基线清单和提交范围；
2. 功能迁移矩阵中的下线、合并和业务规则争议；
3. 三个可运行 Mock 原型；
4. 库存调拨完整业务矩阵；
5. 每个领域迁移完成状态；
6. 生产等价验收结果；
7. 旧前端精确删除清单；
8. 最终全量切换、合并或推送。

在检查点未确认时，可以继续只读审计和可逆的准备工作，但不得开始其后的不可逆步骤。
