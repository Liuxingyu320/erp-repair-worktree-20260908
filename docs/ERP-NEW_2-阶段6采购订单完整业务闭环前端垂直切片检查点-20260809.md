## 3. 后端数据与并发边界

- 列表、详情、供应商目录、三类物料目录、收货批次和待检批次均使用当前精确仓库，不扩展到门店、公司或相邻仓库；
- 保存只接受白名单 DTO；商品名称、编码、供应商和金额等可伪造字段不会成为权威输入；
- 保存、提交、收货、质检、取消和删除在行锁后再次复核单据存在、仓库和状态；
- 采购单、采购明细、收货批次、批次明细、入库记录、质检记录、质检附件、库存和库存日志的关键写入均核对精确受影响行数；
- 收货数量与逐行质检数量在 Bean Validation 和服务层双重限制为最多 14 位整数、4 位小数；绕过 Controller 直接调用服务也会失败关闭；
- 收货数量不得超过该明细未收数量；质检必须满足合格、拒收和让步之和等于本次检验数量且不超过待检数量；拒收或让步必须填写原因；
- 质检附件只接受 `/file/public/`、`/profile/` 或 `/uploads/erp-new-2/` 下的规范化本地路径；拒绝绝对外部 URL、共享路径、遍历、片段、用户信息和编码绕过；
- 所有新增和调整的采购读取及写响应统一要求 `Cache-Control: no-store, max-age=0` 与 `Pragma: no-cache`。

## 4. 前端契约与交互

- Java `Long` 始终保持正十进制字符串；数量与金额使用十进制字符串和 `decimal.js`，不经 JavaScript 浮点数往返；
- 真实 Gateway 强制同源 Cookie、CSRF、`Dept-NumId`、组织漂移复核、请求标识、幂等键、禁缓存响应和 Excel MIME/25 MiB 上限；
- 上传服务若返回绝对本地域名，前端先规范化为本地路径再进入质检命令，浏览器不会把外部主机地址写回业务单据；
- 未修改表单的失败重试复用请求 ID，表单变化后生成新 ID；写命令不自动重试；
- 保存并提交、详情提交/取消/删除、收货和质检均使用统一确认弹层；弹层打开后焦点进入安全返回按钮，Tab 焦点留在弹层内，Esc 关闭后返回原触发按钮；
- 确认时再次读取当前会话权限和组织，后端锁内复核最新状态，避免仅依赖页面加载时的陈旧快照；
- 设计参考 21st.dev、React Bits、UI Prompt Library、Magic UI、Motion Primitives、Uiverse 与 MotionSites 的信息层级和局部反馈原则，不复制外部代码、品牌或资产；
- 高频筛选、表格和逐行输入即时响应，不使用页面入场编排、循环光效、视差或布局动画；`prefers-reduced-motion` 下关闭非必要过渡。
