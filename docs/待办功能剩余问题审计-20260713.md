# 待办功能剩余问题审计

- 日期：2026-07-13
- 范围：桌面待办列表、手机待办列表、调拨审批详情、审批确认、关键词空结果
- 方式：本机真实浏览器复查，未提交任何业务操作

## 总体结论

主流程已经可用，列表统计、范围说明、筛选、详情优先和确认弹窗都正常。剩余问题主要集中在手机端主操作的可发现性、确认信息完整性、跨组织上下文切换以及大待办量的排序解释。

## 流程步骤

1. **桌面待办列表：基本健康**
   - 证据：[01-desktop-no-org.png](audit-screenshots/todo-20260713-r4/01-desktop-no-org.png)
   - 910px 宽度时“查询”按钮单独换行，形成一块明显空白。不阻断使用，但窄桌面/平板横屏下布局不够紧凑。

2. **手机待办列表：可用，但大待办量分流不足**
   - 证据：[02-mobile-list.png](audit-screenshots/todo-20260713-r4/02-mobile-list.png)
   - 102 条待办时没有可见的排序规则或排序控件。实际代码会按紧急度和创建时间排序，但使用者看不出原因。

3. **手机调拨详情初始状态：需优化**
   - 证据：[03-mobile-detail.png](audit-screenshots/todo-20260713-r4/03-mobile-detail.png)
   - 初次打开只看到底部“刷新列表/切换上下文”，主操作“审批通过/审批驳回”位于详情滚动区末尾，首屏看不到。

4. **手机调拨详情滚动到底：可操作，但主次层级倒置**
   - 证据：[05-mobile-detail-scrolled-actions.png](audit-screenshots/todo-20260713-r4/05-mobile-detail-scrolled-actions.png)
   - 复核确认不是 CSS 真正覆盖：用户滚动约 100px 后可看到审批按钮。问题是次要操作常驻，主要操作需要额外发现。

5. **审批确认：流程健康，摘要不完整**
   - 证据：[04-mobile-confirm.png](audit-screenshots/todo-20260713-r4/04-mobile-confirm.png)
   - 确认弹窗重复了标题、单号和时间，但调拨审批没有再次展示申请数量和参考总价。

6. **关键词空结果：可用，统计口径易误解**
   - 证据：[06-mobile-empty-keyword.png](audit-screenshots/todo-20260713-r4/06-mobile-empty-keyword.png)
   - 搜索结果是 0 条时，上方仍显示“全部 48”。当前设计是统计仅受来源和组织范围影响，不受关键词影响，但使用者容易理解为数据不一致。

## 剩余问题优先级

### P1

1. **手机详情主操作首屏不可见**
   - 建议将“审批通过/驳回”放入详情常驻底栏；“刷新/切换上下文”收入更多操作或页头。

2. **调拨确认摘要缺少数量和金额**
   - 建议不再只使用通用 `item.detail`，而是为各业务类型提供结构化 `reviewFields`，调拨至少包含调出、调入、数量、金额和当前审批节点。

3. **跨组织待办会改变全局当前组织**
   - 实测进入北京柏悦单据后，返回待办再选“当前组织”已是北京柏悦。页面显示了新组织，但没有明确告知这是持久上下文切换。
   - 建议优先采用临时业务上下文；若必须全局切换，需显示提示、支持一键恢复原组织。

### P2

4. **关键词与上方统计口径不直观**
   - 可选方案：统计跟随关键词；或在搜索框旁明确写“上方统计不受关键词影响”。

5. **大待办量缺少排序解释和快速聚焦**
   - 建议显示“紧急优先·最早创建优先”，并补充“只看临期/只看我能处理”等高价值快速筛选。

6. **窄桌面筛选区换行不稳定**
   - 建议将桌面筛选区响应式断点从 900px 适当提高，或直接使用网格布局，避免查询按钮单独占行。

## 无障碍与证据边界

- 已确认的优点：分类按钮有按下状态，搜索和范围控件有可访问名称，详情和确认使用模态对话框语义，主要触摸目标为 44px。
- 风险：主审批按钮首屏不可见是触屏可发现性问题，但按钮本身仍在语义和焦点顺序中。
- 未完整验证 VoiceOver/其他屏幕阅读器、200% 缩放和软键盘弹出后的所有组合状态，因此不声称完整 WCAG 合规。
- 浏览器控制台本轮为 0 条错误。

## 工程侧已知风险

- 生产构建仍有入口包体积警告，应将路由级拆包和 Element UI 体积治理列为后续性能任务。
- 工作区 `erp-ui/node_modules` 当前为异常自引用链接，本机 Homebrew Node 也有动态库缺失；目前需依赖隔离的本机临时目录和内置 Node 才能稳定复现构建。
