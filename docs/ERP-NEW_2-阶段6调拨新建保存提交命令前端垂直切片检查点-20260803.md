## 1. 本检查点结论

新前端的调拨新建页已从单一“完成 Mock 演练”拆成“保存 Mock 草稿”和“提交 Mock 审核”两个明确命令。页面仍默认使用 ERP-NEW_2 内存 Mock，不会因为本检查点启动任何真实服务；同时冻结了可切换到隔离后端的 HTTP writer，路径和安全边界与当前后端 `InvTransferController` 的 `/transfer/save`、`/transfer/submit` 一致。

## 2. 命令契约

- `transfer-command.contract.ts` 使用严格 Zod 对请求 ID、组织上下文、调拨类型、组织方向、明细数量和物料行去重进行校验。
- 浏览器层保留字符串标识，允许隔离 Mock 使用 `mock-*` 标识；HTTP writer 在发送前要求组织、调拨单、版本、仓库、物料、批次和库位标识均为浏览器安全范围内的正整数。
- 请求 ID 只作为 `X-Request-Id` 头发送，不进入 JSON body；组织上下文只通过 `ErpHttpClient` 的组织头发送，也不进入 body。
- JSON body 仅保留后端 `InvTransferOrder`/`InvTransferDetail` 已确认的字段白名单。页面的“期望到货日期”仍是当前原型的 UI 校验字段，未在后端字段契约冻结前偷偷写入命令。
- 响应只接受调拨标识、单号、生命周期状态和版本四个字段；保存必须返回 `draft`，提交不得仍为 `draft`，版本倒退或单据标识漂移立即失败即关闭。

## 3. 页面与 Mock 行为

- 新建页在第三步提供保存草稿和提交审核两个操作；同一操作的重试复用同一个请求 ID，Mock 侧按请求指纹拒绝同 ID 不同 payload。
- 操作进行中两个按钮均禁用，成功后展示单号、标识、版本状态和“未向后端、数据库或共享服务发送内容”的明确提示。
- 页面继续遵循 ERP/SaaS 高频工作台动效门槛：不增加列表、表单或对话框进入动画，只保留确认反馈和键盘可操作性。
