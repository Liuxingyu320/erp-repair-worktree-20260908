## 1. 本检查点完成内容

P12 在 P11 只读退回发货计划之后建立了一个退回专属、固定隔离来源的 V2 原子发货创建参与者：

- 新增浏览器安全请求 DTO 和 JavaScript 安全结果 VO；
- 新增纯创建策略，验证根请求、计划版本、固定依据、审批修订、唯一明细、仓库存模式、数量和成本；
- P10 生命周期增加包内协作缝，可先锁定全部隔离事实并校验 P11 计划，再对本批任意数量做无 DML 精确消费预演，最后绑定真实发货标识执行同一消费计划；
- 新增退回专属条件 Mapper，只负责推进子调拨累计发货数量和主单状态；
- 新增 `Propagation.MANDATORY` 创建 Service，在未来根幂等事务中统一创建 V2 发货、消费隔离预留并写不可变审计；
- 新增双条件独立写开关，`write-enabled` 和 `receipt-boundary-ready` 均默认 `false`。

没有修改普通 FEFO/FIFO 发货候选选择、普通调拨预留消费或旧发货入口。

## 2. 固定锁序与首条 DML 边界

创建参与者的锁序固定为：

1. 退回子调拨主单；
2. 当前已审批封存修订；
3. 唯一调拨明细；
4. 来源仓库存模式；
5. P10 隔离预留归属事实；
6. 汇总库存；
7. 精确隔离余额；
8. ACTIVE 序列号绑定和物理序列号。

首条 DML 之前已经完成：

- P11 `planVersion` 重算与精确匹配；
- 子调拨来源、状态、版本、审批轮次和唯一明细一致性验证；
- 当前审批修订和封存快照验证；
- 明细库存权威模式与非空对账批次验证；
- P10 任意数量消费预演，证明本批不超量、冻结库存守恒、成本不漂移，且序列号只能使用已冻结绑定的确定前缀。

任何事实漂移都会在创建发货批次之前失败关闭，不降级到普通库存或共享库存。

## 3. 同一事务内的写入顺序

验证通过后，未接线创建参与者按以下顺序写入：

1. 创建带根请求、P11 计划版本、封存修订和对账批次的 `V2_DETAIL` 发货批次；
2. 创建唯一发货明细；
3. 通过 P10 已锁定事实消费汇总/精确冻结库存、序列号和隔离预留，并追加消费事件；
4. 写汇总库存日志；
5. 写 `FIXED_RETURN` 不可变来源分配；
6. 写发货序列号不可变审计；
7. 写明细库存不可变流水；
8. 以旧数量、旧状态、旧版本、审批轮次和来源归属为条件推进子调拨明细及主单；
9. 写状态日志并返回字符串化业务标识、数量、金额和版本。

任一生成键或影响行数异常都会抛错，交由未来根事务整体回滚；本实现没有补偿 SQL。

## 4. 关闭性与静态隔离审计

- 创建 Service 仅引用自身，生产代码中没有 Controller、Command Service、HTTP、前端或自动回调调用点；
- P10 生命周期 Service 的新增包内协作缝只被自身和该未接线创建参与者引用；
- 创建方法强制 `Propagation.MANDATORY`，不能自行开启孤立事务；
- 两个开关仅在代码注入点声明默认 `false`，资源配置中没有启用值；
- 新 Mapper XML 只有 `advanceChildDetail`、`advanceChildOrder` 两条条件 `UPDATE`，没有查询、插入、删除或额外锁；
- 本检查点没有新增 DDL 或 SQL 迁移文件；
- 新生产文件未发现受保护业务库名、受保护原项目路径、Docker Compose、JDBC、Nacos 或共享 Redis 连接字样；
- inventory 当前为 407 个主 Java 源文件、155 个测试 Java 源文件。
