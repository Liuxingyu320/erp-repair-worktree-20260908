# ERP-NEW_2 阶段 13P4：受损隔离库存原子写销实施计划

> 日期：2026-08-03

> 分支：`codex/erp-new-2-rebuild`

> 基线：`b6e297f4 feat: add accessible frontend empty states`

## 1. 目标

为 `damaged + damage_write_off/transport_loss_write_off` 建立一个仍未接入生产入口的真实原子效果边界：只从 V2 收货生成的受损隔离库存中扣减裁决动作数量，同步报废相关序列号，并追加不可变库存流水、损失台账和序列号处置台账。

执行入口继续默认关闭并保留最终无条件硬停止。本阶段不执行 SQL、不连接数据库、不启动服务，也不代表真实业务数据已发生写销。

## 2. 权威锚点与守恒

写销事实必须沿唯一关系解析：

1. 差异事项 `inv_transfer_receipt_discrepancy_case`；
2. 裁决头和目标动作；
3. 事项绑定的 V2 收货批次与收货分配；
4. 分配记录中的 `damaged_target_lot_id`、`quarantine_location_id`、`damaged_target_balance_id`；
5. 收货批次的目标仓库和该物料唯一汇总库存；
6. `disposition=damaged` 的收货序列号及其当前隔离位置。

动作数量与金额使用裁决冻结值，不重算当前商品价格。写销前后必须同时满足：

- 汇总库存：`current = available + locked + quarantine`；
- 受损余额：`current = available + locked + quarantine`，并且该余额只允许 `available=0`、`locked=0`；
- 当前数量、隔离数量和总成本均足以覆盖本动作；
- 动作金额等于本次从汇总库存和受损余额移除的成本；
- 收货分配累计已写销数量加本动作不得超过其原始受损数量；
- 序列号策略下，动作数量必须为整数，选中的隔离序列号数量必须与动作数量完全一致；非序列号策略不得出现序列号处置记录。

## 3. 固定锁序与 DML 所有权

未来外层执行事务固定按以下顺序持锁：

1. 差异事项；
2. 裁决头；
3. 全部裁决动作；
4. 同请求历史执行事件；
5. V2 收货批次；
6. V2 收货分配；
7. 目标汇总库存；
8. 受损派生批次；
9. 隔离库位；
10. 受损批次库位余额；
11. 相关收货序列号与当前序列号事实。

新增效果所有者使用 `Propagation.MANDATORY`，只能加入既有事务。它是本效果唯一允许执行库存、余额、序列号和损失台账 DML 的组件。所有单行更新或插入必须精确影响一行，否则抛错并由外层事务整体回滚。

未来事务必须在物理 DML 前先追加本请求的不可变执行事件；损失台账插入会按请求、事项、裁决、动作、前后版本、效果类型和事件指纹重新核验该事件存在。这样即使效果所有者被错误地放入一个无执行事件的普通事务，最终条件插入也会失败并将前序库存 DML 标记为回滚。

## 4. 序列号分配协议

裁决请求没有客户端序列号清单，因此服务端不得接受客户端自由指定物理单件。对序列号物料，Mapper 锁定该收货分配仍处于原受损余额、批次和隔离库位的全部 `damaged` 序列号，纯策略按 `receipt_serial_id, serial_id` 稳定排序，选择本动作所需数量。

每个选中单件必须先从 `quarantine` 精确更新为 `scrapped`，再追加动作—收货序列号映射。映射表对 `receipt_serial_id` 和 `serial_id` 分别设置唯一约束，从数据库层阻止同一单件被其他写销动作重复消费。后续退回效果必须复用同一“剩余未处置单件”协议并排除已写销映射。
