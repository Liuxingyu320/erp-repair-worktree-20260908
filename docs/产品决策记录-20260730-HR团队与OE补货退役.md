# 产品决策记录：HR 团队与独立 OE 补货退役

- 决策日期：2026-07-30
- 状态：已批准并实施
- 决策编号：DEC-20260730-01、DEC-20260730-02

## 决策

### DEC-20260730-01：退役“我的团队”

“我的团队”不再是需要独立维护的产品能力，删除 PC/移动入口、前后端专属代码、菜单、按钮权限和功能开关。

员工档案、组织关系、资料完整度和健康证仍是现役能力；原团队查询场景统一由这些页面按既有数据范围承接。

### DEC-20260730-02：退役独立 OE 补货链路

OE 属于固定资产，只走固定资产上报通道。保留 OE 主数据、固定资产配置、固定资产上报记录、额度台账及其正常查询；固定资产上报不再投递独立补货事件。

删除以下独立链路：

- OE 补货页面、移动路由、接口和待办；
- OA 固定资产补货发件箱接口、调度器、运维台和死信待办；
- 库存补货需求处理服务、专用调拨创建入口、专属指标和告警；
- 三个退役功能开关及相关菜单、角色权限。

## 数据处理原则

- 不删除 `oa_fixed_asset_replenishment_outbox`、`inv_oe_replenishment_demand`、`inv_oe_replenishment_transfer` 中的历史业务行。
- 未完成发件箱统一终止为 `DEAD / FEATURE_RETIRED`；未完成补货需求统一关闭并写入退役原因。
- 已产生的调拨单和关联关系继续保留，可按历史单据完成必要的发货、收货和审计查询。
- 禁止新建或编辑来源为 `oe_replenishment` 的调拨；普通调拨也不得直接选择 OE 固定资产。
- 旧建表迁移和 2026-07-14 发布证据作为历史记录保留，不代表功能仍在运行。

## 实施记录

| 范围 | 结果 |
|---|---|
| Web/移动端 | 删除团队页、OE 补货页、路由、API、快捷入口和深链映射 |
| HR 后端 | 删除团队专属 Controller、Service、Mapper 和 DTO |
| OA 后端 | 固定资产上报仅写固定资产记录与台账；删除补货发件箱运行时代码 |
| 库存后端 | 删除补货需求运行时代码和专用调拨创建；保留历史调拨兼容 |
| 菜单与权限 | 通过退役迁移删除菜单、按钮授权和功能开关 |
| 历史数据 | 只归档未完成状态，不删表、不删业务行 |
| 运维 | 现役对账与告警移除 OE 补货；旧合同归档到 `docs/releases` |

数据库执行文件：`sql/erp_retire_hr_team_oe_replenishment_20260730.sql`。

## 验收口径

1. PC、移动端、待办和菜单中均无“我的团队”及“OE 补货需求”入口。
2. 固定资产上报不依赖 OE 补货功能开关，且不创建发件箱或库存补货需求。
3. 退役权限和配置不存在，新接口不能创建 `oe_replenishment` 调拨。
4. 旧发件箱、需求、关联和调拨数据仍可用于审计，迁移可重复执行。
5. 现役监控、对账和发布检查不再把退役队列当成运行故障。
