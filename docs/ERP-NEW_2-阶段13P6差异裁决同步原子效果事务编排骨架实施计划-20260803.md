# ERP-NEW_2 阶段 13P6：差异裁决同步原子效果事务编排骨架实施计划

> 日期：2026-08-03
>
> 分支：`codex/erp-new-2-rebuild`
>
> 基线：`3f840130 feat: enforce adjudication coverage closure`
>
> 范围：组合已有三类同步效果、执行事件和状态推进；不接线执行入口，不实现补发/退回，不执行 SQL

## 1. 审计结论

阶段 13P2 至 13P5 已分别建立执行纯策略、条件状态 Mapper、责任/短缺损失台账、受损隔离库存写销和双覆盖维度，但还不能形成一次原子执行：

1. 当前没有唯一外层事务拥有“锁定 → 准备 → 事件 → 效果 → 状态”的完整顺序；
2. 已有执行事件读模型没有对应的精确请求重放策略；
3. 受损写销要求执行事件先存在，责任/短缺台账尚未在 SQL 中复核同一事件，两个同步效果边界不一致；
4. 补发和退回仍缺少受动作唯一约束的 V2 子调拨创建、库存冻结、终态核验与恢复协议；
5. 当前硬关闭入口只有 Gate，不注入 Mapper 或效果所有者，必须继续保持不可达。

因此本阶段只能组合已经具备权威效果实现的三类同步动作：

- `responsibility_ledger`；
- `shortage_loss_ledger`；
- `quarantine_write_off_and_loss_ledger`。

`reship_workflow` 与 `return_workflow` 在首个事件或效果 DML 前失败关闭。

## 2. 唯一事务与固定顺序

新增一个没有生产调用点的事务所有者，固定顺序为：

1. 从服务端登录快照校验独立执行权限；
2. 解析并校验当前组织范围；
3. 锁定差异事项主行；
4. 以只读组织锚点验证事项属于授权范围；
5. 锁定裁决头；
6. 按 `action_sequence, adjudication_action_id` 锁定全部动作；
7. 锁定同请求历史执行事件；
8. 若存在事件，只允许完全一致的请求与同一操作者只读重放；
9. 若不存在事件，使用纯策略重新推导效果、覆盖维度、版本和聚合状态；
10. 在任何物理效果前追加一条不可变执行事件；
11. 由效果类型唯一选择一个同步效果所有者；
12. 条件推进目标动作、裁决计划和差异事项；
13. 返回服务端执行结果快照。

任一步骤抛错、条件 DML 不是精确一行或效果 DML 不守恒，整个事务回滚；执行事件也随事务回滚，不留下“有事件、无效果”的部分事实。

## 3. 幂等重放

重放必须比较：

- 请求 ID、事项、事项前版本、裁决、动作、动作前版本；
- 命令与效果引用；
- 服务端重新推导的动作类型、覆盖维度和效果类型；
- 事件中的前后版本、前后状态、权限、操作者和指纹格式；
- 同步/异步转换矩阵与效果引用格式。

请求 ID 被不同事项、动作、版本、命令、引用或操作者占用时失败关闭。重放不再次执行效果、不追加事件、不推进状态。

## 4. 事件先行与效果路由

两个原子台账 Mapper 补充与受损写销一致的事件存在条件：请求、事项、裁决、动作、版本、效果类型和事件指纹必须完全匹配，才能追加业务台账。

事务所有者只允许以下路由：

| effectKind | 所有者 | 新请求命令 |
| --- | --- | --- |
| `responsibility_ledger` | 原子台账效果所有者 | `dispatch` |
| `shortage_loss_ledger` | 原子台账效果所有者 | `dispatch` |
| `quarantine_write_off_and_loss_ledger` | 受损写销效果所有者 | `dispatch` |

异步补发/退回无论 `dispatch` 还是 `complete` 均不进入本事务骨架的写路径。

## 5. 组织与请求边界

- 内部命令继续不接受操作者、权限、效果类型、数量、金额、责任方或覆盖维度；
- 操作者与权限只从 `SecurityUtils` 登录快照取得；
- 当前组织通过独立 `ShopScopeService` 解析，事项关联原调拨的来源或目标组织必须命中授权集合；
- 组织校验只读，不把原调拨头纳入 `FOR UPDATE` 锁序；
- 事务方法不加入 Controller、HTTP、RPC、任务、消息消费者或现有硬关闭入口。

## 6. 验证

离线测试至少证明：

- 三种同步效果各自只路由到唯一所有者；
- 执行事件严格先于效果，效果严格先于三层状态推进；
- 完全一致请求只读重放，不产生任何 DML；
- 请求或操作者漂移、组织越权、异步动作、任一非单行 DML均失败关闭；
- 外层方法拥有回滚事务，两个效果所有者仍要求 `MANDATORY`；
- 原硬关闭入口字段、Gate 默认值、最终异常和无生产调用点保持不变；
- Mapper 绑定、SQL 条件、inventory 模块回归和 `git diff --check` 全部通过。

## 7. 停止线

- 不实现或模拟补发、退回子调拨；
- 不开放执行 Service，不新增 Controller、路由、菜单或权限种子；
- 不启用 Gate，不修改运行配置；
- 不执行 SQL，不连接数据库，不启动服务或中间件；
- 不使用 Docker，不安装或升级依赖，不处理真实秘密；
- 不删除旧前端，不访问受保护原项目，不合并、不推送。
