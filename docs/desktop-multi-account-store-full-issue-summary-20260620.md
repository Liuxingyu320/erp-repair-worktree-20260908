# 多账号多店铺桌面端全流程检查问题汇总（2026-06-20）

## 检查结论

本次检查覆盖电脑网页端的多账号、多店铺/仓库上下文、主要页面菜单、页面按钮、弹窗、副流程和高风险业务流程。按真实运行库 `BossERP_stock_state_75c59ee` 统计，当前启用桌面页面 45 个、功能/按钮权限 178 个。

本报告只汇总问题和改进建议，未修改业务代码。破坏性动作没有真实提交，例如实际发货、实际收货、实际库存调整、实际退货确认、实际盘点确认等，只检查到弹窗、按钮、权限、源码提交路径和非提交前的流程。

## 重要校正

1. 真实运行库是 `BossERP_stock_state_75c59ee`，不是 `BossERP`。前面按 `BossERP` 查出的部分角色/菜单结论已作废。
2. 运行库里 `codex_184407_store`、`codex_184407_multi`、`cx190041wh` 可登录；`codex_184407_warehouse` 因用户名长度被登录规则拒绝。
3. “调拨记录没有入口”这一早期判断已校正：运行库中门店端和仓库端菜单都已有调拨记录入口。
4. “茶艺师权限过大”这一早期判断来自旧库，不作为当前问题。当前确认的问题是店长角色 `dz` 权限偏宽。

## P1 高优先级问题

### P1-01 用户名保存规则和登录规则不一致

现象：用户实体和前端用户表单允许较长用户名，但登录服务只允许用户名长度不超过 20。运行库里存在 `codex_184407_warehouse`，但登录时报“用户名不在指定范围”。

证据：
- `erp-auth/src/main/java/com/erp/auth/service/SysLoginService.java:66` 登录限制 `USERNAME_MAX_LENGTH`。
- `erp-api/erp-api-system/src/main/java/com/erp/system/api/domain/SysUser.java:159` 用户账号注解允许最大 30。
- `erp-ui/src/views/system/user/index.vue:134` 输入框 `maxlength="30"`，同文件 `:269` 表单规则又写 2 到 20。

建议：统一用户创建、导入、编辑、登录的用户名长度规则。已有超过登录上限的账号需要迁移或禁止保存。

### P1-02 门店店长角色权限偏宽

现象：真实门店账号登录后角色为 `dz`，运行时权限包含库存调整、调拨发货、调拨收货、调拨审批、发货通知执行、盘点确认、销售退货确认等高风险权限。虽然部分按钮会被门店/仓库上下文隐藏，但权限码本身偏宽，后端接口层仍存在越权风险。

证据：
- 真实账号 `liu123` 获取到 `inv:stock:adjust`、`inv:transfer:deliver`、`inv:transfer:receive` 等权限。
- 运行库 `sys_role_menu` 中 `dz` 角色包含库存调整、调拨出库/入库、调拨审批、执行发货、盘点确认等权限。

建议：按岗位拆分门店店长、门店收货、仓库发货、库存调整、审批角色。高风险接口必须以组织类型和责任节点二次校验，不能只靠前端隐藏。

### P1-03 无成本查看权限也能看到商品采购价/成本价

现象：门店账号没有成本查看权限，但商品管理页仍显示“采购价”“成本价”列。

证据：
- `erp-ui/src/views/inventory/product/index.vue:111` 显示采购价列。
- `erp-ui/src/views/inventory/product/index.vue:116` 显示成本价列。
- 这些列没有 `v-hasPermi` 或专门的成本查看控制。

建议：采购价、成本价、毛利相关字段统一加权限控制。无权限时隐藏列或脱敏显示。

### P1-04 门店账号界面可见“库存调整”

现象：门店店长账号进入门店库存页时可以看到“库存调整”按钮，且角色权限包含 `inv:stock:adjust`。

证据：
- 门店账号访问 `/inventory/stock?stockEntry=store` 时按钮列表包含“库存调整”。
- `erp-ui/src/views/inventory/stock/index.vue:832` 库存调整提交有确认框，但门店店长是否应具备该入口需要业务明确。

建议：库存调整建议独立为高权限能力，默认不授予普通门店店长。门店盘点差异应走盘点确认流程，不应随意手工调整。

### P1-05 运行库和常用库名不一致，容易误操作

现象：服务实际连接 `BossERP_stock_state_75c59ee`，但手工检查时很容易误查 `BossERP`。这会导致账号、角色、菜单结论错位，也可能导致运维改错数据库。

证据：
- `erp-modules/erp-system/src/main/resources/application-dev.yml` 和 `bootstrap.yml` 指向 `BossERP_stock_state_75c59ee`。

建议：本地启动说明、SQL 脚本、检查命令统一标注当前运行库。避免同机器保留多个相似库名且无明显提示。

## P2 中优先级问题

### P2-01 采购收货缺少二次确认

现象：采购收货弹窗点击“提交收货”后，校验通过即调用收货接口，缺少包含采购单号、仓库、商品数量的二次确认。

证据：
- `erp-ui/src/views/inventory/purchase/index.vue:603` `submitReceive()`。
- `erp-ui/src/views/inventory/purchase/index.vue:637` 直接调用 `receivePurchase(...)`。

建议：增加确认框，展示采购单号、当前仓库、收货商品、数量汇总，并提示会写入库存。

### P2-02 采购质检缺少二次确认

现象：采购质检弹窗提交后直接调用质检接口，没有再次确认质检结果和影响。

证据：
- `erp-ui/src/views/inventory/purchase/index.vue:653` `submitQualityCheck()`。
- 后续直接调用 `qualityCheckPurchase(...)`。

建议：质检通过/不通过都应二次确认，尤其要提示会推进采购单状态或影响后续入库流程。

### P2-03 调拨发货缺少二次确认

现象：仓库调拨发货弹窗信息较完整，但点击“确认发货”后直接调用接口。该动作会生成发货批次并影响仓库库存。

证据：
- `erp-ui/src/views/inventory/transfer/index.vue:1000` `submitShipment()`。
- `erp-ui/src/views/inventory/transfer/index.vue:1010` 直接调用 `deliverTransfer(...)`。

建议：增加确认框，展示调拨单号、要货门店、发货仓库、本次发货数量和商品列表。

### P2-04 调拨收货缺少二次确认

现象：门店调拨收货弹窗点击“确认收货”后直接调用接口。该动作会写入门店库存。

证据：
- `erp-ui/src/views/inventory/transfer/index.vue:1064` `submitReceipt()`。
- `erp-ui/src/views/inventory/transfer/index.vue:1078` 直接调用 `receiveShipment(...)`。

建议：增加确认框，展示批次号、要货门店、来源仓库、本批待收和本次入库数量。

### P2-05 采购退货确认提示过粗

现象：采购退货确认有二次确认，但只提示“将扣减对应商品的库存”，没有展示仓库、退货单号、供应商、数量汇总。

证据：
- `erp-ui/src/views/inventory/purchaseReturn/index.vue:357` `handleConfirm(row)`。
- `erp-ui/src/views/inventory/purchaseReturn/index.vue:359` 确认文案过于笼统。

建议：确认文案补充退货单号、当前仓库、供应商、商品数量和库存影响。

### P2-06 采购退货页面上下文提示不足

现象：采购页面有“当前采购仓库”提示，采购退货页没有同等强度的当前仓库提示。新增退货单弹窗里也没有明确扣减哪个仓库。

建议：页面顶部和新增/确认弹窗都显示当前仓库和库存影响方向。

### P2-07 系统工具父菜单禁用但子菜单启用

现象：`表单构建`、`代码生成`、`系统接口` 是启用子菜单，但父级“系统工具”处于禁用/隐藏状态，入口和授权关系不一致。

证据：
- 运行库 `sys_menu` 中子菜单 `114/115/116` 启用，父菜单 `3` 状态不是启用。

建议：父子菜单状态保持一致。若功能不使用，应全部禁用；若要使用，应启用父菜单并纳入导航。

### P2-08 监控和工具外链硬编码 localhost

现象：Sentinel、Nacos、Admin、Swagger 等菜单直接指向 `localhost`。部署到其他机器或给普通用户使用时会打开用户本机地址。

证据：
- 运行库菜单中存在 `http://localhost:8718`、`http://localhost:8848/nacos`、`http://localhost:9100/login`、`http://localhost:8080/swagger-ui/index.html`。

建议：改为配置项或相对网关地址，并按环境显示。

### P2-09 调拨审批配置入口和调拨业务入口割裂

现象：调拨审批配置挂在系统管理下，而调拨业务在进销存/仓库管理下。业务人员配置审批规则时不容易从调拨业务流转到配置页。

证据：
- 运行库 `调拨审批配置` 菜单在系统管理下。

建议：调拨管理页增加“审批规则配置”入口，或在调拨审批配置页增加业务说明和返回调拨管理入口。

### P2-10 调拨审批规则可配置成无候选人

现象：此前检查发现审批规则可以出现无候选人的配置，后续审批会卡住。

建议：规则保存时必须校验候选角色/用户/组织不为空；预览时展示候选人数量和具体范围。

### P2-11 调拨审批预览信息不足

现象：预览只看到类似“匹配规则：市场部门”的结果，缺少完整审批路径、审批人范围、兜底规则、无候选风险提示。

建议：预览展示命中的规则、节点列表、每个节点候选人、找不到候选人的处理策略。

### P2-12 OA 首页仍引导采购申请，但采购申请菜单不可用

现象：OA 首页文案建议用户使用采购申请，但运行库当前没有启用采购申请页面，只保留待办/已办等入口。

建议：首页文案按实际启用菜单动态展示，避免引导用户去找不存在的入口。

### P2-13 劳动合同员工选择缺少组织/门店信息

现象：劳动合同员工下拉会展示较宽范围用户，缺少当前组织、门店、岗位等上下文，容易选错员工。

证据：
- `erp-ui/src/views/oa/laborContract/index.vue:526` 附近员工选择逻辑。

建议：员工下拉显示“姓名 + 部门/门店 + 岗位”，并默认按当前组织过滤。

### P2-14 劳动合同模板/文件链接存在环境硬编码风险

现象：此前检查发现合同模板链接存在 `localhost:8080` 相关路径或旧文件中类似逻辑，环境切换后可能打不开。

建议：统一走 `VUE_APP_BASE_API` 或后端返回可访问的文件网关地址，避免直接拼本机地址。

### P2-15 库存盘点列表/详情展示原始组织 ID

现象：库存盘点部分列表或详情展示门店/仓库 ID，而不是名称。后端已有名称字段时前端没有优先显示名称。

建议：列表、详情、导出统一显示组织名称，ID 只作为调试信息或隐藏字段。

### P2-16 薪资计算按钮权限前端控制不完整

现象：此前检查发现薪资计算按钮缺少前端 `v-hasPermi` 控制，后端需要权限但前端入口展示不够一致。

建议：工资查询、工资计算、工资配置、导出等按钮统一加前端权限控制，并保留后端校验。

### P2-17 多个新增/配置弹窗缺少当前组织提示

现象：销售退货、客户、供应商、薪资参数、劳动合同等弹窗中没有明显展示当前门店/仓库/组织。多账号多店铺场景下容易误操作。

建议：所有会新增、修改或影响业务数据的弹窗顶部显示当前组织，并在保存确认中再次出现。

### P2-18 商品选择器允许选择资料不完整商品

现象：采购选择商品时，部分商品缺少供应商或采购参考价仍可选，最后保存时才报错。

证据：
- `erp-ui/src/views/inventory/purchase/index.vue:512` 附近保存时才校验商品供应商。

建议：商品选择器中提前标记“资料不完整”，不可选或给出原因。

### P2-19 调拨记录和详情存在原始 ISO 时间

现象：调拨记录列表/详情会显示 `2026-06-18T04:17:22.000Z` 这类技术格式。

证据：
- `erp-ui/src/views/inventory/transfer/records.vue:53` 等时间列直接使用原始字段。

建议：统一格式化为 `YYYY-MM-DD HH:mm:ss`，并按本地时区显示。

### P2-20 导出确认文案不统一

现象：部分导出确认已包含筛选范围和安全提示，例如发货通知、调拨；部分仍只有“确认导出当前查询条件下的数据”，缺少数据范围和敏感性提示。

建议：所有导出统一包含当前组织、筛选条件、数据范围、安全提示。

## P3 低优先级体验问题

### P3-01 部分列表缺少重置按钮

现象：部分页面搜索区只有查询或导出，没有统一的重置按钮。此前观察到的页面包括采购、采购退货、库存变动日志、销售、销售退货、客户、供应商、考勤、工资、劳动合同模板页等。后续部分页面已有重置，但仍需逐页统一。

建议：所有带筛选条件的列表统一提供“搜索/重置”组合，并清空分页回到第一页。

### P3-02 公司/集团也允许进入系统，库存页又要求重选组织

现象：组织选择页允许选择公司/集团进入系统，但库存、采购、调拨类页面只接受门店/仓库上下文，用户会多走一步。

建议：如果当前账号主要是库存业务角色，默认推荐或自动选择第一个门店/仓库。公司/集团入口应明确是“汇总/系统管理视角”。

### P3-03 仓库/门店切换后的菜单标题有重命名逻辑，容易造成理解偏差

现象：门店上下文下“仓库管理”会变成“商品资料”，这是为了减少误解，但同一路由在不同组织下名字变化，培训和排查时容易混淆。

建议：保留业务化命名的同时，在页面面包屑或提示里显示真实模块归属。

### P3-04 库存调整商品选择信息不足

现象：库存调整选择商品时重点展示商品名称/编码，缺少批次、当前库存、库位、单位等信息，容易选错。

建议：选择器中展示当前组织库存、批次、库位、可用数量，并支持只选当前有库存商品。

### P3-05 采购退货、销售退货空状态可以更具体

现象：部分空状态只提示暂无数据，缺少下一步建议，例如去调整筛选、先创建销售单/采购单、切换组织。

建议：空状态按上下文显示下一步动作，并区分“无权限”“无组织”“无数据”。

### P3-06 初始密码提醒会阻断进入系统

现象：首次进入系统弹出“您的密码还是初始密码，请修改密码”。这是安全上正确的，但用户如果只是审计或临时账号，会多一步取消。

建议：保留提醒，但可增加“稍后处理”说明，或在账号创建时明确需要改密。

### P3-07 路径命名不统一

现象：同一库存/仓库模块存在 `/inventory/...` 和 `/cangku/...` 两套路径语义。虽然路由隔离有效，但排查和复制链接时容易混淆。

建议：统一路径命名或建立清晰的路径映射说明。

## 建议处理顺序

1. 先修用户名规则不一致、成本价泄露、店长权限偏宽。

3. 然后统一组织上下文提示、导出确认、重置按钮、时间格式。
4. 最后整理菜单层级、外链配置、路径命名和空状态体验。
