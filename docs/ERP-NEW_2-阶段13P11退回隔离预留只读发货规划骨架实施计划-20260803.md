# ERP-NEW_2 阶段 13P11：退回隔离预留只读发货规划骨架实施计划

> 日期：2026-08-03
>
> 分支：`codex/erp-new-2-rebuild`
>
> 基线：`89e5557f feat: govern adjudication return reservation lifecycle`
>
> 范围：建立无 DML、无 HTTP、无生产调用点的专属退回发货规划；不创建发货，不消费或释放库存

## 1. 审计结论

普通 V2 发货规划和创建链不能直接服务于差异退回子调拨：

1. 普通规划只接受 `available_quantity` 大于零的合格候选，并明确排除隔离库位；
2. 普通创建只锁定和消费 `inv_transfer_reservation`，差异退回拥有的是 `inv_transfer_quarantine_reservation`；
3. 普通明细 DML 扣减 `available_quantity`，退回发货必须从唯一受损余额的 `locked_quantity` 消费；
4. 普通序列号要求物理状态为 `available`，退回序列号当前状态为 `quarantine_reserved`；
5. 普通 FEFO/FIFO 会在多个可用批次库位中分配，退回只能使用 P9 已冻结的唯一批次、库位及具体单件；
6. P10 已实现权威消费策略和事务所有者，但当前必须先有合法 V2 发货及发货明细才能追加消费事件。

因此 P11 只建立专属只读规划，冻结未来命令所需的输入、来源和计划指纹；写事务仍留在后续阶段。

## 2. 规划语义

规划只接受 P10 可消费的开放预留：

- 预留状态为 `ACTIVE` 或 `PARTIAL`；
- 子调拨状态为 `approved`、`reserved` 或 `partial_delivered`；
- 当前审批轮次与预留轮次一致；
- `reserved = consumed + released + remaining`，且开放预留的 `released = 0`；
- 子调拨累计发货量等于预留累计消费量；
- 汇总库存与精确隔离余额的维度、版本、成本和数量守恒完整；
- 序列号物料的 ACTIVE 绑定数等于剩余数量，物理状态仍为 `quarantine_reserved`。

只读计划默认建议一次发出全部剩余量。批次物料形成一个固定的余额/批次/库位分配；序列号物料按 `receipt_serial_id, serial_id` 稳定列出全部剩余单件。未来分批发货命令可以在新事务中提交正数且不超过计划上限的数量，但必须重新锁定并重放 P10 纯消费策略，不能直接信任预览。

## 3. 计划版本

`planVersion` 使用 SHA-256 覆盖：

- 裁决动作、工作流和决策指纹；
- 子调拨、唯一明细、审批轮次、状态和累计发货量；
- 隔离预留标识、请求、状态、版本及数量/成本；
- 汇总库存和精确余额的标识、版本、全部数量与总成本；
- 固定批次、库位和来源仓库；
- 每个剩余序列号绑定、收货单件、物理序列号、快照、状态和版本。

生成时间只用于展示，不进入计划版本。相同权威事实必须得到相同指纹；任一库存、预留、子调拨或序列号事实变化都必须改变指纹或使规划失败。

## 4. 代码边界

新增：

- `InvTransferReceiptDiscrepancyReturnShipmentPolicy`：组合 P10 纯消费预览并生成确定性计划；
- `InvTransferReceiptDiscrepancyReturnShipmentPlanningVo`：对 JavaScript 安全的只读返回结构，业务标识和小数均使用字符串；
- `InvTransferReceiptDiscrepancyReturnShipmentPlanningMapper` 及 XML：四个普通 `SELECT`，读取预留、汇总库存、精确余额和 ACTIVE 序列号，不使用 `FOR UPDATE`；
- `InvTransferReceiptDiscrepancyReturnShipmentPlanningService`：只读事务所有者，当前生产零调用点。

调整 P10 纯策略，将“消费计划”和“绑定到已存在发货的消费命令”拆开：

- `planAllRemainingConsumption(...)` 只验证并返回全部剩余量的纯变换；
- `prepareConsumption(...)` 继续校验真实发货标识和命令上下文，然后复用同一纯变换；
- P10 Service、Mapper 和运行时行为不接线、不改变。

## 5. 验证

- P10 纯策略回归证明全量与分批消费结果不变；
- P11 纯策略覆盖 lot、serial、确定性指纹、事实变化敏感性和无效生成时间；
- Mapper XML 测试证明所有方法已绑定、结果属性存在、没有 `FOR UPDATE`、DML、共享连接或运行配置；
- Service 测试覆盖成功映射、缺失预留、缺失库存事实和稳定生成时间；
- 静态引用测试证明新 Service 没有 Controller、HTTP、任务、消息或其他生产调用者；
- inventory 定向测试与完整离线 Reactor 通过。

## 6. 停止线

- 不新增或修改 Controller、路由、权限或前端 Gateway；
- 不创建 `InvTransferShipment`、发货明细、分配、序列号审计、库存日志或明细库存流水；
- 不调用 P10 生命周期 Service，不消费或释放任何预留；
- 不执行 SQL，不连接数据库，不启动应用、Docker 或其他服务；
- 不修改普通发货规划/创建、普通预留、审批或裁决执行入口；
- 不删除旧前端，不访问受保护原项目，不合并、不推送。
