## 1. 本检查点结论

门店补货新建页已从静态名称映射、静态 Mock 明细和浏览器库存上限，改造成稳定 ID、授权目录和服务端库存规划驱动的第一类正式调拨表单。草稿允许记录超过可用库存的申请数量并明确展示缺口；提交必须持有与当前组织、路线、物料和数量完全一致的新鲜规划，并且后端提交事务仍会重新锁定、校验和冻结全单库存。

本切片遵循正式方案第 4.8 节的内部顺序，只在 `NewTransferPage.vue` 实现“门店向仓库要货”。异店调货、门店返仓和销售发货自动调拨继续使用共享领域基础，但后续必须采用独立页面/流程，不能把所有方向堆入一个巨型条件表单。

## 2. 后端权威规划边界

- 新增 `POST /inventory/transfer/draft-planning` 对应的请求 DTO、只读 VO、服务和控制器入口；入口复用新增、编辑、提交权限，设置 `Cache-Control: no-store`，不使用 `@PersistentCommand`，不生成任何库存或业务写入。
- 请求冻结调拨类型、来源/目标组织、返仓原因和逐行物料身份/Decimal 数量；Bean Validation 限制 10,000 行、Long 正整数以及最多 14 位整数和 4 位小数。
- `InvTransferDraftPlanningService` 复用 `InvTransferDirectionPolicy`、组织授权范围和 `InventoryItemResolver`；停用物料、越权组织、错误方向、商品/物料身份漂移和不完整主数据均在库存读取前失败关闭。
- 来源和目标使用“当前用户获授权的全部有效门店/仓库”集合，而不是把当前门店的祖先/后代关系误当仓库权限；因此公司级授权下的兄弟仓库可以正常补货，未授权仓库仍会在读取物料或库存前被拒绝。
- 商品归属保持更窄的当前门店相关范围：允许当前门店及其祖先/后代组织商品，不会因为用户另有兄弟门店权限而串用兄弟门店商品。
- 同一来源仓库和商品归属校验也已加入现有 `saveDraft` 写入口，防止客户端绕过只读规划直接提交任意仓库或商品标识；新建草稿会先完整解析、授权并计算明细，再执行任何 Mapper 写调用。方向与组织类型仍由 `InvTransferDirectionPolicy` 二次校验。
- `InvTransferReservationService.previewForDraft` 与提交预留共用来源库存维度和确定性排序，但规划查询只读取 `available_quantity`、库存标识和版本；不读取成本字段，不执行 `FOR UPDATE`，不修改库存或预留记录。
- 缺失库存事实按可用量零返回；负可用量视为无效事实。响应逐行返回申请量、可用量、缺口、阻断原因，并使用库存标识/版本生成 SHA-256 `planVersion`。
- 最终提交继续由 `reserveForSubmission` 在一个事务内重新校验并冻结全部明细；规划结果不是写入授权，也不能避免规划之后的并发库存冲突。

## 3. 前端契约、HTTP 与 Gateway

- `transfer-draft-planning.contract.ts` 使用严格 Zod + Decimal 校验路线方向、稳定 ID、商品身份、数量精度、逐行缺口算术、重复物料、提交资格和阻断原因的一致性。
- HTTP reader 将浏览器字符串 ID 转为安全整数后调用同源规划端点；要求当前组织与 CSRF 上下文及响应 `no-store`，拒绝 Mock 标识、组织切换、可缓存响应、Mock 数据源、响应路线漂移和响应数量漂移。
- `TransferGateway`、不可用 Gateway 和隔离 Mock Gateway 已统一增加 `loadDraftPlanning`。真实运行时未装配时继续失败关闭；Mock 规划也经过同一 Zod 契约，不再从商品档案字段伪造库存余额。
- Mock 可用量使用独立的库存事实映射；组织状态按后端约定使用 `0=启用`。Mock 不连接任何服务、数据库或共享资源。
- 组织、路线、物料或数量变化立即使旧规划过期；关键字变化会中止并丢弃迟到目录响应；组织切换后的迟到命令结果不会覆盖新会话。
- 同一未确定结果的原载荷重试保留请求 ID；业务载荷变化会换新幂等键，避免同一请求 ID 携带不同 payload。
- 保存或提交命令进行中会冻结返回编辑与重新规划操作，避免旧载荷结果和新表单状态并发交错。

## 4. 新建门店补货页面

- 当前门店由会话组织锁定；来源只能从授权组织目录中的启用仓库选择，页面不允许代替其他门店发起补货。
- 商品通过当前组织商品目录查询、添加和移除；命令使用真实组织 ID、商品 ID/物料 ID 和 Decimal 字符串，不再维护名称到 Mock ID 的映射。
- 数量只校验正数与精度，不把可用库存当成草稿输入上限。缺货规划显示逐行可用量和缺口，保存草稿保持可用，提交按钮失败关闭。
- 规划未知、失败或过期时仍可保存结构有效的草稿，但禁止提交；充足规划允许提交，同时明确提示服务端仍会原子复核。
- 去除了未获得后端持久化契约支持的“期望到货日期”，避免把仅存在于 UI 的字段误导为已保存业务事实。
- 步骤切换后焦点移动到新步骤标题；异步状态使用 `aria-live`，校验错误定位到具体控件，组织/目录/规划失败均显示明确的失败关闭提示。

## 5. 视觉与动效决策

- 设计参考遵循项目已记录的 21st.dev、React Bits、UI Prompt Library、Magic UI、Motion Primitives、Uiverse 和 MotionSites 方向，但本页按 ERP 高频生产工具约束使用 Emil Kowalski 为主、Jakub Krehel 为辅的克制权重。
- 高频输入、商品添加/移除和键盘操作保持即时，不添加弹跳、循环光效、呼吸 CTA 或装饰性背景动画。
- 只对低频步骤切换和库存规划结果切换提供功能性状态过渡：进入约 180–200ms，退出约 90–120ms，使用自定义 Bézier；仅动画 `opacity`、`transform` 和 `filter`。
- `prefers-reduced-motion: reduce` 将所有新增过渡缩短到近即时，功能和焦点顺序不依赖动画。
