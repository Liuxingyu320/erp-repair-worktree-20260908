## 1. 本检查点结论

ERP-NEW_2 新前端继续沿用“服务端事实优先、浏览器边界显式校验、Mock 与真实 HTTP 读取路径分离”的重建原则。本切片冻结了调拨创建所需的组织树/物料目录读取契约，并把已经冻结的调拨详情读取契约接入只读详情页和工作台详情入口。

本检查点没有启动后端、Docker、MySQL、Redis、Nacos 或前端开发服务，也没有把任何页面接到真实运行环境。Mock 网关仍然只在 `VITE_ENABLE_MOCKS=true` 的 ERP-NEW_2 前端运行时内提供内存数据。

## 2. 组织与物料目录契约

- `transfer-catalog.contract.ts` 仅保留组织标识、名称、组织类型、启用状态和物料选择所需的展示字段；组织树递归校验，重复标识直接失败，不静默丢弃畸形子节点。
- `transferProductOptionSchema` 明确丢弃采购价、成本价、供应商联系方式等敏感或未冻结字段，兼容后端 Long/状态字段在 JSON 中的数字表达，并在浏览器侧规范化为字符串。
- 物料查询只接受组织、关键词、页码和页大小；禁止页面自行传入库存范围或未冻结的客户端过滤字段。
- `flattenTransferOrganizationTree` 把授权树转换成平面选项，同时保留组织类型和启用状态，供后续新建表单组合仓库/门店选择。

## 3. HTTP、Mock 与 Gateway 边界

- `transfer-catalog.http.ts` 使用同源 `GET /api/system/dept/shop-tree` 读取用户授权组织树，不发送 CSRF 或业务组织请求头；该接口本身由登录态和服务端授权范围保护。
- 物料读取使用 `GET /api/inventory/product/list?pageNum=...&pageSize=...&keyword=...&status=0`，要求当前组织请求头，并由 `ErpHttpClient.expectedOrganizationId` 防止组织切换后的陈旧请求发出。
- 真实读取器在发请求前拒绝 Mock 组织标识、路径化输入和超出浏览器安全整数范围的标识；网络响应继续通过旧系统 envelope/page 适配器和 Zod 契约校验。
- `TransferGateway`、不可用 Gateway 和 Mock Gateway 已同步提供 `loadOrganizationOptions`、`loadProductOptions`；Mock 目录支持关键词过滤、分页和 AbortSignal 检查，不连接任何服务。
- `TransferDetailPage.vue` 通过 `TransferGateway.loadDetail` 加载只读详情，路由 `/inventory/transfer/:transferId` 已接入；工作台桌面/移动操作均新增“详情”入口。页面不计算库存、不执行写入，成本/金额仅在 `inv:cost:view` 能力下呈现。
