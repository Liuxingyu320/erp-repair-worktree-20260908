## 2. 本轮完成的优化

### 2.1 查询契约与 Provider

- 统一增加 `urgent`、`important`、`normal` 三种优先级查询值，空白值规范化为未筛选。
- inventory、OA、system 对非法优先级统一返回 `不支持的待办优先级`，不静默回退。
- inventory 和 OA 在已计算优先级的公共事实集外层过滤，list、recent、counts 共用同一口径。
- system 在构造事项后、排序和分页前过滤，summary 与 page 共用同一结果集。
- 修正 system 待办列表成功响应原先仍使用默认 `code=0` 的问题，现与另外两个 Provider 一致返回成功码和 `查询成功`。

### 2.2 桌面与移动端易用性

- URL、请求参数、精确缓存键、分页和活动筛选标签全部纳入 `priority`。
- 全局顶部汇总保持不受页面优先级影响；页面 scoped summary 与列表使用同一优先级。
- 桌面端增加“全部、紧急、重要、普通”单选组，并支持单项移除和一键重置。
- 移动端增加 44px 高的可横向滚动优先级条，使用 `aria-pressed` 暴露选中状态。
- 移动卡片直接显示优先级文字，空态、排序说明和活动筛选摘要都能说明当前条件。
- 旧请求晚返回、Provider 精确缓存回退和 scoped summary 竞态由自动化测试锁定。

### 2.3 本机原生联调能力

- 新增 `scripts/local-todo-stack.sh`，支持 `preflight/start/status/health/logs/restart/stop`。
- 支持通过环境变量选择六个互不重复的备用端口，并按端口组合隔离 PID 与日志目录。
- local 服务发现和网关路由通过环境变量注入，不改 dev/prod Nacos 配置。
- 前端开发代理可指向选定的本机网关端口。
- 启动前检查 JAR 是否早于源码或构建配置，避免旧 JAR 伪造验收结果。
- 停止前核对 PID 对应完整命令，不抢占或停止非本脚本进程。
- local 网关验证码仅在本机脚本启动时关闭，未改变其他环境默认值。

### 2.4 首屏包体

- Element UI 改为按需注册，生产源码不再从根入口同步加载完整组件库。
- 自动扫描覆盖 62 个实际使用组件及程序式服务。
- 当前生产构建 app 入口为 1.469 MiB，低于项目更严格的 1.500 MiB 上限。
- `chunk-elementUI` 为 512.77 KiB（gzip 129.17 KiB）。
- 最大 gzip 资源为 213.65 KiB，低于 244 KiB 上限。
