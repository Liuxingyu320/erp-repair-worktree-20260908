# ERP-NEW_2 阶段 13P2：差异裁决动作权威引用与持久化契约实施计划

> 日期：2026-08-03
>
> 分支：`codex/erp-new-2-rebuild`
>
> 基线：`0b4422d6 feat: add adjudication execution safety skeleton`
> 范围：修正异步效果引用生命周期，冻结事项/计划/动作/事件的锁序与条件 DML；不接线执行入口，不执行任何物理库存、物流或财务效果

## 1. 审计结论

正式方案要求差异处理保留数量、金额、证据、责任方、操作者和前后状态，且只有真实效果完成后才能解决事项。对当前代码与 V2 表结构的只读审计得到以下结论：

1. 受损品在 V2 收货时进入目标仓 `quarantine_quantity`，并保留受损目标批次、余额、隔离库位和序列号处置审计；报损或受损运输损耗必须从这些权威明细扣减并追加损失台账。
2. 短缺没有进入目标库存；短缺运输损耗只写独立损失台账，不能伪造库存扣减。
3. 补发需要重新建立有明确库存归属的发货流程；退回应创建反向调拨流程，旧 V1 的直接聚合库存回加不满足 V2 批次、库位、序列号和成本事实。
4. 当前没有可证明满足 V2 要求的责任调整台账和运输损耗台账，后续必须使用新增的不可变业务台账，不能复用旧差异字段冒充效果。
5. 阶段 13O 的异步动作只在完成命令中记录子调拨引用，调度后无法权威定位在途子流程；同时事件表的效果引用唯一键会阻止同一引用追加“完成”事件。该缺口必须在持久化接线前修正。

## 2. 本阶段结果

本阶段建立一个仍不可运行的持久化契约：

- 异步补发/退回在 `dispatch` 成功时即绑定格式受限的子调拨引用；
- `complete` 必须使用动作上已经绑定的同一引用，不能替换子流程；
- 动作表保存唯一的 `execution_effect_reference`，事件表允许同一引用依次产生调度和完成两条事件；
- 新 Mapper 只覆盖事项、裁决头、裁决动作和执行事件，不包含任何库存、余额、批次、库位、序列号、调拨创建或财务 DML；
- 真实入口仍只有 Gate 字段、没有 Mapper、没有事务，并在 Gate 之后无条件硬停止。

这只是未来原子事务的结构边界，不表示任何动作已经产生物理效果。

## 3. 固定锁序

未来唯一允许的本地事务锁序为：

1. 差异事项主行；
2. 当前裁决计划头；
3. 当前计划全部动作，按 `action_sequence, adjudication_action_id` 稳定顺序；
4. 效果专属资源，按每类效果另行冻结的稳定顺序；
5. 请求 ID 对应的执行事件重放检查；
6. 执行物理效果；
7. 追加执行事件；
8. 条件推进动作、计划和事项。

任何条件更新行数不为 1、物理效果行数不守恒或事件唯一约束冲突，都必须回滚整个事务。不能先提交状态，再异步补写物理效果。

## 4. 本阶段 DML 白名单

新持久化 Mapper 只允许：

- `SELECT ... FOR UPDATE`：事项、当前裁决头、当前裁决全部动作、指定请求的执行事件；
- `INSERT`：追加执行事件；
- `UPDATE`：以精确前状态、前版本和已追加事件为条件，分别推进一个动作、一个计划头和一个事项；
- 禁止 `DELETE`；
- 禁止接触库存、库存明细、批次、库位、序列号、预留、发货、收货、调拨单、总账或旧差异表。

这些 DML 不接入任何生产调用点，直至效果专属事务能够与它们在同一事务中组合。

## 5. 后续效果分片

物理效果按证据充分程度拆分，不能用统一空实现替代：

1. `responsibility_ledger`：新增不可变责任调整台账；数量金额和责任方精确锚定裁决动作。
2. `shortage_loss_ledger`：新增不可变短缺损失台账；不变更目标库存。
3. `quarantine_write_off_and_loss_ledger`：锁定目标聚合库存、受损余额、批次、隔离库位和相关序列号，原子扣减隔离量并追加损失台账。
4. `reship_workflow`：创建受裁决动作唯一约束的补发子调拨，重新冻结明确来源库存并走 V2 发货/收货。
5. `return_workflow`：创建受裁决动作唯一约束的反向子调拨，从目标隔离库存发回来源仓。

补发和退回只有子调拨达到以后续计划冻结的权威终态时才能执行 `complete`。

## 6. 验证与停止线

验证包括纯策略引用状态、SQL 加法结构、MyBatis 绑定、DML 白名单、精确条件更新和无生产调用点。随后运行库存模块离线 Reactor。

本阶段不执行 SQL，不启动 Docker、服务或中间件，不连接 MySQL、Redis、Nacos 或任何数据库，不安装依赖，不开放 Controller/HTTP Writer，不修改运行配置，不删除旧前端，不合并、不推送。
