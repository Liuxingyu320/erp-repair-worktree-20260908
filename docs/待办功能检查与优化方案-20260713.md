# 待办功能检查与优化方案（2026-07-13）

## 目标与约束

- 覆盖首页入口、顶部待办、桌面待办中心、移动待办中心、组织切换、筛选与分页、精确跳转、服务异常与恢复。
- 优先修复会把用户带错位置、显示错组织或造成数量认知不一致的问题，再补充可恢复性和使用说明。
- 全程使用本机原生前后端服务与 Codex 内置浏览器，不使用虚拟机、Docker 或其他虚拟化环境。
- 工作区已有大量用户改动；修改只落在待办相关文件，并保留所有无关改动。

## 检查方法

1. 代码与数据契约检查：路由、Vue 生命周期、组织上下文、Vuex 汇总范围、三类待办提供方、现有测试。
2. 桌面真实流程：进入系统 → 顶部待办 → 待办中心 → 范围筛选 → 点击具体待办 → 验证目标业务与组织上下文。
3. 移动真实流程：移动待办 → 点击具体待办 → 验证详情与操作入口；只打开确认层，不提交业务数据。
4. 异常与恢复：提供方未启动、部分数据未知、刷新、返回待办中心、组织切换。
5. 修改后回归：自动化测试、构建检查、桌面/移动同路径截图对比、控制台和网络错误检查。

## 本轮发现

| 优先级 | 问题 | 用户影响 | 处理方案 |
| --- | --- | --- | --- |
| P0 | 桌面待办点击后，缓存中的待办中心继续监听新路由，把 `todoType/businessId` 覆盖为待办筛选参数 | 不能精确打开目标单据，用户需要二次查找 | 给桌面/移动待办页增加活动路由与 `activated/deactivated` 生命周期保护，非待办路由不再同步筛选参数 |
| P0 | 待办跳转切换组织后，顶部导航仍显示旧门店 | 用户可能在错误的组织认知下操作 | 让顶部导航订阅 `erp:dept-changed`，以响应式上下文渲染组织名称 |
| P1 | 顶部汇总请求未明确传 `scopeMode`，与待办中心默认“当前组织”口径可能不一致 | 徽标数量与列表数量不一致 | 汇总请求使用与页面相同的上下文感知范围：有效门店/仓库为 `current_org`，否则为 `all_authorized` |
| P1 | 顶部弹层点“查看全部”或具体待办后仍可能保持打开；数据未知时只能等待 | 遮挡后续页面，恢复入口不明显 | 跳转前关闭弹层；未知空态提供“重试”按钮 |
| P1 | “当前组织”未说明审批/个人事项仍按本人权限展示；移动端也不显示当前组织名称 | 容易误以为所有待办都只来自所选组织 | 桌面和移动增加范围口径说明；移动列表标题显示当前组织名称 |
| P2 | 首页入口文案只提“审批”，未覆盖执行、退回和风险 | 功能入口认知不完整 | 改为“集中处理审批、执行与风险事项” |
| P2 | 个别移动业务详情仍显示原始 ISO 时间 | 阅读成本偏高 | 记录为业务详情层后续统一格式化项，不在本轮扩大修改范围 |

## 修改范围与顺序

1. `erp-ui/src/views/workbench/todo/index.vue`：修复离开页面后的路由覆盖与异步写入，增加范围说明。
2. `erp-ui/src/views/mobile/todo/index.vue`：补齐同类生命周期保护，显示组织名称与范围说明。
3. `erp-ui/src/layout/components/Navbar.vue`：组织上下文响应式更新。
4. `erp-ui/src/store/modules/todo.js`：统一汇总与列表的范围参数。
5. `erp-ui/src/layout/components/HeaderTodo/index.vue`：关闭弹层、未知状态重试与更明确的无障碍标签。
6. `erp-ui/src/views/index.vue`：修正待办入口说明。
7. 扩充 `erp-ui/test/unifiedTodoDesktop.test.js`、`unifiedTodoMobile.test.js`、`unifiedTodoStore.test.js`，覆盖离开路由、重新激活、组织更新、范围参数和弹层行为。

## 验收标准

- 桌面点击待办后保留精确定位参数，并直接打开对应业务处理目标。
- 跳转导致组织切换时，顶部组织名称与实际上下文立即一致。
- 顶部汇总与默认待办列表使用相同范围口径；范围切换后页面信息明确。
- 离开待办中心后，其监听器不再改写业务页面 URL；返回后能按待办 URL 恢复筛选并刷新。
- 顶部待办弹层在导航后关闭，未知数据可手动重试。
- 桌面和移动目标测试、全量前端测试与构建通过；真实浏览器同路径无新增错误。
