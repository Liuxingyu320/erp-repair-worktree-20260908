## 1. 本检查点交付

- 新增专属退回发货纯规划策略，只建议消费当前退回隔离预留的全部剩余量；
- 复用 P10 的库存、精确余额、序列号及数量守恒规则，不复用普通可用库存、FEFO/FIFO 或普通预留链；
- 新增 JavaScript 安全的只读计划结构，业务标识、版本、数量和金额均以字符串输出；
- 新增只读 Mapper 和 Service，固定读取当前审批轮次、退回工作流、唯一隔离余额及 ACTIVE 序列号绑定；
- `planVersion` 使用 SHA-256，长度前缀编码覆盖预留、子调拨、裁决、工作流、库存、余额和序列号权威事实，展示时间不进入指纹；
- P10 的真实发货消费入口保持原签名和行为，只抽取无命令身份的纯消费计划供 P11 复用。

## 2. 边界证明

- 新 Mapper XML 仅有 4 个普通 `SELECT`；不存在 `FOR UPDATE`、`INSERT`、`UPDATE`、`DELETE` 或 `SELECT KEY`；
- 新 Service 使用 `@Transactional(readOnly = true)`，且生产代码中除自身外没有 Controller、HTTP、任务、消息或其他调用者；
- 未修改普通发货规划、普通发货创建、普通库存预留、裁决执行入口或 P10 生命周期事务 Service；
- 当前计划不会创建发货批次、明细、分配、库存日志、序列号审计或生命周期事件；
- 缺失预留、汇总库存或精确余额时按读取顺序失败关闭，不会降级到共享或普通库存来源；
- 没有引入设计参考站点的组件代码、运行依赖或远程引用。前端设计仍遵循本工作树既有参考约束和克制动效原则。
