# ERP-NEW_2 阶段 13F：收货差异裁决只读投影与前端契约实施计划

> 日期：2026-08-02
> 分支：`codex/erp-new-2-rebuild`
> 基线：`731ce0c2 feat: add atomic discrepancy adjudication persistence`
> 范围：裁决角色的权限/组织范围双约束读取、计划一致性核验、浏览器安全 VO 与新前端 Zod 契约；不开放 Controller、路由、菜单、Gate 或写入口

## 1. 结果目标

阶段 13F 为后续“差异负责人待裁决事项”页面建立可验证的只读数据边界。后端只返回一个 V2 差异事项的权威事实、双方当前确认状态，以及存在时已经原子保存的裁决计划和动作；新前端只冻结对应运行时契约和确定性展示模型。本阶段不会让浏览器调用裁决写事务，也不会把计划状态误报为已执行或已解决。

## 2. 读取授权与数据范围

- 登录快照必须精确拥有 `inv:transfer:discrepancy:adjudicate`；不接受客户端权限声明，不使用旧 `inv:transfer:discrepancy:handle`，也不把管理员通配符当作本阶段的新授权。
- 所选店铺/仓库必须通过 `ShopScopeService` 核验，并展开为非空组织范围。
- 权威查询只允许返回调出库存组织或调入库存组织落在该范围内的事项；不存在和越权使用同一拒绝结果，不泄露事项是否存在。
- SQL 和服务层同时核验组织范围、V2 收货/发货/调拨归属、数量金额和事实指纹，不能只依赖 Controller 注解。

## 3. 状态与计划一致性

- `awaiting_confirmation`：必须没有裁决计划；返回双方当前确认投影。只有双方确认都匹配当前版本和事实指纹时，`readyForAdjudication=true`。
- `adjudication_planned`：必须恰好存在一条计划头，且事项当前版本等于计划的 `caseVersionAfter`；计划前版本、事实指纹、双方确认事件、差异类型、数量金额和计划状态必须与权威事项一致。
- 裁决动作必须按 `sequence=1..N` 连续排列，数量与金额均为非负精度内十进制数，数量总和等于事项差异数量，金额总和等于事项差异金额；动作类型、责任方和执行状态必须在已冻结白名单内。
- 当前尚未定义物理执行状态机，因此动作只接受 `pending`，计划只接受 `adjudication_planned`；出现任何未知、部分或矛盾状态时读取失败关闭。

## 4. 浏览器安全响应

响应保留页面必须理解的业务信息：调拨/发货/收货编号、物料、差异类型、数量金额、说明与证据、双方组织及确认、案件状态、计划说明、裁决人显示名、计划动作和时间。

响应不得包含：

- 来源成本；
- 幂等 `requestId`；
- 事实指纹和决策指纹；
- 确认人或裁决人的内部用户标识；
- 内部权限快照、`createBy` 或数据库技术字段。

所有标识和十进制值以字符串返回，时间使用 ISO-8601 时间点，避免 JavaScript 安全整数和浮点结算问题。

## 5. 新前端契约

在 `erp-ui-next/src/domains/inventory/transfer/` 新增独立 Zod 契约：

- 严格拒绝未知字段，防止后端意外暴露内部值；
- 校验事项状态、确认状态、`readyForAdjudication` 和计划是否存在之间的组合关系；
- 使用 `decimal.js` 重新验证动作数量/金额守恒、连续序号、动作类型兼容性和唯一标识；
- 当前只提供解析与只读展示模型，不增加 Gateway 方法、HTTP 调用、路由、页面入口或提交命令。

手写 Zod 只是在独立服务尚未启动阶段冻结浏览器运行时边界，不冒充由正式版本化 OpenAPI 生成的类型。后续真实接口开放前必须用 ERP-NEW_2 独立服务的 OpenAPI 生成结果替换或比对。

## 6. 文件与实现顺序

1. 新增纯投影核验策略和浏览器安全 VO；
2. 新增只读 Mapper/XML，严格限定为 `SELECT`，并复用 V2 权威关联链；
3. 新增只读事务服务，依次核验登录权限、所选组织范围、事实和计划；
4. 新增前端 Zod 契约及解析器；
5. 增加 Mapper 白名单、服务失败关闭、序列/守恒和敏感字段测试；
6. 运行库存模块、后端 reactor、新前端全量门禁和隔离扫描。

## 7. 停止线

若需要新增 Controller、HTTP 路由、菜单、权限种子、功能 Gate、写调用点、DML、迁移执行、物理补发/退回/报损/核销、数据库连接、服务启动、依赖安装或 Docker，立即停止并拆分到后续检查点。本阶段不得连接旧差异处理器或旧差异表，也不得访问受保护原项目。
