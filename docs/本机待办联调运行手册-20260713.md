# 本机待办联调运行手册

## 1. 适用范围

本手册用于在 macOS 本机启动统一待办最小链路：系统、认证、OA、库存、网关和前端。整个流程只使用本机原生 Java、Node、MySQL 和 Redis，不使用虚拟机或容器，也不启动文件、代码生成和定时任务等非最小依赖。

脚本只管理自己写入 PID 文件的进程。目标端口若已被其他终端、IDE 或其他工作区占用，脚本会显示 PID 和脱敏后的命令并立即拒绝接管，不会抢占或按名称批量停止进程。

## 2. 进程与默认端口

| 启动顺序 | 服务 | 端口 | 构建产物/入口 |
| --- | --- | ---: | --- |
| 1 | erp-system | 9201 | `erp-modules/erp-system/target/erp-modules-system.jar` |
| 2 | erp-auth | 9200 | `erp-auth/target/erp-auth.jar` |
| 3 | erp-oa | 9204 | `erp-modules/erp-oa/target/erp-modules-oa.jar` |
| 4 | erp-inventory | 9205 | `erp-modules/erp-inventory/target/erp-modules-inventory.jar` |
| 5 | erp-gateway | 8080 | `erp-gateway/target/erp-gateway.jar` |
| 6 | erp-ui | 1025 | `erp-ui/node_modules/@vue/cli-service/bin/vue-cli-service.js` |

停止时严格按前端、网关、库存、OA、认证、系统的反向顺序执行。所有 Java 服务使用 `--spring.profiles.active=local`；脚本启动的本机网关会关闭验证码，便于自动化只读验收，这项覆盖只存在于当前进程参数，不修改其他环境配置。前端固定使用：

```text
/Users/liuxingyu/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node
```

默认端口被其他工作区占用时，不要停止或接管对方进程。可在同一个终端为当前工作区选择一组互不重复的空闲端口；脚本会同步覆盖服务发现、网关路由、CORS 和前端代理：

```bash
export LOCAL_TODO_SYSTEM_PORT=19201
export LOCAL_TODO_AUTH_PORT=19200
export LOCAL_TODO_OA_PORT=19204
export LOCAL_TODO_INVENTORY_PORT=19205
export LOCAL_TODO_GATEWAY_PORT=18080
export LOCAL_TODO_UI_PORT=11025
```

端口值必须为 `1-65535` 的整数，六个目标端口必须互不相同。同一组环境变量必须贯穿 `preflight`、`start`、`status`、`health`、`logs`、`restart` 和 `stop`；不要在进程运行期间更换端口组。带服务名的 `stop` 只处理当前端口组合中脚本拥有的该服务，不会扫描或停止其他端口组合。

## 3. 首次准备

在仓库根目录执行 Java 打包；此命令只生成本机 `target` 构建产物，不会启动服务或写业务数据：

```bash
mvn -pl erp-auth,erp-gateway,erp-modules/erp-system,erp-modules/erp-oa,erp-modules/erp-inventory -am -DskipTests package
```

确认以下本机依赖已经由使用者自行启动并可连接：

- MySQL：`127.0.0.1:3306`，数据库为 `BossERP_stock_state_75c59ee`。
- Redis：`127.0.0.1:6379`。
- `erp-ui/node_modules` 已安装。
- Java 和固定 Node 文件可执行。

数据库和 Redis 凭证只通过现有配置支持的环境变量传入，不写入脚本、PID、日志或本文档：

```bash
export MYSQL_USERNAME='本机数据库账号'
export MYSQL_PASSWORD='本机数据库密码'
export REDIS_PASSWORD='本机 Redis 密码（无密码则不要设置）'
```

## 4. 标准操作

所有命令均从仓库根目录执行。

只读预检，不创建目录、不改 PID、不启停进程；预检还会拒绝早于当前模块源码、公共待办契约或 Maven 配置的旧 JAR：

```bash
./scripts/local-todo-stack.sh preflight
```

按依赖顺序启动六个进程：

```bash
./scripts/local-todo-stack.sh start
```

只读查看 PID 身份和端口状态：

```bash
./scripts/local-todo-stack.sh status
```

执行端口、Actuator/首页和可选业务探针：

```bash
./scripts/local-todo-stack.sh health
```

查看库存日志；输出会对常见 Authorization、Cookie、Password 和 Token 字段做脱敏：

```bash
./scripts/local-todo-stack.sh logs inventory
```

只重启库存 Provider，其他五个进程保持不变：

```bash
./scripts/local-todo-stack.sh restart inventory
```

只停止库存 Provider，用于统一待办降级和恢复验收；其他五个进程保持不变：

```bash
./scripts/local-todo-stack.sh stop inventory
```

单服务停止支持 `system`、`auth`、`oa`、`inventory`、`gateway` 和 `ui`。服务名非法时命令会失败并打印有效服务集合；目标端口空闲且没有 PID 文件时返回幂等的 `SKIP`，不会回退为停止全部服务。没有 PID 文件但端口仍被其他进程占用时返回 `REFUSE`，不会把“无法证明所有权”误报为“已经停止”。恢复时继续使用 `restart <service>`：

```bash
./scripts/local-todo-stack.sh restart inventory
```

按反向依赖顺序停止脚本拥有的六个进程：

```bash
./scripts/local-todo-stack.sh stop
```

默认端口组的运行文件只保存在被 Git 忽略的 `output/local-todo-stack/`；备用端口组保存在带六端口后缀的独立目录，例如 `output/local-todo-stack-19201-19200-19204-19205-18080-11025/`。每个服务一个 `.pid` 和一个 `.log`，不同端口组不会共享进程所有权。不要把这些目录复制到提交清单。

## 5. 三层健康检查

`health` 的结论分三层，不能混为一谈：

1. `L1` 端口监听：进程绑定了预期端口。
2. `L2` 应用健康：五个 Java 服务的 `/actuator/health` 返回 HTTP 2xx 且 `status=UP`；前端首页返回 HTTP 2xx。
3. `L3` 登录后的网关业务探针：库存、OA、系统三个汇总接口返回合法统一待办结构。

第三层凭证只从环境变量读取：

```bash
export TODO_GATEWAY_BEARER_TOKEN='登录后取得的访问令牌'
export TODO_GATEWAY_SHOP_DEPT_ID='可选的门店组织 ID'
./scripts/local-todo-stack.sh health
unset TODO_GATEWAY_BEARER_TOKEN TODO_GATEWAY_SHOP_DEPT_ID
```

脚本通过标准输入把认证头交给 `curl`，不会把令牌放进命令行或打印响应正文。未设置 `TODO_GATEWAY_BEARER_TOKEN` 时，`health` 会明确显示 `L3` 未执行；这时只能确认基础健康，不能宣称三个 Provider 的业务链路全绿。

业务探针为只读请求：

- `/inventory/todo/summary`
- `/oa/todo/summary`
- `/system/todo/summary`

## 6. 安全边界

- `preflight`、`status` 和 `health` 只读取文件、端口与 HTTP 状态。
- `start` 只在所有依赖、JAR、Node、前端依赖和端口检查通过后启动。
- 部分启动失败时，只回收本次命令刚启动且命令身份仍匹配的 PID。
- `stop`、`stop <service>` 和 `restart` 在发送终止信号前，必须确认 PID 的完整命令包含预期 JAR 或 Vue CLI 绝对路径。
- PID 无效、身份不匹配或端口由其他工作区占用时，脚本拒绝停止。
- 脚本不执行数据库迁移、不创建测试业务数据、不调用待办写接口。

## 7. Provider 故障注入

故障注入只用于本机隔离端口组，并且必须先让 `status` 和 `health` 通过。以 inventory 为例：

```bash
./scripts/local-todo-stack.sh status
./scripts/local-todo-stack.sh health
./scripts/local-todo-stack.sh stop inventory
./scripts/local-todo-stack.sh status
./scripts/local-todo-stack.sh restart inventory
./scripts/local-todo-stack.sh health
```

浏览器只预热一个组织范围和一个优先级的精确缓存，再停止 Provider。验收时记录：已预热条件显示 `stale`、未预热条件显示 `unknown`、其他 Provider 保持实时、恢复后回到 `live`。不要把预期的 Provider 网络错误记成“总数为 0”，也不要在截图或 console 记录中保存 Authorization、Cookie 或用户隐私信息。对 `oa` 和 `system` 使用相同步骤；system 停止后只观察已登录页面，不把用户资料接口不可用与待办缓存契约混为一谈。

## 8. 常见问题

### 8.1 预检提示缺少 JAR

重新执行第 3 节的 Maven 打包命令。不要用旧目录里的同名 JAR 替换当前工作区产物。

如果提示“JAR 早于当前源码或构建配置”，也必须重新打包。仅有同名文件并不代表运行产物包含当前改动。

### 8.2 端口显示 `UNMANAGED`

这说明端口属于其他终端、IDE 或工作区。先根据脚本打印的 PID/命令确认来源；可以由该进程的启动者在原终端正常停止，也可以按第 2 节给当前工作区选择一组备用端口。不要删除本脚本 PID 文件来冒充所有权。

### 8.3 PID 显示 `STALE`

`status` 为只读，不会清理。下一次 `start` 会在确认 PID 不存在后清除陈旧文件；也可以执行 `stop`，让脚本只清理这个已不存在进程的 PID 文件。

### 8.4 库存日志仍提示找不到 `erp-system`

依次确认：

1. 当前库存进程确实使用 `local` profile。
2. `erp-system` 正在监听当前 `LOCAL_TODO_SYSTEM_PORT`（默认 9201）且 Actuator 为 `UP`。
3. 默认端口运行时，库存 `bootstrap.yml` 的本机简单发现包含 `erp-system -> http://127.0.0.1:9201`；备用端口运行时，库存进程命令包含脚本生成的简单发现覆盖参数。
4. 重启库存后再执行 `health`，不要只看旧日志。

### 8.5 调整等待时间

仅在本机启动确实较慢时临时调整，值必须为正整数：

```bash
export LOCAL_TODO_START_TIMEOUT_SECONDS=120
export LOCAL_TODO_STOP_TIMEOUT_SECONDS=30
export LOCAL_TODO_HEALTH_TIMEOUT_SECONDS=5
export LOCAL_TODO_LOG_LINES=200
```

验收结束后，在端口环境变量仍保持不变的同一终端执行 `./scripts/local-todo-stack.sh stop`，再执行 `./scripts/local-todo-stack.sh status`，确认脚本拥有的进程均已停止，最后再 `unset LOCAL_TODO_SYSTEM_PORT LOCAL_TODO_AUTH_PORT LOCAL_TODO_OA_PORT LOCAL_TODO_INVENTORY_PORT LOCAL_TODO_GATEWAY_PORT LOCAL_TODO_UI_PORT`。
