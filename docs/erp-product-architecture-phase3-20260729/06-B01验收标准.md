# ERP B01 验收标准

> 文档版本：V1.0 评审稿
> 日期：2026-07-29
> 用途：B01-1、B01-2、B01-3 开发与发布门禁
> 原则：没有证据等同于未通过；页面能打开不等同于业务完成

## 1. 验收结论规则

B01 只允许三种验收结论：

| 结论 | 条件 |
|---|---|
| `PASS` | 所有 P0 条件通过，P1 遗留有责任人、规避方案和期限 |
| `CONDITIONAL PASS` | 仅非核心、非安全、非一致性 P1 可条件通过；不得扩大灰度 |
| `FAIL` | 任一 P0 不通过，或无法提供可复现证据 |

以下问题一票否决：

- 越权读取或写入；
- 重复建单、重复审批、重复入库、重复库存调整、重复员工档案或重复合同归档；
- PC 与移动对同一业务 ID 显示不同状态或允许不同非法动作；
- 审批已完成但业务静默未更新；
- 盘点冻结期间库存仍可变化；
- 已签合同或签署证据被删除/覆盖；
- 功能关闭后仍可直调写接口；
- 数据库迁移无法回退应用或丢失已发生业务；
- 用超级管理员测试代替有限角色测试。

## 2. 验收前置条件

- [ ] `01-业务规则冻结文档` 已签字；
- [ ] `02-数据库影响评估` 已签字；
- [ ] `03-接口影响评估` 已签字；
- [ ] `04-权限模型确认` 已签字；
- [ ] `05-B01开发任务拆解` 已确认负责人和顺序；
- [ ] 代码、数据库、配置、菜单和测试数据基线唯一；
- [ ] 候选人、员工、经理、采购员、HR、仓库、有限管理员账号可用；
- [ ] 测试数据使用隔离前缀，具备清理方案；
- [ ] 测试环境不连接生产消息、支付、签署或真实库存执行通道；
- [ ] 每个功能开关有默认值、负责人和回退说明；
- [ ] 旧接口和旧路由调用量可以监控。

## 3. 通用验收对象

所有核心详情必须验证：

- `businessId/businessNo/businessType`；
- `status/statusLabel`；
- `version`；
- `allowedActions`；
- `approvalInstanceId/approvalRound`；
- 当前组织；
- 附件/签约/来源关系；
- 更新时间；
- 待办、消息和深链。

所有核心写动作必须验证：

- 权限；
- 数据范围；
- 当前组织；
- 记录所有权或审批候选人；
- 功能开关；
- 业务状态；
- 业务版本；
- 幂等键；
- 下游失败和补偿；
- 审计日志。

## 4. B01-1 基础统一验收

### 4.1 状态与动作

- [ ] 采购申请、采购订单、行政采购、盘点、入职、签约、审批均有状态目录；
- [ ] 同一业务 ID 在 PC、移动、导出和待办中使用同一状态名称；
- [ ] 状态码由服务端返回，前端不自行推导另一套状态；
- [ ] 详情返回服务端计算的 `allowedActions`；
- [ ] 客户端伪造目标状态被拒绝；
- [ ] 状态变化后旧动作和旧版本立即失效；
- [ ] 退回、拒绝、撤回、取消、关闭、作废和终止均保留原因。

### 4.2 权限与组织

- [ ] 每个角色只看到职责内入口；
- [ ] 修改 URL、业务 ID、组织头或请求正文不能越权；
- [ ] 未知数据范围 fail-closed；
- [ ] 当前组织不在用户范围时拒绝；
- [ ] 店仓授权与部门数据范围同时生效；
- [ ] 权限撤销后旧页面不能继续操作；
- [ ] 候选人只能看本人入职/签约；
- [ ] 审批人必须同时有业务审批权限且是当前任务候选人；
- [ ] 敏感字段在列表、详情、导出、消息和日志中一致脱敏。

### 4.3 错误与格式

- [ ] 无权限、无数据、功能关闭、组织不匹配、版本冲突、冻结和下游失败可区分；
- [ ] PC 和移动对同一错误码显示一致含义；
- [ ] 金额、数量、日期时间和时区口径一致；
- [ ] 库存数量精度不因移动输入而截断；
- [ ] 错误响应不包含堆栈、SQL、令牌或敏感个人信息；
- [ ] Provider 失败不显示为业务数量 0。

### 4.4 版本与幂等

对每个核心命令执行：

1. 首次请求成功；
2. 相同幂等键和相同载荷重复至少两次；
3. 验证返回同一业务结果；
4. 验证数据库只有一个业务结果和一个有效副作用；
5. 相同幂等键改载荷；
6. 验证返回 `IDEMPOTENCY_CONFLICT`；
7. 两个用户使用同一旧版本并发操作；
8. 验证只有一个合法成功，另一个返回版本/状态冲突。

必须覆盖：

- 创建/提交采购申请；
- 转采购订单；
- 收货、质检入库；
- 开始/提交盘点；
- 审批动作；
- 创建签约包、签署回调；
- 入职最终审批和激活。

### 4.5 数据库迁移

- [ ] 迁移只做新增或安全扩展；
- [ ] MySQL 5.7 和 8.0 均通过；
- [ ] 迁移可重复运行或有明确一次性保护；
- [ ] 执行前有只读预检；
- [ ] 回填可分批、可续跑、可核对；
- [ ] 现有采购订单不生成虚假申请；
- [ ] 现有签约包不在证据不足时强行关联入职；
- [ ] 迁移失败不会留下应用误认为可用的半完成结构；
- [ ] 回退应用不要求删除新表或覆盖数据库备份。

### 4.6 B01-1 Gate

通过标准：

- P0 越权 0；
- P0 重复副作用 0；
- P0 静默覆盖 0；
- 契约测试全部通过；
- 六类角色和候选人验证通过；
- 数据库 Expand/回填演练通过；
- 评审人签字。

## 5. B01-2 移动框架验收

### 5.1 五入口

- [ ] 一级入口固定为工作台、消息、待办、应用、我的；
- [ ] 候选人和六类正式角色结构一致，内容按权限变化；
- [ ] 旧移动路由有兼容重定向；
- [ ] 登录后恢复原业务深链；
- [ ] 浏览器返回、移动容器返回和页面返回不形成死循环；
- [ ] 当前组织在需要组织上下文的页面始终可见；
- [ ] 切换组织后列表、详情、动作和计数缓存失效；
- [ ] 新壳开关关闭可完整返回旧结构。

### 5.2 工作台

- [ ] 第一屏能看到有效待办、提醒和快捷入口；
- [ ] 数据项有更新时间；
- [ ] 真 0、加载中、失败、无权限和功能关闭不同；
- [ ] 快捷入口根据角色、权限、组织和开关生成；
- [ ] 普通员工不见采购配置、流程配置、角色和参数；
- [ ] 候选人只见本人资料、签署和消息；
- [ ] 卡片点击进入正确业务 ID，并重新鉴权；
- [ ] 工作台只读聚合，不直接改变业务状态。

### 5.3 消息

- [ ] 系统、审批、任务、库存异常、合同提醒类型统一；
- [ ] 消息包含稳定业务引用和深链；
- [ ] 消息已读不完成待办；
- [ ] 业务无权或已切换组织时，深链拒绝并给出正确说明；
- [ ] 重复业务事件不产生重复有效消息；
- [ ] 消息 Provider 失败显式展示；
- [ ] 敏感信息不进入消息摘要。

### 5.4 待办

- [ ] 待审批、待执行、已退回、风险和个人任务分类清楚；
- [ ] 摘要数量等于同条件列表数量；
- [ ] Provider 部分失败不返回完整成功；
- [ ] 采购待办区分库存采购与行政采购；
- [ ] 审批动作统一进入 `/approval/tasks/*`；
- [ ] 处理后待办消失或进入正确结果状态；
- [ ] 已读消息不改变待办；
- [ ] 无效深链、已完成任务和权限撤销有正确恢复路径。

### 5.5 应用

- [ ] 应用由服务端有效能力、权限和组织共同计算；
- [ ] PC 专属配置不进入普通移动应用；
- [ ] 功能关闭的应用不显示，或显示明确关闭说明；
- [ ] `NOT_INSTALLED` 财务不可开启；
- [ ] 旧应用入口被受控重定向而非直接 404；
- [ ] 新旧路由不会同时创建业务。

### 5.6 屏幕与交互基础

B01-2 不是完整视觉验收，但至少要求：

- [ ] 320×568 和 390×844 不遮挡主操作；
- [ ] 软键盘出现后可完成表单；
- [ ] 安全区和底部导航不重叠；
- [ ] 主按钮可被键盘聚焦，表单有可读标签；
- [ ] 错误后输入不丢失；
- [ ] 加载、空、错、关、无权限状态可辨识。

视觉细节、完整可访问性和 59 个路由全面重构保留在 B02。

### 5.7 B01-2 Gate

通过标准：

- 七类身份导航通过；
- 旧深链和返回栈通过；
- 工作台、消息、待办数量与业务核对；
- 普通角色不见后台配置；
- 新壳回退演练通过；
- 没有新增移动端独立业务写逻辑。

## 6. B01-3 统一审批验收

### 6.1 通用审批

- [ ] 每个 `businessCode + businessId + businessRound` 只有一个实例；
- [ ] 发起幂等键唯一；
- [ ] 流程使用已发布不可变版本；
- [ ] 候选人解析结果可追踪；
- [ ] 同意、退回、拒绝、撤回、终止和转交记录唯一；
- [ ] 重复动作不重复生效；
- [ ] 业务回调使用事件键幂等；
- [ ] 回调失败可自动重试；
- [ ] 超过重试上限进入可见死信；
- [ ] 人工重放有专权、原因和审计；
- [ ] 待办与业务状态最终一致；
- [ ] 原生/旧审批不会同时产生两个活动实例。

### 6.2 `OA_PURCHASE`

- [ ] 页面、待办和消息显示“行政采购”；
- [ ] 保存、提交、撤回、关闭权限拆分；
- [ ] 重复提交不创建多个审批实例；
- [ ] 通过、退回、拒绝和撤回正确更新 `oa_purchase`；
- [ ] 回调重复不重复更新轮次或状态；
- [ ] 行政采购不能转库存采购订单。

### 6.3 `INV_TRANSFER`

- [ ] 同一调拨只有一个审批实例；
- [ ] 统一待办处理后旧审批页不保留可操作任务；
- [ ] 通过后进入正确待发货状态；
- [ ] 退回/拒绝不产生库存变化；
- [ ] 原生开关切回时历史实例仍可查看；
- [ ] 跨组织和无仓库授权处理被拒绝。

### 6.4 `INV_STOCK_CHECK`

正常场景：

- [ ] 开始盘点原子生成冻结批次和快照；
- [ ] 同仓库第二个活动盘点被拒绝；
- [ ] 全仓/分类/指定/抽盘范围符合冻结规则；
- [ ] 无差异盘点完成并释放；
- [ ] 有差异审批通过后只生成一次库存调整；
- [ ] 调整流水、盘点、冻结批次和审批实例可互查；
- [ ] 调整成功后释放。

并发场景：

- [ ] 采购质检入库被 `INVENTORY_FROZEN` 阻止；
- [ ] 出库、退货、调拨、手工调整被阻止；
- [ ] 批次/库位库存写入被阻止；
- [ ] 两人同时开始盘点只有一个成功；
- [ ] 两人同时提交/审批只有一个合法结果；
- [ ] 解冻前任何写入均不能部分成功。

异常场景：

- [ ] 退回/拒绝释放冻结并使本轮不可继续；
- [ ] 取消释放并记录原因；
- [ ] 超时产生风险待办，不静默释放；
- [ ] 紧急释放要求专权、双确认和原因，并使盘点失效；
- [ ] 释放失败可重试；
- [ ] 无孤儿活动冻结；
- [ ] 关闭冻结开关后能回到快照失效保护。

### 6.5 `INV_PURCHASE_REQUEST`

- [ ] 库存采购申请和行政采购分表、分接口、分权限；
- [ ] 申请状态符合冻结目录；
- [ ] 部门审批和采购审核使用一个流程实例的不同节点；
- [ ] 未批准申请不能转订单；
- [ ] 一份申请可拆多单；
- [ ] 多份申请可合单；
- [ ] 转换总量不超过批准量；
- [ ] 重复转换请求不重复生成订单或关系；
- [ ] 订单可追溯申请明细和转换数量；
- [ ] 历史订单显示 `LEGACY_DIRECT`，不伪造来源；
- [ ] 直接创建订单要求专权和原因；
- [ ] 收货、质检和入库继续使用现有库存服务；
- [ ] 冻结盘点时质检过账被阻止。

### 6.6 `HR_HEALTH_CERTIFICATE`

- [ ] 新基础能力不破坏现有健康证审批；
- [ ] 重复回调不重复投影员工档案；
- [ ] 功能关闭不创建新审批或待办；
- [ ] 审批人无组织范围时拒绝；
- [ ] 旧数据可读。

### 6.7 `HR_ONBOARDING`

正常场景：

- [ ] 创建的是入职任务，不是正式员工；
- [ ] 需要本人参与时创建受限候选人身份；
- [ ] 候选人只能填写本人资料和签署；
- [ ] 资料预校验通过后才生成签约包；
- [ ] 入职任务和签约包版本可追溯；
- [ ] 完整签署后进入待激活审核；
- [ ] 最终通过后只创建一个员工档案；
- [ ] 同一候选人身份升级为正式员工，不重复账号；
- [ ] 角色、岗位、组织和合同归档全部成功后才显示完成；
- [ ] PC 和移动查看同一员工档案和合同。

签署后整改：

- [ ] 完整签署后没有普通“驳回并结束”；
- [ ] 非合同要素退回整改保留原合同；
- [ ] 合同关键字段变化锁定激活并要求处置/重签；
- [ ] 原签约包、文件、哈希、证书和事件不删除；
- [ ] 终止入职必须先完成合同处置并保存依据；
- [ ] 取消后候选人身份停用而非删除。

补偿：

- [ ] 员工档案成功、角色授权失败时进入激活异常；
- [ ] 账号成功、组织授权失败时账号保持受限；
- [ ] 合同归档失败时不显示入职完成；
- [ ] 重试不重复建档、账号、角色或合同；
- [ ] 每一步有请求 ID、状态和审计；
- [ ] 关闭新流程后已签数据仍可完成补偿。

### 6.8 不存在业务的验收

- [ ] 没有创建 `OA_LEAVE` 空表、空接口、空审批模板或假待办；
- [ ] 考勤中的 `leave` 结果状态未被误认为请假申请；
- [ ] 合同签署动作未被误记为审批同意；
- [ ] 合同处置审批只在 HR/法务签字后登记。

### 6.9 B01-3 Gate

通过标准：

- 已切换业务逐一 PASS；
- 未切换业务保持原行为且无双写；
- 审批回调异常可发现、重试和重放；
- 采购、盘点和入职真实写流程通过；
- 每个业务编码独立回退通过；
- 灾难与补偿演练有记录。

## 7. 功能中心验收

### 7.1 功能登记

- [ ] 所有现有 `feature.*` 已登记；
- [ ] 部署开关标记为只读；
- [ ] 每个功能有负责人、风险、依赖和默认值；
- [ ] 依赖图无环；
- [ ] 完整财务为 `NOT_INSTALLED`；
- [ ] 已登记功能不能通过通用参数页面绕过修改。

### 7.2 有效状态

对每个首批功能验证：

```text
全局关闭
→ PC 入口关闭
→ 移动入口关闭
→ 写接口拒绝
→ 不产生新待办
→ 不产生新消息
→ 已创建流程按登记规则完成或终止
```

另外：

- [ ] 配置服务不可用时 fail-closed；
- [ ] 权限不能绕过硬关闭；
- [ ] 开关不能授予权限；
- [ ] 客户端版本不足返回明确状态；
- [ ] 变更前后、原因、操作人、复核人和请求 ID 可审计；
- [ ] 高风险变更操作人与复核人不同；
- [ ] 回退到上一状态后入口、API、待办和消息一致。

## 8. PC-Mobile 一致性场景

每个已切业务至少执行：

| 编号 | 场景 | 期望 |
|---|---|---|
| PM-01 | PC 创建，移动查看 | 同一 ID、状态、版本、附件和动作 |
| PM-02 | 移动创建，PC 查看 | 同上 |
| PM-03 | PC 提交，移动审批 | 同一实例和任务 |
| PM-04 | 移动提交，PC 审批 | 同上 |
| PM-05 | 移动处理后 PC 刷新 | 业务、待办、消息一致 |
| PM-06 | PC 处理后移动深链 | 最新状态且无过期动作 |
| PM-07 | 两端同时编辑 | 一个成功，一个版本冲突 |
| PM-08 | 网络超时后重试 | 不重复副作用 |
| PM-09 | 中途撤销权限 | 后续动作拒绝 |
| PM-10 | 中途切换组织 | 旧数据和旧动作失效 |
| PM-11 | 功能关闭 | 两端入口和写接口一致关闭 |
| PM-12 | 下游失败 | 两端显示同一可恢复中间态 |

## 9. 非功能验收

### 9.1 安全

- [ ] 直接接口越权套件通过；
- [ ] 文件下载重新鉴权；
- [ ] 深链重新鉴权；
- [ ] 日志和错误无敏感信息；
- [ ] 候选人会话不能进入员工应用；
- [ ] 高风险动作全部审计；
- [ ] 内部服务接口使用内部认证，外部不可访问。

### 9.2 可靠性

- [ ] Outbox 可重试且无并发重复消费；
- [ ] 回调重复、乱序、超时和服务重启通过；
- [ ] 补偿任务可续跑；
- [ ] 不存在永久 `PROCESSING` 且无监控的记录；
- [ ] Provider 失败可定位。

### 9.3 性能

本阶段不凭空设定生产 SLO。先记录现有测试环境基线，然后要求：

- 核心详情、列表、工作台和待办 P95 不比基线退化超过 20%；
- 功能解析使用批量和缓存，不形成逐项远程调用；
- 盘点开始的冻结范围在生产等量数据副本完成锁影响测试；
- 新索引经执行计划验证；
- 大批量回填不会长事务锁住核心业务表；
- 超出阈值必须优化或缩小首批灰度。

### 9.4 可观测性

- [ ] 可按 `requestId` 追踪跨服务调用；
- [ ] 可按 `businessId` 查业务、审批、待办和消息；
- [ ] 可按 `instanceId` 查审批动作和回调；
- [ ] 可按 `freezeBatchId` 查冻结、阻塞和释放；
- [ ] 可按 `onboardingId` 查候选人、签约版本、审批和激活；
- [ ] 告警不包含身份证、银行卡、合同正文或完整个人信息。

## 10. 回退验收

每个开关在测试环境执行：

1. 开启新能力；
2. 创建并完成一笔新业务；
3. 创建一笔处理中业务；
4. 关闭开关；
5. 验证不再创建新业务；
6. 验证已完成业务仍可查看；
7. 验证处理中业务按登记规则完成、终止或补偿；
8. 验证没有孤儿待办、消息、冻结或审批；
9. 重新开启；
10. 验证没有重复副作用。

禁止用数据库恢复覆盖步骤 2—3 的业务数据。

## 11. 真实业务桌面演练

至少完成：

### 11.1 库存采购

```text
员工/经理创建库存采购申请
→ 部门审批
→ 采购审核
→ 采购员拆单/合单
→ 仓库收货
→ 质检
→ 入库
→ 对账申请量、订单量、收货量、合格量和库存流水
```

### 11.2 冻结盘点

```text
创建盘点
→ 开始冻结
→ 尝试入库/出库/调拨并确认被阻止
→ 实盘
→ 差异审批
→ 唯一库存调整
→ 释放
→ 原被阻止业务成功重试
```

### 11.3 入职签约

```text
创建入职任务
→ 候选人填资料
→ HR 预校验
→ 候选人签署
→ 最终审核
→ 激活员工/账号/组织
→ PC 与移动查看同一员工档案和合同
```

另执行一次“签署后退回整改”和一次“激活中途失败后补偿”。

### 11.4 行政采购

```text
创建行政采购申请
→ 统一审批
→ 行政执行
→ 验收
→ 确认未进入库存采购订单或商品库存成本
```

## 13. Go/No-Go

### Go

- [ ] B01-1、B01-2、B01-3 对应 Gate 通过；
- [ ] 所有 P0 缺陷为 0；
- [ ] P1 遗留已接受；
- [ ] 生产等量迁移和锁影响测试通过；
- [ ] 监控、告警和回退已演练；
- [ ] 首批组织、账号和负责人明确；
- [ ] 业务负责人同意灰度。

### No-Go

出现任一情况不得发布：

- 无法证明两端一致；
- 无法证明幂等；
- 无法证明盘点冻结覆盖全部写路径；
- 无法证明已签合同和证据不被删除；
- 无法按业务编码回退审批；
- 使用未签字的合同处置规则；
- 把完整财务或请假空壳夹带进 B01；
- 依赖人工改数据库才能完成流程。
