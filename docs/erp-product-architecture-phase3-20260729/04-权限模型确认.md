# ERP 第三阶段权限模型确认

> 文档版本：V1.0 评审稿
> 日期：2026-07-29
> 状态：待安全、业务和技术评审；未签字前不得批量调整角色授权

## 1. 权限结论

统一采用：

```text
认证身份
∩ 功能已开放
∩ 功能权限
∩ 数据范围
∩ 当前组织
∩ 记录所有权/审批候选人
∩ 字段权限
∩ 业务状态允许动作
= 最终允许动作
```

任何一层不满足都拒绝。PC 与移动端使用相同权限码和相同服务端判定，不建立两套角色。

冻结原则：

1. 页面可见不等于可以调用接口；
2. 功能开关不授予权限；
3. 超级管理员之外也不得因为未知数据范围而放行全部数据；
4. 采购申请、审批、订单执行、收货、质检和库存调整必须拆权；
5. 签署后合同处置、盘点紧急释放、直接创建采购订单、功能发布属于高风险专权；
6. 候选人身份只能访问本人入职与签署数据；
7. 详情响应中的 `allowedActions` 由服务端计算，客户端只负责呈现；
8. 执行动作时服务端必须再次校验，不能信任旧的 `allowedActions`。

## 2. 当前能力与缺口

### 2.1 已有基础

- `sys_menu.perms` 和 `sys_role_menu` 承载功能权限；
- `sys_role.data_scope` 承载部门数据范围；
- `sys_user_shop` 承载店仓授权；
- 控制器使用 `@RequiresPermissions` 和 `@RequiresLogin`；
- 审批任务具备候选人所有权；
- HR 已有字段脱敏和敏感访问审计基础；
- 部分服务在功能配置不可用时 fail-closed。

### 2.2 已发现问题

| 领域 | 当前问题 | 风险 |
|---|---|---|
| OA 行政采购 | 保存、提交、关闭、撤回共用 `oa:purchase:add` | 申请人可获得过宽生命周期动作 |
| 库存采购 | 新增、提交、收货、质检已拆分，但缺申请审批与转换权限 | 无法隔离需求审批和采购执行 |
| 盘点 | 录入与提交共用 `inv:stockCheck:submit`；取消/删除共用 `remove` | 动作语义不清，高风险操作过宽 |
| 入职 | 权限按现有四态设计 | 无候选人本人、签署、最终审批、激活补偿专权 |
| 电子签 | 员工移动操作依赖登录所有权，HR 操作较细 | 与入职任务无稳定关系，已签后处置权限未定义 |
| 功能开关 | 可通过通用参数权限修改全局参数 | 可绕过专用审计、依赖检查和复核 |
| 审批 | 业务审批权限映射已集中，但内置业务有限 | 新业务若未登记会运行时报错或被业务模块自行实现 |
| 移动应用 | 部分后台配置曾进入移动应用目录 | 普通用户可见不适合移动的管理入口 |

## 3. 身份类型

### 3.1 身份定义

| 身份类型 | 说明 | 可登录 | 是否员工 |
|---|---|:---:|:---:|
| `CANDIDATE` | 待入职候选人，只能处理本人资料、签署和消息 | 是，受限 | 否 |
| `EMPLOYEE` | 已激活员工 | 是 | 是 |
| `ADMIN` | 管理账号，仍按角色和数据范围授权 | 是 | 不一定 |
| `SERVICE` | 内部服务身份，不进入用户界面 | 否 | 否 |

候选人规则：

- 不进入普通员工列表；
- 无默认部门业务数据范围；
- 不继承“普通员工”角色全部权限；
- 只通过所有权访问本人入职任务、签约包和消息；
- 不允许导出、搜索其他候选人或访问组织通讯录；
- 激活时使用同一用户 ID 升级，不新建重复账号；
- 取消时停用并保留审计。

### 3.2 角色不是身份类型

`采购员`、`仓库人员`、`HR`、`部门经理`、`有限管理员`属于角色；`CANDIDATE/EMPLOYEE` 是账户生命周期属性。两者不能用一个自由文本角色互相替代。

| 填写本人入职资料 | 本人 | - | - | - | - | 范围 | - |
| 员工档案管理 | - | 本人查看 | 部门查看 | - | - | 范围编辑 | 脱敏查看 |
| 合同本人签署/查看 | 本人 | 本人 | - | - | - | 范围管理 | - |
| 合同模板/企业/印章 | - | - | - | - | - | 专权 | - |
| 合同作废/处置 | - | - | - | - | - | 专权 | 审计只读 |
| 创建库存采购申请 | - | ✓ | ✓ | ✓ | 范围 | - | - |
| 审批库存采购申请 | - | - | 候选任务 | 采购审核节点 | - | - | - |
| 转采购订单 | - | - | - | ✓ | - | - | - |
| 直接创建采购订单 | - | - | - | 专权 | - | - | - |
| 收货登记 | - | - | - | 范围查看 | 范围 | - | - |
| 质量检验 | - | - | - | - | 范围 | - | - |
| 盘点创建/分配 | - | - | - | - | 范围 | - | - |
| 盘点录入 | - | - | - | - | 被分配范围 | - | - |
| 盘点差异审批 | - | - | 候选任务 | - | 候选任务 | - | - |
| 盘点紧急释放 | - | - | - | - | - | - | 专权 |

| 行政采购审批 | - | - | 候选任务 | - | - | 候选任务 | - |
| 审批配置 | - | - | - | - | - | - | 专权 |
| 功能中心查看 | - | - | - | - | - | - | ✓ |
| 功能中心发布 | - | - | - | - | - | - | 专权/复核 |

审批权最终来自“权限 + 当前任务候选人”，仅有审批权限但不是该任务候选人时仍不能处理。

新增：

| 权限码 | 用途 |
|---|---|
| `inv:purchaseRequest:list` | 管理范围列表 |
| `inv:purchaseRequest:query` | 详情 |
| `inv:purchaseRequest:add` | 创建 |
| `inv:purchaseRequest:edit` | 编辑草稿/退回 |
| `inv:purchaseRequest:submit` | 提交 |
| `inv:purchaseRequest:withdraw` | 撤回 |
| `inv:purchaseRequest:cancel` | 取消 |
| `inv:purchaseRequest:close` | 关闭剩余需求 |
| `inv:purchaseRequest:approve` | 统一审批业务权限映射 |
| `inv:purchaseRequest:convert` | 合并/拆分生成订单 |
| `inv:purchaseRequest:export` | 导出 |

`approve` 只表示该业务类型的审批资格，仍需是统一审批任务候选人。

保留当前权限并治理：

| 当前/目标权限 | 处理 |
|---|---|

| `inv:purchase:add` | 保留为订单草稿管理；新流程主要由转换产生 |
| `inv:purchase:submit` | 逐步解释为确认订单，不能代替申请审批 |
| `inv:purchase:receive` | 保留 |
| `inv:purchase:qc` | 保留 |
| `inv:purchase:remove` | 拆分草稿删除与订单取消 |
| `inv:purchase:export` | 保留 |
| `inv:purchase:directCreate` | 新增高风险应急专权 |
| `inv:purchase:cancel` | 新增显式取消 |

### 5.3 行政采购

| 权限码 | 用途 |
|---|---|

| `oa:purchase:add` | 创建草稿 |
| `oa:purchase:edit` | 编辑 |
| `oa:purchase:submit` | 提交 |

| `inv:stockCheck:list/query` | 列表/详情 |
| `inv:stockCheck:add` | 创建草稿 |
| `inv:stockCheck:edit` | 分配和修改草稿 |

### 5.5 入职

现有 `hr:onboarding:*` 兼容保留，目标增加：

| 权限码 | 用途 |
|---|---|
| `hr:onboarding:invite` | 创建/关联候选人身份 |
| `hr:onboarding:dataReview` | 资料与合同关键字段预校验 |
| `hr:onboarding:sendSign` | 生成/发送签约包 |

| `hr:onboarding:return` | 退回资料或整改 |
| `hr:onboarding:activate` | 激活编排服务权限，不直接授予普通用户 |
| `hr:onboarding:retryActivation` | PC 补偿专权 |
| `hr:onboarding:startTermination` | 已签后终止流程专权 |
| `hr:onboarding:restore` | 受控重开 |

候选人本人填写不使用上述 HR 管理权限，而使用登录所有权策略。

### 5.6 签约与合同处置

保留现有：

- `oa:signPackage:list/query/add/send/void/template`
- `oa:signSeal:list/edit`
- `oa:signTask:*`

新增建议：

| 权限码 | 用途 |
|---|---|
| `oa:signPackage:remediate` | 处理签署后整改 |
| `oa:signPackage:terminate` | 已签后合同处置专权 |
| `oa:signPackage:technicalEvidence` | 受控查看技术证据 |
| `oa:signPackage:replayCallback` | 回调补偿专权 |

员工/候选人的签署、拒签、最终确认仍采用“登录 + 签约包所有权 + 当前状态”，不授予管理权限。

### 5.7 功能中心

新增：

| 权限码 | 用途 |
|---|---|
| `system:feature:list` | 查看目录 |
| `system:feature:query` | 查看详情和依赖 |
| `system:feature:validate` | 发布前检查 |
| `system:feature:change` | 创建变更草稿 |
| `system:feature:approve` | 复核高风险变更 |
| `system:feature:publish` | 发布 |
| `system:feature:rollback` | 回退 |
| `system:feature:audit` | 查看变更历史 |

已登记的 `feature.*` 不再允许通过通用 `system:config:edit` 修改。

### 5.8 统一审批

现有审批管理权限保留：

- 模板/规则列表、查询、编辑、发布；
- 任务转交；
- 实例终止；
- 回调重放；
- 配置验证。

普通审批人的同意、退回和拒绝由：

```text
登录
∩ 业务审批权限
∩ 当前候选人
∩ 任务 PENDING
∩ 业务功能开启
```

共同决定。

## 6. 数据范围

### 6.1 统一范围

数据范围评估顺序：

1. 获取登录用户和有效角色；
2. 解析当前组织；
3. 验证当前组织属于用户可选范围；
4. 计算部门数据范围；
5. 计算店仓授权；
6. 应用记录所有权或审批候选人例外；
7. 应用业务状态和字段投影；
8. 查询和写入都使用同一范围。

### 6.2 采购

- 申请人可查看本人申请；
- 部门经理查看管理范围内申请；
- 采购员按获授权组织和仓库查看已批准需求；
- 供应商、价格和成本字段需采购/成本专权；
- 仓库人员只能查看与收货、质检相关的订单字段；
- 行政采购与库存采购的数据范围互不借用。

### 6.3 盘点

- 盘点创建人必须有目标仓库授权；
- 盘点人只能录入分配给本人且处于活动冻结的批次；
- 审批人能看到决策所需差异和证据，但无成本权限时不返回成本；
- 紧急释放人必须同时具备仓库范围和专权；
- 修改请求中的仓库 ID 不能绕过当前组织。

### 6.4 入职与签约

- 候选人仅访问本人 `candidate_user_id` 关联记录；
- HR 按组织和门店范围管理入职；
- 部门经理只看业务必要字段，不看身份证、银行卡、薪资等完整值；
- 签约 HR 根据签约范围查看；
- 技术证据、合同文件和个人信息采用不同权限；
- 审批人通过任务访问详情时仍执行字段脱敏。

## 7. 字段级权限

| 字段类别 | 默认策略 |
|---|---|
| 身份证件 | 无权不下发；必要场景脱敏 |
| 银行账号 | HR/财务专权；移动本人仅查看受控值 |
| 薪资 | 薪资专权，不随普通 HR 权限自动获得 |
| 采购成本/供应商报价 | 采购/成本专权 |
| 客户隐私 | 业务范围 + 隐私专权 |
| 合同正文 | 本人、签约 HR、法务/授权管理人 |
| 签署技术证据 | 技术证据专权；普通业务详情只返回验签结论 |
| 操作日志 | 脱敏，只读；清理使用独立高风险权限 |
| 功能配置 | 普通查看不返回敏感部署配置 |

导出接口执行与页面相同或更严格的字段投影，不能因为导出绕过脱敏。

## 8. 服务端允许动作

推荐统一算法：

```text
状态机动作集合
∩ 当前用户功能权限动作
∩ 数据范围/所有权动作
∩ 功能开关动作
∩ 审批候选人动作
∩ 并发/冻结/依赖可用动作
= allowedActions
```

示例：

- 库存采购申请为 `APPROVED`，采购员有 `convert` 且有目标仓库范围，才返回 `CONVERT_TO_ORDER`；
- 盘点为 `CHECKING`，当前用户是被分配盘点人且冻结仍活动，才返回 `INPUT`；
- 入职为 `SIGNED_PENDING_ACTIVATION`，当前用户是审批任务候选人，才返回审批动作；
- 已签后存在关键字段变化时，不返回普通 `REJECT`，只返回 `RETURN_FOR_REMEDIATION` 或专权 `START_TERMINATION`。

动作执行时重新读取数据库行版本、任务状态和冻结状态。

## 9. 高风险动作

| 动作 | 附加控制 |
|---|---|
| 盘点紧急释放 | PC、独立权限、双确认、原因、审计、盘点失效 |
| 直接创建库存采购订单 | 独立权限、来源 `DIRECT_EXCEPTION`、原因、金额/数量限制 |
| 已签合同作废/终止 | HR/法务授权、材料、不可变事件、禁止删除证据 |
| 入职激活补偿 | PC 专权、显示已成功步骤、幂等重试 |
| 审批实例终止 | 独立权限、原因、通知业务模块 |
| 审批回调重放 | 独立权限、事件预览、幂等 |
| 功能发布/回退 | 影响预览、复核、审计、禁止操作人自审高风险变更 |
| 日志清理/强退用户 | 独立权限、审计，不进入普通移动应用 |

## 10. 权限迁移

```text
导出现有菜单、权限和角色矩阵
→ 建立新旧权限映射
→ 插入新权限但默认不授权
→ 测试角色最小授权
→ 单组织灰度
→ 记录旧权限调用
→ 回收过宽权限
→ 保留迁移审计
```

禁止：

- 自动把全部新权限授予所有管理员角色；
- 以超级管理员测试代替有限角色测试；
- 先隐藏按钮、后补服务端权限；
- 在同一次迁移中删除旧权限并切换所有角色；
- 通过功能开关替代授权迁移。

## 11. 必测越权场景

- 修改业务 ID 访问他人采购申请；
- 修改仓库或当前组织头访问未授权库存；
- 候选人访问其他候选人的入职任务或签约包；
- 普通员工直调采购转换、盘点释放、入职激活；
- 仅有审批权限但不是候选人时处理审批；
- 任务转交后原候选人继续处理；
- 权限被撤销后使用旧页面和旧 token 操作；
- 功能关闭后直调写接口；
- 无字段权限通过详情、列表、导出或日志读取敏感值；
- 重放已使用的签署、审批、激活和库存调整请求；
- 通用参数管理员修改已登记功能开关；
- 有全局角色但无当前店仓授权时操作仓库业务。

## 12. 权限验收门槛

- [ ] PC 与移动使用同一权限码；
- [ ] 候选人身份与员工角色明确分离；
- [ ] 申请、审批、采购执行、收货、质检和调整完成职责拆分；
- [ ] OA 采购提交、撤回、关闭不再共用 `add`；
- [ ] 盘点录入、提交、取消和紧急释放完成拆权；
- [ ] 签署后处置和功能发布为高风险专权；
- [ ] 数据范围未知或组织无效时 fail-closed；
- [ ] 审批必须同时满足业务权限和任务候选人；
- [ ] 敏感字段在列表、详情、导出、日志中一致受控；
- [ ] `allowedActions` 两端一致，执行时服务端复核；
- [ ] 六类有限角色和候选人账号通过直接接口越权测试；
- [ ] 角色迁移有导出快照和可恢复方案。

## 13. 评审责任

| 评审人 | 必须确认 |
|---|---|
| 产品负责人 | 角色可见功能和端职责 |
| 采购负责人 | 申请、审核、订单、收货和质检职责分离 |
| 仓库负责人 | 盘点与紧急释放人员范围 |
| HR/法务 | 候选人、签约、激活和合同处置权限 |
| 安全负责人 | 身份、数据范围、字段权限、高风险动作 |
| 技术负责人 | 所有接口服务端强制校验 |
| 测试负责人 | 有限角色、直调接口和并发越权用例 |

签字前不得批量修改生产角色或默认授予新权限。
