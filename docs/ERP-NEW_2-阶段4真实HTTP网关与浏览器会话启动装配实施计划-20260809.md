## 1. 目标与范围

把新前端非 Mock 启动从“全部 Gateway 不可用”推进到可验证的同源 HTTP 装配：先建立 ERP-NEW_2 专属浏览器会话、CSRF 和会话读取契约，再组合仓库内已经冻结并有测试的领域 HTTP 适配器。没有真实契约、仍标记为 Mock 演练或功能目录明确关闭的能力继续失败关闭，不以类型断言或伪造响应提前开放。

本切片不启动 Docker、Vite、后端服务、MySQL、Redis 或 Nacos，不连接任何运行环境；只修改当前隔离工作树，并通过单元测试、静态检查和构建验证。真实登录页面、验证码交互、生产等价浏览器联调以及服务端运行健康检查属于后续切片。

## 2. 已确认现状

- `ErpHttpClient` 已限制同源基础路径，并支持 Cookie、CSRF、组织上下文、请求标识和陈旧组织阻断。
- 各审批、消息、OA、采购、库存、销售及多数调拨 HTTP 适配器已经存在，但 `bootstrapApplication` 在 `VITE_ENABLE_MOCKS=false` 时直接安装 `unavailableGateways` 并清空会话。
- 后端 `/auth/login` 当前把 Bearer Token 返回给前端，网关只读取 `Authorization`；尚无 HttpOnly Cookie 或 Cookie 模式 CSRF 校验。
- `/system/user/getInfo` 已返回当前用户、角色和权限，但尚未返回新前端已知功能清单；`/system/dept/shop-tree` 已按当前用户授权范围返回组织树。
- 调拨工作台聚合、真实发货/收货页面动作和差异裁决提交仍有明确的 Mock/关闭边界，不能在本切片中伪装为真实能力。

## 3. 安全与兼容契约

- 保留现有 Bearer Token 客户端兼容行为；只有显式启用的 ERP-NEW_2 浏览器会话才接受专属 Cookie。
- Cookie 使用 ERP-NEW_2 唯一名称、`HttpOnly`、`SameSite=Strict`、`Path=/`；生产默认要求 `Secure`。访问令牌只允许出现在专属 `Set-Cookie` 中，不得进入响应 JSON。
- CSRF 令牌使用独立的 ERP-NEW_2 本地/部署秘密与会话令牌做 HMAC 绑定；不复用 JWT 密钥、原项目 `.env`、密码或任何现有秘密。
- Cookie 鉴权的非安全 HTTP 方法必须携带匹配的 `X-CSRF-Token`，缺失、错误或配置不可用均在网关失败关闭；Bearer 客户端保持既有行为。
- 网关鉴权失败必须返回真实 HTTP 401/403，同时保留结构化响应码；不得以 HTTP 200 包装鉴权失败。
- 会话、用户授权和组织树响应不得进入浏览器缓存。前端只接受已知功能标识，未知标识默认拒绝。
- 浏览器会话功能由独立开关和独立秘密启用；未配置时不得退回 Bearer 本地存储、共享环境或 Mock 会话。

## 5. 实施顺序

1. 在公共模块实现会话绑定 CSRF 的 HMAC 生成与常量时间比较，并以单元测试锁定空值、错误秘密和篡改令牌行为。
2. 在认证服务增加浏览器登录、会话令牌读取和退出端点；设置/清除专属 HttpOnly Cookie，响应仅暴露 CSRF 和过期信息，并强制 `no-store`。
3. 扩展网关鉴权：Bearer 优先保持兼容；Cookie 模式注入内部 Bearer 头，非安全方法验证 CSRF；修正 401/403 的真实 HTTP 状态，并将浏览器登录纳入验证码校验。
4. 让系统登录信息显式返回新前端功能清单和前端权限集合；功能与权限、业务开关不满足时不发布能力。
5. 新增前端会话 HTTP 适配器，联合浏览器会话、`getInfo` 和授权组织树构造严格 `SessionSnapshot`；组织缺失、未知功能或契约不符时失败关闭。
6. 新增真实 `AppGateways` 组合器，装配已有 HTTP 适配器；调拨聚合、差异裁决提交和仍叫 `simulate*` 的动作保留 unavailable。
7. 改造非 Mock 启动：先加载并验证会话，再原子安装真实 Gateway；401 标记会话过期，网络/配置/契约错误标记不可用并恢复 unavailable Gateway。
8. 运行公共安全、认证、网关、系统模块定向测试，随后执行前端 `npm run verify`、后端相关依赖模块测试和 `git diff --check`，记录独立检查点。

## 6. 验证门禁

- 浏览器登录响应 JSON 和应用日志中不存在访问令牌；令牌仅由专属 `Set-Cookie` 传输，Cookie 属性、唯一名称与清除属性有测试证据。
- Cookie 模式 GET 可通过，POST/PUT/PATCH/DELETE 缺少或篡改 CSRF 时返回 HTTP 403，正确令牌才进入下游。
- 无效/过期 Cookie 返回 HTTP 401；现有 Bearer 请求在无 CSRF 时仍保持兼容。
- 浏览器会话开关关闭、秘密为空或长度不足时 Cookie 鉴权失败关闭，且不会读取其他 Cookie 名称。
- 前端非 Mock 启动只在三份会话事实一致时进入 `ready`；授权组织中不存在当前组织、功能标识未知或响应可缓存时不得安装真实 Gateway。
- 组合测试证明现有已冻结适配器被安装，同时所有未完成真实动作仍明确拒绝。
- 静态扫描证明没有 `erp-ui` import/symlink、没有真实秘密、没有原项目路径引用、没有 Docker/数据库连接或网络运行命令。

## 7. 风险、回滚与停止线

- Cookie 登录是兼容增加，不替换或删除旧 Bearer 端点；若测试发现旧客户端行为变化，停止在兼容层而不是强制切换。
- CSRF 秘密只通过 ERP-NEW_2 独立环境变量提供；仓库示例只保留生成提示，真实值进入 gitignore 的本地配置。
- 当前切片不开放真实发货、收货和差异裁决页面写动作；这些页面仍显示 Mock 文案时不得接入真实 Writer。
- 不启动任何服务，不检查或占用宿主端口，不访问数据库、中间件或已有容器。
- 不删除旧前端、不修改受保护原项目、不合并、不推送。
