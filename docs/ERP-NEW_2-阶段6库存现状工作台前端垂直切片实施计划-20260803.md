# ERP-NEW_2 阶段 6：库存现状工作台前端垂直切片实施计划

> 日期：2026-08-03
> 基线：`eebe92cf feat: add personal message center skeleton`
> 状态：实施中；只读库存工作台切片，不代表库存管理全能力迁移完成

## 1. 目标与范围

在 `erp-ui-next/` 内新增 `/inventory/stock` 库存现状工作台，覆盖当前组织的库存健康指标、物料筛选、分页列表、桌面表格、移动卡片、加载/错误/空状态和明确的数据范围提示。

本切片只实现只读列表与汇总：

- `GET /inventory/stock/list`；
- `GET /inventory/stock/summary`；
- 权限 `inv:stock:list`；
- 当前组织范围和已授权可见范围；
- 商品、运营耗材、礼赠品三类物料；
- 正常、低库存、缺货状态；
- 批次、效期、序列号和库位的只读展示；
- 当前页/服务端筛选、分页和响应式布局。

以下能力明确留待后续切片：分类树、指定门店筛选、库存详情接口、库存调整、变动日志、导出、成本查看、保存视图、Playwright 真实浏览器验证和真实运行时注入。

## 2. 审计结论与硬边界

### 2.1 旧页面和后端

- 旧页面：`erp-ui/src/views/inventory/stock/index.vue`；
- 旧 API：`erp-ui/src/api/inventory/stock.js`；
- 后端：`InvStockController`、`InvStockServiceImpl`、`InvStockMapper.xml`；
- 旧列表权限为 `inv:stock:list`，详情、调整、日志和导出分别使用独立权限；本切片不能把这些权限合并或虚构成新权限。
- `ownOnly=true` 只查询当前门店或仓库；`ownOnly=false` 由服务端按当前账号和组织计算可见范围，前端不得自行提交任意组织 ID 扩大范围。
- 商品状态必须由可用量与安全库存下限计算：可用量小于等于 0 为缺货，大于 0 且小于等于安全库存为低库存，其余为正常。
- 不同物料单位的数量不能直接汇总成一个“总件数”；指标使用品项数、预警数、缺货数和覆盖组织数。

### 2.2 组织头兼容差异

当前后端 `ShopHeaderUtils` 读取 `Dept-NumId`，而新前端 `ErpHttpClient` 默认发送 `X-ERP-Organization-Id`。本切片为 HTTP Client 增加闭合集合内的显式 `organizationHeaderName` 选项：

- 默认继续使用 `X-ERP-Organization-Id`；
- 只有兼容当前旧端点的客户端实例可显式选择 `Dept-NumId`；
- 不同时发送两个组织头；
- 无组织或组织在请求确认后变化时继续在 `fetch` 前失败关闭；
- 默认应用启动仍只注入 Mock，兼容客户端不进入运行时。

### 2.3 成本字段暴露

现有后端列表、详情和汇总会返回 `costPrice`、`totalCost`，但普通库存角色可能没有 `inv:cost:view`。本切片：

- 新领域模型不包含任何成本字段；
- Zod 适配只提取页面需要的安全字段，未知成本字段被丢弃；
- 页面和 Mock 不显示或保留成本；
- 明确记录：客户端丢弃不能替代服务端脱敏，后端修复和负向契约测试完成前不得注入生产运行时。

## 3. 设计与动效决策

项目是高频 ERP/SaaS 工作台，采用 Emil Kowalski 为主、Jakub Krehel 为辅的权重：

- 参考 `docs/previews/warehouse-stock-management-preview.png` 的指标层级和风险概览，但使用现有 Vue 3 设计系统重新实现；
- 参考 UI Prompt Library、21st.dev 和 Motion Primitives 的信息层级与状态连续性，不复制外部代码、组件、品牌或付费提示词；
- 搜索、筛选、分页和键盘提交高频发生，保持即时，不播放入场动画；
- 只允许按钮按压和悬停阴影等 120～180ms 可中断 CSS 过渡；
- 只过渡 `transform`、`opacity` 或 `box-shadow`，不动画布局属性；
- 所有过渡提供 `prefers-reduced-motion: reduce` 关闭路径；
- 不新增 React、Tailwind、Motion、GSAP、远程字体或其他依赖。

## 5. 实施顺序

1. 先新增失败测试，固定十进制字符串、Long 安全、状态推导、成本字段丢弃、旧组织头显式模式、组织漂移预拒绝、Mock 范围和分页、页面状态、路由与导航。
2. 实现库存模型和契约，所有数量保持十进制字符串，使用 `decimal.js` 做比较，不用二进制浮点推导库存状态。
3. 实现只读 Gateway、旧接口 HTTP Reader 和隔离 Mock；真实 Reader 不注入默认运行时。
4. 实现响应式工作台，并让筛选表单支持键盘提交；公司级组织不发送库存请求，而是提示切换门店或仓库。
5. 接入 `inventory.stock.view` 功能开关、`inv:stock:list` 权限、主导航与命令检索。
6. 更新迁移矩阵为“重设计 / 部分实现”，明确未迁移动作和生产阻断项。
7. 运行定向测试、全量 `npm --prefix erp-ui-next run verify`、阶段 1 生成器、确定性哈希和隔离审计。
8. 只有全部门禁通过才创建本地提交；不推送、不合并。

## 6. 验证标准

- 畸形分页、畸形汇总、不安全 Long、非十进制数量和未知物料类型全部失败关闭；
- 列表解析后不存在成本字段；
- HTTP Reader 使用同源路径、Cookie、显式 `Dept-NumId` 兼容模式、必需组织、GET 无 CSRF，并能在组织漂移时不调用 `fetch`；
- Mock 的当前组织/可见范围、关键词、类型、状态和分页行为可重复；
- 页面同时覆盖桌面表格和移动卡片，不依赖 hover 才能理解状态；
- 只有同时具备 `inventory.stock.view` 与 `inv:stock:list` 才能看到并访问入口；
- 全量前端验证、迁移生成器和隔离扫描通过；
- `erp-ui/`、受保护原项目、Docker、服务、数据库、依赖清单和真实配置保持零改动。

## 7. 停止线

发现以下任一情况立即停止，不采用可能影响原项目的替代方案：

- 需要连接数据库、启动服务或读取受保护原项目才能继续；
- 需要修改旧 `erp-ui/`、安装依赖或接入真实运行时；
- 服务端成本脱敏被误当成前端隐藏即可解决；
- 组织头、数据范围或库存状态语义无法从当前工作树证据确定；
- 需要启用库存调整、导出、日志或其他写/高影响动作而未完成独立计划与检查点。
