## 1. 本检查点完成内容

在已提交商品目录基础上新增 `/inventory/products/:productId` 只读详情闭环：

- 真实 HTTP Gateway 读取 `GET /inventory/product/{productId}`；
- 详情路由要求既有 `inventory.product.view` feature 与精确 `inv:product:query` 权限；
- 商品目录仅在具备详情权限时渲染桌面表格和移动卡片入口；
- 新增状态摘要、身份信息、分类规格、库存参数、销售参考、供应与说明分组；
- 提供返回目录、组织不可用、权限不足、加载、失败和重试状态；
- ERP-NEW_2 Mock 详情数据确定、可复制且按商品 ID 与当前组织同时过滤；Mock 不虚构组织层级图，真实 HTTP 的上级共享商品范围仍由后端权威校验。

## 2. 详情契约与敏感字段边界

### 2.1 白名单投影

详情领域只保留：

- 商品 ID、编码、名称、SKU、条码、内部名称；
- 分类 ID/名称/路径、等级、规格、尺寸、单位；
- 销售参考价、250g/500g 售价；
- 安全库存上下限；
- 供应商名称、商品描述、普通维护备注；
- 所属库存组织和启停状态。

即使服务端多返回，下列字段也不会进入 `ProductDetail` 或页面 DOM：

- `purchasePrice`、`costPrice`；
- `supplierPhone`、`supplierRemark`；
- 图片/附件 URL、删除标记及未知扩展字段。

销售参考和安全库存只接受有限非负十进制数；安全库存上限低于下限时失败关闭。商品名称上限已与后端 `InvProduct` 的 128 字符约束对齐。

### 2.2 标识、组织和缓存

- Java `Long` 商品标识保存为十进制字符串，路径型、零值、越界或不安全 number 均在 fetch 前拒绝；
- 成功详情的商品 ID 必须与请求 ID 一致；响应库存组织允许是后端已授权的上级共享组织，不再由前端误判为必须等于请求组织；
- 请求只发送一个 `Dept-NumId` 组织头，GET 不发送 CSRF；
- 请求前组织漂移继续由共享 HTTP Client 失败关闭；
- 成功响应必须包含 `no-store`，否则 Gateway 拒绝；
- 后端详情继续由 `assertAndGetScopedProduct` 校验关联组织范围，无 `inv:cost:view` 时清空采购价和成本价。

> 2026-08-09 维护命令切片复核修正：`InvProductCatalogScopeTest` 已证明仓库可读取关联上级组织的共享商品，因此此前“响应组织必须与请求组织一致”的表述和前端限制过窄。请求头与会话组织仍必须一致，返回数据范围以服务端授权结果为准。

## 3. 权限一致性修复

前端 `hasPermission` 现在与后端 `FrontendFeatureCatalog` 一致识别管理员 `*:*:*`：

- 管理员通配权限满足精确权限要求；
- 普通账号仍要求每一项权限逐项存在；
- 无 `inv:product:query` 时目录不显示详情入口，详情组件自身也不发送请求；
- 直接访问详情路由由统一路由守卫默认拒绝。

## 4. 界面与动效决策

按高频企业 ERP/SaaS 详情处理，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 使用“状态摘要 + 分组详情 + 读取边界”结构；
- 吸收用户列出的 21st.dev、React Bits、UI Prompt Library、Magic UI、Motion Primitives、Uiverse 和 MotionSites 的信息层级提示，不复制外部代码、品牌或资产；
- 不使用页面入场序列、循环光效、弹跳、视差、大幅缩放或布局动画；
- 只给目录/详情链接提供 140–160ms 的可中断按压与悬停反馈；
- `prefers-reduced-motion: reduce` 下关闭非必要过渡；桌面双列在 900px 以下转单列，600px 以下操作与事实网格纵向排列。
