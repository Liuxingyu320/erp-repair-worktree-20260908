## 1. 结果与范围

本切片补齐正式方案阶段 2 的两个通用设计系统基础：

1. 任务状态面板：同时表达当前状态、等待对象、唯一下一步和业务说明；
2. 过程时间线：用稳定、可读屏、可移动端浏览的有序列表呈现节点、状态、处理人、时间和说明。

首个业务消费者是库存调拨审批原型。本轮只重构展示层，不改变审批契约、Gateway、Mock 数据、路由、权限或提交语义。

## 2. 已确定设计决策

- 项目上下文为高频 ERP/SaaS 工作台；动效权重为 Emil 主、Jakub 辅；
- 任务状态和时间线是高频阅读界面，不增加入场、逐项、脉冲、弹跳、粒子或持续光效；
- 组件使用现有 ERP 令牌和 `ErpStatusBadge`，不引入 React、Tailwind、Motion 或新依赖；
- 状态不仅靠颜色表达，时间线使用真实 `<ol>`，当前节点使用 `aria-current="step"`；
- 任务面板使用可控标题层级和具名 `region`，移动端触控操作由现有按钮/链接保持至少约 44px；
- 新组件本身不依赖动效才能理解，全局 `prefers-reduced-motion` 降级继续生效。

## 4. 实施顺序

1. 先为两个组件编写失败测试，锁定标题、状态文字、等待对象、下一步、有序列表、当前节点和时间语义；
2. 实现领域无关的 Vue 3 + TypeScript 严格组件，只使用项目令牌和现有组件；
3. 将调拨审批页的当前责任信息接入任务状态面板，将页面级审批轨迹改为通用时间线；
4. 删除被通用组件取代的页面级时间线样式，保留审批业务交互与请求幂等行为；
5. 执行定向组件/页面测试，再执行完整 `npm run verify`。

## 5. 验证门禁

- 组件测试验证语义化标签、可访问名、标题层级、可选内容、时间标签与 `aria-current`；
- 调拨审批回归测试证明封存版本、操作选择、原因校验、确认和重试幂等未变；
- `npm run verify` 必须通过 Prettier、ESLint、Vue TypeScript strict、OpenAPI 静态门禁、Vitest 和 Vite 生产构建；
- `git diff --check` 与源码隔离测试必须通过；
- 静态扫描必须证明无 `erp-ui/src` import/symlink、无新依赖、无真实连接、无服务启动配置。

## 6. 停止线

- 不启动 Vite/Playwright web server、Docker、MySQL、Redis、Nacos 或后端服务；
- 不执行 `npm install`、`npm ci` 或任何联网依赖命令；
- 不修改 `.env.local`、端口、凭据或运行数据；
- 不将真实 Writer 注入前端，不触发真实业务写操作；
- 不访问受保护原项目，不删除旧前端，不合并、不推送。
