> 执行日期：2026-07-14
>
> 结论：当前混合工作区与 HR-R5-0 干净发布范围均通过 MySQL 5.7.31 家族级兼容复验；正式目标精确小版本仍需确认

## 1. 环境

- 常驻数据库：本机原生 MySQL 8.0.45，端口 3306，全程未停止、未修改。
- 复验数据库：Oracle 官方归档 MySQL Community Server 5.7.31，macOS x86_64 原生二进制，经 Rosetta 执行。
- 官方包 MD5：`d4f3ecaa960f987c225fb8aada8c4bf0`，下载后校验一致。
- 临时端口：3357，仅绑定 `127.0.0.1`。
- 临时库：名称包含 `rehearsal`，使用随机临时账号和进程内口令。
- 基线来源：既有非业务人事只读隔离快照，仅复制迁移和原生测试需要的表。
- 干净发布范围：基于 `b694659d` 的 `codex/hr-master-data-release-20260714` 独立工作树。

Oracle 官方归档在 macOS 上可取得的最后一个 5.7 压缩包是 5.7.31；5.7.44 没有 macOS 构建。因此本记录证明当前迁移和流程可在真实 MySQL 5.7 家族运行，不冒充正式目标精确小版本的验证结果。



最后在两个范围中分别实际执行 3 个原生用例：

```text
HrEmployeeHealthCertificateNativeMySqlTest

```

首次准备当前工作区夹具时遗漏了员工 Mapper 本身依赖的 `hr_onboarding`、`sys_user_role` 和 `sys_user_shop` 表，导致员工查询用例以“缺基础表”失败；这不是产品迁移或 MySQL 5.7 语法缺陷。补齐基础表后重新创建全新临时库，完整步骤从头执行并通过。

干净范围复验第一次导入夹具时，MySQL 8.0 快照导出包含 5.7 不识别的 `utf8mb4_0900_ai_ci`。该临时实例立即销毁；第二次只在只读导出流中将它映射为 `utf8mb4_general_ci`，未修改源快照或项目迁移，再创建全新实例从头执行并通过。

源隔离快照中的 `feature.hr.health-certificate.enabled` 为 `true`，迁移双跑后仍为 `true`，再次证明迁移不会覆盖已有运行开关。正式发布前必须通过独立配置变更显式设为 `false`，不能依赖迁移自动关闭。
