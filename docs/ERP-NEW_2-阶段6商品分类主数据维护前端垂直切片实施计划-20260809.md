## 1. 目标与范围

在已经完成的商品目录、详情和维护闭环基础上，新增 `/inventory/categories` 商品分类主数据工作台：

- 读取真实 `GET /inventory/category/tree` 分类树；
- 支持关键字、状态筛选以及树节点展开/收起；
- 支持根分类和子分类新增、分类编辑、停启用字段维护及两步删除确认；
- 分类维护结果在隔离 Mock 中立即同步到商品编辑器的分类选项；
- 桌面表格与移动卡片共用同一份树投影、权限判断和命令状态；
- 补齐后端分类请求校验、写响应禁缓存和备注持久化缺口。

本切片不实现分类拖拽排序、编辑时迁移父级、批量导入导出、商品级联迁移、旧页面删除或真实运行环境验收。

## 2. 权限、组织与安全边界

- 路由 feature 为 `inventory.category.view`，由 `inv:category:list` 发布；
- 读取要求 `inv:category:list`；新增要求 `inv:category:add`；编辑要求同时具备 `inv:category:query` 与 `inv:category:edit`；删除要求 `inv:category:remove`；管理员通配权限仍由统一权限平台解释；
- 页面只允许门店或仓库组织上下文，公司层级与无有效库存组织时失败关闭且不发送请求；
- 所有请求只发送一个 `Dept-NumId`；读取不发送 CSRF，写操作必须发送 CSRF、`X-Request-Id` 与 `Idempotency-Key`；
- 写操作不自动重试；相同未修改表单重试复用请求 ID，修改表单后生成新请求 ID；
- 所有成功响应必须包含 `Cache-Control: no-store`，否则 HTTP Gateway 失败关闭；
- Java `Long` 在前端保持十进制字符串，拒绝零、负数、越界值和路径型标识；排序号为非负 32 位整数；状态只允许 `0` 或 `1`；
- 新增返回分类必须属于当前库存组织；详情和更新返回 ID 必须与请求一致，关联组织范围仍由后端权威判断；
- 创建命令只允许 `parentId`、`categoryName`、`orderNum`、`status`、`remark`；更新命令只允许 `categoryId`、`categoryName`、`orderNum`、`status`、`remark`，不接受父级、祖先链、组织、编码或删除标记。

## 3. 后端补强

- `InvProductCategoryController` 的详情、新增、编辑和删除响应统一写入 no-store/no-cache；
- `InvProductCategoryServiceImpl` 拒绝负排序号、非法状态、负父级和停用父分类；
- 编辑继续忽略传入的父级和祖先链，避免未授权迁移树结构；
- `InvProductCategoryMapper.xml` 在更新时持久化普通备注；
- 保持现有相关组织范围、子分类阻断、商品引用阻断、缓存清理和服务端编码生成逻辑。

## 4. 前端架构与界面

新增独立分类领域：model、Zod 运行时契约、Gateway 接口和真实 HTTP 适配器；不 import、symlink 或运行时引用旧 `erp-ui` 源码。

工作台包含：

- 分类总数、启用数、根分类数和最大层级四个指标；
- 关键字与状态筛选；筛选时保留命中节点的祖先路径；
- 可访问的展开按钮、层级缩进、状态徽标与组织归属；
- 按权限显示新增根分类、新增子分类、编辑和删除动作；
- 编辑对话框包含父级只读/选择、名称、排序、状态和备注；
- 删除采用静态两步确认并显示精确名称与编码；存在子节点时前端直接阻止，商品引用仍以后端结果为准；
- 加载、空状态、失败重试、保存失败保留表单和移动端可操作布局。

## 5. 动效与可访问性

本页属于高频 ERP/SaaS 工作台，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 树展开、筛选、键盘操作和列表刷新即时完成，不添加页面入场序列或布局动画；
- 仅为按钮、链接和对话框交互提供 140–180ms、可中断的自定义 Bé塞尔反馈；
- 不使用循环光效、弹跳、视差、大幅缩放、模糊遮蔽或全局 `will-change`；
- 只过渡 `transform`、`opacity` 或 `box-shadow`，不动画宽高、位置和间距；
- `prefers-reduced-motion: reduce` 下关闭非必要过渡；焦点陷阱、Escape 关闭、明确标签、错误关联和状态文本不依赖动效。

- 非法标识、非法父级、停用父级、负排序、非法状态、可缓存成功响应、组织漂移和响应身份不一致均失败关闭；
- 无对应权限时不渲染动作且不发送越权请求；公司层级不加载分类；
- 桌面与移动均可完成筛选、展开、增改删确认和失败重试；所有对话框键盘可达；
- Prettier、ESLint、TypeScript strict、OpenAPI、Vitest、Vite 构建、后端定向测试和迁移生成器全部通过；
- 不启动服务、不安装依赖、不执行 SQL、不修改端口/配置/运行数据/旧 `erp-ui/` 或受保护原项目；
- 不删除旧前端，不合并、不推送。
