**F01 · P1 · 采购、采购退货和销售退货草稿缺少编辑版本校验，旧内容会覆盖新修改**

触发：两个人或两个标签页同时打开同一草稿。A 修改金额或明细并保存，B 随后提交打开时的旧内容。

影响：B 的请求仍被接受；A 刚保存的内容会被覆盖。记录行锁只串行执行请求，不能识别旧编辑快照；后续提交可能使用已经被覆盖的数量和金额。

当前证据：已逐层检查服务、DTO 和 mapper。采购使用当前 mapper 的 UPDATE，在 MySQL 会话临时表中执行 A、B 两次更新，二者受影响行数均为 1，最终金额由 20 恢复为旧值 10。该实测覆盖 mapper 条件；两类退货的结论来自服务和 mapper 源码，未冒充完整 HTTP 并发验收。

建议修改：详情返回版本，保存和提交携带打开时的版本；更新时同时校验主键、状态和版本。冲突时保留本地输入，展示最新记录供核对，禁止自动覆盖。

验收：A 保存后，B 的旧版本保存/提交必须失败；A 的主表和明细完整保留；B 的输入仍能查看。验证真实事务、两名用户和两个标签页。
