# ERP-NEW_2 阶段 12B：权威收货规划实施计划

> 日期：2026-08-02
> 基线：`aad80067 feat: add guarded transfer receipt skeleton`
> 范围：只修改 ERP-NEW_2 隔离工作树；只读代码与离线测试，不启动服务、不连接数据库、不执行迁移

## 1. 结果与边界

新增 `GET /transfer/shipments/{shipmentId}/receipt-planning`，以 Stage 11 的不可变 V2 发货分配和序列号关联为唯一来源，生成可供收货页面展示和未来写事务重放的 `receiptPlanVersion`。

本阶段不实现收货写入，不修改 Stage 12A Gate，不增加启用配置，不创建 SQL 迁移。Stage 12C 落地逐分配累计进度前，只允许规划累计收货为零的 V2 发货批次；如果发现发货明细已有历史累计收货但无法归属到来源分配，必须显示阻断，不能猜测分摊。

## 2. 权威输入

按以下来源批量读取，禁止逐行 N+1：

1. `inv_transfer_shipment`：发货 ID、调拨 ID、V2 写版本、发货规划版本、封存修订、来源对账批次、状态。
2. `inv_transfer_order`：组织方向、目标仓、业务状态和版本。
3. `inv_transfer_shipment_allocation` 联结发货明细、调拨明细、来源批次和来源库位：逐来源分配数量、成本、跟踪策略、来源维度和发货明细累计收货。
4. `inv_transfer_shipment_serial` 联结当前 `inv_inventory_serial`：审计快照、当前状态和当前归属。
5. 目标仓 `inv_warehouse_stock_mode`：必须 `dual + detail + passed` 且有非空对账批次。
6. 目标仓 `inv_warehouse_location`：启用、非虚拟的正常存储库位和隔离库位，按类型、排序号和 ID 稳定排序。

成本参与服务端哈希与守恒校验，但不返回给普通收货前端。

## 3. 规划规则

- 只接受 `inventory_write_version=V2_DETAIL`；LEGACY 发货在读取目标库存事实前拒绝。
- 用户必须处于调拨目标组织范围，并通过既有方向策略的收货校验。
- 发货批次必须为 `pending_receive`，调拨单必须为 `partial_delivered/delivered/partial_received`。
- 每条来源分配的 ID、归属、来源仓/余额/批次/库位、物料、数量、成本、跟踪策略必须完整且唯一；来源仓必须与 V2 发货头快照一致。
- 同一发货明细的来源分配合计必须精确等于发货数量；发货明细累计收货不得为负或超过发货量。
- Stage 12B 遇到任一正数历史累计收货即阻断，等待 Stage 12C 的逐分配累计字段，不按比例或排序猜测。
- serial 分配要求审计序列号数等于分配整数数量；每个序列号当前仍为 `shipped`，并保持发货后的来源余额/批次/库位归属。
- lot 分配不得出现任何序列号关联。
- 至少存在一个正常存储库位和一个隔离库位，才能允许开始物理收货；这样现场发现残损时不会被迫错误入正常库存。
- UI 默认把全部剩余量填为合格收货并选取稳定排序第一的正常库位；操作者可在未来写入口中按实物改成部分、残损或短缺。

收货规划不是对现场结果的替代。未来写服务要求 `receiptPlanVersion` 与服务端边界事实一致，然后校验操作者分类数量、目标库位和序列号均位于规划允许范围；不会要求分类数量与默认建议逐字相同。

## 4. 稳定指纹

`receipt-plan-v1` 的 SHA-256 覆盖：

- 发货 ID、调拨 ID、发货状态、V2 写版本、原发货规划、封存修订、来源仓和来源对账批次；
- 调拨单版本、状态、来源/目标组织和仓库；
- 目标仓模式、读写模式、对账状态和目标对账批次；
- 每条来源分配的所有 ID、跟踪策略、分配数量、单位成本、金额、来源批次/库位事实和发货明细累计量；
- 每个序列号 ID、快照、审计状态、当前状态和当前位置；
- 所有候选目标库位 ID、编码、类型、排序和启用/虚拟状态；
- 稳定排序后的阻断原因。

查询时间、操作者、组织名称和序列号掩码不进入哈希。相同数据库事实必须生成相同版本；任一余额归属、序列号状态、目标模式/库位或累计量变化都必须改变版本。

## 5. 输出契约

响应所有 Long ID 和 decimal 数量均使用字符串：

- 发货/调拨标识、单号、状态、来源和目标名称；
- `receiptPlanVersion`、目标库存权威快照、生成时间；
- 正常与隔离库位候选及建议默认 ID；
- 逐来源分配的物料、来源批次/库位、跟踪策略、已发/已收/剩余/默认合格数量；
- serial 物料返回序列号 ID、掩码和 `shipped` 状态；
- `canCreateReceipt`、全局及逐分配阻断原因、`dataSource=server`。

响应设置 `Cache-Control: no-store`，权限为 `inv:transfer:receive`，不带 `@PersistentCommand`。
