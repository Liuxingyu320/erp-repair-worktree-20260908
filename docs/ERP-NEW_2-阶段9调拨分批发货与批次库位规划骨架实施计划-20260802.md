# ERP-NEW_2 阶段 9：调拨分批发货与批次库位规划骨架实施计划

> 日期：2026-08-02
> 基线：`807efacb feat: add dual-engine transfer approval flow`
> 范围：只修改 ERP-NEW_2 隔离工作树；不启动服务、不连接数据库、不执行 SQL

## 1. 目标

审批通过后的下一条业务链路是“待调出确认 → 分批发货 → 批次/库位分配 → 在途”。本阶段先建立新前端可验证的发货规划骨架：显示封存版本、剩余待发量、后端权威 FEFO/FIFO/序列号建议和阻断原因，并只在隔离 Mock 中演练“接受服务器建议并形成发货命令”的交互。

本阶段不把现有 `POST /inventory/transfer/deliver/{transferId}` 接入新页面。现有写入口只接受调拨明细和数量，尚不能承载批次、库位、序列号、计划版本和人工改选证据；直接接入会造成界面表达强于后端事实，因此必须失败即关闭。

## 2. 业务不变量

1. 审批数量 = 已发数量 + 剩余待发数量，所有数量使用十进制字符串。
2. 本批建议发货量不得超过剩余待发量；每个分配数量不得超过后端返回的可分配量。
3. 批次、库位、余额和序列号标识必须由后端建议返回，前端不得自行查询或计算库存余额。
4. 有效期物料由服务端按 FEFO 排序，无有效期物料按 FIFO；前端只显示策略、排序和依据。
5. 过期、隔离、待检、冻结、残损和禁用库存不得出现在可接受建议中。
6. 序列号物料必须逐件绑定后端返回的可用序列号事实，数量必须为整数且与序列号数量一致。
7. 任何不完整轨迹、守恒错误、重复余额、重复序列号、阻断项或非服务端建议都不得生成命令。
8. 命令携带调用方生成的唯一请求标识与计划版本；真实接口未来接入时不得自动重试，结果不确定的人工重试复用原标识。

## 3. 本骨架交付

- 新增调拨发货规划 Zod 契约和守恒校验。
- 新增“从服务端建议派生 Mock 发货命令”的纯函数，禁止自由输入库存维度。
- 扩展 Transfer Gateway、隔离 Mock 和固定发货规划 fixture。
- 新增受功能与权限保护的发货规划路由、工作台入口和统一待办深链。
- 新增移动优先发货规划页：业务摘要、策略说明、批次/库位卡、序列号摘要、阻断项和两步 Mock 确认。
- 新增领域、深链和页面测试；运行完整前端门禁。

## 4. 界面结构与参考取舍

采用“业务摘要 + 主分配清单 + 粘性确认区”的后台任务结构：

- 21st.dev 仅用于观察组件层级与提示词表达，不复制 React/shadcn 代码。
- React Bits 与 Magic UI 只提供状态卡和局部层次灵感，不使用营销型背景、WebGL 或持续动画。
- UI Prompt Library 的指标卡、三栏/主从内容提示用于组织高密度信息。
- Motion Primitives 用于借鉴克制的确认面板和状态连续性；实际用 Vue 与现有 CSS token 独立实现。
- Uiverse 只用于按钮、加载和输入等局部细节参考。
- MotionSites 只作为动效提示词补充，不把营销页编排带入高频仓库作业。

页面最多使用一次约 180ms 的 `opacity + translateY(4px)` 进入动效；策略切换、接受建议和错误状态即时更新，并完整支持 `prefers-reduced-motion`。

## 5. 明确边界

- 不新增或执行数据库迁移，不启用 `dual/shadow/detail` 仓库模式。
- 不声称真实 FEFO/FIFO 已运行；Mock 排序只用于冻结展示契约。
- 不改造现有库存扣减、发货事务或明细流水。
- 不上传证据，不扫码真实序列号，不调用摄像头。
- 不启动 Docker、前端开发服务、后端或中间件。
- 不连接任何共享或生产服务，不删除旧前端，不推送。

## 6. 后续真实闭环前置条件

1. 后端提供组织受控、`no-store` 的发货规划读取接口，并返回计划版本和权威分配建议。
2. 建立批次、库位、序列号 Java domain/mapper 与统一库存变动服务。
3. 发货命令在同一事务内锁定业务单、作业任务、批次、余额、序列号和汇总行。
4. 数据库唯一键保护请求标识；双写失败整体回滚。
5. 独立 ERP-NEW_2 数据库完成建表、回填、对账和并发测试后，才允许真实写 Gateway 接入。
