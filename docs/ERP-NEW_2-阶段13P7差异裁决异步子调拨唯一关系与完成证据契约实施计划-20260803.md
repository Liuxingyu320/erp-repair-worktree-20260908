# ERP-NEW_2 阶段 13P7：差异裁决异步子调拨唯一关系与完成证据契约实施计划

> 日期：2026-08-03
>
> 分支：`codex/erp-new-2-rebuild`
>
> 基线：`87473d07 feat: compose adjudication sync execution`
>
> 范围：冻结补发/退回子调拨方向、库存来源、唯一关系和完成证据；不创建子调拨、不冻结库存、不接线执行入口

## 1. 审计结论

阶段 13P6 已能在一个未接线事务中执行三类同步效果，但补发和退回仍在首个事件或效果 DML 前关闭。现有代码只能为补发复用一部分能力，不能把两个异步动作当成同一种库存来源：

1. 补发应保持原调拨方向，从原来源仓重新冻结可用库存；现有 `InvTransferReservationService.reserveForSubmission` 已具备全单锁定、全量校验和失败回滚语义。
2. 退回应反转原调拨方向，并冻结目标仓 V2 收货形成的隔离余额、受损批次、隔离库位和序列号；现有商品级预留只操作可用聚合库存，不能用于退回。
3. 当前 `inv_transfer_order.source_business_type/source_business_id` 只有普通索引，不能单独证明一个裁决动作只创建一个子调拨。
4. 动作上的 `execution_effect_reference` 只能保存引用，不能证明子调拨方向、物料、数量、成本、库存来源和裁决事实一致。
5. 子调拨只有达到 `received`、全部发货均为 `V2_DETAIL`、已产生收货且没有未解决 V2 差异事项时，才能作为 `complete` 的权威证据。

因此本阶段先建立两个未来效果所有者共同消费的窄契约，避免它们分别推导方向、引用和终态。

## 2. 固定语义

### 2.1 补发

- 动作：`shortage/reship`；
- 效果：`reship_workflow`；
- 子调拨方向：原来源仓 → 原目标仓；
- 子调拨类型：保持原调拨类型；
- 库存来源：`available_stock`；
- 业务来源：`transfer_discrepancy_reship` + 裁决动作 ID；
- 效果引用：`reship_transfer:<childTransferId>`。

### 2.2 退回

- 动作：`damaged/return_to_source`；
- 效果：`return_workflow`；
- 子调拨方向：原目标仓 → 原来源仓；
- 原类型 `warehouse` 与 `store_return` 互换，`cross_store` 保持不变；
- 库存来源：`quarantine_detail`；
- 必须锚定受损目标余额、批次和隔离库位；序列号物料的后续效果所有者还必须稳定锁定明确单件；
- 业务来源：`transfer_discrepancy_return` + 裁决动作 ID；
- 效果引用：`return_transfer:<childTransferId>`。

## 3. 唯一关系

新增惰性表 `inv_transfer_receipt_discrepancy_adjudication_workflow_link`，保存：

- 事项、裁决、动作和父调拨锚点；
- 唯一子调拨 ID；
- 动作/效果/工作流类型；
- 原方向与实际子调拨方向；
- 物料、数量、源成本和金额；
- 收货分配、发货分配以及退回隔离余额/批次/库位锚点；
- 库存来源、业务来源、效果引用；
- 决定指纹、工作流指纹、创建人和创建时间。

数据库同时约束一个动作只能绑定一个子调拨、一个子调拨只能归属一个动作、效果引用唯一、业务来源唯一。该表只追加，不更新状态，不复制子调拨生命周期。

## 4. 纯策略

新增纯领域策略，负责：

1. 校验差异/动作组合、标识、SHA-256、数量金额和原调拨方向；
2. 唯一推导子调拨方向、类型、业务来源、库存来源和效果引用；
3. 在绑定时验证子调拨只有一条完全匹配的明细，已精确冻结动作数量，且尚未发货或收货；
4. 生成包含全部裁决、方向、物料、库存来源和子调拨事实的稳定工作流指纹；
5. 在完成时验证同一不可变关系、子调拨终态、全量发货、纯 V2 发货、至少一个收货以及零未解决 V2 差异。

客户端、Controller、Service 或 Mapper 不得自行拼接效果引用或决定终态。

## 5. 未接线 Mapper

新增窄 Mapper 只允许：

- 锁定动作已有关系；
- 条件追加唯一关系；
- 按关系锁定子调拨头和唯一明细；
- 只读统计子调拨预留、V2/旧发货、收货和未解决 V2 差异。

它不创建或更新调拨单、明细、库存、预留、批次、库位、序列号、发货、收货、执行事件或裁决状态，并且不得有生产调用点。

## 6. 后续事务顺序

本阶段冻结但不实现未来异步事务：

### dispatch

1. 沿阶段 13P6 顺序锁定事项、裁决和全部动作；
2. 锁定动作工作流关系，存在时只允许精确重放；
3. 由对应效果所有者创建并提交唯一子调拨，同时完成精确库存冻结；
4. 条件追加不可变关系并获得服务端效果引用；
5. 使用引用准备执行事件；
6. 追加事件并把动作推进到 `in_progress`。

### complete

1. 沿同一顺序锁定事项、裁决、动作和关系；
2. 锁定子调拨头与明细；
3. 读取 V2 发货、收货和差异终态证据；
4. 纯策略验证完成事实；
5. 追加完成事件并条件推进动作、计划和事项。

任何步骤失败均由同一外层事务回滚。补发/退回的具体库存锁序必须在各自效果所有者阶段继续冻结。

## 7. 验证

- 两种动作唯一推导方向、类型、库存来源、业务来源和效果引用；
- 方向、物料、数量、成本、预留或子调拨归属漂移全部失败关闭；
- 退回缺少隔离余额/批次/库位时失败关闭；
- 非 `received`、存在旧发货、没有 V2 发货/收货、未全量发货或仍有未解决差异时不能完成；
- SQL 只增加一张关系表，不写业务数据；
- Mapper XML 可解析、方法全部绑定、DML 只有一个条件插入且没有生产调用点；
- 定向测试与 inventory 完整离线 Reactor 通过。

## 8. 停止线

- 不创建、提交、审批、发货或收货任何子调拨；
- 不冻结、释放、扣减或移动可用/隔离库存；
- 不修改阶段 13P6 事务，不开放硬关闭执行入口；
- 不执行 SQL，不连接数据库、Redis 或 Nacos；
- 不启动 Docker、服务或中间件，不安装依赖；
- 不修改运行配置、端口、密码或密钥；
- 不删除旧前端，不访问受保护原项目，不合并、不推送。
