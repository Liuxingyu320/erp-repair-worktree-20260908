# ERP-NEW_2 阶段 6：审批流程定义只读目录前端垂直切片实施计划

> 日期：2026-08-03
> 基线：`67129a8c feat: add approval instance monitor skeleton`
> 状态：实施中；只读审批模板目录切片，不代表流程配置、规则管理或统一审批闭环迁移完成

## 1. 目标与范围

在 `erp-ui-next/` 内新增 `/approvals/definitions` 审批流程定义目录，覆盖拥有审批模板列表权限的管理员查看统一审批业务模板、按业务类型、名称、来源、引擎和状态筛选、服务端分页、当前页状态摘要，以及响应式只读展示。

本切片只实现：

- `GET /approval/templates`；
- 权限 `approval:template:list`；
- 明确的管理员跨组织只读语义，请求不发送组织头；
- 业务类型、模板名称、业务来源、引擎模式和模板状态筛选；
- 服务端总记录数，以及当前页启用、统一引擎、有限配置和停用数量；
- ERP-NEW_2 隔离 Mock 默认运行时和未注入的真实只读 HTTP Reader；
- 桌面表格、移动卡片、加载、错误、空状态和最近成功筛选语义。

以下能力明确留待后续独立切片：模板详情、规则列表、版本详情、草稿、编辑、复制、发布、停用、候选人预览、配置检查、真实运行时注入和旧审批管理页面下线。

## 2. 审计结论与硬边界

### 2.1 接口与权限拆分

- 模板列表：`GET /approval/templates`，权限 `approval:template:list`；
- 模板详情、规则详情和候选人预览使用 `approval:template:query`；
- 规则创建/编辑、草稿、版本保存和停用使用 `approval:template:edit`；
- 版本发布使用 `approval:template:publish`；
- 本切片不得展示详情或任何写命令伪入口，也不得用列表权限调用规则、版本或检查端点。

### 2.2 跨组织管理员目录

- `ApprovalDefinitionController.templates` 与 `ApprovalTemplateMapper.selectTemplateList` 是系统级模板目录，没有当前组织过滤；
- 新 Reader 显式省略组织头，不把当前店铺或仓库误表达为服务端过滤条件，也不发送 `params`、组织 ID 或任意规则字段；
- 页面明确标注“管理员跨组织只读”，所选业务组织不改变目录范围；
- 默认 Provider 只注入隔离 Mock；真实 Reader 在版本化 OpenAPI、服务端 `no-store` 和生产等价权限负向测试完成前保持未注入。

### 2.3 状态、字段与敏感投影

- 当前业务类型闭集为 `OA_PURCHASE`、`INV_TRANSFER`、`INV_STOCK_CHECK`、`HR_HEALTH_CERTIFICATE`；
- 引擎模式闭集为 `NATIVE`、`LEGACY`，定义模式闭集为 `FIXED`、`LIMITED`，模板状态闭集为 `DRAFT`、`ACTIVE`、`DISABLED`；
- 模板 ID 必须经过 Java Long 边界，名称与代码按后端长度限制收紧；未知代码、来源、模式或状态失败关闭；
- 新列表只保留模板 ID、业务代码、模板名称、业务来源、引擎模式、定义模式和模板状态；
- 旧引擎适配器、回调服务、创建更新操作人及时间、备注、锁版本和 `params` 不进入新模型；
- 跨组织配置响应必须显式声明 `Cache-Control: no-store`，否则 Reader 失败关闭。当前端点没有该响应头证据，因此仍是生产注入阻断项。

## 3. 设计与动效决策

这是高频 ERP/SaaS 管理目录，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 使用“管理员跨组织范围 → 服务端总记录/当前页配置结构 → 明确筛选 → 模板事实”的层级；
- 模板、业务来源、引擎、定义模式和状态在桌面与移动端保持等价；
- 搜索、状态筛选、键盘提交、分页和列表替换不播放动画；
- 只允许按钮按压的 140ms 可中断 `transform` 过渡；
- `prefers-reduced-motion: reduce` 下关闭所有非必要过渡；
- 21st.dev 与 UI Prompt Library 仅用于后台目录的信息层级，Motion Primitives 仅用于状态连续性；不复制外部代码、素材、品牌或付费提示词；
- 不新增 React、Tailwind、Motion、GSAP、远程字体或外部组件依赖。

## 6. 验证标准

- 不安全 Long、非法业务类型、来源、模式、状态和越界筛选全部失败关闭；
- 新模型不包含适配器、回调服务、内部操作人、时间、备注、锁版本或原始参数；
- HTTP Reader 只发送允许参数，不发送组织头或 CSRF，并强制响应 `no-store`；
- 默认隔离 Mock 可以展示多个 ERP-NEW_2 模拟业务来源，且不会读取任何真实或共享业务数据；
- 页面明确区分服务端总记录和当前页统计，不把分页样本误报为全局统计；
- 筛选成功后才更新已应用条件，失败时保留最近成功标签并可重试最后请求；
- 页面没有详情、规则、草稿、编辑、发布、停用、预览、检查、导出或新建伪入口；
- 功能开关和列表权限同时满足才可见且可访问；
- 完整前端验证、迁移生成器、确定性哈希和隔离扫描通过；
- 旧 `erp-ui/`、受保护原项目、Docker、服务、数据库、依赖和真实配置保持零改动。

## 7. 停止线

发现以下任一情况立即停止：

- 需要读取或修改受保护原项目、连接数据库、启动服务或安装依赖；
- 需要修改旧 `erp-ui/`、注入真实 Reader 或把当前组织头误当作管理员目录的数据范围；
- 需要规则、版本、检查或写命令而没有独立计划；
- 需要扩大普通用户权限或不能证明跨组织目录仅由管理员权限控制；
- 不能证明全部文件、运行目录和测试只位于 ERP-NEW_2 隔离工作树。
