> 状态：权威累计进度与纯请求校验骨架完成；事务锁协调器尚未接线

## 1. 实际结果

本检查点完成阶段 12C2 的前置依赖，但不宣称整个 12C2 已完成：

1. 收货规划不再因为存在历史收货就整体阻断，而是读取每个来源分配的累计合格、残损、显式短缺和 `receiptVersion`，权威计算当前剩余量。
2. 同一发货明细下，来源分配总量必须与已发量守恒，累计合格量必须与发货明细累计已收量守恒；任一分配不可核验都会使整个规划不可执行。
3. 已完成分配使用独立 `complete` 状态；仍有剩余的序列号分配只暴露尚未被 V2 收货审计分类的来源序列号。
4. 收货规划指纹加入三类累计进度和 `receiptVersion`，逐次收货进度变化会让旧页面规划版本失效。
5. 新增纯 Java 请求策略：严格校验规划版本、来源分配、数量、目标库位、差异证据、lot/serial 边界、全请求序列号唯一性和完成标志，并输出不可变规范化命令。
6. 规范化命令按来源分配和序列号 ID 稳定排序，生成 SHA-256 `requestFingerprint`，为后续业务幂等键提供确定输入。
7. 加法迁移源码为 `(shipment_id, shipment_serial_id)` 增加唯一键，防止同一发货序列事实被多个普通收货批次重复分类。
