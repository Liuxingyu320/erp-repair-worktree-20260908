# ERP-NEW_2 前端设计参考与使用约束

> 核验日期：2026-08-03
> 状态：纳入 ERP-NEW_2 前端重建目标
> 适用范围：设计系统、三个 Mock 原型及后续全部领域页面

## 1. 使用原则

外部站点用于学习信息架构、构图、层级、动效节奏和提示词表达，不用于拼装一个与 ERP 业务脱节的营销站。最终代码必须服务于 Vue 3、Element Plus、桌面高密度管理和移动任务闭环。

优先级保持不变：

1. 业务状态、权限、数据和下一步操作清楚；
2. 真实岗位用户无需培训即可完成任务；
3. 动效帮助理解变化、反馈和空间关系；
4. 装饰性视觉不得牺牲性能、可读性或无障碍。

## 3. Vue 3 原创适配规则

- 不在 `erp-ui-next/` 中引入 React、Next.js、shadcn/ui 或仅为复刻示例而增加的 Tailwind 依赖。
- 先描述要解决的业务问题和运动语义，再使用 Vue 3 Composition API、项目设计令牌和必要的 CSS 实现。
- Element Plus 只作为底层控件；外部统一通过 ERP 设计系统组件暴露，禁止页面直接形成多套视觉语言。
- 外部示例的颜色、字体、圆角、阴影、间距和动效参数必须映射到 ERP-NEW_2 令牌，不原样复制品牌外观。
- 不能复制外部站点的商标、插画、图片、文案、完整页面编排或具有识别性的品牌组合。

## 4. 动效标准

- ERP 属于高频生产力工作台，动效决策采用“Emil Kowalski 的克制与频率门禁为主、Jakub Krehel 的生产级细节为辅、Jhey Tompkins 只用于低频引导与空状态”的权重。
- 键盘触发和一天内高频重复的表格操作默认即时完成，不播放入场动画；日常浮层与状态反馈只使用短促、可打断的过渡。
- 进入可以使用少量透明度、约 4～8px 位移或轻微模糊；退出必须比进入更弱，避免与下一状态争夺注意力。
- 浮层和菜单必须从触发点产生，连续快速点击时应自然重定向到新状态，不能排队播放关键帧。
- 专业业务界面不使用弹跳、弹性、全屏缩放、视差或持续吸睛光效；按钮按下反馈可在不影响布局时使用约 `scale(0.97)`。
- 动效必须回答“发生了什么、从哪里来、现在在哪里、下一步是什么”。
- 高频控件反馈通常控制在 120～200ms；浮层、抽屉和页面区域过渡通常控制在 180～280ms。
- 列表刷新、状态变更和数量更新优先使用局部过渡，不让整页重新入场。
- 核心表格、表单、审批、发货和收货页面禁止持续循环的装饰动画。
- 工作区域禁止使用影响文字对比度的动态背景；WebGL、3D 和大面积粒子效果不进入核心任务流。
- 使用 transform 和 opacity 为主，避免引发布局抖动；普通办公设备和移动 WebView 必须保持流畅。
- 必须支持 `prefers-reduced-motion`；关闭非必要动画后，状态和层级仍完整可理解。
- 动效不得延迟主操作反馈；点击改变业务状态的操作后 300ms 内仍必须出现明确处理中状态。

## 5. 分场景采用策略

### 工作台与导航

- 优先参考 UI Prompt Library 的侧栏、三栏和指标卡结构，以及 21st.dev 的成熟布局变体。
- 动效只用于导航层级、待办增减、异常出现和组织切换反馈。

### 库存调拨

- 参考 Motion Primitives 的克制转场表达状态推进、抽屉详情和差异展开。
- 发货、收货、差异和库存数量必须以稳定文字、数字和审计时间线为主，不能依赖动画表达事实。

### 登录、空状态与品牌时刻

- 可以有限参考 Magic UI、React Bits、Uiverse 和 MotionSites 的构图或质感。
- 动态背景必须轻量、可关闭且不影响登录表单对比度；不得把营销式 Hero 套到业务工作区。

### 移动网页

- 参考提示词库的底部导航、任务卡和单列流程，但保持约 44px 触控目标、固定主操作和清晰返回路径。
- 禁止仅在 hover 时显示操作或信息。
