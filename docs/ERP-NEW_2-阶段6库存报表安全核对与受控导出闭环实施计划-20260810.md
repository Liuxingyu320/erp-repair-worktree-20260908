## 1. 目标与范围

把现有 `/inventory/report` 只读前端切片扩展为可安全接入真实后端、可选择商品、可核对库存明细并可受控导出预警的响应式经营工作台，同时关闭旧 `/inventory/report/summary` 对无成本权限角色返回成本字段的服务端漏洞。

本切片完成：

1. 报表汇总、预警、商品候选和导出统一 `no-store`；
2. 无 `inv:cost:view` 时由服务端清空库存成本、采购净额、销售成本和毛利；
3. 报表权限用户无需额外商品主数据权限即可查询当前库存组织内的安全商品候选；
4. 预警行可在具备库存详情权限时钻取到精确库存记录；
5. 汇总卡片可在具备对应权限时进入库存、采购或销售工作台核对；
6. 新增 `inv:report:export` 独立权限和仅含安全库存字段的预警 Excel 导出；
7. Mock 与真实 HTTP Gateway 使用同一商品候选、摘要、预警和导出契约。

本切片不实现趋势接口、跨组织汇总、报表配置或任意 SQL 分析器；这些能力没有现成后端契约，继续作为后续经营分析阶段。仍不启动 Docker、服务或数据库，不删除旧前端，不访问受保护原项目。

## 2. 审计基线与必须修正的问题

### 2.1 既有正式能力

旧页面和后端正式提供：

- `GET /inventory/report/summary`：库存健康、采购、销售、成本与毛利汇总；
- `GET /inventory/report/stock-warning`：低库存、缺货和安全阈值未配置列表；
- 当前精确门店或仓库、商品和经营日期筛选；
- `inv:report:list` 报表读取权限与 `inv:cost:view` 成本显示权限。

现有新前端已覆盖安全模型、Mock、筛选、分页、桌面表格和移动卡片，但真实 HTTP 在无成本权限时必须跳过整个 summary，因此普通报表用户看不到非成本经营摘要。

### 2.2 安全和体验缺口

1. `InvReportController` 没有 `Cache-Control: no-store`。
2. summary 只校验 `inv:report:list`，仍向无 `inv:cost:view` 角色返回成本字段。
3. 旧商品选择器额外依赖 `inv:product:list/query`，部分报表角色只有 `inv:report:list`，会出现有报表权限却无法选商品。
4. 页面使用手填商品 ID，无法安全发现当前组织可报表商品。
5. 预警行和汇总卡片没有核对入口。
6. 预警无法导出，且现有权限树没有独立报表导出权限。

## 3. 后端设计

### 3.1 Controller 边界

修改 `InvReportController`：

- `summary`、`stock-warning`、新增 `product-options` 和新增 `stock-warning/export` 均设置 `no-store, max-age=0` 与 `Pragma: no-cache`；
- `summary` 返回前按 `inv:cost:view` 或管理员身份决定是否保留成本字段；
- `product-options` 使用 `inv:report:list`，不要求商品主数据权限；
- `stock-warning/export` 使用独立 `inv:report:export`，记录导出审计日志；
- 导出只使用当前成功查询条件和当前精确库存组织。

### 3.2 商品候选

新增 `InvReportProductOption` 与 Mapper 查询：

- 只从当前组织 `inv_stock` 与有效商品关联结果中返回去重候选；
- 字段仅包含商品 ID、编码、名称、规格和单位；
- 关键词长度不超过 100 字符，最多返回 50 条；
- 关键词使用 MyBatis 参数绑定，不拼接 SQL；
- 候选不返回成本、供应商、图片、内部版本或其他组织信息。

### 3.3 安全导出

新增 `InvReportWarningExportRow`：

- 只包含商品编码/名称/分类/规格/单位、库存组织、批次/效期/序列号/库位、当前/可用库存、安全下限、缺口、预警状态和最后变动时间；
- 不使用 `InvStock` 直接导出，避免空白成本列和未来实体字段意外进入报表；
- 导出结果仍由服务端组织范围和状态筛选决定，前端不重新计算业务事实。

### 3.4 权限迁移

新增独立、幂等 SQL：

- 权限码：`inv:report:export`；
- 挂在库存报表菜单下；
- 不自动授予任意现有角色，真实独立环境初始化时由项目负责人按角色授权；
- 仅新增菜单/权限数据，不连接或修改任何现有数据库。

## 4. 新前端领域与 HTTP 契约

扩展 `report.model.ts`、`report.contract.ts`、`report.gateway.ts` 和 `report.http.ts`：

- `ReportProductOption`、`ReportExportFile` 和有界商品搜索参数；
- summary 对无成本权限仍要求安全字段完整，但允许四个成本字段为 `null` 或缺失；
- 商品候选严格校验 Long 字符串、文本长度和当前请求上下文；
- 所有报表响应强制验证 `no-store`；
- 导出使用 POST、CSRF、当前组织头和请求 ID，不自动重试；
- Excel MIME 必须合法、文件非空且不超过 25 MiB；
- 任何组织漂移、跨组织预警、非法日期、非法十进制或错误文件类型均失败关闭。

隔离 Mock 增加商品候选和预警导出，并继续按当前组织、商品、日期和预警状态过滤；导出只生成本地内存 Blob，不访问文件系统或服务。

## 5. 页面与交互

### 5.1 商品筛选

- 组织切换后加载当前组织前 20 个候选；
- 支持按编码或名称显式搜索，不在每次按键时发送请求；
- 选择结果保存服务端商品 ID，但页面展示编码、名称和规格；
- 搜索失败保留已选择商品并提供独立重试，不覆盖最近成功报表。

### 5.2 核对入口

- 有 `inv:stock:query` 时，预警行显示“查看库存”并进入 `/inventory/stock/{stockId}`；
- 有 `inv:stock:list`、`inv:purchase:list` 或 `inv:sales:list` 时，汇总区域提供清晰的独立核对入口；
- 没有目标权限时只展示指标，不渲染不可用链接；
- 不声称目标页面已经消费报表筛选条件，避免制造伪精确钻取。

### 5.3 受控导出

- 仅有 `inv:report:export` 时显示导出按钮；
- 只导出最近一次成功应用的商品和预警状态条件，不使用尚未提交的草稿筛选；
- 二次确认展示当前组织、已应用条件和服务端记录数；
- 导出期间阻止重复提交，失败保留页面数据，成功后恢复焦点并显示文件名；
- 继续遵循高频 ERP 的克制交互和 `prefers-reduced-motion`。

## 9. 风险、兼容与回滚

- 旧客户端继续使用原 summary 和 stock-warning 路径，字段只在无成本权限时由敏感值变为 `null`，属于安全收紧；
- 新导出权限默认不自动授予角色，避免扩大数据分发范围；
- 商品候选只覆盖当前有库存的商品，避免报表筛选出现当前组织完全无事实的数据；
- Excel 导出不复用宽泛 `InvStock` 注解，防止未来字段扩展造成静默泄漏；
- 所有变更局限于专属分支，可通过回退本地阶段提交恢复；不 push、不 merge、不操作其他 worktree。
