# 销售退货成本复核补修

实施目录：问题修复实施_20260909。只修改隔离副本与本地测试库，未进行生产操作、提交或部署。

## 处理规则

1. 根据原销售明细 ID，经发货通知明细关联实际出库记录，使用冻结的出库金额；商品与同编号礼盒、同物料不同原销售行分别计算。出库数量必须完整覆盖该原明细累计已出库数量。
2. 仅在一个物料只有唯一已出库原行，并且原销售出库流水完整覆盖累计数量时，兼容旧订单物料级成本证据。不会使用当前库存成本替代原成本。
3. 本次实际返还成本按“原行累计出库成本减历史已返成本”的余额分摊。数量余额只扣实际已退数量，草稿和待确认预约不扣成本；最后一次退完剩余数量时结清全部剩余成本。
4. 每条退货明细保存实际已退数量、实际已返成本和原明细关联。查询包括同事务此前已经处理的同源行，因此一个退货单出现多个相同原明细时也不会重复返还成本。
5. 库存总成本、退货明细成本事实、库存流水精确金额在确认事务内一起保存。出库流水同步保存实际扣减成本金额，报表的出库和退货两侧都优先读取流水精确金额；兼容旧流水的既有数量乘成本单价口径。

例：先出库 5 件成本 50、退回成本 50，再出库 5 件成本 10，下一次退 5 件只返成本 10。出库 3 件总成本 5，全退返 5；先退 1 件返 1.67，最后退 2 件返 3.33。

## 历史记录边界

历史已退行若只有整单流水、缺少可证明的原明细已返成本，保持空值，不回填为 0，不猜分配。该物料再次确认退货会提示核对历史退货记录，阻止新的库存和成本写入。历史详情仍可读取；草稿编辑和提交不会调用成本分摊，仍要求选择明确原销售行。已经退货的单据禁止再编辑或重复确认，由既有状态规则在成本处理前拦截。

成本金额字段不从退货 JSON 接收，也不通过普通退货详情返回；由确认操作根据可信记录产生。历史报表金额不会被本次修复重写。
