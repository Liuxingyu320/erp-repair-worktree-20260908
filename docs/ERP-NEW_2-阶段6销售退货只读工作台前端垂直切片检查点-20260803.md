## 1. 本检查点结论

`erp-ui-next/` 已新增 `/sales/returns` 销售退货只读工作台，使用 `inventory.sales-return.view` 与 `inv:salesReturn:list` 双重门禁，只在门店上下文读取当前门店隔离 Mock。页面覆盖退货单号、原销售单号、客户和状态筛选、服务端分页、当前页状态指标，以及桌面表格与移动卡片的等价展示。

本切片没有提供详情、新建、编辑、保存、提交、确认退货、取消或导出入口，也没有把库存回补与金额冲回写流程描述为已迁移。

## 2. 契约与隔离证据

- 列表端点：`GET /inventory/salesReturn/list`。
- 入口权限：`inv:salesReturn:list`。
- Reader 只发送 `pageNum`、`pageSize`、`returnNo`、`salesOrderNo`、`customerName` 与 `status`，以及一个当前会话 `Dept-NumId`；GET 不发送 CSRF。
- 请求前通过 `expectedOrganizationId` 拒绝组织漂移，解析后拒绝任一跨门店记录。
- 状态闭集为 `draft`、`submitted`、`returned`、`cancelled`；未知状态失败关闭。
- Java Long、有效业务日期和非负十进制金额均由运行时契约校验。
- 来源销售单 ID、申请人 ID、申请部门 ID、详情、数据范围参数、内部更新字段与跨商品单位数量汇总均被丢弃。
- 默认 Provider 仍只注入 ERP-NEW_2 隔离 Mock；真实 HTTP Reader 未接入应用启动流程。
- 后端列表响应没有显式 `Cache-Control: no-store` 证明，这是生产注入阻断项。
