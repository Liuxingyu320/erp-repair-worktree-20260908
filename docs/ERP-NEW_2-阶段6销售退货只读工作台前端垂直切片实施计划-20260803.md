# ERP-NEW_2 阶段 6：销售退货只读工作台前端垂直切片实施计划

> 日期：2026-08-03
> 基线：`c0391129 feat: add sales order workbench skeleton`
> 状态：只读销售退货列表前端切片与完整门禁已完成；不代表售后退货业务闭环迁移完成

## 1. 目标与范围

在 `erp-ui-next/` 内新增 `/sales/returns` 销售退货工作台，覆盖当前门店退货单的筛选、服务端分页、来源销售单、退货金额、业务状态和响应式只读展示。

本切片只实现：

- `GET /inventory/salesReturn/list`；
- 权限 `inv:salesReturn:list`；
- 当前门店严格数据范围；
- 退货单号、原销售单号、客户和状态筛选；
- 服务端总记录数，以及当前页草稿、待确认、已退货和已取消数量；
- ERP-NEW_2 隔离 Mock 默认运行时和未注入的真实只读 HTTP Reader；
- 桌面表格、移动卡片、加载、错误、空状态和最近成功筛选语义。

以下能力明确留待后续独立切片：我的退货、详情、新建、编辑、保存、提交、确认退货、取消、导出、原销售单与明细选择、真实运行时注入和旧销售退货页面下线。

## 2. 审计结论与硬边界

### 2.1 迁移顺序

- 正式方案阶段 6 第 3 项要求迁移客户、销售、退货和配送；
- 销售退货通过 `sales_order_id` 与 `sales_detail_id` 绑定已经冻结的来源销售单和明细；
- 当前切片只冻结退货列表的门店、金额、来源单据和状态语义，不把库存回补或金额冲回写流程伪装成已迁移闭环；
- 配送通知继续作为后续独立切片，不与退货写流程耦合。

### 2.2 接口与权限拆分

- 列表：`GET /inventory/salesReturn/list`，权限 `inv:salesReturn:list`；
- “我的退货”：`GET /inventory/salesReturn/my`，虽复用列表权限，但属于个人视图，不在本切片；
- 详情、保存、提交、确认退货、取消和导出均使用独立权限或端点；
- 本切片不得展示详情、导出或任何写动作伪入口，也不得用列表权限调用其他端点。

### 2.3 组织与数据范围

- 旧桌面页面和移动入口都把销售退货限定为门店场景，保存服务也使用 `requireStoreContext`；
- 列表服务当前使用 `appendShopScope`，技术上可按选择组织的子部门过滤，但本切片不提供公司或仓库层级聚合；
- Reader 只能发送当前会话门店组织头，不能接受 `shopDeptId`、`scopeDeptIds` 或 `dataScope` 查询参数；
- 请求携带 `expectedOrganizationId`，组织漂移在 `fetch` 前失败；解析后任何跨门店记录都拒绝整页；
- 默认启动只注入隔离 Mock，真实 Reader 在完成版本化 OpenAPI、响应缓存策略和生产等价验证前保持未注入。

### 2.4 金额、数量、日期与状态

- 分页字段为 `pageNum`、`pageSize`；后端列表只声明 `returnNo`、`salesOrderNo`、`customerName` 与 `status` 筛选，不伪造日期区间参数；
- 状态闭集为 `draft`、`submitted`、`returned`、`cancelled`；未知状态失败关闭；
- `returnId` 与 `shopDeptId` 必须经过 Java Long 边界；退货金额使用非负十进制字符串，不使用二进制浮点；
- `returnDate` 是业务日期，统一为 `YYYY-MM-DD`；`createTime` 是旧本地日期时间标签；
- Mapper 返回的 `totalQuantity`、`returnedQuantity` 与 `remainingQuantity` 可能跨不同商品单位聚合，新列表模型必须丢弃；
- 来源销售单 ID、申请人 ID、申请部门 ID、数据范围参数、详情和内部更新字段不进入列表模型。

## 3. 设计与动效决策

这是高频 ERP/SaaS 售后工作台，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 使用“门店范围 → 总记录/当前页退货状态 → 明确筛选 → 退货单事实”的层级；
- 来源销售单、金额、退货日期、客户、经办人与状态在桌面和移动端保持等价；
- 搜索、状态筛选、键盘提交、分页和列表替换不播放动画；
- 只允许按钮按压的 140ms 可中断 `transform` 过渡；
- 只过渡 `transform`、颜色或 `box-shadow`，不动画布局属性；
- `prefers-reduced-motion: reduce` 下关闭所有非必要过渡；
- 不新增 React、Tailwind、Motion、GSAP、远程字体或外部组件依赖。

1. 固定安全 Long、状态闭集、真实日期、非负金额、字段丢弃和有界筛选。
2. 固定 Mock 的门店隔离、单号/原单号/客户/状态筛选、分页和当前页统计。
3. 固定 HTTP Reader 的精确 URL、单一 `Dept-NumId`、无 CSRF、组织漂移和跨门店返回拒绝。
4. 固定页面的门店加载、仓库/公司零请求、桌面/移动等价展示、显式筛选和失败后保留最近成功条件。

6. 实现最小领域、Mock、HTTP、页面、路由和导航，使测试转绿。
7. 更新迁移覆盖层为“重设计 / 部分实现”，明确所有延期动作与跨单位数量边界。
8. 运行完整 `verify`、阶段 1 生成器两次、确定性哈希和隔离审计；全部通过后只做本地提交。

## 6. 验证标准

- 不安全 Long、非法状态、畸形金额和无效日期全部失败关闭；
- 新模型不包含来源销售单 ID、申请人 ID、申请部门 ID、跨单位数量汇总、详情或内部更新字段；
- HTTP Reader 只发送允许参数和一个旧组织头；组织漂移与跨门店记录都失败；
- 仓库和公司上下文不调用 Gateway；门店只能读取自身隔离 Mock；
- 页面明确区分服务端总记录和当前页状态，金额保持十进制语义；
- 筛选成功后才更新已应用条件，失败时保留最近成功标签并可重试最后请求；
- 页面没有详情、保存、提交、确认、取消或导出伪入口；
- 功能开关和列表权限同时满足才可见且可访问；
- 完整前端验证、迁移生成器、确定性哈希和隔离扫描通过；
- 旧 `erp-ui/`、受保护原项目、Docker、服务、数据库、依赖和真实配置保持零改动。

## 7. 停止线

发现以下任一情况立即停止：

- 需要读取或修改受保护原项目、连接数据库、启动服务或安装依赖；
- 需要修改旧 `erp-ui/`、注入真实 Reader 或绕过门店数据边界；
- 需要跨门店经营汇总而当前会话不能证明逐行授权范围；
- 需要启用详情、保存、提交、确认、取消或导出而没有独立计划；
- 不能证明全部文件、运行目录和测试只位于 ERP-NEW_2 隔离工作树。
