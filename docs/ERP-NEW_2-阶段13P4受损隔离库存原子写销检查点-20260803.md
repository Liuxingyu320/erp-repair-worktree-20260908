## 1. 检查点结论

已建立 `damaged + damage_write_off/transport_loss_write_off` 的真实受损隔离库存原子效果边界：它沿 V2 收货分配的权威目标维度扣减汇总库存与受损批次库位余额，按需要把相关隔离序列号更新为报废，并追加不可变明细库存流水、受损损失台账和序列号消费台账。

本边界仍未接入执行入口。执行服务继续默认关闭，即使两个 Gate 被误开也会最终无条件硬停止；新增效果所有者、Mapper 和 SQL 均没有 Controller、任务或其他生产调用点。

## 2. 权威事实与锁序

写销不接受客户端库存、批次、库位或序列号标识，而是从差异事项唯一绑定的 V2 收货批次和收货分配解析：

- 目标仓库；
- 物料与跟踪策略；
- `damaged_target_lot_id`；
- `quarantine_location_id`；
- `damaged_target_balance_id`；
- `disposition=damaged` 的收货序列号审计。

效果所有者加入未来外层执行事务后固定锁定收货批次/分配、汇总库存、受损批次、隔离库位、受损余额和序列号。该顺序位于既有事项、裁决、动作和请求事件锁之后；所有库存 DML 前还必须由外层事务追加本次不可变执行事件。

## 3. 数量、成本与版本守恒

纯策略和条件 SQL 双层保护以下不变量：

- 汇总库存与受损余额都必须满足 `current = available + locked + quarantine`；
- 受损余额必须保持 `available=0`、`locked=0`；
- 当前数量、隔离数量和总成本必须足以覆盖动作；
- 收货分配累计写销加本动作不得超过原始受损数量；
- 原始受损总成本必须等于冻结成本价乘受损数量并按 6 位小数取整；
- 库存和余额版本都精确加一，前值或版本漂移即零行失败；
- 当写销后当前数量为零时，剩余总成本也必须为零；
- 库存流水使用由全局动作 ID 与动作前版本派生的短幂等标识，不复用或截断客户端请求 ID。

动作金额沿用裁决冻结金额，因此多动作金额尾差不会重新取商品当前价或使用浮点数计算。

## 4. 序列号确定性处置

序列号跟踪物料要求动作数量为整数。Mapper 锁定该收货分配仍处在原受损余额、批次和隔离库位中的全部可写销单件，纯策略按 `receipt_serial_id, serial_id` 稳定排序并选择动作所需数量。

每个单件必须从 `quarantine` 精确更新为 `scrapped`。不可变子台账分别对 `receipt_serial_id` 和 `serial_id` 建立唯一约束，阻止跨动作重复消费；任一单件更新或台账插入不为一行，整个外层事务必须回滚。

批次跟踪物料不得混入序列号处置记录。

## 5. 不可变事实与事务所有权

新增两张加法表：

1. 受损写销损失头台账，保存事项/裁决/动作、三层前后状态和版本、收货分配锚点、库存与余额前后数量/成本/版本、证据、权限、操作者和两类指纹；
2. 动作—收货序列号消费子台账，保存单件位置和 `quarantine -> scrapped` 状态。

效果所有者使用 `Propagation.MANDATORY`，每个单行 DML 都要求恰好影响一行。损失头的条件插入还会重核当前事项、裁决、动作、收货分配、冻结成本、累计写销、说明/证据以及同事务执行事件；失败会抛错并将此前库存、余额、序列号和库存流水变更整体回滚。
