# ERP-NEW_2 阶段 6：审批实例详情与管理员异常处置前端垂直切片实施计划

> 日期：2026-08-03
> 基线：`a6c057f8 feat: add approval rule version audit skeleton`
> 状态：实施中；补齐统一审批安全详情、终止、改派与回调重放，不代表个人审批任务、真实运行时或统一审批闭环完成

## 1. 目标与范围

扩展 `erp-ui-next/` 的 `/approvals/instances` 工作台，让具备相应权限的管理员先读取脱敏详情上下文，再对明确可操作的原生审批对象执行终止实例、改派当前待办候选人或重放死信/待重试回调。

本切片实现：

- `GET /approval/instances/{id}` 的安全详情适配；
- `POST /approval/instances/{id}/terminate`；
- `POST /approval/tasks/{id}/reassign`；
- `POST /approval/callbacks/{id}/replay`；
- `approval:instance:query`、`approval:instance:terminate`、`approval:task:reassign` 与 `approval:callback:replay` 的逐动作失败关闭；
- 实例、任务、候选人、动作历史和回调事件的脱敏审计投影；
- 操作原因、目标复核、二次确认、CSRF、幂等请求标识和不确定网络结果下的同标识重试；
- ERP-NEW_2 隔离 Mock 中可验证的状态迁移与追加审计；
- 桌面与移动等价的详情入口和管理员操作体验。

旧引擎实例、个人审批同意/退回/拒绝、目录用户搜索、自动转交、真实运行时注入和后端权限修复留待独立切片。

## 2. 审计结论与硬边界

### 2.1 详情契约

- 当前 `ApprovalRuntimeController.detail` 只标注 `@RequiresLogin`，但 Service 对非管理员要求参与者身份，对持有 `approval:instance:query` 的管理员允许跨组织查看；Controller 权限注解与旧页面按钮权限并不完全一致。
- 详情响应为 `{ instance, tasks, candidates, actions, callbacks }`。新投影只保留业务状态、任务节点、候选人显示信息、动作审计和回调处置事实。
- 业务/路由快照、摘要、幂等键、规则内部 ID、用户 ID、动作键与请求 ID、回调 payload/服务/代码、锁、内部操作者字段和 BaseEntity 审计字段不得到达页面。
- 详情成功响应必须显式声明 `Cache-Control: no-store`；当前端点没有该证据，因此真实详情 Reader 保持未注入。

### 2.2 命令契约

- 终止实例独立要求 `approval:instance:terminate`，且后端只允许 `RUNNING` 实例；成功后进入 `TERMINATING` 并创建终止回调。
- 改派独立要求 `approval:task:reassign`，且源任务和源候选人都必须为 `PENDING`；新用户不得已在候选快照中，并必须是有效、在职且拥有该业务审批权限的目录用户。
- 回调重放独立要求 `approval:callback:replay`，且只允许 `RETRY` 或 `DEAD` 回调；成功后回调与实例回到 `PENDING`。
- 三类请求都要求非空、最多 500 字原因，以及 8～128 位安全 `requestId`。页面对一次确认只生成一个请求标识；网络结果不确定时重试必须复用同一标识。
- 管理员动作按全局实例 ID 定位，不携带当前组织头；所有 POST 必须要求 CSRF。页面不得把当前所选门店伪装为执行范围。

### 2.3 默认运行时

- 默认 Provider 只使用 ERP-NEW_2 自有脱敏、可变 Mock；所有状态变化只存在当前浏览器内存，不连接真实业务数据。
- HTTP Reader/Writer 只作为未注入适配器接受契约测试；详情权限注解、`no-store`、生产会话、CSRF 和审计门禁未完成前不得接入默认运行时。
- Mock 成功命令后必须更新实例/任务/候选人/回调状态并追加脱敏动作历史；相同 `requestId` 与相同命令返回首次结果，冲突复用必须拒绝。

## 3. 设计与动效决策

项目属于高频 ERP/SaaS 管理工作台，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 列表、详情、任务切换、键盘提交和状态刷新均即时，不播放动画；
- 高风险动作先展示目标、前置状态、后果和必填原因，再进入显式二次确认；
- 对话框不使用缩放、弹跳、模糊或大范围位移，避免把危险操作包装成视觉奖励；
- 仅按钮按压提供 140ms 可中断 `transform` 反馈；
- `prefers-reduced-motion: reduce` 下关闭非必要过渡；
- 不新增动画、React、Tailwind、Motion、GSAP 或其他依赖。

## 6. 验证标准

- 无详情权限时没有详情入口；无对应动作权限时没有该动作入口；不能用列表权限替代详情或命令权限。
- 终止只针对 `RUNNING` 实例，改派只针对 `PENDING` 任务/候选人，重放只针对 `RETRY/DEAD` 回调。
- 命令确认前目标 ID、当前状态、后果和原因均清晰可读，提交中禁止重复触发。
- 网络错误后保留同一请求标识；成功或主动取消后才清除。
- 详情与命令不发送组织头；详情不发送 CSRF，命令必须发送 CSRF。
- 页面不可读取业务/路由快照、回调 payload、固定用户 ID、锁版本或内部请求键。
- 默认运行时不发起真实 HTTP，不启动服务、不连接数据库，不修改旧 `erp-ui/`。
- 完整前端验证、迁移生成器、确定性哈希和隔离扫描通过。

## 7. 停止线

发现以下任一情况立即停止：

- 需要访问或修改受保护原项目、连接数据库、启动服务或安装依赖；
- 需要修改旧 `erp-ui/`、注入真实 Reader/Writer 或绕过 CSRF；
- 无法证明动作权限独立、目标状态合法或请求标识可安全复用；
- 后端详情中的敏感快照或内部键无法在契约层阻断；
- 需要把组合容器擅自标记为合并/下线，或需要删除旧前端。
