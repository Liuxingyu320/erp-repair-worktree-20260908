# ERP-NEW_2 阶段 6：销售订单只读工作台前端垂直切片实施计划

> 日期：2026-08-03
> 基线：`9ba6124c feat: add customer service card workbench skeleton`
> 状态：只读销售订单列表前端切片与完整门禁已完成；不代表客户与销售领域迁移完成

## 1. 目标与范围

在 `erp-ui-next/` 内新增 `/sales/orders` 销售订单工作台，覆盖当前门店的销售单筛选、服务端分页、订单金额、履约状态和响应式只读展示。

本切片只实现：

- `GET /inventory/sales/list`；
- 权限 `inv:sales:list`；
- 当前门店的严格数据范围；
- 销售单号、标题、客户、状态和销售日期区间筛选；
- 服务端总记录数，以及当前页草稿、待通知、已通知和已出库数量；
- ERP-NEW_2 隔离 Mock 默认运行时和未注入的真实只读 HTTP Reader；
- 桌面表格、移动卡片、加载、错误、空状态和最近成功筛选语义。

以下能力明确留待后续独立切片：详情、客户选择、新建、编辑、保存、提交、取消、导出、生成发货通知、发货执行、销售退货、真实运行时注入和旧销售页面下线。

## 2. 审计结论与硬边界

### 2.1 迁移顺序

- 正式方案阶段 6 第 3 项要求迁移客户、销售、退货和配送；
- 销售退货通过 `sales_order_id` 和 `sales_detail_id` 绑定来源销售单与明细；
- 配送通知通过 `salesOrderId` 从已提交销售单生成；
- 因此先冻结销售列表的状态、金额、日期和门店语义，再分别迁移退货与配送，禁止把三个写流程一次性拼成伪闭环。

### 2.2 接口与权限拆分

- 列表：`GET /inventory/sales/list`，权限 `inv:sales:list`；
- “我的销售单”：`GET /inventory/sales/my`，仍使用列表权限，但属于个人视图，不在本切片；
- 详情使用 `inv:sales:query`；保存、提交、取消和导出使用独立权限；
- 生成配送通知属于 `inv:deliveryNotice:add`，不是销售列表权限；
- 本切片不得展示详情、导出或任何写动作伪入口，也不得用列表权限调用其他端点。

### 2.3 组织与数据范围

- 旧桌面页面明确提示销售业务需要门店，移动销售入口也只允许 `STORE`；销售保存服务使用 `requireStoreContext`；
- 列表服务当前使用 `appendShopScope`，技术上可按选择组织的子部门过滤，但本切片不提供跨门店经营汇总；仓库和公司上下文不得发请求；
- Reader 只能发送当前会话的门店组织头，不能接受 `shopDeptId`、`scopeDeptIds` 或 `dataScope` 查询参数；
- 请求携带 `expectedOrganizationId`，组织漂移在 `fetch` 前失败；解析后任何跨门店记录都拒绝整页；
- 默认启动只注入隔离 Mock，真实 Reader 在完成版本化 OpenAPI、缓存策略和生产等价验证前保持未注入。

### 2.4 金额、数量、日期与状态

- 分页字段为 `pageNum`、`pageSize`，日期区间字段为 `params[beginOrderDate]` 与 `params[endOrderDate]`；
- 状态闭集为 `draft`、`submitted`、`noticed`、`delivered`、`cancelled`；未知状态失败关闭；
- `orderId` 与 `shopDeptId` 必须经过 Java Long 边界；销售金额使用非负十进制字符串，不使用二进制浮点；
- `orderDate` 是业务日期，统一为 `YYYY-MM-DD`；`createTime` 是旧本地日期时间标签；
- Mapper 返回的 `totalQuantity`、`deliveredQuantity` 与 `remainingQuantity` 可能跨“盒、罐、件”等单位聚合，新列表模型必须丢弃，不能作为当前页指标；
- 客户 ID、申请人 ID、申请部门 ID、数据范围参数、详情和内部更新字段不进入列表模型。

## 3. 设计与动效决策

这是高频 ERP/SaaS 销售工作台，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 使用“门店范围 → 总记录/当前页履约状态 → 明确筛选 → 销售单明细”的层级；
- 金额、销售日期、客户、经办人与状态在桌面和移动端保持等价；
- 搜索、状态/日期筛选、键盘提交、分页和列表替换不播放动画；
- 只允许按钮按压与悬停阴影等 140ms 可中断 CSS 过渡；
- 只过渡 `transform`、颜色或 `box-shadow`，不动画布局属性；
- `prefers-reduced-motion: reduce` 下关闭所有非必要过渡；
- 不新增 React、Tailwind、Motion、GSAP、远程字体或外部组件依赖。

## 6. 验证标准

- 不安全 Long、非法状态、畸形金额、无效日期和反向日期区间全部失败关闭；
- 新模型不包含客户 ID、申请人 ID、申请部门 ID、跨单位数量汇总、详情或内部更新字段；
- HTTP Reader 只发送允许参数和一个旧组织头；组织漂移与跨门店记录都失败；
- 仓库和公司上下文不调用 Gateway；门店只能读取自身隔离 Mock；
- 页面明确区分服务端总记录和当前页状态，金额保持十进制语义；
- 筛选成功后才更新已应用条件，失败时保留最近成功标签并可重试最后请求；
- 页面没有详情、保存、提交、取消、导出、生成配送通知或发货伪入口；
- 功能开关和列表权限同时满足才可见且可访问；
- 完整前端验证、迁移生成器、确定性哈希和隔离扫描通过；
- 旧 `erp-ui/`、受保护原项目、Docker、服务、数据库、依赖和真实配置保持零改动。

## 7. 停止线

发现以下任一情况立即停止：

- 需要读取或修改受保护原项目、连接数据库、启动服务或安装依赖；
- 需要修改旧 `erp-ui/`、注入真实 Reader 或绕过门店数据边界；
- 需要跨门店经营汇总而当前会话不能证明逐行授权范围；
- 需要启用详情、保存、提交、取消、导出、配送或退货而没有独立计划；
- 不能证明全部文件、运行目录和测试只位于 ERP-NEW_2 隔离工作树。
