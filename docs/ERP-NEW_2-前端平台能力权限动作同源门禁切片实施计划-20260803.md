## 1. 问题与目标

正式方案要求“路由、按钮、接口和待办深链共用同一功能标识”。当前路由已同时校验 feature 和 permission，但调拨工作台的“新建调拨”、“发货规划”和“收货”链接仍仅根据行状态渲染。用户可以看到无权动作，然后在路由守卫处被拒绝，按钮与路由语义不一致。

本切片建立一个失败关闭的 capability 判定，作为路由与可操作链接的共同权威函数，并将调拨工作台桌面/移动动作全部收口到受权组件。

## 2. 已确定契约

- 会话不是 `ready`、会话快照缺失、功能标识未知/已停用或任一必需权限缺失时一律拒绝；
- capability 判定返回结构化原因：会话不可用、功能不可用、权限缺失；
- 路由守卫使用该判定并保持现有跳转语义：会话问题进入 session unavailable，功能/权限问题进入 access denied；
- 权限动作组件默认隐藏未授权动作，可显式选择禁用模式以显示可读屏原因；
- 可点击动作同时满足 feature 与所有 permissions，不允许页面用独立布尔值绕过；
- 调拨工作台中的版本、新建、发货和收货动作将同时覆盖桌面表格与移动任务卡片；
- 只显示决策结果，不在动作出现/消失时增加 animation、transition、淡入、脉冲或弹跳。

## 4. 实施顺序

1. 先用纯函数测试锁定会话、未知/停用功能、单个/多个权限和授权成功的判定结果；
2. 先用组件测试锁定授权链接、默认隐藏与显式禁用原因；
3. 实现 capability 判定和受权动作组件，再让路由守卫委托给同一函数；
4. 将调拨工作台所有动作链接改为受权组件，并为移动卡片补齐可执行动作；
5. 定向验证授权与受限会话，再执行完整 `npm run verify`。

## 5. 验证门禁

- capability 测试覆盖所有拒绝原因和未知/禁用功能默认拒绝；
- 路由回归测试保持原有 session/access-denied 跳转语义；
- 组件测试覆盖可访问链接、隐藏模式和可读屏禁用原因；
- 调拨工作台测试覆盖完整权限和只读权限两种会话；
- `npm run verify` 必须通过 Prettier、ESLint、Vue TypeScript strict、OpenAPI 门禁、Vitest 与 Vite 构建；
- `git diff --check` 与源码隔离测试必须通过；
- 静态扫描必须证明无新依赖、无新环境配置、无旧前端引用和无真实网络请求。

## 6. 停止线

- 不启动 Vite/Playwright web server、Docker、MySQL、Redis、Nacos 或后端服务；
- 不执行 `npm install`、`npm ci` 或任何联网依赖命令；
- 不修改真实 Writer、`.env.local`、端口、凭据或运行数据；
- 不使用前端隐藏代替后端权限校验；本切片只保证前端入口与路由判定一致；
- 不访问受保护原项目，不删除旧前端，不合并、不推送。
