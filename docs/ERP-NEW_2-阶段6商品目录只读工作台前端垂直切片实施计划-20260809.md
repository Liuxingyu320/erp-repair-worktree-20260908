## 1. 目标与范围

在全新前端 `erp-ui-next/` 内新增 `/inventory/products` 商品目录只读工作台，为采购、库存、盘点、调拨和销售后续切片提供安全、稳定的商品主数据入口：

- 分页读取 `GET /inventory/product/list`；
- 在具备 `inv:category:list` 或 `inv:category:tree` 时读取 `GET /inventory/category/tree`；
- 支持商品关键词、分类、供应商名称、等级和启停状态筛选；
- 展示商品编码、名称、分类路径、等级、规格、单位、供应商、所属库存组织和状态；
- 提供桌面表格、移动卡片、加载、失败、陈旧结果、空状态和分页；
- 接入 `inventory.product.view` 前端功能码、`inv:product:list` 权限、路由、主导航和命令检索。

本切片只读。商品详情、新增、编辑、删除、导入、导出、分类维护、供应商维护、图片素材和价格编辑均留待独立契约冻结后实施。

## 2. 契约审计与安全边界

### 2.1 组织与权限

- 商品列表入口只要求 `inv:product:list`，不能把分类或供应商权限错误合并进路由门槛；
- 分类树端点使用 `inv:category:list` / `inv:category:tree` 的 OR 语义，页面仅在会话具备其中任一权限时请求；无分类权限时保留商品列表和文本筛选，不触发必然失败的请求；
- 商品与分类查询继续由服务端 `resolveShopDeptId`、`appendRelatedShopScope` 和数据范围约束；前端只发送当前会话组织头，不能提交任意组织集合；
- 公司层级没有可执行库存组织上下文时不发送请求，提示切换到门店或仓库。

### 2.2 成本字段阻断项

正式方案明确要求成本价使用独立成本权限。当前 `InvProductController` 在无 `inv:cost:view` 时只清空 `purchasePrice`，仍把 `costPrice` 返回浏览器，且现有测试将该行为固化。真实 HTTP 接线前必须：

- 将无成本权限时的商品列表与详情同时清空 `purchasePrice` 和 `costPrice`；
- 保留管理员或具有 `inv:cost:view` 用户的字段；
- 增加列表、详情正负向测试，防止成本字段再次泄露；
- 新前端商品模型完全不声明采购价、成本价或成本汇总字段，Zod 适配只提取白名单主数据字段；
- 本切片页面不展示价格，客户端丢弃只作为纵深防御，不能替代服务端脱敏。

### 2.3 响应缓存

商品与分类响应包含组织范围内业务资料，服务端列表/树端点必须返回 `Cache-Control: no-store, max-age=0` 和 `Pragma: no-cache`。HTTP Gateway 使用共享 `requireNoStore` 失败关闭，避免浏览器或中间缓存持久化授权数据。

## 3. 前端领域设计

- 所有 Java `Long` 标识保存为十进制字符串；不安全 JSON number 失败关闭；
- 商品查询通过 Zod 限制页码、页大小和文本长度；只发送非空、已知查询键；
- 分类树递归解析时限制最大深度和节点总数，拒绝循环、重复 ID、越界 Long 和畸形 children；
- 商品行必须属于请求组织或服务端授权关联组织；前端不根据组织名称猜测权限；
- 分类树失败不使商品列表失效，页面显示明确的“分类筛选暂不可用”，保留上一次成功树或降级为无分类筛选；
- 商品列表刷新失败时保留上一次成功页并显示陈旧状态，不把失败伪装为空数据；
- Mock 数据只属于 ERP-NEW_2，确定性支持筛选与分页，不引用旧前端运行时代码。

## 4. 交互与动效

本页面是高频企业 ERP/SaaS 工作台，采用 Emil Kowalski 为主、Jakub Krehel 为辅：

- 参考用户列出的 21st.dev、React Bits、UI Prompt Library、Magic UI、Motion Primitives、Uiverse 与 MotionSites 的信息层级和交互提示，但不复制外部代码、品牌、付费提示词或不明许可证资产；
- 分类选择、筛选、键盘提交和分页保持即时，不做入场序列、循环光效、弹跳、视差或大幅缩放；
- 仅对可点击按钮和分类项提供约 140ms、可中断的按压/悬停反馈，使用项目现有 `cubic-bezier(0.2, 0, 0, 1)`；
- 只过渡 `transform`、`opacity` 或 `box-shadow`，不动画宽高、位置或其他布局属性；
- `prefers-reduced-motion: reduce` 下关闭所有非必要过渡；状态变化同时使用文本和语义属性表达，不依赖颜色或动效。

## 5. TDD 与实施顺序

1. 先修改/新增后端失败测试，固定无成本权限脱敏、授权角色保留成本和 no-store 响应头；
2. 新增商品 model / contract 测试，固定 Long、查询、字段白名单、分类树边界和成本字段丢弃；
3. 新增 HTTP Gateway 测试，固定路径、查询键、单一组织头、GET 无 CSRF、no-store、取消和组织漂移失败关闭；
4. 新增 Mock Gateway 与页面测试，覆盖分类权限降级、筛选、分页、加载、失败保留、空状态和响应式语义；
5. 实现后端脱敏与缓存头，再实现前端领域、真实 HTTP Gateway、Mock 和页面；
6. 接入 AppGateways、功能目录、后端 feature 发布、路由、导航与测试会话；
7. 更新阶段 1 迁移覆盖层，将旧商品页标记为“重设计 / 部分实现”，明确未迁移动作；
8. 运行定向测试、全量前端 `verify`、受影响后端模块测试、迁移生成器、隔离扫描与自审；
9. 全部门禁通过后创建独立本地提交；不推送、不合并。

## 7. 验收与停止线

- 无 `inv:cost:view` 的列表和详情响应不再包含有效采购价或成本价；授权角色行为不回退；
- 畸形分页、越界 Long、循环/重复/过深分类树、可缓存成功响应和组织漂移全部失败关闭；
- 页面在没有分类权限、分类失败、商品失败、空结果和组织不可用时均给出准确状态；
- 只有同时具备 `inventory.product.view` 和 `inv:product:list` 才能看到并访问入口；
- Prettier、ESLint、TypeScript strict、OpenAPI 门禁、Vitest、Vite 构建和后端定向测试全部通过；
- 不启动 Vite、Playwright Web Server、Docker、MySQL、Redis、Nacos 或后端服务；
- 不执行依赖安装、SQL 或迁移，不修改真实配置、端口、凭据、运行数据、旧 `erp-ui/` 或受保护原项目；
- 不删除旧前端，不合并、不推送。
