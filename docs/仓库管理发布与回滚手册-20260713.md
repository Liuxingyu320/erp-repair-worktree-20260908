# 仓库管理发布与回滚手册

> 版本：2026-07-14
> 发布基线：MySQL 8.0；先在本机独立克隆库演练，再进入目标环境维护窗口。
> 禁止：在未备份的业务库直接演练回填/修复；默认 MySQL 5.7 Docker 组合不是本版发布基线。

## 1. 发布结论

本版可发布的业务能力：

- 调拨发货必须有完整、匹配且已通过的审批实例/任务。
- 采购业务阶段统一到桌面、移动和待办。
- 采购收货保存收货批次，桌面/移动逐行填写合格、拒收、让步数量。
- 采购退货使用真实可退量，支持商品/OE/礼盒和原因/责任/附件。
- 盘点支持四种范围、盲盘、盘点人、截止时间和超阈值复盘。
- 采购/调拨桌面操作收敛为主动作 + 更多，调拨时间统一为本地时间。
- 菜单迁移把重复入口合并到“仓储作业”，提供精确角色菜单回滚。

本版只部署、不默认启用的能力：

- 批次/库位/序列号明细库存新表。
- 历史库存回填、`dual` 双写、`shadow/detail` 新读。

新库存模式必须经本机数据演练、7 天零差异和逐仓库签字后另行启用。

## 2. 数据库发布顺序

### A. 发布前只读检查

1. 备份数据库结构和相关 `inv_*` 数据，记录备份编号。
2. 使用只读账号执行：
   - `erp_inventory_transfer_approval_integrity_20260713.sql`；
   - `erp_inventory_purchase_inbound_reconcile_20260713.sql`；
   - `erp_inventory_daily_healthcheck_20260713.sql`。
3. 审批完整性、负库存、库存公式和流水算术任一异常时停止发布。
4. 历史 QA 数据和备份表可作为治理工单，但必须与真实业务异常分类。
5. 执行统一发布门禁的只读预检；OA 采购 `submitted`、运行任务、运行实例任一非 0 都必须停止：

```bash
ERP_UNIFIED_TODO_MYSQL_DATABASE=<目标库> \
ERP_UNIFIED_TODO_MYSQL_USER=<只读用户> \
./scripts/verify-unified-todo-release.sh --preflight
```

### B. 应用必需迁移

以 `scripts/unified-todo-release-20260714.list` 为唯一顺序源，共 7 个脚本：

1. `erp_inventory_purchase_return_item_20260713.sql`
2. `erp_inventory_stock_check_scope_20260713.sql`
3. `erp_inventory_receipt_quality_20260713.sql`
4. `erp_inventory_performance_indexes_20260713.sql`
5. `erp_inventory_warehouse_navigation_20260713.sql`
6. `erp_hr_health_certificate_20260713.sql`
7. `erp_unified_todo_business_scope_20260713.sql`

`stock_check_scope` 必须早于 `performance_indexes`；不得依赖目录字母顺序。必需表结构未执行时不得启动新后端。

写入必须使用显式确认令牌，并由脚本持有命名锁：

```bash
ERP_UNIFIED_TODO_APPLY_CONFIRMATION=APPLY_UNIFIED_TODO_20260714 \
ERP_UNIFIED_TODO_MYSQL_DATABASE=<目标库> \
ERP_UNIFIED_TODO_MYSQL_USER=<发布用户> \
./scripts/verify-unified-todo-release.sh --apply
```

### C. 可提前建表但不切换

1. 执行 `erp_inventory_lot_location_schema_20260713.sql`。
2. 确认 `inv_warehouse_stock_mode` 只有 `legacy/legacy`。
3. 不在本次发布中把 `@enable_lot_location_backfill` 设为 1。
4. 不手工修改 `write_mode/read_mode`。

## 3. 应用发布顺序

1. 停止新的采购收货、质检、调拨发货和盘点提交，等待在途请求完成。
2. 执行必需数据库迁移。
3. 发布后端，检查健康接口和 MyBatis Mapper 加载。
4. 发布前端，清理 CDN/浏览器旧资源版本。
5. 先放开一个仓库用户进行冒烟，再恢复全部用户。

## 4. 发布后冒烟

### 调拨

- 无审批实例、串单、运行中或任务不完整的单据前后端都不得发货。
- 合法审批单可部分发货/收货，库存和流水对平。

### 采购

- 分两次收货，每次产生独立收货批次。
- 同批两行分别录入合格/拒收/让步，数量守恒。
- 拒收只回退对应行已收数；合格和让步数才增加库存。
- 桌面和手机都不得默认“合格”，历史待检才显示整单兼容模式。

### 退货与盘点

- 退货数量不超过有效已收 - 历史已退，OE/礼盒可正常提交。
- 四种盘点范围生成正确快照；盲盘不泄露账面量；超阈值无复盘不得提交。

### 数据

- 执行每日健康脚本，核心 `issue_count` 为 0。
- 库存和流水的数量公式为 0 差异。
- 新收货批次、质检记录、附件和入库记录链接完整。

## 5. 性能门槛

| 场景 | 数据规模 | 目标 |
|---|---:|---:|
| 库存列表 | 10 万余额 | P95 < 1.5s |
| 统一待办 | 33 类待办 | P95 < 1.0s |
| 收货/质检提交 | 100 行 | P95 < 500ms |
| 单笔库存变动 | 并发 20 | P95 < 300ms，0 超扣 |
| 流水列表 | 100 万行 | P95 < 1.5s |
| 经营汇总 | 1 年区间 | P95 < 3s，超时转异步 |

索引迁移前后保存 `EXPLAIN FORMAT=JSON`；如新索引未被使用或明显增加写入延迟，单独回滚该索引，不与业务代码回滚绑定。

## 6. 回滚

### 应用紧急回滚

1. 再次暂停库存写操作。
2. 回滚前后端到上一个已验证版本。
3. 保留新收货批次和质检事实，不执行物理删除。
4. 运行只读对账，确认回滚窗口内没有半笔余额/流水。

### 菜单回滚

先执行 `erp_unified_todo_business_scope_rollback_20260713.sql`，恢复 OA 旧菜单状态和原角色授权，但不开启 OA 采购写开关。

再执行 `erp_inventory_warehouse_navigation_rollback_20260713.sql`。它使用发布前菜单逐字段快照和精确角色菜单关系恢复，不使用“猜测角色”。新增表、字段、索引和健康证历史保留，不做破坏性删除。

### 批次库位模式回退

仅在未来已启用单仓灰度时，对该仓库执行带显式开关的 `erp_inventory_lot_location_rollback_20260713.sql`。该脚本只切回 `legacy/legacy`，不删除追溯事实。

## 7. 日常治理

- 每日：执行健康检查，核心异常立即告警。
- 每周：处理超过 7 天的盘点草稿和无主任务。
- 每月：审查业务库备份表、QA 数据、索引使用和慢查询。
- 任何数据修复：先 dry-run、生成样本、人工确认、记录原值/目标值/原因/批次号，最后才允许写入。
