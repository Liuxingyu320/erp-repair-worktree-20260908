# ERP 项目持续改进实施计划

日期：2026-07-30

状态：已完成（已识别问题完成分批改进；负责人隔离、结构拆分、工程治理及 MySQL 5.7/8.0 实库门禁均已收口）

## 目标与范围

在保留当前工作区既有改动的前提下，分批改进项目审查中已经确认的问题，并为每批改动建立可重复的验证结果。

明确排除：用户管理列表手机号脱敏。用户列表允许展示完整手机号，依据
`docs/decisions/2026-07-30-user-list-phone-display-decision.md` 执行。

## 约束

- 当前工作区包含大量未提交和未跟踪改动；不得重置、覆盖或夹带无关文件。
- 每一批只解决一个清晰边界，先运行聚焦测试，再运行所属模块测试。
- 签约任务归属已按负责人隔离收口，普通 HR 必须同时满足业务权限、组织范围和任务负责人一致；管理员、技术只读及历史未绑定数据例外以
  `docs/decisions/2026-07-31-sign-task-owner-isolation.md` 为准。
- Git 历史清理、部署产物迁移等会影响协作方式的动作单独实施，不与业务修复混合。

## 执行阶段

### 第一阶段：恢复可信测试门禁

1. 按已确认的手机号展示决策调整 `SysUserManageMapperSourceTest`，测试列表返回完整用户名和手机号，不再要求脱敏投影。
2. 对齐已废弃的签约 HR 权限同步钩子及其旧存储过程测试，验证当前兼容行为而不是已经移除的过程调用。
3. 清理前端 Finder 风格重复测试/源文件；删除前先确认每个文件都有对应原文件且内容一致。
4. 更新产品选择器测试，使其验证三种现有上下文标题，不使用易碎的整段模板正则。
5. 修正只因 SQL 空白格式变化而失败的库存 Mapper 断言。
6. 避免 Approval Mapper 测试扫描整个包导致挂起，改为注册测试实际使用的精确类型别名。

### 第二阶段：签约权限策略收口

1. 采用负责人隔离策略并形成决策记录：普通签约 HR 只能看到和处理
   `assigned_hr_user_id` 为本人的任务。
2. 统一 `OaSignHrAccessService`、统一待办 SQL、公司工作列表、通知失败、任务关联签约包、批量动作服务和回归测试。
3. 使用同组织其他 HR、跨组织 HR、管理员、技术只读人员和历史未绑定数据验证“应看见、必须看不见、可以处理、不能处理”。

### 第三阶段：公司工作列表性能与副作用

1. 记录当前列表一次请求的批次数、SQL 次数和耗时基线。
2. 将逐批详情读取改为批量投影查询，保持组织范围和已确认的任务归属策略。
3. 将过期生成租约恢复从普通列表读取路径移到明确的恢复动作或后台任务。
4. 验证结果集合、排序、上限和并发租约语义不变，并比较优化前后查询次数与 P95。

### 第四阶段：结构性拆分

1. 先为 `OaSignPackageServiceImpl` 建立用例级契约测试，再按草稿准备、员工签署、公司签署、文件证据和生命周期拆分。
2. 前端按页面面板和业务流程抽离组件及状态模块；不在同一批次升级 Vue 主版本。
3. 每次只迁移一个用例，保持接口、路由和用户可见行为兼容。

### 第五阶段：工程治理

1. 增加版本库内的干净环境流水线：后端测试、前端测试、生产构建、MySQL 集成测试和数据库清单校验。
2. 把部署压缩包、运行时 JAR 和真实业务数据移出 Git 工作区；历史重写另行审批。
3. 从单一迁移登记表生成 Docker 初始化与发布清单，并在干净数据库执行演练。
4. 完成全项目测试、生产构建和剩余风险记录后，再关闭持续改进目标。
