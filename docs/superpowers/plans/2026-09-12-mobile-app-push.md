# 手机网页封装与系统推送

目标：复用当前手机网页和ERP账号，封装Android/iOS客户端；后台和锁屏通知由系统推送承载，点击后进入当前账号有权访问的手机页面。

## 当前边界

- 工作目录是独立手机App副本，基于 `76b69e3dd808e4f9c526474e2ddaab84e12bd5d1` 加本轮开始时原修复目录的全部未提交内容；不修改原修复目录。
- 用户没有准备苹果开发者/推送账号，拟考察第三方签名服务。只进行本地实现、构建和测试；不注册账号、不购买服务、不对生产发通知。
- 正式HTTPS接口地址等待用户提供；不放宽原生传输安全限制。
- 当前Android通道是FCM；没有Google Play服务的员工设备仍需选定并接入适用厂商推送服务，不能以FCM编译通过替代国内机型验收。

## 实施顺序

1. 前端：冷启动通知暂存、登录就绪后消费、接收账号校验、手机消息中心与通知权限状态；网页保留现有行为。
2. 后端：补健康证和消息中心路由协议、接收人字段；支持APNs专用p12证书与现有p8密钥；对启用后的新站内消息增加事务待发送记录与重试，不扫描旧消息。
3. 封装：同步Capacitor插件，按平台修正凭证检查，区分Debug/Release推送环境；构建Android和iOS代码。
4. 交付检查：核对签名后IPA的实际Bundle ID、Team ID、推送环境、profile有效期与安装范围；生成第三方交接说明。
5. 回归：前端消息生命周期/账户切换/拒绝权限测试，后端协议与队列测试，原生编译、源码增量独立复核。

## 验收层级

- 单测和编译只能证明本地实现；签名包验证只能证明包的签名/配置。
- 正式接入后须真机验证安卓主要机型和iPhone的前台、后台、锁屏、断网恢复、点击通知及退出账号；没有外部配置时保留这些未完成项。
- 回滚通过关闭新站内消息自动推送开关和恢复旧包完成；新增队列表保留用于排查，不删除业务消息或历史记录。
