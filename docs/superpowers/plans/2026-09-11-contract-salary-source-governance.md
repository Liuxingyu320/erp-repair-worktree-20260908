# 合同工资来源调整计划

日期：2026-09-11；业务简化更新：2026-09-12。
状态：本地修改与回归已完成；登录后的流程验收及生产发布待执行。未部署或修改生产数据。

## 当前采用的规则

用户确认：旧薪资管理弃用，“人事管理 → 员工档案 → 批量处理入职合同”是主要签约入口，Excel 中每个人的工资是本入口的正确来源。

2026-09-12 用户要求取消增加操作负担的严格步骤。因此，以以下简化流程替代最初方案的“单独确认工资、填写依据、选择适用日期”：

1. HR 导入并核对合同 Excel，按现有流程点击“生成合同”。
2. 系统自动取服务端导入行中的五项工资，写入员工档案及来源记录。
3. 同步成功后生成合同；旧薪资方案不参与取值。
4. 工资同步成功但合同生成失败时，保留已同步结果。再次点击生成会在后台恢复原请求，不重复入档。
5. 工资合计不符、员工不匹配、并发修改等实际冲突仍由系统检查。取消额外的工资确认弹窗、单独确认按钮、必填说明和日期输入。

原有合同资料核对、公司印章选择、历史补签或公司差异提示属于既有签约流程，本次不扩大修改。

## 实施事项

### 工资来源

- 新增不可变工资来源及员工当前来源关联，与档案五项金额、原导入审计在同一事务写入。
- 金额只取服务端导入行；不接收浏览器提交的工资金额。
- 普通员工资料保存不能另改或清空工资。
- 正式转正、调岗如改变工资，继续记录变更来源；续签金额不变时保留原来源。
- 新 Excel 合同生成时绑定同步的工资版本。后台保留合计、身份、组织范围、经办人、并发与重复请求检查。
- 新来源校验不得卡住启用前已经留签名并生成最终文件的历史合同闭环。

### 旧入口

- 旧薪资管理停止计算、重算和参数修改，保留历史查看和导出。
- 旧薪资方案停止方案、档位、角色及员工绑定等写入，保留历史查询。
- 旧独立劳动合同停止新建、保存、发送、模板及旧印章维护；保留历史文件、既有待签签署和必要作废。
- 新签约流程共用的公司、印章和模板服务继续使用，Excel 导入保持启用。
- 旧页面显示去员工档案的入口，菜单改为历史记录类名称。

### 历史数据与发布

- 提供只读证据导出和离线分类工具，输出待核对清单，不自动补来源或覆盖金额。
- 历史全面来源强校验保持关闭。正式人事合同的全面发送版本检查留待历史核对，不在本次继续增加阻断步骤。
- 新表、配置与菜单迁移按仓库镜像约定提供；上线前核实目标版本、主入口权限与历史在途合同。
- 本次不执行生产迁移、工资更正、历史重算、部署或发布。

- 请求超时、部分批次成功和生成失败可以重试，已完成同步不重复写入。
