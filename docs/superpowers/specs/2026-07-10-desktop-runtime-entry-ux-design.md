# 电脑端运行验收入口体验修复设计

## 背景

2026-07-10 在本地完整服务环境中，以 1440×900 电脑端视口完成了登录、组织选择、首页、员工档案分页与搜索、全局菜单搜索、公告页和组织上下文保持的运行验收。核心业务流程均可完成，自动化修复对应的 HR 服务端分页、统计同步和组织上下文策略也通过了真实页面验证。

运行验收确认三个入口体验缺口：

1. 登录验证码实际要求填写图片中算式的计算结果，但输入框、校验提示和图片替代文本只写“验证码”；用户容易直接输入图片中的数字或表达式，产生可避免的失败。
2. 全局菜单搜索返回结果后仍将 `activeIndex` 重置为 `-1`；即使只有一个结果，直接按回车也不会进入，必须先按方向键。
3. 顶部搜索与通知入口主要依赖鼠标图标交互，缺少清晰的可访问名称和完整的键盘入口。

本设计在既有 Element UI、SVG 图标、对话框和通知浮层结构上做最小修复，不改变视觉语言，不新增页面。

## 目标

- 让用户在提交登录前明确知道验证码应填写“算式结果”。
- 让菜单搜索的首个结果在结果刷新后立即可通过回车打开，同时保留方向键切换。
- 让顶部搜索和通知入口可被辅助技术识别，并可用键盘操作。
- 保持桌面端和手机 Web 登录行为一致。
- 通过自动化测试和真实浏览器回归固定上述行为。

## 非目标

- 不修改验证码生成算法、有效期、刷新接口或后端校验协议。
- 不移除验证码，也不自动识别或自动提交验证码。
- 不重做全局搜索排序算法、结果样式或菜单权限逻辑。
- 不对整个系统开展一次性 WCAG 全量整改。
- 不改变通知接口、已读状态或公告详情交互。

## 方案选择

采用用户确认的 A 方案：入口体验最小闭环。

相比只改文案，本方案同时修复已经通过真实操作复现的回车断点；相比全站无障碍重构，本方案只处理本轮运行验收直接触达的顶部入口，控制回归范围。

## 设计

### 1. 算式验证码说明

桌面端与手机 Web 共用以下语义：

- 输入框占位文案改为“请输入图中算式结果”。
- 必填校验文案改为“请输入图中算式结果”。
- 验证码图片使用“验证码算式，点击刷新”作为替代文本。
- 图片容器声明为可操作控件，提供“刷新验证码”的可访问名称。
- 鼠标点击、Enter 和 Space 均调用现有 `getCode`，不新增刷新逻辑。

刷新验证码时先清空已输入结果，再沿用现有接口更新图片与 UUID。加载中或图片暂不可用时显示“验证码加载中”，避免把不可操作状态误写成验证码内容。

### 2. 全局菜单搜索默认选择

搜索结果每次刷新后遵循以下状态规则：

- 有结果：`activeIndex = 0`，首项呈现既有选中样式。
- 无结果：`activeIndex = -1`。
- 清空搜索：展示完整搜索池并默认选择首项；若搜索池为空则保持 `-1`。
- 按 ↑/↓：继续在当前结果集内循环切换。
- 按 Enter：打开当前选中项；因此用户输入后可直接回车进入首项。
- 鼠标移入：仍可临时切换选中项；鼠标移出不再清空有效键盘选择，而是保留最后选中项，避免回车再次失效。

菜单权限、路径去重、Fuse 模糊匹配和安全文本高亮逻辑保持不变。

### 3. 顶部搜索入口

搜索图标入口改用语义化 `button`，从而原生具备按钮角色、焦点入口和 Enter/Space 激活行为，并增加：

- `aria-label="搜索菜单"`
- 不改变现有 SVG 图标和视觉尺寸

对话框打开后继续使用现有 `onDialogOpened` 聚焦输入框；Esc 继续由对话框关闭行为处理。

### 4. 顶部通知入口

通知铃铛入口改用语义化 `button`，从而原生具备按钮角色、焦点入口和 Enter/Space 激活行为，并增加：

- 动态可访问名称：无未读时为“通知公告”，有未读时为“通知公告，N 条未读”
- Tab 只聚焦按钮，不自动打断浏览；按 Enter/Space 后打开现有通知浮层并将焦点送入浮层
- “全部已读”和公告项使用原生按钮，焦点在浮层内部移动时不关闭
- Escape 关闭浮层并把焦点送回通知按钮，且不会因焦点返回而重新打开

鼠标悬停行为保持不变。通知列表为空、加载中、预览和全部已读仍复用现有逻辑。

## 状态与错误处理

- 验证码接口失败仍沿用当前静默错误策略，不增加全局 500 提示。
- 搜索结果为空时，回车不执行导航，并继续显示现有空状态。
- 搜索结果变化时不保留越界索引。
- 键盘事件使用 `.prevent`，避免 Space 导致页面滚动或重复触发。
- 现有鼠标点击和悬停路径必须继续可用。

## 测试策略

### 自动化测试

先增加失败测试，再修改实现：

1. 登录页桌面和手机验证码输入均包含“请输入图中算式结果”。
2. 验证码图片具有替代文本，刷新容器可通过 Enter/Space 触发。
3. 搜索查询有结果时默认选择首项，无结果时保持 `-1`。
4. Enter 在未额外按方向键时可以打开首个结果。
5. 顶部搜索与通知入口具有角色、可访问名称、焦点入口和键盘事件；通知浮层内部操作可用 Tab/Enter，Escape 可关闭并恢复焦点。
6. 既有安全高亮、验证码接口、通知读取和鼠标交互测试继续通过。

### 真实页面回归

在本地完整服务环境中验证：

1. 登录页文案明确，点击和键盘均可刷新验证码。
2. 输入正确算式结果可以登录，错误结果仍显示后端校验反馈。
3. 全局搜索输入“通知公告”后直接按 Enter 进入 `/system/notice`。
4. Tab 可聚焦搜索与通知入口，Enter/Space 可打开对应界面。
5. 组织选择、员工档案搜索和分页不受影响。

## 验收标准

- 用户无需试错即可理解验证码应填写计算结果。
- 单结果和多结果搜索均可在输入后直接回车进入首项。
- 搜索和通知入口在可访问性树中具有明确名称，并支持键盘操作。
- 不改变接口契约、菜单权限、通知数据和现有视觉布局。
- 聚焦测试、相关前端测试和生产构建通过，真实浏览器回归无阻断。
