# 商品选择搜索体验优化设计

日期：2026-06-28

## 背景

仓库管理、采购管理、销售开单、库存查询、报表、调拨、固定资产和手机端表单中都有商品选择入口。当前主要问题是商品数量多时难以定位：有些入口只能按商品名称查，有些只能按商品名称或精确商品编码查，采购多选弹窗筛选条件少，固定资产页还有独立实现。

本次优化不引入 SKU 概念。系统只围绕业务人员实际可识别的字段搜索和展示：商品名称、商品编码、分类、供应商、规格、单位、参考价。

## 目标

1. 让所有商品选择入口都能按商品名称、商品编码、供应商、规格进行关键字搜索。
2. 采购商品选择弹窗支持更适合大量商品的筛选和批量选择。
3. 尽量收敛重复实现，通用商品选择入口复用统一搜索规则。
4. 保持现有组织权限、商品状态和成本价格权限控制不变。

## 覆盖范围

桌面端共用商品下拉：

- `erp-ui/src/views/inventory/components/ProductSelect.vue`
- 库存查询、库存调整、库存日志、库存报表、销售开单、调拨库存选择筛选等使用该组件的位置

桌面端独立商品选择：

- `erp-ui/src/views/inventory/purchase/index.vue` 的“选择采购商品”弹窗
- `erp-ui/src/views/oa/fixedAsset/config/index.vue` 的固定资产商品远程下拉
- `erp-ui/src/views/oa/fixedAsset/repair/index.vue` 的已配置固定资产选择，仅优化展示和本地筛选，不改成全商品选择

手机端：

- `erp-ui/src/views/mobile/feature/components/MobileEntityPicker.vue`
- `erp-ui/src/views/mobile/feature/mobileEntityService.js`
- 覆盖手机端采购、销售、退货、盘点、固定资产报修等 `entity: "product"` 表单

不纳入本次范围：

- 采购退货、销售退货中从原单带出的商品明细逻辑
- 商品主数据新增、导入、编码生成规则
- SKU 字段搜索、展示和解释

## 推荐方案

后端商品列表接口增加 `keyword` 查询字段，匹配商品名称、商品编码、供应商、规格。继续复用现有 `/inventory/product/list`，不新增一套并行接口，避免权限和价格脱敏逻辑分叉。

桌面通用 `ProductSelect.vue` 改为发送 `keyword`，选项中展示商品名称、商品编码、分类、规格、单位、供应商。下拉仍保持轻量，不做复杂弹窗。

采购商品弹窗改为大批量选择入口：

- 将“商品名称”输入改为“关键字”，可查名称、编码、供应商、规格。
- 保留供应商筛选，增加分类筛选。
- 表格展示商品名称、商品编码、分类、规格、单位、供应商、采购参考价。
- 默认分页放大到 20 或 30 条，保留分页。
- 已选商品再次添加时沿用当前逻辑：已有明细数量加 1。
- 对未绑定供应商的商品继续阻止加入采购明细。

固定资产配置页复用同一商品关键字搜索，展示商品名称、商品编码、分类、规格、供应商。固定资产维修页只选择已配置资产，保持业务范围不变。

手机端商品选择器继续使用现有移动端选项服务，但前端展示文案改成“搜索商品名称/编码/供应商/规格”。如果移动端后端服务不能完整覆盖供应商和规格，则前端 fallback 到 `/inventory/product/list?keyword=`，保持结果字段可用于自动带出商品信息。

## 备选方案

方案 A：只在前端多次调用现有接口，分别按名称、编码、供应商、规格搜索后合并。

优点是后端改动少。缺点是请求多、分页总数不准确、不同入口容易出现结果不一致。

方案 B：只优化采购弹窗。

优点是最快解决当前最痛的采购场景。缺点是销售、库存、调拨、固定资产和手机端仍然不好找商品。

推荐使用统一 `keyword` 的方案，因为它能一次解决多个入口，搜索规则稳定，后续维护成本最低。

## 数据流

1. 用户在商品选择入口输入关键字。
2. 前端将关键字作为 `keyword` 传给商品列表接口。
3. 后端在当前组织权限范围内筛选启用商品，并匹配商品名称、商品编码、供应商、规格。
4. 后端继续执行现有数据权限和成本字段脱敏。
5. 前端展示更完整的商品上下文，用户选择后沿用现有商品带出和表单保存逻辑。

## 错误处理

- 商品接口失败时，选择器显示空结果并保留现有错误提示方式。
- 采购弹窗未选择商品时继续提示“请选择商品”。
- 采购商品未绑定供应商时继续提示具体商品名称，不允许加入明细。
- 选中商品被停用或权限不可见时，不出现在可选结果中。

## 测试计划

前端静态/单元测试：

- 通用商品选择器应发送 `keyword`，不再依赖 SKU。
- 采购弹窗应包含关键字、供应商、分类筛选和商品上下文字段。
- 固定资产配置商品搜索应使用统一关键字规则。
- 手机端商品选择器文案和服务不出现 SKU。

后端测试：

- `/inventory/product/list` 支持 `keyword` 匹配商品名称、商品编码、供应商、规格。
- 关键字搜索仍受组织范围限制。
- 成本字段脱敏逻辑不受影响。

人工验证：

- 在采购新建弹窗搜索商品名称、商品编码、供应商、规格，都能筛出商品。
- 在销售开单、库存查询、库存报表、调拨、固定资产配置、手机端商品选择中执行同样搜索。
- 确认页面上不出现 SKU 文案。

## 自检

- 无待定项。
- 范围聚焦在商品选择体验，不改商品主数据结构。
- 搜索字段明确排除 SKU。
- 权限和价格脱敏沿用现有接口与控制器逻辑。
