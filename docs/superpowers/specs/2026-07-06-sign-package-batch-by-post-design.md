# 按岗位批量生成签约包设计

## 背景

当前员工签约模块以单个员工签约包为核心：运营人员选择员工、补充合同字段、保存草稿，再发送给员工移动端签署。模板管理只描述单个文件模板，并通过场景、用工类型、社保口径、岗位等级、薪酬版本匹配文件清单。

新的需求是：运营人员可以预先配置一套岗位合同方案，例如“项目总监方案”，把该岗位常用合同文件和默认字段放在方案里。批量操作时选择方案和员工范围，系统按员工生成独立签约包草稿。运营人员逐个点开确认无误后，再使用现有“发送”流程发给员工。

## 目标

- 支持按岗位批量生成签约包草稿，不直接批量发送。
- 支持维护“签约方案”，保存方案名称、适用岗位、默认字段和默认合同清单。
- 生成后的每个员工仍是独立签约包，沿用现有详情、发送、撤回、移动端签署、文件下载和证书流程。
- 对缺少必填信息的员工做明确提示；批量创建只允许完整行生成草稿，缺失行需要在预览中补录或取消勾选。
- 支持编辑 `draft` 签约包，运营人员可以逐个点开草稿核对并修改快照字段。

## 非目标

- 不把员工身份证、住址、薪资等信息从备注中猜测出来。
- 不改变员工主数据结构。
- 不做“一键直接发送所有人”的批量发送能力。
- 不替代现有单员工新建签约包流程。

## 产品流程

1. 运营人员进入“员工签约”页面。
2. 点击“批量按岗位生成”。
3. 选择签约方案，例如“项目总监方案”。
4. 系统带出方案默认字段和默认合同清单。
5. 运营人员按岗位、部门或员工关键字筛选候选员工，并勾选要生成的人。
6. 系统展示批量预览列表：员工、手机号、部门、岗位、缺失字段、将生成的文件清单。
7. 运营人员在预览表中补录缺失字段，或取消勾选资料不完整的员工。
8. 点击“生成草稿”后，系统为每个完整选中员工创建一个 `draft` 签约包。
9. 运营人员逐个打开草稿，核对并可修改身份证、住址、岗位等级、薪资和合同日期等信息。
10. 草稿通过发送前校验后，使用现有“发送”按钮发给员工。

## 数据模型

新增 `oa_sign_plan`：

- `plan_id`：方案 ID
- `plan_name`：方案名称，例如“项目总监方案”
- `scenario`：签约场景，默认 `onboard`
- `post_name`：适用岗位名，例如“项目总监”
- `employment_type`、`social_type`、`service_person_type`、`insurance_type`
- `post_level_snapshot`、`salary_version`
- `entry_date`、`contract_start_date`、`contract_end_date`、`probation_start_date`、`probation_end_date`
- `base_salary`、`post_salary`、`field_allowance`、`salary_total`
- `status`、`sort_order`、`remark`、审计字段

新增 `oa_sign_plan_template`：

- `id`
- `plan_id`
- `template_id`
- `template_type`
- `sort_order`

扩展 `oa_sign_package`：

- `source_plan_id`：来源方案 ID
- `source_plan_name`：来源方案名称快照

第一版方案绑定具体模板 ID。这样“项目总监方案”打开时看到的是确定的一套文件，避免同类型模板因为规则变化导致批量生成结果漂移。

## 后端接口

新增方案接口：

- `GET /oa/signPackage/plan/list`
- `GET /oa/signPackage/plan/{planId}`
- `POST /oa/signPackage/plan`
- `PUT /oa/signPackage/plan`
- `POST /oa/signPackage/plan/{planId}/status`

新增批量接口：

- `POST /oa/signPackage/batch/preview`
- `POST /oa/signPackage/batch/createDrafts`

`preview` 输入方案 ID、岗位名、部门 ID、员工 ID 列表等筛选条件，返回候选员工、默认字段、每个员工的缺失字段和可编辑预览行。`createDrafts` 只创建资料完整的草稿，不发送。每个草稿写入 `source_plan_id` 和 `source_plan_name`，方便追溯。

新增草稿编辑接口：

- `PUT /oa/signPackage/{packageId}`

该接口仅允许编辑 `draft` 状态的签约包，不能修改已发送、已查看、已签署或已撤回的包。

## 校验规则

- 方案名称必填且同一组织下不能重复。
- 方案至少绑定一个启用模板。
- 批量创建时员工必须存在且在当前组织权限范围内。
- 批量创建不允许自动发送，所有新包状态固定为 `draft`。
- 若预览行缺身份证、手机号、姓名、场景等核心字段，该行不能生成草稿，直到运营人员在预览表中补齐。
- 发送签约包前复用并强化现有校验：必填快照字段、模板清单、岗位等级和薪酬版本必须完整。

## 前端设计

“员工签约”页面新增：

- 主按钮：`批量按岗位生成`
- Tab 入口：`签约方案`

批量弹窗包含三段：

- 方案区：选择方案，展示方案默认字段和合同清单。
- 员工区：按岗位、部门、关键字筛选，支持勾选员工。
- 预览区：展示每个员工会生成的草稿、缺失字段、可编辑快照字段和模板数量。

生成成功后跳回签约包列表，并自动筛选新生成的草稿，运营人员逐个点开确认后发送。

草稿详情增加“编辑”入口，仅 `draft` 状态可见。编辑弹窗复用现有新建签约包字段，保存后重新匹配并展示方案文件清单。

## 复用与边界

- 复用 `OaSignPackage`、`OaSignTemplate`、`OaSignPackageDocument` 和现有发送、签署、下载逻辑。
- 复用现有模板占位符校验和文件生成逻辑。
- 发送时如果签约包来自方案，优先使用方案绑定模板；没有来源方案的包继续使用现有模板匹配规则。
- 不把批量方案直接做成文件模板，因为方案描述的是“一组合同和默认字段”，不是单个文件。
- 不新增员工移动端逻辑，员工看到的仍是现有“我的签约”。

## 测试

后端测试：

- 方案保存时拒绝空名称和空模板。
- 批量预览按岗位筛出正确员工。
- 批量创建只生成草稿，不生成文件、不发送。
- 缺必填字段的员工在预览中返回缺失字段，未补齐时不能生成草稿。
- 草稿编辑只允许 `draft` 状态。
- 草稿发送时仍按方案模板生成正确文件。

前端测试：

- API 方法覆盖方案管理、批量预览、批量创建。
- 页面包含“批量按岗位生成”和“签约方案”入口。
- 批量弹窗展示方案、员工、预览和缺失字段。
- 草稿行展示“编辑”入口，非草稿行不展示。
- 不出现批量直接发送按钮。

## 风险与处理

- 员工资料不完整：通过预览缺失字段和发送前校验处理。
- 岗位名不统一：第一版使用精确岗位名匹配，同时支持人工勾选员工兜底。
- 模板规则变化影响历史方案：方案绑定具体模板 ID，生成时快照模板信息。
- 批量生成重复草稿：预览中提示同员工同方案已有未发送草稿，默认跳过，允许手动选择是否再次生成。
