# 人事管理工作台优化设计

## 背景

当前 `人事管理` 页面已经能进入，但体验仍停留在“能打开”的水平：页面用一个共享表格承载员工档案、入职、资料完整度和导入导出，字段少、信息密度不合理，HR 难以快速判断某个员工是谁、在哪、当前要处理什么。

本设计承接两个既有方案：

- `2026-07-08-hr-personnel-management-design.md`：人事管理应包含员工档案、入职管理、资料完整度、人事导入导出。
- `2026-07-06-user-employee-profile-fields-design.md`：员工档案字段已经按系统账号、组织岗位、个人身份、学历、用工合同、联系人银行等口径拆分。

本轮优化目标不是新增一套复杂流程，而是把已有 HR 页面从“字段堆表格”调整为“HR 工作台 + 分层资料”的可用体验。

## 已确认方向

采用 `HR 工作台式列表`，并使用更松的默认布局：

- 顶部展示任务队列和关键指标。
- 主区域保留完整员工列表空间。
- 员工详情不常驻占位，点击员工后再打开右侧抽屉。
- 详细资料和编辑页按字段分组展示完整档案。

不采用以下方案：

- 只补强当前表格：改动小，但仍会让 HR 在横向大表中找信息。
- 一次性完整重做全流程：体验最好，但会把未完成的数据结构、入职确认、导入预检、账号绑定全部压入同一轮，交付风险过高。

## 页面结构

### 顶部任务队列

顶部用指标卡承载 HR 每天要处理的队列：

- 全部员工
- 待补资料
- 待确认入职
- 合同将到期
- 离职待处理

每个指标卡可以作为快捷筛选入口。默认不占用左侧常驻导航，避免主列表空间变窄。

### 主列表

主列表是默认工作区，用于找人、筛选、查看风险和发起操作。

列表顶部提供：

- 智能搜索：姓名、手机号、工号、身份证后四位。
- 高级筛选：部门/门店、员工状态、人员类别、入职时间、完整度、账号绑定状态。
- 列设置：允许高级用户临时打开更多列。
- 导入导出入口。

员工行采用两行摘要：

- 第一行：姓名、工号、手机号、公司/门店/岗位/职级、员工状态、完整度或风险标签。
- 第二行：直属主管、入职日期、账号状态、当前可执行动作。

这样列表可以比普通表格更容易扫读，同时保留分页、筛选和导出能力。

### 简略资料抽屉

点击员工后打开右侧抽屉。抽屉用于快速确认和处理，不替代完整详情页。

抽屉展示：

- 基本身份：姓名、手机号、性别、年龄、员工状态、人员类别。
- 工作信息：所属公司、部门、门店、职位、职级、部门主管、直属主管、入职日期。
- 入职合同摘要：合同类型、社保类型、试用期、计划转正、实际转正、合同到期风险。
- 资料风险：入职必填完整度、完整档案完整度、缺失项摘要、附件状态摘要。
- 账号信息：是否绑定账号、账号是否启用。
- 数据记录：资料来源、最后更新人、最后更新时间。

抽屉操作：

- 查看详细资料
- 编辑档案
- 查看缺失资料
- 绑定/查看账号
- 导出该员工资料

### 详细资料和编辑页

详细资料与编辑页按同一字段分组，避免维护两套信息结构。

分组如下：

1. 基础信息：姓名、手机号、性别、出生日期、民族、婚姻状况、国籍、是否外籍、健康状况、政治面貌。
2. 组织岗位：所属公司、1/2/3 级部门、4 级门店、职位、职级、部门主管、直属主管、法人单位。
3. 身份户籍：证件类型、证件号码、血型、户口所在地、现居住地址。
4. 教育信息：第一学历、第一学位、毕业时间、毕业学校、专业、最高学历、最高学位、最高学历毕业时间、最高学历毕业学校、最高学历专业。
5. 用工合同：员工状态、人员类别、招聘渠道、参加工作时间、入职时间、试用期、计划转正日期、实际转正日期、本岗位任职日期、合同起止日、合同类型、合同期限、续签次数、工作所在地、城市级别、考勤方式、离职时间。
6. 社保户籍：户口性质、社保类型、社保缴纳地、公积金缴纳地。
7. 联系人与银行：办公电话、邮箱、紧急联系人、关系、联系电话、开户银行、银行卡号。
8. 附件与记录：身份证人像面、身份证国徽面、学历证书、学位证书、离职证明、员工照片状态、资料来源、更新人、更新时间。

## 字段分层

### 默认列表字段

默认列表只展示高频识别字段和风险字段：

- 姓名
- 工号
- 手机号
- 所属公司
- 部门/门店
- 职位
- 职级
- 员工状态
- 人员类别
- 入职日期
- 资料完整度
- 账号绑定状态
- 关键风险标签

### 列设置可选字段

列设置允许打开但默认隐藏：

- 直属主管
- 部门主管
- 合同起始日
- 合同到期日
- 合同类型
- 社保类型
- 社保缴纳地
- 公积金缴纳地
- 法人单位
- 招聘渠道
- 离职时间

### 敏感字段

敏感字段不进入默认列表：

- 证件号码
- 银行卡号
- 户口所在地
- 现居住地址

这些字段只在详细资料或编辑页展示，并按权限脱敏或隐藏。完整导出仍要求 `hr:employee:export` 权限。

## 四个页面的职责

### 员工档案

作为 HR 主工作台，承载全量员工查询、简略资料、详细资料、编辑和导出。

### 入职管理

只展示入职相关队列：

- 待填写
- 待补资料
- 待确认
- 已入职
- 取消入职

入职管理复用员工档案字段分组，但默认聚焦入职必填项、预计入职日期、资料完整度、确认入职动作。

### 资料完整度

以问题排查为主，不作为普通员工列表的重复页面。

提供两个视角：

- 按员工：显示完整度、缺失字段数量、缺失项摘要、去补资料。
- 按部门/门店：显示员工数、完整人数、缺资料人数、完整率。

### 人事导入导出

作为批量操作中心：

- 下载入职资料模板
- 下载员工档案模板
- 导入待入职人员
- 导入或更新员工档案
- 导出员工档案
- 导出待补资料清单

第一轮优化可以先保留现有导入导出能力，页面上明确模板、导入、导出和结果区；后续再做两步导入预检。

## 数据与接口策略

短期保持当前 `SysUser + SysUserProfile` 返回结构，先优化前端体验和 HR 专用接口包装：

- `/system/hr/employee/list`
- `/system/hr/employee/{userId}`
- `/system/hr/onboarding/list`
- `/system/hr/completeness/list`
- `/system/hr/employee/export`
- `/system/hr/employee/importData`
- `/system/hr/employee/importTemplate`

完整入职流程所需的 `onboarding_status`、待入职未绑定账号、导入预检、确认入职等后端能力放入下一阶段，不阻塞本轮页面体验优化。

## 权限与安全

- HR/管理员可查看完整人事资料。
- 店长/主管可按数据范围查看简略资料。
- 敏感字段按权限脱敏或隐藏。
- 完整导出、单人资料导出、导入确认均保留独立权限。
- 离职人员的账号停用风险在列表和抽屉中提示，但是否自动停用账号按后端规则另行实现。

## 测试计划

前端静态测试：

- HR 页面存在并指向 HR 专用 API。
- 员工档案页面包含顶部任务队列、智能搜索、高级筛选、列设置、员工摘要行、详情抽屉入口。
- 字段分组包含基础信息、组织岗位、身份户籍、教育信息、用工合同、社保户籍、联系人银行、附件记录。
- 默认列表不包含证件号码、银行卡号、户籍地址、现居住地址。

后端契约测试：

- HR 控制器保留员工档案、入职管理、资料完整度接口。
- HR 导入导出接口保留独立权限。
- 登录用户查询不因员工档案字段缺失导致 SQL 报错。

构建验证：

- `npm --prefix erp-ui run test -- hrPersonnelRoutes.test.js`
- 新增 HR 页面优化静态测试。
- `npm --prefix erp-ui run build:prod`
- `mvn -pl erp-modules/erp-system -am -Dtest=HrPersonnelControllerSourceTest -Dsurefire.failIfNoSpecifiedTests=false test`

## 分阶段实施

### 本轮

- 优化员工档案列表为 HR 工作台。
- 增加顶部任务队列和风险指标。
- 扩展筛选、列设置、摘要行。
- 将详情抽屉调整为简略资料。
- 新增详细资料分组展示。
- 调整入职管理、资料完整度、导入导出页面的页面职责和空/加载/错误状态。

### 下一轮

- 后端独立 HR profile DTO。
- 待入职人员允许未绑定账号。
- 入职确认和取消入职。
- 完整度后端统一计算。
- Excel 两步导入预检和确认。
- 附件上传、预览和审核。

## 设计结论

本轮采用“更松的人事工作台 + 按需详情抽屉 + 完整分组资料”的优化方案。它保留完整员工档案字段，同时避免默认界面拥挤；先解决 HR 查人、补资料、看风险、进入详情这些高频任务，再逐步补齐入职流程和导入预检。
