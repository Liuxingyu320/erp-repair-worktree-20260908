# OE/礼盒资料库存管理式页面改造设计

## 背景

系统已经具备 OE 分类、OE 管理、礼盒分类、礼盒管理，以及进销存只读查询入口。当前 `OE管理`、`OE资料查询`、`礼盒管理`、`礼盒资料查询` 复用的是简单资料页结构：顶部筛选卡、表格、详情抽屉。用户要求这些页面要和 `库存管理` 页面差不多，手机端也要对齐；同时确认手机端只做查询展示，不做新增、编辑、删除、导入。

本设计只改 OE/礼盒资料页面体验，不改变 OE/礼盒数据模型，不把 OE/礼盒接入库存业务，不新增手机端维护能力。

## 目标

- 桌面端 `OE管理`、`OE资料查询`、`礼盒管理`、`礼盒资料查询` 都改为库存管理式工作台布局。
- 桌面维护入口保留新增、编辑、删除、导入、下载模板、导出。
- 桌面查询入口保持只读，只保留查询、重置、刷新、详情、导出。
- 手机端 `/mobile/oe`、`/mobile/gift` 只做查询展示，列表和详情体验向手机库存页靠齐。
- OE/礼盒图片在详情中可预览，不再只展示图片 URL 文本。
- 改造不影响商品、库存、采购、销售、调拨、盘点页面。

## 非目标

- 不新增 OE 或礼盒库存表。
- 不增加 OE/礼盒库存调整、库存流水、入库、出库、盘点能力。
- 不让手机端维护 OE/礼盒资料。
- 不改固定资产 OE 关联规则。
- 不改变后端权限模型，仅使用现有 OE/礼盒列表、详情、分类树、导出、导入和维护权限。

## 桌面端设计

### 页面结构

`OE管理`、`OE资料查询` 继续复用 `erp-ui/src/views/inventory/oe/index.vue`，通过现有 `readonlyMode` 区分维护和查询。

`礼盒管理`、`礼盒资料查询` 继续复用 `erp-ui/src/views/inventory/gift/index.vue`，通过现有 `readonlyMode` 区分维护和查询。

两个页面都改为库存页同款三段式结构：

- 左侧分类面板。
- 右侧筛选和统计区域。
- 右侧表格区域。

### 左侧分类面板

OE 页面使用 OE 分类树，根节点文案为 `全部OE`。

礼盒页面使用礼盒分类树，根节点文案为 `全部礼盒`。

分类面板行为对齐库存页：

- 支持分类搜索。
- 支持刷新分类。
- 支持收起和展开。
- 点击分类后写入 `queryParams.categoryId`，重置页码并刷新列表。
- 底部显示当前分类和当前列表总数。
- 分类加载失败时显示简短错误提示。

桌面窄屏下分类面板改为顶部纵向区域，收起后不占高度。

### 筛选区

筛选区使用库存页 `search-card` 风格。

OE 筛选项：

- 物品名称。
- 产品编号。
- 供应商。
- 状态。

礼盒筛选项：

- 礼盒名称。
- 礼盒编码。
- 等级。
- 状态。

分类不再作为右侧下拉主筛选，改由左侧分类树承担。重置时清空分类、关键词和状态，并将分类树选回根节点。

维护入口按钮：

- 刷新。
- 新增。
- 导入。
- 下载模板。
- 导出。

查询入口按钮：

- 刷新。
- 导出。

新增、导入、下载模板、编辑、删除在只读模式中不可见。

### 统计卡

统计卡不新增后端接口，优先基于当前分页返回数据和列表总数计算轻量指标。统计口径为当前筛选条件下的当前页可见数据，标题文案避免表达成全库汇总。

OE 统计卡：

- `资料总数`：使用接口返回 `total`。
- `当前页启用`：当前页 `status === "0"` 数量。
- `当前页停用`：当前页 `status === "1"` 数量。
- `当前页有成本价`：当前页成本价大于 0 的数量。

礼盒统计卡：

- `资料总数`：使用接口返回 `total`。
- `当前页启用`：当前页 `status === "0"` 数量。
- `当前页停用`：当前页 `status === "1"` 数量。
- `当前页有指导价`：当前页 `guidePrice1` 或 `guidePrice2` 大于 0 的数量。

如果后续需要全量统计，再单独补后端 summary 接口；本次不扩大后端范围。

### 表格区

表格卡对齐库存页：

- 卡片头部显示当前分类。
- 右侧提供刷新按钮。
- 表格上方显示状态切换和总条数。
- 行点击打开详情。
- 表格保持小尺寸、无厚重边框，视觉靠近库存表格。

OE 状态切换：

- 全部OE。
- 启用OE。
- 停用OE。

礼盒状态切换：

- 全部礼盒。
- 启用礼盒。
- 停用礼盒。

维护入口表格操作：

- 详情。
- 编辑。
- 删除。

查询入口表格操作：

- 详情。

### 详情展示

桌面详情统一改为库存详情风格的弹窗，左侧图片预览，右侧 `el-descriptions` 字段详情。

OE 详情字段：

- 产品编号。
- 物品名称。
- 上线分类。
- 产品类别名称。
- 订货单位。
- 成本价。
- 供应商。
- 供应商电话。
- 产品描述。
- 状态。
- 备注。

礼盒详情字段：

- 礼盒编码。
- 产品名称。
- 上线分类。
- 等级。
- 规格。
- 补货单位。
- 指导售价1。
- 指导售价2。
- 产品描述。
- 状态。
- 备注。

图片为空时显示 `暂无图片`。

### 维护表单

维护表单继续使用现有抽屉和校验逻辑，不在本次改成弹窗。这样可以减少对新增、编辑、导入流程的影响。

## 手机端设计

### 范围

手机端只改 `/mobile/oe`、`/mobile/gift` 的查询展示体验，不新增维护入口。

不出现这些操作：

- 新增。
- 编辑。
- 删除。
- 导入。
- 下载模板。

可以保留：

- 刷新。
- 搜索。
- 快捷筛选。
- 查看详情。
- 导出，前提是用户有导出权限且现有手机导出能力可用。

### 快捷筛选

OE：

- 启用OE。
- 停用OE。
- 全部OE。

礼盒：

- 启用礼盒。
- 停用礼盒。
- 全部礼盒。

默认进入启用资料。

### 搜索

OE 搜索字段：

- OE名称。
- OE编码。
- 供应商。

礼盒搜索字段：

- 礼盒名称。
- 礼盒编码。
- 等级。

### 列表卡片

OE 列表卡片展示：

- 标题：物品名称。
- 编码：产品编号。
- 摘要：上线分类、成本价。
- 仓库上下文可显示供应商；门店上下文隐藏供应商。
- 状态：正常或停用。

礼盒列表卡片展示：

- 标题：产品名称。
- 编码：礼盒编码。
- 摘要：上线分类、指导售价1、指导售价2。
- 状态：正常或停用。

### 详情

手机详情继续使用 `MobileDetailSheet`。字段与桌面详情保持一致，但 OE 在门店上下文隐藏供应商和供应商电话；仓库上下文显示供应商信息。

手机详情不展示维护按钮。

## 权限和数据边界

桌面维护入口按现有维护权限控制：

- OE：`inv:oe:add`、`inv:oe:edit`、`inv:oe:remove`、`inv:oe:import`、`inv:oe:export`。
- 礼盒：`inv:gift:add`、`inv:gift:edit`、`inv:gift:remove`、`inv:gift:import`、`inv:gift:export`。

桌面查询入口按现有列表、详情、导出权限控制。

手机端不因为用户有维护权限而展示维护动作，只展示查询体验。

## 实现边界

建议先在 OE/礼盒页面内部复用库存页样式结构，避免把库存页直接拆成公共组件造成额外风险。可抽取少量通用方法名和 CSS 类，但不做跨模块大重构。

涉及文件：

- `erp-ui/src/views/inventory/oe/index.vue`
- `erp-ui/src/views/inventory/gift/index.vue`
- `erp-ui/src/views/mobile/mobileRouteDefinitions.js`
- `erp-ui/src/views/mobile/feature/featureSearchConfigs.js`
- `erp-ui/src/views/mobile/feature/featureMapper.js`
- `erp-ui/test/oeGiftManagement.test.js`
- 视实现需要补充或更新手机端相关测试。

## 测试验收

前端静态测试需要覆盖：

- OE 页面包含库存式分类布局、统计卡、状态切换。
- 礼盒页面包含库存式分类布局、统计卡、状态切换。
- 只读模式隐藏新增、编辑、删除、导入、下载模板。
- 维护模式保留新增、编辑、删除、导入、下载模板、导出。
- OE 详情展示图片预览、成本价、供应商信息。
- 礼盒详情展示图片预览、指导售价。
- 手机 OE 和礼盒快捷筛选包含启用、停用、全部。
- 手机 OE 和礼盒不配置新增、编辑、删除、导入动作。
- 手机 OE 门店上下文隐藏供应商，仓库上下文显示供应商。

手工验收建议：

- 桌面宽屏查看四个入口，确认布局接近库存管理。
- 桌面窄屏查看分类面板上下排列和收起效果。
- 手机端访问 `/mobile/oe` 和 `/mobile/gift`，确认只有查询展示能力。
- 在查询入口确认无法触发维护操作。

## 风险

- 当前统计卡不做全量汇总，只统计 `total` 和当前页可见状态数量；如果业务需要全量启用/停用统计，需要后端新增 summary 接口。
- 维护页和查询页复用同一组件，必须确保 `readonlyMode` 条件覆盖所有写操作入口。
- 手机端通用 feature 运行时被多个模块复用，改动应只针对 `oe` 和 `gift` 配置，避免影响库存、商品、销售等模块。
