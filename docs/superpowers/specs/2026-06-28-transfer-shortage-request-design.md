# 调拨缺货要货设计

日期：2026-06-28

## 背景

当前调拨管理的门店要货流程要求先选择要货仓库，再从该仓库的可用库存中加入商品明细。这个设计适合仓库已有库存的补货场景，但当仓库没有该商品库存时，门店无法把真实需求提交到调拨流程中，导致后续只能转到线下沟通或另走采购申请，仓库也看不到统一的门店要货进度。

后端调拨单保存和提交并不要求提交时已有仓库库存；库存校验发生在仓库发货阶段。因此本次改造优先解决前端入口限制，让门店可以在调拨管理内提交“仓库当前无货但门店需要”的要货单。

## 目标

- 门店在调拨管理发起要货时，可以选择仓库当前有库存的商品，也可以选择仓库当前无库存的商品。
- 仓库无库存商品加入明细后，在页面上明确标记为“仓库缺货”。
- 门店可以保存草稿并提交包含缺货商品的要货单。
- 审批通过后，单据仍进入仓库待处理列表。
- 仓库当前库存不足时不能发货，必须先采购入库或库存调整；库存补足后继续在原调拨单上发货。
- 保持原有审批、分批发货、按批次收货和调拨记录流程不变。

## 非目标

- 不新增独立的缺货申请模块。
- 不把调拨单自动转成采购单。
- 不新增数据库字段保存缺货状态。
- 不改变仓库发货扣库存和门店收货入库的后端库存规则。
- 不允许仓库负库存发货。

## 已确认方案

### 调拨里增加“从商品档案选择”

在“发起要货”弹窗中保留现有“从仓库库存选择”，同时新增“从商品档案选择”。商品档案选择使用现有 `ProductSelect`，不依赖仓库库存记录。加入明细后，系统根据当前选择的仓库实时查询库存并显示可用数量；没有库存或可用数量为 0 时显示“仓库缺货”。

采购动作仍由仓库或采购人员在现有采购入库、库存调整流程中完成；调拨单不自动生成采购单。

## 页面交互

### 发起要货弹窗

- “添加明细”区域拆成两个入口：
  - “从仓库库存选择”：沿用当前库存选择弹窗，只显示仓库可用库存商品。
  - “从商品档案选择”：打开商品档案选择弹窗，使用现有商品选择组件搜索启用商品。
- 从商品档案选择商品后，加入要货明细，默认数量为 1。
- 明细行继续展示商品、编码、要货数量、单位、仓库可用和规格。
- 仓库可用显示规则：
  - 可用数量大于 0：显示数量。
  - 没有库存记录或可用数量等于 0：显示“仓库缺货”。
- 同一个商品不能重复加入同一张要货单。
- 切换要货仓库时，已选明细保留，但重新计算每个商品在新仓库的可用库存和缺货提示。

### 调拨处理中列表和详情

列表不新增主状态。缺货与否是仓库当前库存的实时状态，不作为主单状态保存。

详情中继续展示要货明细、已发货和剩余待发。若后续需要更强提示，可以在详情明细中按当前仓库库存补充“当前可用/缺货”展示，但本期不强制。

### 仓库发货

仓库发货弹窗保持原流程。用户点击发货时，后端继续按当前仓库库存做强校验：

- 库存足够：扣减仓库库存，生成待收货批次。
- 库存不足：阻止发货，并提示“库存不足，请先采购入库或调整库存后再发货”。

## 后端行为

后端调拨保存和提交继续复用现有 `saveDraft`、`submitTransfer` 和 `prepareDetails` 逻辑。提交阶段只校验商品、数量、门店和仓库权限，不增加库存必须充足的校验。

发货阶段继续由 `deliverTransfer` 锁定调拨单和库存行，按商品、来源仓库检查可用库存。库存不足时抛出业务异常，不允许负库存或超量发货。

本期不新增表结构。`inv_transfer_detail` 继续保存商品、数量、已发货、已收货、单位、规格和排序。缺货状态由前端根据当前仓库库存查询结果派生。

## 权限和数据范围

- 门店仍只能在当前门店上下文发起要货。
- 要货仓库仍只能选择当前用户可见或业务允许的仓库。
- 商品档案选择仍只允许选择启用商品，并遵守现有商品查询权限。
- 仓库仍只能处理自己有权限的来源仓库调拨单。

## 错误处理

- 未选择要货仓库时，不能添加明细。
- 未选择商品或数量小于等于 0 时，不能保存或提交。
- 商品档案选择失败时，提示用户重新查询或稍后再试。
- 查询仓库库存失败时，明细保留，但仓库可用列显示“库存待确认”，保存和提交不受阻断。
- 仓库发货库存不足时，保留原单据状态，仓库补足库存后可继续发货。

## 测试

### 前端单元测试

- 发起要货弹窗同时存在“从仓库库存选择”和“从商品档案选择”入口。
- 从商品档案选择仓库无库存商品后，可以加入明细并显示“仓库缺货”。
- 缺货明细可以通过前端校验并提交。
- 切换要货仓库后，明细不丢失，库存提示重新加载。
- 已选商品不能重复加入。

### 后端单元测试

- 门店可以提交包含无库存商品的仓库补货调拨单。
- 仓库库存不足时发货失败，错误信息明确，调拨单状态不被推进。
- 仓库补足库存后，同一张调拨单可以继续发货。

### 回归测试

- 仓库有库存商品的原有要货、审批、发货、收货流程不变。
- 分批发货和按批次收货流程不变。
- 普通用户不能选择未授权要货仓库。
