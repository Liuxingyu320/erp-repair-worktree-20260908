# HR 操作记录与员工字段人性化设计

## 目标

修复入职操作记录和员工档案中直接暴露技术值的问题，让业务用户看到可理解、可行动、时区正确的内容，同时保留脱敏和审计边界。

## 操作记录

- 后端详情日志增加结构化的 `fromStatus`、`toStatus`、`changedFieldKeys`，继续保留 `summary` 作为兼容字段。
- 编辑请求没有任何实际变更时直接返回当前详情，不更新版本、不写空日志。
- 前端使用集中映射把操作类型、状态和字段 key 转为中文，不解析敏感字段的前后值。
- 日志按最新优先显示，默认显示最近 5 条，可展开更早记录。
- 时间按中国业务时区显示为 `MM-DD HH:mm`，完整时间作为辅助信息。
- 文案采用“操作人 + 业务动作”，例如“管理员将状态从待到岗退回待补资料”“管理员修改了目标门店、备注”。

## 员工字段

- 后端员工详情 DTO 增加 `departmentName` 和 `postNames`，前端不再展示 `deptId`、`postIds`。
- 后端写入 `fields` Map 前，把所有日期字段转换为 GMT+8 的 `yyyy-MM-dd` 字符串，避免 Map 值绕过字段注解后输出 UTC ISO 时间。
- 前端集中格式化枚举：性别、是否外籍、空值和数组，不直接展示 `0`、`1`、`[81]`。
- 组织岗位使用部门名与岗位名；无法解析时显示“名称未配置”，而不是内部 ID。

## 缺失资料

- 从共享 `DETAIL_GROUPS` 自动生成完整字段标签表，所有缺失字段都使用中文标签。
- 按基础信息、组织岗位、身份户籍、教育信息、用工合同、社保公积金、联系人与银行分组。
- `READ_ONLY_DERIVED_FIELDS` 单独归入“系统待完善”，说明由组织配置或系统计算，避免用户被要求填写不可编辑字段。
- 可编辑缺失项显示分组数量和“编辑档案”入口；不再使用逗号或顿号拼成长段文本。

## 交互与可访问性

- 入职确认按钮不可用时显示明确原因，不只依赖灰色禁用态。
- 日志展开按钮可键盘操作，状态信息同时使用文字而非只依赖颜色。
- 保持敏感字段默认脱敏，查看原值继续走现有权限与审计接口。

## 验收

- 截图中的 `STATE_CHANGE`、`READY -> DRAFT`、`targetStoreId`、ISO 日期、`sex=0`、`deptId=1150`、`postIds=[81]` 和英文缺失字段不再出现。
- 无字段变化的保存不会新增操作日志。
- 后端结构化日志、GMT+8 日期、部门/岗位名称测试通过。
- 前端字段映射、分组、日志呈现测试及生产构建通过。
