## 1. 问题与目标

正式方案要求后台页面形成稳定、可复用的数据浏览骨架。当前调拨工作台已经具备筛选、视图密度、列偏好、导出和桌面/移动双布局，但筛选字段、桌面表格容器、移动卡片列表和空结果语义仍全部内嵌在领域页面中，无法由后续库存、采购、销售等工作台复用。

本切片提取标准筛选栏、筛选字段和响应式数据视图三个平台组件，并将调拨工作台作为第一个真实消费者。组件只负责语义、布局、密度和空结果呈现；领域页继续掌握数据过滤、列定义、行内容、权限动作、偏好保存和导出逻辑。

## 2. 已确定契约

- `ErpFilterBar` 使用原生 `form` 与 `role="search"`，阻止默认提交，提供筛选字段默认插槽和工具区插槽；
- `ErpFilterField` 负责可点击标签、筛选控件尺寸与响应式宽度，不持有筛选值，不改变输入事件；
- `ErpResponsiveDataView` 使用原生 `table`、`caption`、`thead`、`tbody` 和移动端有序列表；桌面表格与移动卡片通过命名插槽保留领域类型边界；
- 数据视图明确接收 `empty`、空结果标题和说明；空结果时只渲染现有 `ErpEmptyState`，不制造占位行；
- 密度只控制已有紧凑/舒适间距，不改变可见字段、筛选结果或可执行动作；
- 调拨工作台的筛选、视图偏好、列偏好、CSV 导出、Mock Gateway、功能权限和路由行为保持不变；
- 高频筛选、密度切换、键盘操作和桌面/移动布局切换不增加 animation、transition、keyframes、弹跳或循环动效；
- 不复制 21st.dev、React Bits、Magic UI、Motion Primitives、Uiverse、UI Prompt Library 或 MotionSites 的代码，只沿用已记录的企业后台设计原则。

## 4. 实施顺序

1. 先用组件测试锁定筛选表单语义、标签关联、工具插槽和默认提交阻止；
2. 先用组件测试锁定原生表格结构、移动列表、密度类和显式空结果；
3. 实现三个无领域依赖的平台组件；
4. 将调拨工作台筛选区和桌面/移动结果区接入组件，删除已下沉的重复样式；
5. 补充调拨工作台筛选无结果与清除筛选回归测试；
6. 执行定向测试、完整 `npm run verify`、源码隔离扫描和 Git 隔离复核。

## 5. 验证门禁

- 筛选栏具备可访问搜索区名称，标签与输入控件保持原生关联，提交不会刷新或导航；
- 数据视图在有数据时同时提供语义正确的桌面表格和移动列表，在无数据时只展示明确空结果；
- 调拨工作台完整权限与只读权限动作测试继续通过；
- 搜索或状态筛选为零结果时展示空结果，清除筛选后恢复数据；
- `npm run verify` 必须通过 Prettier、ESLint、Vue TypeScript strict、OpenAPI 门禁、Vitest 与 Vite 构建；
- `git diff --check` 与源码隔离测试必须通过；
- 静态扫描必须证明无新依赖、无旧前端引用、无真实网络请求、无 Docker/数据库配置变化。

## 6. 停止线

- 不启动 Vite/Playwright web server、Docker、MySQL、Redis、Nacos 或后端服务；
- 不执行 `npm install`、`npm ci` 或任何联网依赖命令；
- 不修改真实 Writer、`.env.local`、端口、凭据或运行数据；
- 不访问受保护原项目，不删除旧前端，不合并、不推送。
