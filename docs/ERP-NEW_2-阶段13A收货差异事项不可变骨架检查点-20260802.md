## 1. 已完成结果

- 新增加法迁移源码 `sql/erp_inventory_transfer_discrepancy_v2_20260802.sql`，只定义 ERP-NEW_2 专属 `inv_transfer_receipt_discrepancy_case`，未执行迁移。
- 每个 V2 收货分配按 `damaged`、`shortage` 分别生成不可变事项；同一分配同时存在两类差异时生成两条，不合并语义。
- 事项保存数量、来源成本、六位小数金额、说明、证据引用与 SHA-256 事实指纹，初始状态固定为 `awaiting_confirmation`、版本为 `0`。
- Planner 在第一条 DML 前完成稳定排序和全部事实构造；Executor 在第一条 DML 前复核事项维度、金额、证据与指纹。
- Mapper 使用受关系约束的 `insert ... select`，从刚写入的不可变收货分配核对数量、成本、说明和证据；单行数或生成键不满足时，由现有唯一外层事务回滚整次收货。
- 持久化顺序固定为：收货事实与收货分配 → 差异事项 → 序列号 → 累计量 → 台账 → 生命周期。
- 旧 `InvTransferDiscrepancyProcessor` 与旧差异 Mapper 没有接线、没有访问 V2 新表；现有写入和持久化就绪 Gate 仍默认为 `false`。
